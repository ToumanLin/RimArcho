Spike corpusrun — RimArcho's own attribution and sorter over the HugsLib log corpus
(docs/research/00-日志语料顶层设计.md, P1: G1 attribution, G2 ordering)
Run: 2026-10-20, local machine. Only aggregate numbers are recorded here; per-log results stay with
the corpus (results-v3.jsonl next to RimArcho-corpus, not in any repository).

== Setup

- Sample: one whole day per month (the 15th, UTC) from 2025-07 to 2026-10 via the GitHub API
  listing (180,479 gists indexed, 6,093 downloaded) plus the P0 window (998). 6,734 logs of 1.6
  kept for this run (1.5 and older dropped; the 50 logs of 1.7 are tracked separately).
- Research environment: a separate RIMARCHO_HOME, the public 1.6 branch installed with SteamCMD
  (D:\RimWorld16, Core + 5 DLCs), the author's 1,275 Workshop mods, and 1,960 downloaded mods (the
  top 3,000 packages of the sample that were neither local nor unmappable; packageId -> Workshop id
  via RimSort's steamDB.json, by packageId or a unique name; the download is checked against
  About.xml's own packageId). 3,475 instances.
- Per log: its mod list becomes ModsConfig.xml; the product's analysis (patch simulation), then
  AnalyzeLogText on the log body (G1), then SortInput + order.Sort on the log's own order (G2).
- Library coverage per log (mod entries the environment resolves): p10 0.65, median 0.82, p90 0.94;
  3,884 logs >= 0.80.
- Mods are the current Workshop versions, not the versions the players had.

== Performance found on the way (fixed, d4e074e, schema v10)

Analysis took 74-133 s per log: saveHarmony deletes each instance's facts by (instance_id,
game_mm), and SQLite used type_fact_mm (all rows share game_mm) and scanned harmony_id. 63% of the
CPU. With composite indexes: 3.5-13 s. 6,734 logs in about 11 h.

== G4 severity calibration

For each finding: does the same log have a problem cluster attributed to a subject mod (any role),
of the classes the finding predicts, and how often would that happen by chance (a log where a
share b of the resolved mods has such a cluster gives 1-(1-b)^k for k subject mods)? "text": a
cluster that names the finding's def, patch file or Harmony target (message, details or stack).

                            findings  logs  severity  expected class: observed / chance   text
  patch.no-match               2,091   227  warning   patch-failed            42.9% / 1.3%  14.5%
  patch.contested              1,713   287  info      patch/xml/xref          39.3% / 8.6%   0
  harmony.multi-transpiler     3,124   482  warning   exception/harmony       33.2% / 9.2%   0.3%
  harmony.skip-prefix         41,156   592  info      exception/harmony       32.8% /11.7%   0.5%
  harmony.shared-target       82,657   631  info      exception/harmony       31.5% /10.3%   0.4%
  def.abstract-collision       2,603   372  warning   xml-load/xref           22.2% / 8.8%   1.2%
  dep.inactive                   527   239  error     xml/xref/exc/patch      20.5% /13.8%   0
  def.parent-missing           1,455    83  error     xml-load/xref           17.0% / 4.4%  14.7%
  def.override                42,178   656  info      xml/xref/exception      14.1% /10.5%   0.7%
  harmony.manual              17,148   658  info      exception/harmony        8.8% / 4.9%   0
  patch.unknown-op             4,206   554  info      patch-failed/xml         7.6% / 1.8%   0
  order.violated (any class)   2,713   491  warning   any                     28.7% /14.8%
  official.order (any class)     192   192  error     any                     15.1% / 6.4%
  incompat.active (any class)     20    18  error     any                     30.0% /17.4%
  order.cycle (any class)         45    45  warning   any                      6.7% /15.8%
  dep.missing                      4     4  error     (548 more: the player had the dependency,
                                                       the library does not; not counted)

Reading:
- patch.no-match is the best-calibrated finding: 33x chance, and in 14.5% the log's patch-failed
  cluster names the same patch file. Warning fits. Not checked why 57% have no matching error;
  candidates: operations inside a Sequence/FindMod whose failure the game does not log, and mod
  versions in the library that differ from the player's.
- def.parent-missing (error) is 4x chance and the only def finding whose text shows up (14.7%);
  but 83% of the findings have no visible error. "likely" confidence is right, error severity is
  too high for an unseen effect.
- dep.inactive (error) is only 1.5x chance; official.order (error) 2.4x on any class. These are
  declared, not observed, problems; with load-order errors rare (G2), error is too strong.
- def.override (info) is at chance (1.3x): keeping it hidden by default is right.
- The Harmony findings are 3x chance, but their subjects are patchers and the attribution of
  harmony-stack clusters names patchers by the Harmony lines in the stack, so part of this is
  circular. The target method appears in the error's stack for < 1% of findings: shared targets,
  skip prefixes and multiple transpilers almost never show up as an error on that method.
  multi-transpiler as warning is not supported by the logs; skip-prefix and shared-target as info
  are.
- order.cycle is below chance (45 findings).
Correlation only, on logs players shared because something went wrong; the library has current
mod versions, not the players'.

== G5 pattern library v0 (summary; details in spikes/patterns/RESULT.txt)

- 46 generic rules over cluster templates recognise 87.0% of the 610,910 problem clusters of the
  6,734 logs (75.5% of occurrences). Stages: load 70%, save 21%, runtime 9%.
- The current MCP diagnosis workflow covers 30% of the clusters, partly 29%, not 41% (save-load,
  missing assets, assembly dependencies, config errors); 74.5% of logs have an uncovered cluster.
- 1,036 mod-specific patterns (>= 10 logs from >= 5 sessions) over 317 mods.
- Sessions: 1,727 consecutive pairs; 400 with 1-3 changes. Without any change, load-stage errors
  stay (0-6% disappear), save/runtime errors disappear 5-26% anyway, so fix evidence for them
  must beat that control. Removing the source mod and the error going is rare (87 mod patterns).
- Draft for MCP Instructions / analyze_log: docs/research/01-范式库接入草案.md.
