G7 agent evaluation: RimArcho MCP tools only, scored against the G6 benchmark (corpuslabel/2)
=========================================================================================

Setup
-----
- 140 tasks (G6 tasks.jsonl): 96 dev (tuning), 44 held-out. Held-out was run and scored once,
  at the end, for both builds. No held-out item was looked at while tuning.
- Agent: Claude Sonnet subagent, one per task. It sees the task (log cluster, mod list,
  Player.log through read_upload) and calls only read-only archo MCP tools through
  `agenteval call` (8 research homes, one Loadout each). No answers, packets or review files
  are reachable; every trace was checked for reads of labels/packets/config: 0 invalid.
- base = master before G7 (31b195b tools); v1 = 8c32023 (G7 attribution, output and Instructions).
- "RimArcho alone" = `archo log --cluster` on the same build and homes, no agent.
- Scoring: a source hit means the agent's sources meet the gold sources. Precision and recall
  are over named sources. "undecidable-ok" means the gold says unknown and the agent named no
  source. Stage, cause type and fix kind are agreement rates.
- 4 answer files (2 base, 2 v1) had Windows paths with lone backslashes. The scorer now repairs
  them; before that they counted as "no answer".

Reading
-------
- Dev improved on every axis except stage. The largest gains are cause type (+13.5) and
  fix kind (+10.4). RimArcho alone on dev went from 80.6% to 96.4% precision.
- Held-out: source finding is unchanged (20 of 28 gold sources hit in both runs; precision
  and recall are identical). The gains that carried over are knowing when to say unknown
  (+6.2 undecidable-ok) and cause type (+11.3). Tier 1 (clearer gold) improved; tier 2 got
  slightly worse. With 28 gold sources, one task moves recall by about 3.6 points, so the
  held-out source difference is within noise.
- RimArcho-alone gains did not reach held-out. The new attribution rules fix patterns
  that were frequent in dev (HugsLib upload, Quickstart/Defaults callers, field-error
  context, Harmony 1.x, harmony.log.txt); held-out has few of them.
- Agents use fewer calls with v1 (about 20% fewer archo calls on dev). The cluster view now
  shows the full message, extra lines and nearby messages. On dev, raw-log reads (read_upload)
  fell from 351 to 230, and the largest search output fell from 324 KB to 18 KB.

Improvements (done / not done)
------------------------------
Done (internal/app, internal/cmds, internal/surface):
  1. MCP output capped at 24 KB with a "narrow the call" note (searches had returned up to 324 KB).
  2. patches --failed header: "N failed of M operations simulated, K not simulated".
  3. Failing type's owner is the source; mods that only call into it are demoted.
  4. HugsLib log upload errors and HugsLib Quickstart / Defaults callers are not the source.
  5. Errors writing harmony.log.txt are a machine problem; every mod is demoted.
  6. Harmony 1.x type references: no dependency providers listed; the failing assembly's loader
     becomes the source, else a detail says no enabled mod loads it.
  7. Typeref errors: the assembly named on the following lines is used.
  8. "Could not load type of field": the declaring type's mod.
  9. Field errors count a file only if it holds the Context's def type.
 10. Cluster view: full message (1200 bytes), up to 6 extra lines, nearby log messages.
 11. Patch-failed owner stays the source, with a detail (also when it no longer fails here).
 12. Instructions: framework vs caller vs source, when to say undecided, patch-reason meanings,
     assembly loading, the 24 KB cap.
 Tests: internal/app/logcallers_test.go, catalog_test.go, golden files; logCacheVersion 3 -> 6.
Not done:
  - Lowercase packageId display in some outputs.
  - Version-mismatch reasoning (installed copy newer than the player's): agents still mostly
    say "unknown" there.
  - Tier-2 tasks (multi-mod, weaker gold): no targeted change; held-out tier 2 is weakest.
  - Missing mods in the research library limit both agent and RimArcho alone (several dev
    silences), a research-environment limit, not a product one.

Caveats
-------
- Gold is packet-based. On dev, several baseline "overclaims" looked right on inspection
  (gold says unknown). They are kept as scored; agents were not tuned toward them.
- One model (Sonnet), one run per task: no variance estimate.
- Data stays outside the repo (corpus-kb, agenteval/runs). This file holds aggregates only.

Rerun
-----
  agenteval prepare | brief -run <r> (rewrites AGENT.md from mcp.Instructions + Catalog)
  agenteval warm -run <r> -slot <s> -ids ...       RimArcho alone
  agent prompt: agenteval prompt -run <r> -task <id>; one subagent per home at a time
  agenteval score -run <r> -gold <tasks.jsonl> -split dev|heldout -traces <subagents dir>

Reading:
- The intervals are wide per class on held-out (n 19-20, about +-15 points). Only large gaps
  are real: the agent beats RimArcho alone overall (+18.6 dev, +22.4 held-out, intervals do not
  overlap) and in assembly (+68 dev, +42 held-out), exception, harmony-stack and patch-failed;
  xref-missing and xml-load show no agent gain (alone is equal or higher on agree because it
  stays silent where gold is "unknown" and the agent over-claims).
- Held-out is 5 points below dev for both the agent and RimArcho alone. The product and the
  brief were not tuned on either, so it is not overfitting; the two intervals overlap. Classes are in
  the same proportions in both splits.
- Cause type (about 50-63%) is the weakest field and the part gold is least sure of (see
  below); fix kind 68-75%.
- static-ctor held-out 63.2% (alone 26.3%): 5 wrong, the one class that dropped clearly
  (dev 85.4%).

Cost (agent, dev, from the 219 transcripts that were available): median 39 s, 6 tool calls,
8 archo calls, 85k final context, 2.0k output tokens; total 158 min agent time, 1,851 archo
calls, 176 M input tokens processed. Held-out: 1,436 tool calls over 156 tasks.

Limits:
- Gold is one reviewer (Opus) over a labeller (Haiku tier 1, Sonnet tier 2); 140 v2 tasks
  keep their v2 gold (migrated to corpuslabel/3). Reviewer-vs-labeller agreement: tier 1
  cause type 40/60, kappa 0.50; tier 2 146/180, kappa 0.75. Gold "unknown" for cause type is
  49% (v2: 63%); every unknown carries a reason.
- Two items describe the same thing with different labels (EX47 Bees: version-mismatch;
  HS47 Biomes framework: optional-absent).
- Rule "game older than the mod -> version-mismatch, fix update ludeon.rimworld" was added to
  the review brief after the first reviewers had started; EX37 and PF48 were fixed by hand,
  the rest of the earlier reviewed items were not re-checked.
- SC22 and SC24 quote files in corpus-kb/home-g12s/vanilla (kept for that reason).
- One run per task, one model: no variance estimate; agree can move several points between
  two runs of the same build (G11 saw 8 of 140 tasks differ).
- Cost lines cover 219 of 344 dev transcripts (the rest did not match a kept transcript).
