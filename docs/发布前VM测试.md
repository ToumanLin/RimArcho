# 发布前 VM 测试

新功能、新按键和改了行为的旧功能，做完就在下表加一行。
可目视的UI更改不应该加入此列表。
发新版本之前，在 VM 里用真实数据把表里每一行走一遍，找潜在的 bug，做法同 [2026-10-27 的情景 5、6、9](research/2026-10-27_VM情景5-6-9.md)。

- 发现的问题记进当次的 research 报告，修掉或记成待办。测过的行移进那份报告，这里只留没测的。
- **真的进游戏**：每轮真实情景测试都要启动游戏 → 进主菜单 → 新开一个殖民地并玩几分钟（暂停、加速、开几个窗口）→ 存档 → 读这个存档 → 从游戏菜单正常退出。之后看游戏日志页（Player.log 和 ArchoMonitor.log）、能不能跑的“上次运行的报错”，确认加载、读档、游玩三段的报错都对得上。只启动到主菜单不算测过和游戏日志有关的行。这一轮用 `pwsh scripts/vm/round.ps1` 跑，不用截图点游戏。它自己检查各步和阶段顺序，跑完把 `archo problems`、`archo log` 的输出放进证据目录。之后的界面检查用 `cdp.mjs text` 读页面文字。
- VM 的用法见 [scripts/vm/README.md](../scripts/vm/README.md)。场景的写法见 [VM 自动化测试方案](research/2026-10-27_VM自动化测试方案.md) §5、§7；§3 是全部玩家动作的清单，这张表只记那之后新增或改了的。
- 破坏性操作只对打了 “I Dont Need It” 标签的 Mod 做。动 Steam 账号的操作（订阅、退订、SteamCMD 登录）测完要恢复，因为还原快照不会撤销账号上的变化。
