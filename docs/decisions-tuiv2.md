# TUI v2 decisions (V0 follow-up, V1, V2)

Date: 2026-10-19. Spec: docs/specs/06-TUI.md v2. Commits 280e360 … cb39b54 (local, not pushed).

## V0 follow-up

### 1. Thumbnail ghosting: the image size is RimArcho's, never the terminal's

A thin sliver stayed under the rect after a tall preview (`thumbs-2-after-slow-scroll.png`). The cause:
WezTerm's `preserveAspectRatio=1` does not fit the image into width×height. It keeps the width and derives
the height, so a preview taller than about 0.87:1 runs below the 18×9 rect. The rect clear (ECH on rows
3–11) then leaves the overflow, and rewriting text over image cells does not erase them.

Ruling: scale the thumbnail to fit 18×9 cells, take the fewest rows N that hold it, pad it with
transparent pixels to exactly 18×N cells' pixel aspect, and send `width=18;height=N;preserveAspectRatio=0`.
The image then covers exactly those cells, and ECH over the 18×9 rect erases all of it.
Evidence (07 §6.2):
- 8 magenta test aspects: the drawn extent stays within the rect, and every clear leaves 0 px.
- The original 500-row scroll, replayed: 1398 px of sliver with the old sizing, 0 px in all 10 shots with
  the new one.

06 §6.2 states the sizing and clearing rules.

### 2. archo memory in WezTerm

The single 78–80 MB V0 sample does not reproduce. With identical inputs:
- A fresh start is 31 MB (7 runs, 3 launch methods, Go heap 5–8 MB).
- The tuimem session driven in real WezTerm is 44 MB idle (peak 53), matching the headless 47 MB.

`TuneProcess` is applied on the CLI path, and a SQLite WAL recovery after a killed process was ruled out.
No code change. Re-measure with `spikes/tuiv2-v0/archosession.ps1` after V3 adds the thumbnail cache.

## V1 visual system

3. **Colour under ConPTY.** termenv cannot query a terminal through ConPTY and falls back to no colour.
   The v1 TUI showed no colour in WezTerm either. `SetColors` forces 24-bit colour when the terminal says
   it has it: `COLORTERM=truecolor|24bit`, `TERM_PROGRAM=WezTerm`, or `WT_SESSION`. Other terminals keep
   termenv's detection.
4. **Icons.** `ui.icons auto|nerd|compat` is a new config key (05 §3); auto means Nerd Font icons when
   `TERM_PROGRAM=WezTerm`. Both sets are checked to be 1 cell wide (`TestIconWidths`). Compatibility mode
   was verified in the player's Windows Terminal (`v1v2-wt-compat.png`). The lock icon is not drawn yet:
   Core's place is the `official.order` problem.
5. **Light mode deferred.** The WezTerm host is always dark (`#0E0F12`). In other terminals the dark
   palette is used until V5; background detection is unreliable under ConPTY for the same reason as item 3.
6. **No `#id` in the main screen.** Results are written by the TUI ("启用了 Beta", "Harmony 现在是第 3 个").
   Command errors pass through `humanize`, which replaces instance references by mod names. CLI text
   (still with references) remains in the secondary screens: the save and sort previews, `:` output, and
   the Problems / Changes / Inspect screens until V3/V4.
7. **Needs-attention count** (top bar, until V4 defines the groups). It adds up:
   - errors and warnings a player can act on, with the version-support warnings counted once;
   - Harmony warnings only when a log shows them (06 §7.3);
   - identity questions, an external change of the list, and a list saved for another game version.

   The real environment shows 32.
8. **`archo tui`** is the TUI, the same as no arguments. **wezterm.lua** is generated by
   `internal/wezterm` (the V0 settings plus `exit_behavior = 'CloseOnCleanExit'`). The download and launch
   flow is still V5.

## V2 four columns

9. **Staging lives in the app** (`archo stage list|add|drop|restore`, 05 §3), because the TUI holds no
   business logic. It is one JSON list per environment in the meta table.
   - Each mod staged from the Loadout keeps its old position and an anchor: the mod before it. The anchor
     moves forward past mods staged earlier that stood between, so batches can be staged in any order.
   - Restore follows the anchor chain through mods that are still staged; the position is the fallback.
   - `add` and `restore` are one undo step each. A staged mod that is enabled again by any means (undo,
     enable, checkout) leaves staging.

   Tests: T9 with 20 mods, randomised batches over 12 seeds, anchors after edits, prep-area mods, `--at`.
10. **Hidden staging.** 06 §5.1 said "<140 隐藏暂存列，用 t 键查看", but `t` stages (§5.3). Ruling: `t` keeps
    staging, and ←→ / tab always reach staging, which then takes the first column's place. Below 80 it is
    the third tab (`[ ]`). 06 §5.1 is updated.
11. **Focus.** It cycles over the three lists. The detail column follows the cursor and is not focusable
    in V2; its actions come with V3/V4.
12. **`l` and `h`** now switch columns (06 §5.3), so the log chooser moved into the 需要处理 screen (`l`
    there). `f` (filter cycle) and `1/2/3` are gone: the columns replace the filters, and `!` and `c` open
    the old Problems and Changes screens, with `esc` back.
13. **Filter.** Every word must be a substring of the name, alias, author, package id or folder. Only when
    nothing matches does a subsequence of the name count ("hsl" → "Hair Style Lib"). A subsequence over
    every field matched 222 of 872 mods for "harm".
14. **Drag.**
    - From "not enabled" or staging onto an enabled row: placed at that row's number; below the last row:
      at the end.
    - Within "enabled": move.
    - Onto staging: stage. Enabled onto "not enabled": disable. Staging onto "not enabled": unstage.
    - Press and release on the same row is a click. The status line names the drop while dragging.
15. **Detail column in V2.** Name, author, source · supported versions · position, a one-line problem
    state, and the technical information collapsed behind `i` (the `mod` command, loaded only when
    expanded). The layered detail with the thumbnail is V3.

# Tags, per-column search, details (between V2 and V3)

The user's review of V1+V2 asked for three things before V3: tags, search per column by field, and
more information in the details, including the description. The spec is in 06 §2.1 rule 6 (package id
shown), §5.5 (search), §5.6 (tags), §6.1 (the detail), and §6.4 (description sources, measured).

## Decisions

1. **Search** (`/`, 06 §5.5): free words match name, alias and author fuzzily. The fields are
   `name:`, `author:`, `tag:`, `id:` (package id, Workshop id or `#ref`), `type:` (source
   `official|workshop|local|copy|git|steamcmd`, content `assembly|xml|language`, with the long forms
   `xml-only|language-pack`), and `has:problem|error|tag|note|alias`. `-` negates a term and terms
   are ANDed. A single free word with no match falls back to letters in order. Each column keeps
   its query until esc; the header shows the query and N/M.
2. **Content kinds** (`type:assembly` etc.) come from one GROUP BY over the current snapshots' file
   lists, loaded on the first such query and kept until the database changes. On the real-size copy
   (1353 mods) that is 246 ms once; every later query takes under 1 ms.
3. **Tags** (`#`, 06 §5.6): work on the selection (`v` marks); `word` or `+word` adds, `-word` removes;
   tab completes from the tags in use, most used first. Rows show their tags as a faint suffix when
   there is room. CLI: `tag add|remove <ref> <tags…> --mod <ref>…`. MCP: `set_player_data`.
4. **Detail** (06 §6.1): a non-technical section by default with the package id, version, Workshop id
   (`o` opens the page), tags, alias, note, what the mod requires (✓ enabled, ! not enabled,
   ⨯ not installed), and the description. The technical information stays folded behind `i`.
5. **Description source** (06 §6.4): About.xml is read on demand. The Workshop page is fetched for
   the selected mod only, after a 400 ms dwell, and cached by Workshop id and time_updated.
   `workshop.fetch off` keeps everything offline. Only the Workshop text is shown when About.xml is
   under 300 characters or both start alike (images ignored); otherwise both are shown. Measured on
   1274 mods: Workshop text is ≥ 300 characters for 90%, About.xml for 41%; 55% of Workshop texts
   have images, 7981 in all.
6. **Images**: drawn inline in WezTerm (OSC 1337), at most 60 columns wide; in the detail column at
   most half of the 12 description lines, in the full view at most 20 rows. While loading an image
   takes one line. Elsewhere (and with `workshop.images off`) it is a `[image · host]` placeholder.
   Downloads are cached as PNG at 720 px; GIF shows its first frame; WebP is a placeholder.
   `imgur.com/x.png` links go straight to `i.imgur.com`. Requests carry a RimArcho User-Agent.
   No OCR.
7. **Full-screen detail**: `enter` opens it, and it scrolls (↑↓ j k, PgUp PgDn, g G). `o` opens the
   Workshop page, `r` re-fetches, `#` edits tags, `i` shows the technical information, `tab` opens the
   older inspect pages, `esc` goes back.
8. **Screenshots** are now taken with PrintWindow, so a covered WezTerm window is captured as itself
   and the user's foreground window is never raised over or captured (the first try with
   CopyFromScreen caught another window and was deleted).

# V3: layered details, thumbnail, full-screen details

06 §10 V3: the layered detail, wrapping, the thumbnail and the full-screen detail (T6, T7).
Parts of the detail (the non-technical section, the description, inline images) came
with the previous round; V3 adds the rest.

## Decisions

1. **Thumbnail** (06 §6.2): `About/Preview.png` (any case; JPEG content is accepted) is scaled to
   360 px wide and cached as PNG under `<home>/cache/previews/<snapshot hash>.png`. The mod folder is
   only read. In the column the block is 18×9 cells, always reserved; the image takes the fewest
   rows that hold it (16:9 → 5), padded to exactly 18×N cells, `preserveAspectRatio=0`.
   - It is drawn only after the cursor has rested 150 ms on the mod.
   - On any selection change it disappears in the next frame, and the whole 18×9 block is erased
     with ECH in the same write.
   - A mod without Preview.png shows a faint "无预览" in the block.
   - Below 16 text cells beside the block there is no block.
   - The compatibility mode has no block, and the name starts at the top (§1.3 updated to match §6.1).
2. **Image cache**: encoded images (thumbnails and description images) are kept for at most 24
   entries; the ones not on screen are dropped first. This bounds the TUI's largest allocations.
3. **Full-screen detail** (06 §6.3): `enter`, 36×18 thumbnail, and five numbered sub-sections.
   - The sub-sections are Def, 补丁, Harmony, 规则 and 完整历史; `1`–`5` jump to them.
   - Def, patches and Harmony come from the CLI commands' text, with `#refs` replaced by names.
     Each shows at most 60 lines; `tab` opens the technical pages for the rest.
   - 规则 is About.xml's declared order plus the player's rules that name the mod, written in words.
   - 完整历史 is every change event of the mod, newest first.
   - The column shows a one-line history: the three newest events, e.g. "10 月 19 日首次发现".
4. **Wrapping** (T7): every text in the detail wraps by display width.
   - `wrap()` now shares the description's token wrapper. It breaks at spaces and between CJK
     characters, never inside a Latin word.
   - It follows the kinsoku rules, breaks over-long paths after `\` or `/`, and keeps a line's indent.
   - Status lines, description headers, long dependency names and the footer wrap instead of being
     cut. Only the column's "… enter shows all" and BBCode tables (wide columns) still use "…".

# V4: 需要处理

06 §10 V4: grouping, plain wording, one-key actions, notification-style changes (T8). It
follows 06 §7, with the additions recorded in §7.2 (V4 rulings).

## Decisions

1. **What an item is.** Each item of 需要处理 is built from the problem set and the
   environment's open questions:
   - its group (06 §7.1);
   - one sentence made from mod names;
   - the keys that act on it;
   - whether it is counted.
   Problem codes, `#refs`, `pkg:`, `p:` and the other CLI reference forms never reach the screen.
   They remain in the technical information, the CLI and MCP.
2. **The count.** The top bar shows the number of counted items. A list row has an icon exactly
   when its mod is the subject of one of them.
   - On the real data copy this is 19 instead of the old 32.
   - The 13 that dropped out are 5 `def.abstract-collision` and 8 `patch.no-match` whose target is
     absent rather than disabled.
   - The player cannot act on those, so they moved to the technical information.
   - Harmony warnings without log evidence were already excluded. The 16 errors and 46 warnings of
     the old screen counted info-only folds and stale-log rows as well.
3. **Keys.** Each item names its own keys, shown under the selected item:
   - `S` sort (preview first).
   - `space` enable the dependency, or disable.
   - `o` open the Workshop page: the declared URL, else a Workshop search.
   - `space` on an incompatible pair or a duplicated mod opens a chooser: disable which one, or
     keep which copy.
   - `enter` / `x` on an order cycle: the requirements in words, then ignore the suggested one.
   - `s` / `c` / `u` answer an identity question.
   - `L` / `I` load or ignore an outside ModsConfig.xml change.
   - `w` save a list that was saved for an older version.
   - `enter` on log items opens the log and its evidence (a technical page).
   Screen-level keys are `A` (check the files again) and `l` (choose a log).
4. **Changes** (06 §4.1). After a scan the status line reads "扫描完成 · 3 个 Mod 有更新 · 1 个改了包名 ·
   按 c 查看". `c` lists the last scans' changes in words: mod name and what happened; `enter`
   still shows the changed files. Identity questions and the outside change of ModsConfig.xml
   moved to 需要处理, and the old changes screen with codes and refs is gone.
5. **Safety found while testing.** `app.ChildAnalyze` refuses to start when the executable is a Go
   test binary.
   - A real-data test that opened the app without an in-process analyzer started `tui.test.exe
     analyze`. That binary ran the tests again, which started it again, and so on.
   - Every copy worked only on temp copies of the data, and nothing outside them changed: the real
     ModsConfig.xml md5 and archo.db time were checked afterwards.
   - The processes were stopped, and the real-data tests now set `AnalyzeRunner`.
