# 16 · Interface · First-run guide (§2.15)

> Part of [16 · Interface](README.md). Section numbers run through all of 16 and stay unchanged when split across files.

### 2.15 First-run guide

Before the guide, a GUI running from a RimWorld Workshop item offers **"install RimArcho"** (`firstrun.js`). The install folder defaults to `%LOCALAPPDATA%\Programs\RimArcho`; clicking the address or "change…" opens the native folder picker. The dialog shows the release's required space and the destination drive's free space, and warns below 10 GiB (displayed as "10 GB"). It names replacement when RimArcho is already installed there. "install and restart" confirms copying, restarting and cleaning only the extracted release entries from the old Workshop folder (17 §5.1, 02 §1). An invalid destination or insufficient free space disables confirmation; space is checked again before copying. A failed copy or launch leaves the dialog open for retry. "use here this time", Escape or dismissal continues this session with one persistent warning line. The offer returns on the next start from that folder, including an installation with existing Game Configs.

On a first run whose managed folder is still unchosen, the guide takes the default (`app.LocalDir()`, 17 §3) without asking: `api.ManagedFolder` is read with detection and `ChooseManagedFolder` records it; Settings › folders changes it later. Only when the default cannot be used (its check reports an error, or recording it fails) does the guide start with a **"managed folders"** step before "find the game". It asks "Where should RimArcho keep its downloads?" inside the guide card, not in a dialog. The address defaults to `app.LocalDir()` (17 §3); clicking it or "change…" opens the native folder picker, and the line below shows the drive's free space with the same low-space warning. "use this folder" is the only way on: it saves the choice, records that it was answered and moves to "find the game"; there is no "not now". The step stays in the step bar, done, and can be revisited. Later guide entries, and adding another game, do not show it. Existing managed content is moved with Settings' per-folder controls, rather than abandoned by a new root choice.

The first-run guide is implemented in the GUI (`guide.js`). The page has one column: the step bar (no lead sentence) on the left of a top row, the step's card below at the same left edge. Archo's figure stands at the right end of that row, behind the card: the card's top edge hides her below the shoulders, so she is cut only horizontally, never at the sides. Her expression follows the step (§7.1 "Archo figure"); with `ui.archo.motion` off the row holds only the lead and the steps. After the managed folder (first run only), the first run has three steps, "found", "read the mods" and "first list"; the third is the Import page (§2.18), which the guide opens after the scan, with the same step bar. Add Game Config has the first two, its first named "find the game". Each step can go back to the previous one; the Import page's bar only shows the way. **The sidebar stays empty until the guide ends** (its pages, Settings and feedback hidden, `body.first-run`; the background-tasks line stays), the Import step included: a page's count, such as Can it run's, never shows before the first list. The breadcrumb says "getting started" on all three steps.
1. **“found”** (first run and its preview): RimArcho confirms what it found rather than asking (`view.FirstRun`, `API.GuideFirstRun`). The question reads “RimArcho found these. Untick what it should leave alone.”, then muted section labels over grouped rows:
   - **game**: one card per detected game (03 §3.2), all ticked; untick to leave one out. The card shows “RimWorld 1.6” large, the rest of `Version.txt` (`4633 rev1261`) muted, the chip that says how the game starts (`GameFound.Source`: “Steam”, “Proton” for a Proton game, which always starts through Steam, 09 §2, or “started directly”), the path, and at the right “✓ 13 enabled” from its ModsConfig.xml (`GameFound.GameMods`; on hover: the game's current list stays as it is). There is no name field: the name is the version (`1.6`, `1.6-2` when taken, also among the games on the page, `view.GameAt`); the Game Config page renames it. A ticked game whose user data folder another ticked game of another version also uses (1.6 and 1.7 in one LocalLow) shows, under the later one, “saves and Mod settings: shared with 1.6 | its own”, **its own by default**: it is added with `--saves own`, and its own folder starts from a copy of the game's ModsConfig.xml (`GameFound.GameList`), so its list is the same. Proton games are never asked. Settings › folders and Add Game Config change it later.
   - **Mod folders**, one row each with its icon, path (long ones keep their last three parts, the full path on hover) and Mod count (`env.CountModDirs`, a directory count, no scan): the Steam Workshop folder of the first ticked Steam game and each ticked game's `Mods` folder, marked ✓ (always read), then each folder another manager uses (`app.FindManagerModFolders`, 07 §6.2; “used by RimSort”), with a box, **ticked by default**. A ticked one becomes a shared Mod folder with the first game (`GameFound.Extra`, `EnvSpec.Extra`).
   - **language**: one switch, “follow system (English)” (the language the system resolves to) then each bundled language in its own name; a pick sets `ui.lang` and the page changes language in place; the game cards are read again so their chips (translated by detection) follow, keeping every pick. A preview only shows the pick.
   - The footer: quiet “add another folder” (the native folder picker, §3.1 rule 12; the TUI still accepts typed paths) and “download a version” at the left, the primary “add and read Mods” / “add 2 games and read Mods” at the right. Adding checks every name first (valid, not repeated in the batch, not an existing Game Config, `view.CreateGames`): a clash adds none of the games and says which name to change.
   - **No game found**: the question reads “No RimWorld found”, and two tiles replace the games and folders: “choose its folder” (the folder with RimWorldWin64.exe; the folder picker) and “download a version” (from Valve, with SteamCMD). One muted line says where RimArcho looked (“looked in 1 Steam library and D:\Games”, `env.Searched`), and the language row stays. This step cannot be skipped.
   - **“download a version”** opens from the footer or the tile, with a back button to “found”; the download itself is below.
   Add Game Config's **“find the game”** switches between two ways, three once a Game Config exists:
   - **“a game you have”**: the games detection finds and the games Game Configs use, one picked (radio buttons; a game another config uses can be picked), and “add this folder”; the config's choices follow (below).
   - **“download a version”** (11 §3): if SteamCMD is missing, say that it is downloaded from Valve and show its size and location; download it only after the player clicks “download SteamCMD”. Then show the SteamCMD branches (the current stable version, test versions and older versions, with Steam's descriptions and dates), the game folder (default `<drive>\Games\RimWorld <version>`, on the first Game Config's drive, else the system drive; on Linux `<mount>/Games/RimWorld <version>` when the first Game Config's game is on a writable file system other than the root and the home folder's, else `~/Games/RimWorld <version>`: `app.GamesFolder`; the version folder is joined with the games folder's own separator, `/` on Linux; clicking the address or “change…” opens the folder picker) and an optional Steam account name. The default is anonymous: a blank field uses the account from settings, and an explicit `anonymous` overrides a saved account. The password and Steam Guard code go only into SteamCMD's own window, typed by RimArcho from the corner card's field when SteamCMD asks, or by the player (11 §3 "Password prompt"); when the download signs in (a name in the field, or a saved account with a blank field), the password hints (11 §3 "Password prompt") show under the field, an icon each. During the download, show the stages (start, login, download, verification), a progress bar and safe, mapped stage descriptions; raw authentication logs are never shown. Failures are explained in plain words and can be retried. On success, the Game Config is registered as for an existing game, and the guide goes to step 2.
   - **“copy a game folder”** (03 §3.5), shown when a Game Config exists; the Game Config page's “copy the game folder…” opens Add Game Config on it: the Game Config whose game is copied (the current one first picked), the folder (default `<drive>\Games\RimWorld <name>-copy`; the address or “change…” opens the folder picker), the Game Config name (default `<name>-copy`), the game's Mods folder (not copied, or copied too with its size) and the saves folder (shared, or own folder in RimArcho). The line below says how much it copies and the free space, and warns when it does not fit (confirmation is then disabled). Each change asks `GuideCopyPlan` again. A note says the copy plays the same Mod list and starts with the game's own exe, so Steam never updates it, and that RimArcho's Mod links are made again when it launches. “copy and add” starts `GuideCopy`, a background task; “copy” events fill the bar (bytes of the total); on success the copy is added and the guide goes to step 2; a failure or a stop says so and offers “try again”.
2. **“read the mods”**: scan in a subprocess and show progress (§8.4). If the shared Mod folders have already been scanned, read only the new game's `Data` and `Mods` (`scan --game-only`, 04 §1.1). The game's row says what it is doing: “reading the mods of <game>: <n> of <total>” as each folder is read, “saving the <total> mods read from <game>…”, “adding Archo Monitor to <game>: <n> of <total>” if a second, Monitor-only pass follows (19 §6), then “checking the files of <game>: …” with the analysis' own progress lines (not its closing report). The bar counts each game as one part; within the game being read, the scan fills 90 % of its part (the first pass most of it, a Monitor-only pass the rest; it never goes back) and checking the files the last 10 %. The same text and fraction show on its background task. Before the scan, the guide makes the game's `Mods/` links without scanning in the window (`app.PrepareEnvForScan`): the child scan that follows reads the same folders. When it ends, the row says how many Mods these folders contain (“408 mods found”: the row names the game already, so the text does not repeat it), and the card's heading “Reading your Mods…” becomes “Your Mods are read” (“Some Mods could not be read” when a game's scan failed). On the first run, a section **“while you wait”** follows the bar with two rows, each with an on | off switch: **“check for updates”** (RimArcho, Mods, tools and community data, about 50 MB once; `updates.auto`, which covers community data too, 16 §2.16.1 A07) and **“Archo Monitor”** (a helper Mod added to your lists that names the Mod behind an error; `monitor.default`, 19 §6). Both start as the settings are (on by default). A switch writes its setting at once, so the scan that runs sees it: Monitor off before the scan adds it keeps it out of the first list. The automatic checks (16 §2.16.1 A01) wait while the guide has not passed this step (`API.GuideHold`). Step 2's “next” releases them and, with Archo Monitor off, takes Monitor out of the lists the scan made, one undoable edit each (`API.GuideChoicesDone`, `app.DropMonitor`). A preview shows the switches and writes nothing. Settings › about and Settings › tools › game log change them later.
Then **the first list**, step 3 (A1 of `docs/design/2026-11-18_ux-scenarios.md`): step 2's “next” opens Import (§2.18) in its first-run view, with the guide's step bar at the left of its head: the lead asks “Where does your first list come from?”; the game's current list is the first row, whose “use this list” (the page's one filled button) ends the guide (the scan already made ModsConfig.xml the first list, 07 §1.4). The other rows are those of the page, shown at once, and the managers are surveyed as the page opens: one row per manager found, with what it holds (§2.18 “First-run view”); a list, a move-in or a pack brought in there ends the guide too, and “skip” (`esc`) ends it with the game's list. The first-run view has no export side. When the guide ends, the sidebar fills in.

**Add Game Config** (§2.8) is this page with Game Configs already added: there is no lead, the step bar has only "find the game" and "read the mods", and step 1 picks one game (radio buttons; a game another config uses can be picked) with the config's choices under the list. There is no first-list page: the Mod list is chosen in step 1. Its first choice, when the picked game's user data has a ModsConfig.xml, is “the game's current list (N Mods)” (`GameFound.GameMods`), picked until the player chooses another; it is sent as `gameList` (`EnvSpec.GameList`): the new config takes no list from the copied config, and an own or chosen saves folder without a ModsConfig.xml gets a copy of the game's, so the first use makes that order the config's list (07 §1.4). The other choices are the current config's lists and “New empty list”. Copying the current Game Config's settings is offered only for that config's own game folder; for another game the page says the settings cannot be copied and the config starts with game defaults. A Game Config switch while the first step is open rereads the lists and the copy source; a game picked by hand stays picked, while the previous config's game gives way to the new one's.

**Move over from another manager** is the Import page's “Import another manager's data” row (§2.18), as Settings' "import from RimSort, RimCrow, RimPy or RimStack" row (§2.14) and the sidebar's Import open it; on the first run, finishing an import there ends the guide. Its "found on this computer" section lists what 07 §6.2 discovers; "choose a file…" takes a list, a pack, a RimCrow database or RimSort user rules; pasted lists, share codes and links are below.

**Preview**: Settings › Interface's "first-run guide" row (`guide.preview`, action `guide-preview`) opens the guide as a first run shows it, with the breadcrumb "settings / first-run guide (preview)" and a line under the lead saying nothing chosen is saved. The managed-folder step is not shown, as on a first run whose default folder works, and games already added are listed as not added yet, so they can be picked. The guide reads what it reads on a first run (detection, the folder's free space, `GuideGame`, SteamCMD's branches when SteamCMD is there) but writes nothing: "use this folder" only moves on, adding games and "download and add" play out a made-up download and scan on timers, "download SteamCMD" shows sample branches, and step 2's “next” (where a first run opens Import, which a preview never does), "skip" and "end the preview" (in each step's footer) return to Settings with "preview ended; nothing was saved". Real `guide` and `download` events are ignored while previewing. The TUI lists the row with `archo gui`.

Lists use the existing destination preview below. Player data uses `PreviewManagerImport` before `ApplyManagerImport`: show imported, existing, skipped and conflicting counts and every unresolved item, and say "Existing values stay; importing player data cannot be undone." The final "import" button is the confirmation; it never writes game configuration. A changed source, Game Config, RimArcho data state or superseded preview requires another preview. Importing player data leaves the page open so a list can be imported too. RimSort rule mappings: 07 §6.3.

RimCrow database import also previews profiles with their game folders, conflicts and the shared-folder/deletion warning (03 §6.4). Source Config changes invalidate the preview as well as DB/WAL changes. No profile folder is copied or deleted.

Import uses `view.ReadImport` → `view.PreviewImport` (the preview comes first) → `view.ApplyImport`. Adding a Game Config also starts at step 1, on the Add Game Config page above (§2.8), not in a dialog.

RimCrow profile preview shows profiles once, in a checklist: profile name, game folder, saves location and translated status. Eligible profiles start checked; unconfigured and conflicting profiles are unchecked and skipped. The shared-folder/deletion warning appears above the checklist. Only checked profiles become Game Configs with their own Mod lists.
