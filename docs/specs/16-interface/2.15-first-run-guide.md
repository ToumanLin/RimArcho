### 2.15 First-run guide

Before the guide, a GUI running from a RimWorld Workshop item offers **"install RimArcho"** (`firstrun.js`). The install folder defaults to `%LOCALAPPDATA%\Programs\RimArcho`; clicking the address or "change…" opens the native folder picker. The dialog shows the release's required space and the destination drive's free space, and warns below 10 GiB (displayed as "10 GB"). It names replacement when RimArcho is already installed there. "install and restart" confirms copying, restarting and cleaning only the extracted release entries from the old Workshop folder (17 §5.1, 02 §1). An invalid destination or insufficient free space disables confirmation; space is checked again before copying. A failed copy or launch leaves the dialog open for retry. "use here this time", Escape or dismissal continues this session with one persistent warning line. The offer returns on the next start from that folder, including an installation with existing environments.

On first-run guide entry, over step 1, **"managed folders"** asks "Where should RimArcho keep SteamCMD, downloaded Mods and tools?" The address defaults to `app.LocalDir()` (17 §3), with the same native picker and low-space warning. "use this folder" confirms the choice and records that it was answered; subsequent guide entries do not ask again. "not now" or dismissal writes nothing and permits a later reminder. Existing managed content is moved with Settings' per-folder controls, rather than abandoned by a new root choice. This question is absent when adding another game.

The first-run guide is implemented in the GUI (`guide.js`). It has three steps, and each step can go back to the previous one:
1. **“find the game”**: the player switches between two ways:
   - **“a game you have”**: automatic detection (03 §3.2) lists the games it finds, and several can be selected. “add this folder” chooses a folder directly (§3.1 rule 12; the TUI still accepts typed paths). The name is prefilled with the game version (`1.6`, or `1.6-2` if that name exists).
   - **“download a version”** (11 §3): if SteamCMD is missing, say that it is downloaded from Valve and show its size and location; download it only after the player clicks “download SteamCMD”. Then show the SteamCMD branches (the current stable version, test versions and older versions, with Steam's descriptions and dates), the game folder (default `<drive>\Games\RimWorld <version>`; clicking the address or “change…” opens the folder picker) and an optional Steam account name. The default is anonymous: a blank field uses the account from settings, and an explicit `anonymous` overrides a saved account. The password and Steam Guard code are entered only in SteamCMD's own window. During the download, show the stages (start, login, download, verification), a progress bar and safe, mapped stage descriptions; raw authentication logs are never shown. Failures are explained in plain words and can be retried. On success, the environment is registered as for an existing game, and the guide goes to step 2.
2. **“read the mods”**: scan in a subprocess and show progress (§8.4). If the shared Mod folders have already been scanned, read only the new game's `Data` and `Mods` (`scan --game-only`, 04 §1.1). The row says how many Mods these folders contain.
3. **“where to start”**: “the game's current list” (import ModsConfig.xml as the first plan), “move over from RimSort or RimCrow” (import lists and player data, 07 §6, §7), or “open a pack or a Steam collection” (`pack import`, `archo collection`). A pack is chosen with the system file dialog and a collection URL is pasted separately; typed local paths are never required.

**Move over from another manager** opens the same import page as Settings' "import from RimSort or RimCrow" row (§2.14). It discovers the sources described in 07 §6.2 and lists the manager, source kind and full file path; discovery is read-only and does not scan whole drives. "choose a file…" remains available for a list, a RimCrow database or RimSort user rules. With no candidates, say "No RimSort or RimCrow data found." Pasted lists, share codes and links remain available in the shared list importer.

Lists use the existing destination preview below. Player data uses `PreviewManagerImport` before `ApplyManagerImport`: show imported, existing, skipped and conflicting counts and every unresolved item, and say "Existing values stay; importing player data cannot be undone." The final "import" button is the confirmation; it never writes game configuration. A changed source, environment, RimArcho data state or superseded preview requires another preview. Importing player data leaves the page open so a list can be imported too. RimSort rule mappings: 07 §6.3.

Import uses `view.ReadImport` → `view.PreviewImport` (the preview comes first) → `view.ApplyImport`. Adding an environment on the environment page starts at step 1.
