### 2.15 First-run guide

Before the guide, a GUI running from a RimWorld Workshop item offers **"install RimArcho"** (`firstrun.js`). The install folder defaults to `%LOCALAPPDATA%\Programs\RimArcho`; clicking the address or "change…" opens the native folder picker. The dialog shows the release's required space and the destination drive's free space, and warns below 10 GiB (displayed as "10 GB"). It names replacement when RimArcho is already installed there. "install and restart" confirms copying, restarting and cleaning only the extracted release entries from the old Workshop folder (17 §5.1, 02 §1). An invalid destination or insufficient free space disables confirmation; space is checked again before copying. A failed copy or launch leaves the dialog open for retry. "use here this time", Escape or dismissal continues this session with one persistent warning line. The offer returns on the next start from that folder, including an installation with existing Game Configs.

On a first run whose managed folder is still unchosen, the guide starts with a **"managed folders"** step before "find the game" (`api.ManagedFolder` is read with detection, so the step costs no extra wait). It asks "Where should RimArcho keep SteamCMD, downloaded Mods and tools?" inside the guide card, not in a dialog. The address defaults to `app.LocalDir()` (17 §3); clicking it or "change…" opens the native folder picker, and the line below shows the drive's free space with the same low-space warning. "use this folder" is the only way on: it saves the choice, records that it was answered and moves to "find the game"; there is no "not now". The step stays in the step bar, done, and can be revisited. Later guide entries, and adding another game, do not show it. Existing managed content is moved with Settings' per-folder controls, rather than abandoned by a new root choice.

The first-run guide is implemented in the GUI (`guide.js`). The page has one column: the lead sentence and the step bar on the left of a top row, the step's card below at the same left edge. Archo's figure stands at the right end of that row, behind the card: the card's top edge hides her below the shoulders, so she is cut only horizontally, never at the sides. Her expression follows the step (§7.1 "Archo figure"); with `ui.archo.motion` off the row holds only the lead and the steps. After the managed folder (first run only) it has three steps, and each step can go back to the previous one:
1. **“find the game”**: the player switches between two ways, three once a Game Config exists:
   - **“a game you have”**: automatic detection (03 §3.2) lists the games it finds, and several can be selected. “add this folder” chooses a folder directly (§3.1 rule 12; the TUI still accepts typed paths). The name is prefilled with the game version (`1.6`, or `1.6-2` if that name exists); it also avoids the names already on the page, so two folders of one version get `1.6-2` and `1.6-3` (`view.GameAt`). Adding checks every name first (valid, not repeated in the batch, not an existing Game Config, `view.CreateGames`): a clash adds none of the games and says which name to change.
   - **“download a version”** (11 §3): if SteamCMD is missing, say that it is downloaded from Valve and show its size and location; download it only after the player clicks “download SteamCMD”. Then show the SteamCMD branches (the current stable version, test versions and older versions, with Steam's descriptions and dates), the game folder (default `<drive>\Games\RimWorld <version>`; clicking the address or “change…” opens the folder picker) and an optional Steam account name. The default is anonymous: a blank field uses the account from settings, and an explicit `anonymous` overrides a saved account. The password and Steam Guard code are entered only in SteamCMD's own window. During the download, show the stages (start, login, download, verification), a progress bar and safe, mapped stage descriptions; raw authentication logs are never shown. Failures are explained in plain words and can be retried. On success, the Game Config is registered as for an existing game, and the guide goes to step 2.
   - **“copy a game folder”** (03 §3.5), shown when a Game Config exists; the Game Config page's “copy the game folder…” opens Add Game Config on it: the Game Config whose game is copied (the current one first picked), the folder (default `<drive>\Games\RimWorld <name>-copy`; the address or “change…” opens the folder picker), the Game Config name (default `<name>-copy`), the game's Mods folder (not copied, or copied too with its size) and the saves folder (shared, or own folder in RimArcho). The line below says how much it copies and the free space, and warns when it does not fit (confirmation is then disabled). Each change asks `GuideCopyPlan` again. A note says the copy plays the same Mod list and starts with the game's own exe, so Steam never updates it, and that RimArcho's Mod links are made again when it launches. “copy and add” starts `GuideCopy`, a background task; “copy” events fill the bar (bytes of the total); on success the copy is added and the guide goes to step 2; a failure or a stop says so and offers “try again”. A preview plays the copy out on timers and writes nothing.
2. **“read the mods”**: scan in a subprocess and show progress (§8.4). If the shared Mod folders have already been scanned, read only the new game's `Data` and `Mods` (`scan --game-only`, 04 §1.1). The game's row says what it is doing: “reading the mods of <game>: <n> of <total>” as each folder is read, “saving the <total> mods read from <game>…”, “adding Archo Monitor to <game>: <n> of <total>” if a second, Monitor-only pass follows (19 §6), then “checking the files of <game>: …” with the analysis' own progress lines (not its closing report). The bar counts each game as one part; within the game being read, the scan fills 90 % of its part (the first pass most of it, a Monitor-only pass the rest; it never goes back) and checking the files the last 10 %. The same text and fraction show on its background task. Before the scan, the guide makes the game's `Mods/` links without scanning in the window (`app.PrepareEnvForScan`): the child scan that follows reads the same folders. When it ends, the row says how many Mods these folders contain.
3. **“where to start”**: “the game's current list” (import ModsConfig.xml as the first plan), “move over from RimSort, RimCrow or RimPy” (import lists and player data, 07 §6, §7), or “open a pack or a Steam collection” (`pack import`, `archo collection`). A pack is chosen with the system file dialog and a collection URL is pasted separately; typed local paths are never required. The three choices are equal boxes, each with a title, one line of description and its button on a shared bottom line; the collection link field sits above "choose a pack…".

**Add Game Config** (§2.8) is this page with Game Configs already added: the lead asks for the game and how the config starts, the step bar has only "find the game" and "read the mods", and step 1 picks one game (radio buttons; a game another config uses can be picked) with the config's choices under the list. There is no "where to start": the Mod list is chosen in step 1. Copying the current Game Config's settings is offered only for that config's own game folder; for another game the page says the settings cannot be copied and the config starts with game defaults. A Game Config switch while the first step is open rereads the lists and the copy source; a game picked by hand stays picked, while the previous config's game gives way to the new one's.

**Move over from another manager** opens the Import page (§2.18), as Settings' "import from RimSort, RimCrow or RimPy" row (§2.14) and the sidebar's Import do, and returns to the guide when the import is done. Its "found on this computer" section lists what 07 §6.2 discovers; "choose a file…" takes a list, a pack, a RimCrow database or RimSort user rules; pasted lists, share codes and links are below.

**Preview**: Settings › Interface's "first-run guide" row (`guide.preview`, action `guide-preview`) opens the guide as a first run shows it, with the breadcrumb "settings / first-run guide (preview)" and a line under the lead saying nothing chosen is saved. The managed-folder step is shown even when the folder was chosen already, and games already added are listed as not added yet, so they can be picked. The guide reads what it reads on a first run (detection, the folder's free space, `GuideGame`, SteamCMD's branches when SteamCMD is there) but writes nothing: "use this folder" only moves on, adding games and "download and add" play out a made-up download and scan on timers, "download SteamCMD" shows sample branches, and every way of "where to start", "skip" and "end the preview" (in each step's footer) return to Settings with "preview ended; nothing was saved". Real `guide` and `download` events are ignored while previewing. The TUI lists the row with `archo gui`.

Lists use the existing destination preview below. Player data uses `PreviewManagerImport` before `ApplyManagerImport`: show imported, existing, skipped and conflicting counts and every unresolved item, and say "Existing values stay; importing player data cannot be undone." The final "import" button is the confirmation; it never writes game configuration. A changed source, Game Config, RimArcho data state or superseded preview requires another preview. Importing player data leaves the page open so a list can be imported too. RimSort rule mappings: 07 §6.3.

RimCrow database import also previews profiles with their game folders, conflicts and the shared-folder/deletion warning (03 §6.4). Source Config changes invalidate the preview as well as DB/WAL changes. No profile folder is copied or deleted.

Import uses `view.ReadImport` → `view.PreviewImport` (the preview comes first) → `view.ApplyImport`. Adding a Game Config also starts at step 1, on the Add Game Config page above (§2.8), not in a dialog.

RimCrow profile preview shows profiles once, in a checklist: profile name, game folder, saves location and translated status. Eligible profiles start checked; unconfigured and conflicting profiles are unchecked and skipped. The shared-folder/deletion warning appears above the checklist. Only checked profiles become Game Configs with their own Mod lists.
