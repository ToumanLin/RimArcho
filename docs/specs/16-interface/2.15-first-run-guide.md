### 2.15 First-run guide

Before the guide, a GUI running from a RimWorld Workshop item offers **"install RimArcho"** (`firstrun.js`). The install folder defaults to `%LOCALAPPDATA%\Programs\RimArcho`; clicking the address or "change…" opens the native folder picker. The dialog shows the release's required space and the destination drive's free space, and warns below 10 GiB (displayed as "10 GB"). It names replacement when RimArcho is already installed there. "install and restart" confirms copying, restarting and cleaning only the extracted release entries from the old Workshop folder (17 §5.1, 02 §1). An invalid destination or insufficient free space disables confirmation; space is checked again before copying. A failed copy or launch leaves the dialog open for retry. "use here this time", Escape or dismissal continues this session with one persistent warning line. The offer returns on the next start from that folder, including an installation with existing environments.

On a first run whose managed folder is still unchosen, the guide starts with a **"managed folders"** step before "find the game" (`api.ManagedFolder` is read with detection, so the step costs no extra wait). It asks "Where should RimArcho keep SteamCMD, downloaded Mods and tools?" inside the guide card, not in a dialog. The address defaults to `app.LocalDir()` (17 §3); clicking it or "change…" opens the native folder picker, and the line below shows the drive's free space with the same low-space warning. "use this folder" is the only way on: it saves the choice, records that it was answered and moves to "find the game"; there is no "not now". The step stays in the step bar, done, and can be revisited. Later guide entries, and adding another game, do not show it. Existing managed content is moved with Settings' per-folder controls, rather than abandoned by a new root choice.

The first-run guide is implemented in the GUI (`guide.js`). The page has one column: the lead sentence and the step bar on the left of a top row, the step's card below at the same left edge. Archo's figure stands at the right end of that row, behind the card: the card's top edge hides her below the shoulders, so she is cut only horizontally, never at the sides. Her expression follows the step (§7.1 "Archo figure"); with `ui.archo.motion` off the row holds only the lead and the steps. After the managed folder (first run only) it has three steps, and each step can go back to the previous one:
1. **“find the game”**: the player switches between two ways:
   - **“a game you have”**: automatic detection (03 §3.2) lists the games it finds, and several can be selected. “add this folder” chooses a folder directly (§3.1 rule 12; the TUI still accepts typed paths). The name is prefilled with the game version (`1.6`, or `1.6-2` if that name exists); it also avoids the names already on the page, so two folders of one version get `1.6-2` and `1.6-3` (`view.GameAt`). Adding checks every name first (valid, not repeated in the batch, not an existing environment, `view.CreateGames`): a clash adds none of the games and says which name to change.
   - **“download a version”** (11 §3): if SteamCMD is missing, say that it is downloaded from Valve and show its size and location; download it only after the player clicks “download SteamCMD”. Then show the SteamCMD branches (the current stable version, test versions and older versions, with Steam's descriptions and dates), the game folder (default `<drive>\Games\RimWorld <version>`; clicking the address or “change…” opens the folder picker) and an optional Steam account name. The default is anonymous: a blank field uses the account from settings, and an explicit `anonymous` overrides a saved account. The password and Steam Guard code are entered only in SteamCMD's own window. During the download, show the stages (start, login, download, verification), a progress bar and safe, mapped stage descriptions; raw authentication logs are never shown. Failures are explained in plain words and can be retried. On success, the environment is registered as for an existing game, and the guide goes to step 2.
2. **“read the mods”**: scan in a subprocess and show progress (§8.4). If the shared Mod folders have already been scanned, read only the new game's `Data` and `Mods` (`scan --game-only`, 04 §1.1). The game's row says what it is doing: “reading the mods of <game>: <n> of <total>” as each folder is read, “saving the <total> mods read from <game>…”, “adding Archo Monitor to <game>: <n> of <total>” if a second, Monitor-only pass follows (19 §6), then “checking the files of <game>: …” with the analysis' own progress lines (not its closing report). The bar counts each game as one part; within the game being read, the scan fills 90 % of its part (the first pass most of it, a Monitor-only pass the rest; it never goes back) and checking the files the last 10 %. The same text and fraction show on its background task. Before the scan, the guide makes the game's `Mods/` links without scanning in the window (`app.PrepareEnvForScan`): the child scan that follows reads the same folders. When it ends, the row says how many Mods these folders contain.
3. **“where to start”**: “the game's current list” (import ModsConfig.xml as the first plan), “move over from RimSort or RimCrow” (import lists and player data, 07 §6, §7), or “open a pack or a Steam collection” (`pack import`, `archo collection`). A pack is chosen with the system file dialog and a collection URL is pasted separately; typed local paths are never required. The three choices are equal boxes, each with a title, one line of description and its button on a shared bottom line; the collection link field sits above "choose a pack…".

**Move over from another manager** opens the same import page as Settings' "import from RimSort or RimCrow" row (§2.14). It discovers the sources described in 07 §6.2 and lists the manager, source kind and full file path; discovery is read-only and does not scan whole drives. "choose a file…" remains available for a list, a RimCrow database or RimSort user rules. With no candidates, say "No RimSort or RimCrow data found." Pasted lists, share codes and links remain available in the shared list importer.

Lists use the existing destination preview below. Player data uses `PreviewManagerImport` before `ApplyManagerImport`: show imported, existing, skipped and conflicting counts and every unresolved item, and say "Existing values stay; importing player data cannot be undone." The final "import" button is the confirmation; it never writes game configuration. A changed source, environment, RimArcho data state or superseded preview requires another preview. Importing player data leaves the page open so a list can be imported too. RimSort rule mappings: 07 §6.3.

Import uses `view.ReadImport` → `view.PreviewImport` (the preview comes first) → `view.ApplyImport`. Adding an environment on the environment page starts at step 1.
