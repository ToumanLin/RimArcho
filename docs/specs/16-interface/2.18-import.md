### 2.18 Import

Import is one page where every import starts, so a player who wants to bring something in finds it without knowing which feature owns it (C1 of `docs/design/2026-11-18_ux-scenarios.md`). Since 2026-11-20 it has no export side: the page was “Import & export” before (see “Export” below). It is the first entry in the sidebar's Library group (§2.1), above Lists, with no `shift+` key: `shift+1–8` stay the eight pages the TUI also has (§3.5). The page ID stays `import` (deep links, the `imp` reference numbers, the palette and `i`). The breadcrumb is “library / import”; the group's “library” crumb still opens Lists. The TUI has no Import page; its imports are commands (07 §6.2, §7; 10 §4).

**Entries**: the sidebar entry; `i` in the list editor (All lists' `i` keeps its own import mode); a file dropped on any page (“Dropping files” below); Settings' “import from RimSort, RimCrow or RimPy” row (§2.14); the command palette's “import a list”; and the first-run guide after its scan (§2.15), which opens the page's first-run view (below). They all open this page. All lists' “new / import” form keeps its own import mode for now (§2.17), and the guide still chooses a pack itself.

**Layout** (2026-11-20, the user's sketch; the arrangement of the right side is under review: `docs/design/2026-11-20_import-page.md` compares “2col” and “3col”, and `<html data-import-layout>` or `?import-layout=` switches them until the player's pick is written here): the lead says the page's one gesture, “Drop files or folders anywhere on this window; RimArcho tells what they are.” (on the first run it asks “Where does your first list come from?”), and has no buttons (`esc` leaves, as the hint line says). The **left column** (sticky) is one card of rows, each a name, what it takes in one muted line, and its button at the right; no icons:

| Row | Button | What it does |
| --- | --- | --- |
| “The current list of <Game Config>” with “N mods” after it; “the list the game loads now; other managers save theirs here too”; the path on hover (`Exchange.Game`) | read | reads the game's ModsConfig.xml and shows it next to the selected list on the right (one click). Disabled when the game has none |
| Import a Mod list: “a share code, a Steam collection link, a list file…” | import | opens All lists' new / import form (§2.17, `newList("import")`) |
| Import Mod subscriptions: “Steam Workshop, LoversLab or GitHub links…” | import | opens add a subscription (§2.9) |
| Import a pack: “a .archopack file: a list with its Mods, checked file by file” | import | `API.PickPackFile`, then the pack's task on the right (10 §4; the pack has no other way in) |
| Import another manager's data: “Mod tags, colours, notes and sorting rules from RimSort, RimCrow or RimPy” | — | the managers found as cards under it (below), then “Not found? Add it yourself” with “add…” (`API.PickManagerImport`) |

The row whose result the right shows is tinted in the accent. The **right** is, before anything is read, the drop pane: a dashed area as tall as the view with Archo (176 px) in its middle, “Drop the files or folders to import anywhere on this window” under her and three small marks for what can be dropped (lists, packs, another manager's data; each named on hover). A result replaces it: the order comparison (below), the managers' tree, a pack's task or a refusal, in one card with no label above it (the user, 2026-11-20: what it shows says what it is). The two columns are one height, the view's: the left card and the right card or the drop pane start and end on one line, and what is longer scrolls inside its card (a narrow window stacks them at their own heights); its foot holds the buttons at the right, the filled one last, and stays at the bottom of the view. In “2col” Archo is not shown beside a result; in “3col” a rail at the right (220 px, shown with a result) holds Archo at its top, the counts as a column and the buttons stacked. The hint line shows `enter` import only while a comparison is shown.

**Order comparison** (since 2026-11-20; `listdiff.js`, the RimCrow comparison's idea without its lines): one line of counts, each a coloured dot, a word and its number, named on hover (removed: in your list, not in the incoming one, red; added, green; moved, amber; unchanged: in the same order, grey, its hover saying how many changed number), then “N not installed” (the names on hover) with “subscribe all N” for those with a Workshop page, and a close mark at the right. Under it the two lists side by side, the selected list on the left and the incoming list on the right, each headed by its name and count; the incoming list's header has where it comes from (the format, the file, the game version) on hover and, when the list is for another game version, an amber “RimWorld 1.5” whose tooltip says so. Each row is its number, the Mod's name and, on the right, a red ✕ for a Mod not installed or the versions mark for one installed in another version; removed, added and moved rows are tinted in their colour with a 3 px edge. What “moved” means: the Mods kept in order are a longest common subsequence of the two lists' shared Mods; every other shared Mod moved. Runs of more than four unchanged rows fold to one row, “N unchanged, folded”, keeping the first (and, inside a list, the last); a click opens it. Hovering a Mod outlines it on both sides. The rows come from `ImportPreview.Current` and `.Incoming` (the package id is the key). The foot: the choices that ride along (“follow this collection” for a Steam collection, on; “apply the Mod settings of N mods” for a RimArcho list that carries them, off: it applies all of them, not replacing files the player has; the per-Mod choice stays in All lists' form), then “add only what it lacks”, “save as a new list…” (asks the name, starting from a free one; the game's list starts from its Game Config's name) and “apply to <list>”; the filled one is “apply to <list>” for the game's list and “save as a new list…” for any other. While the import runs its button is busy (a turning mark, `aria-busy`), the status line says “importing…” and Archo thinks. A list the selected list already is shows “<list> already matches the game.” or “<list> already is this list.” and only “close”. A read that fails shows “could not read it” and the reason in amber, with “close”. The selected list is the current list, or the list selected on All lists or in the editor when the page was opened from there.

“add…” and a dropped file send a file where it belongs: a pack to the pack's task, a RimCrow database, a RimSort `aux_metadata.db` or `userRules.json` (`API.ManagerFileKind`) to the managers (it joins the survey and its manager is shown), anything else to the order comparison.

**Dropping files** (since 2026-11-20): a file dragged over any page dims the window under one dashed box, “drop to import” with the list, pack and manager marks (`.xc-dropover`; it takes no pointer events, so the drop reaches the page). Dropped, the file opens the Import page. What it is follows from its name (`dropKind` in `exchange.js`): `.xml`, `.rml`, `.json`, `.txt`, `.rws` are lists (compared); `.archopack` is a pack (its task); a `.db` file or `userRules.json` is another manager's data, and a folder a manager's data folder (it joins the managers and their tree shows). Every failure answers on the right, with Archo shaking and the status line saying it: a name it does not know is refused (“Not imported”, the file's name after a red stop mark, and what RimArcho imports); a list it cannot read shows “could not read it” and the reason; a folder or file with no manager's data in it is refused with “no RimSort, RimCrow or RimPy data in it”. Several files: the first is read and the status line says one file at a time. A form that takes drops itself (All lists' new / import, §2.17) handles them first. A dropped list is read from its content; a dropped pack, database or folder needs its path, which only a native drop gives (`dropped({path})`). **Known gap**: the Windows window uses WebView2 composition hosting (§8.2), under which the window has no OLE drop target, so files dropped on the native window do not reach the page yet; until the window registers one (options in `docs/design/2026-11-20_import-page.md`), drops work in the browser harness only, and without a path a pack is answered “choose it with “import” in Import a pack” and a database or folder “add it with “add…” under another manager's data” (amber mark).

**A pack** is added as a background task in the RimArcho queue (`pack-import`, §2.16; `API.StartPackImport`, 10 §4). A newer revision of a pack the player has (`API.PackUpdateOffer`) first asks “update pack <name> to revision N” with the revision the player has, that saves and settings stay, and the Mods added, removed and changed; “update the pack” starts the task with the update, cancel adds nothing. The preview (“Adding a pack”) shows its name, “adding the pack…” with a moving bar, and “background tasks”; when it ends, the pack's report and “open packs”, or the reason it was not added (amber) with “close” and “choose another pack…”. Leaving the page does not stop it.

**Everything from another manager** (07 §6.5): when the page opens, the page looks for the managers found (`app.FindManagerImports`, 07 §6.2 locations, never whole drives) while `API.ImportSurvey` reads each source in its own session (dry runs; nothing is written) and fills in what it holds. While it reads the source says “looking for RimSort, RimCrow and RimPy…”; with nothing found, “No RimSort, RimCrow or RimPy data found.”

- **A card per manager** under “Import another manager's data”, with a check box, its mark (two letters on the neutral pill colour) and name; nothing is ticked when the page opens. A manager never imported shows what it holds (“profiles 3, notes and tags, rules, saved lists 6”). One imported before shows “imported 11-09” after its name and either a “new” tag and one line of what is new since (“notes 4, tags 2, lists 1, changed lists 1”, cut with an ellipsis, whole in the tooltip; it sorts first) or “nothing new since then” (its mark faded; it sorts last). What is off by default (RimCrow's switched-off rules) is not news.
- **Clicking a card picks the manager**: its new parts that are on by default are ticked, and the right shows its tree; clicking again removes it. Groups with something new open by themselves after an earlier import.
- **The tree**: manager › kind of data (profiles, notes and tags per source or RimSort instance, rules, saved lists) › part. A part is a profile, a list file, or one kind of player data (aliases, notes, groups, tags, colour marks, ignored warnings; user rules, rules switched off there, interlocks). Each row says what it becomes (“41 notes”, “a new list”, “a Game Config with its list”) or “not brought over”; a kind says what its ticked parts become, or “N of M chosen”. A box turns its whole branch on (only what is new), or off when all of it is on; a parent shows a bar when partly on. RimArcho's check box is drawn by the page with the GUI's tokens: 16 px, the small radius, a hairline outline, the accent with the `ok` icon's tick when on.
- **Already in RimArcho**: a part whose values RimArcho already has is grey with a disabled box and “✓ already in RimArcho” (a profile: “✓ already the Game Config …”); a part with new values shows its total and, after an earlier import, a “4 new” tag. A profile that cannot come over (its game is not here) is greyed with the reason. A part the source does not have is not shown.
- **Lists imported before** are not ticked by picking the manager or the kind: “already the list Main colony · import another copy”. When the file changed since, it has a “changed” tag and “your list Main colony, changed since · update it · another copy”. “update it” replaces that list's content (one undoable edit; the list is not opened), “another copy” makes a new list (“Main colony 2”).
- The manager row and the summary under the tree count what is chosen (“5 of 6 parts”, “everything new”, “lists again 1”). The footer says the files are only read, that what is already in RimArcho stays, and that only a list's content can be undone; “cancel” clears the choice; “bring over the selected” starts the run.

**The run** is one background task in the RimArcho queue (`migrate`, `API.StartMigration`), an item per part, brought over one at a time; the window's lock is held for one part at a time, so the window answers between parts. The tree turns into the run in place: the managers' names, “moving in… 5 / 16” and a bar; each part waiting (a dot), running (a spinner), done (a tick and what it came to: “1 added, 3 already there”, “1 kept yours”, “a new list Latest_ModList  1 not installed”, “a Game Config Vanilla+”) or failed (the reason). The manager row says the same with a thin bar. The footer says it runs as a background task and the player can leave; “background tasks” opens it there; “stop” finishes the part in progress, keeps what is done and marks the rest “not done: stopped”, then offers “continue N” and “choose again”. At the end: “retry N” for failed parts, “open lists” when lists came over, and “done”, which reads the managers again, so what came in now shows as imported (or returns to the guide when the page was opened from it). No page-wide loading bar.

**First-run view** (§2.15): opened by the guide after its scan, the lead asks “Where does your first list come from?”, the game's row has its button “use this list” (the page's one filled button), which ends the guide (the scan made that list already); the other rows are there too, and bringing in a list, a pack or another manager's data ends the guide as well; the header's “skip” (`esc`) ends it with the game's list. The managers are not surveyed on the first run.

**Export** is not on this page (removed 2026-11-20 at the user's request; it was a “Share” section with the current list's formats and a pack's file or list). The lists' Export subpage (§2.17: All lists' `e`, the editor's `e`), the pack page's `E` and `e` (10 §4), `archo loadout export`, `archo pack export` and MCP `exchange_list` are unchanged.

**Not on this page**: CLI parity for picking parts (`archo import rimcrow` and `archo import rimsort` still bring everything over); a record of list imports from a file or a link (the record is only for what managers left on this computer).
