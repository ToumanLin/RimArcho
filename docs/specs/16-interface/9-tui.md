## 9. TUI

### 9.1 Positioning and page mapping

The TUI is the **keyboard version of the plan editor**. It opens the current plan's editor by default (§2.5), provides other pages through the command panel, and has no sidebar. The TUI and GUI share view models and keys (§3).

P, command-panel lists, and editor tab only open a list; the launch list remains current and the top bar adds launching X. Only set as current in P, saving with w in that list's editor, or L makes it current. T matches the GUI: in Staging it puts all items back; elsewhere it stages all Enabled items (2026-10-31). - Launch uses the red and yellow wording in §2.3. At the severe level, it lists required and available memory separately before launch. Cancel is selected by default, and the player must explicitly choose launch anyway. See §2.4 for memory comparisons and levels.
- Game runtime status appears at the **right end of the status line**. The GUI has no equivalent sidebar row since its removal on 2026-10-30; it reads new logs itself (§2.1). While running, the TUI shows `● game running since 14:05`, followed by an amber current-error count. A new Player.log after exit shows `● read the new log  shift+2` in the accent color. Otherwise, nothing appears. The status sentence stays on the left while this segment stays on the right. New errors update the top-bar can it run N without opening a dialog (`view.LiveTracker.Update`; interval §2.16.1 G01; wording `view.LiveText`).
- Can it run log items use the phase groups in §2.4. The indented muted headings have no cursor or count; up/down always lands on an actual error. Unmarked logs have no phase headings. Viewing still opens the existing technical page.
- Bubble Tea v1.3.10 does not recognize xterm's `shift+F10` (`CSI 21;2 ~`). The Windows console sends plain F10, and xterm-like terminals send F16 for the Menu key. Therefore F10, `shift+F10`, and F16 all open the TUI context menu; right-click opens it at the pointer. The filter bar spans the full TUI width because the Disabled column cannot fit the filters. Inventory copy details contain notes, actions, status, and fields without a description (**pending**). The TUI has no images (§9.3). At the bottom level of inventory, `esc` returns to the editor because there is no sidebar.
- Page shortcuts are `shift+1`–`8`, which produce `!@#$%^&*` in a US terminal layout; `shift+7` opens texture optimization as a command text panel. Subpages use `tab` / `shift+tab` (§3.5). Since the 2026-10-22 decision, `g` means tags rather than top. The proposed `g`-prefix navigation was not adopted.
- Both `archo` and `archo tui` open the TUI in the current terminal (§9.2). The interface does not show `#id`: results use plain wording and errors pass through `view.Humanize`. Only technical pages and `:` output retain CLI text with references. In a technical page, `enter` follows the selected line's first reference. Unprefixed instance references in printed commands (13 §3.1 rule 11) can also be followed if the current index recognizes them (`lineRef`).

### 9.2 Which terminal runs it

Since 2026-10-30, the TUI no longer bundles a terminal (00 §6 D24). Both `archo` without arguments and `archo tui` run in the terminal that launches them. Double-clicking `archo.exe` lets Windows open its default terminal: Windows Terminal on Windows 11, or a console window on older systems. The TUI runs there and the window closes when it exits. Old shortcuts using `archo --here` are still accepted and behave like `archo` (`cli.globalFlags`).

- The player's terminal determines the font; RimArcho distributes no fonts.
- For colors, termenv cannot query the terminal under ConPTY and falls back to no color. Therefore `SetColors` forces 24-bit color when the terminal declares support through `COLORTERM=truecolor|24bit` or `WT_SESSION` (Windows Terminal). Other terminals retain termenv detection.
- The old data-directory `wezterm\`, generated `wezterm.lua`, and `logs\wezterm-start.log` are unused and are not automatically deleted, as decided on 2026-10-30. Uninstall removes them with the data directory, or the player may delete them. The settings `terminal.host`, `wezterm.path`, `ui.previews`, and `ui.preview_dwell_ms` have been removed; their old database values are no longer read.

### 9.3 Icons, links, images

RimArcho cannot control the font in the player's terminal, so the following rules apply:
- Icons default to the Unicode fallbacks in §7. With `ui.icons compat|nerd`, compat is the default; choose nerd only when the terminal already uses a Nerd Font. An old database value of auto is read as compat. Other old values outside the choices use the default (`cmds.Setting`).
- The TUI draws no images. It has no thumbnail or reserved thumbnail space, and names start flush left. Description images become text placeholders (§4.4).
- Links are not clickable; their domain appears in muted text after the link text.

### 9.4 Command line (`:`)

The advanced input box runs one archo command just as terminal `archo …` does, using the same `cmds.Commands` table and text output (13 §4). The 2026-10-30 decision is that **all commands run directly without extra confirmation**, as in the CLI. To preview a file-changing command that supports it, add `--dry-run`. The implementation is `internal/surface/tui/cmdline.go`.

**Opening and closing:** press `:` in the editor, can it run, updates, or Mod inventory, or choose run archo command in the command panel. In a text panel, including the previous command's output, `:` closes the panel and opens input so commands can run consecutively. The input occupies the bottom line after `❯ archo `, with a help line above and up to 8 candidate rows above that. The `esc` key closes the candidate list first, then the input. Unexecuted text remains for the next `:` (§3.1 rule 8); running a command closes and clears the input.

**Editing:** `←→` moves the cursor, `home` / `end` moves to the line ends, and `ctrl+←` / `ctrl+→` moves by word. The `backspace` / `delete` keys remove characters, `ctrl+w` removes the previous word, and `ctrl+u` clears the line. Direct paste is supported. The leading `archo` is optional. Both `"with spaces"` and `'with spaces'` form one argument, so a printed `archo pack launch "name"` can be copied directly. Backslashes are preserved for Windows paths. The `#` character is not a comment marker; `#a3f9` and `a3f9` both work (13 §3.3).

**The help line** shows the recognized command's usage and one-sentence summary (`cmds.Command.Usage`, `Summary`), in English like `archo help`. Otherwise, it shows `tab complete  ↑↓ history  enter run  esc close`. A usage error from the last Enter appears here in red until the input changes.

**Completion (`tab`)** completes the word at the cursor:
- Command names match by prefix first, then by substring; for example, `remove` finds all removal commands. Candidates show their usage and description.
- A word beginning with `-` offers the command's flags, such as `--dry-run`, and their descriptions.
- Positional arguments follow the usage placeholders. Mod placeholders (`<ref>`, `<ref…>`, `<mod>`, `<A>`, `<B>`) match the current game's Mod names, aliases, package IDs, and references. They insert a reference without `#` (13 §3.1 rule 11) and show the name and reference. For an empty word, the cursor Mod is the first candidate. Other completions include environment names for `env use|set|remove`; list names for `plan use|rename|remove|cost|versions|follow|unfollow|sync` and `test run`; pack names for `pack launch|export|remove|check|stop`; setting keys for `config get|set`; allowed values after `config set <key>`; literal choices in usage such as `same|copy|unrelated` and `yes|no`; and tool names for `deps install|remove`. Paths are not completed.
- A single candidate is inserted directly with a trailing space. Multiple candidates appear above the input, with the first inserted. The `tab` / `↓` keys select the next candidate, and `shift+tab` / `↑` select the previous one, updating the input. The `enter` key accepts without running; continued typing also accepts. The `esc` key closes the list and restores the original word. If there are no candidates, the help line says nothing to complete.

**History:** when no candidate list is open, `↑` recalls previously executed commands, newest first. The `↓` key moves back toward the draft; passing the newest command restores it. The latest 50 commands persist as a JSON array in database meta `tui.cmdline.history` across TUI restarts. Running a duplicate keeps only its latest occurrence. Usage errors are not executed and are excluded.

**Running (`enter`)** follows these rules:
- The command runs in the background (§3.1 rule 9) with its own database connection (`App.ReadSession`), while the interface remains usable and the status says running archo …. Only one command runs at a time. Enter while it is running does not execute another command; the help line says previous command is still running.
- After completion, the list is reread. A single output line appears in the status line with a success or failure marker (§7). Multiple lines open a panel titled `archo …`; a failure also says command failed in the status line. The panel retains the original CLI text and references (§9.1); `↑↓` scrolls and `esc` returns.
- **Usage errors**, including an unknown command, wrong argument count, or unknown flag, have exit code 2. They reopen the unchanged input and show the error in the help line so it can be corrected and run again. The `mcp` and `gui` commands themselves report this kind of error because they require a standalone command line.
- The `scan` command runs in the scan subprocess, like `R`, and `analyze` runs in the analysis subprocess (05 §3); neither runs in the interface process. The `log --follow` command is refused because it never ends. The help line explains that the TUI status already follows the game and that a scrolling log should be run in the terminal.
- As in the CLI, `--env <name>` applies only to this command.
- After execution, `config set ui.lang` and `config set ui.icons` take effect immediately. The `env use` and `plan use` commands switch the interface to the new environment or list, as `E` and `P` do. After `uninstall --yes`, only exit remains available, as on the uninstall page (§2.14).

### 9.5 Differences from GUI

A page-by-page comparison was made on 2026-10-31 (§2.x against §9.1, and keys against §3.5). Names, subpage order, key hints, command-panel commands, list opening and switching, `L` first visiting Launch, and `T` now match the GUI. The remaining differences follow.

**Intentional differences** reflect terminal limits or easier TUI use:
- There is no sidebar. Other pages are secondary screens, and bottom-level `esc` returns to the editor. The `alt+←` / `alt+→` shortcuts do not apply (§3.1 rule 11).
- Can it run has one column rather than before you play and last time columns (§2.4).
- In the editor, `h` and `l` are arrow keys (§3.3), and `i` opens technical information rather than import or export (§3.5).
- Launch has one column containing the current list and launch action, without other lists, packs, or games (§9.1 table).
- There is no click-to-copy or `ctrl+c` copy; the terminal provides text selection (§3.1 rules 12, 13).
- Updates uses three simple lists rather than a table with a detail column (§2.9).

**The following are not yet aligned** and await implementation or a decision:
- In Mod inventory > all, `enter` opens copy details containing only notes, actions, status, and fields, rather than the GUI's full-screen details. TUI full-screen details follow the editor rows (§9.1). Search files results also cannot open full-screen details.
- The outside-page rows at the bottom of can it run are text only, without a key to open inventory or texture optimization.
- The game-log page is pending (§9.1 table). Packs, texture optimization, and background tasks remain text panels without pages.
- Mod inventory > all has only the default size, status, source, and used in columns, with `s` for sorting. It has no GUI column menu for showing or hiding columns.
