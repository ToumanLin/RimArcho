# 16 · Interface · Play review and Saves (§2.11)

> Part of [16 · Interface](README.md). Section numbers run through all of 16 and stay unchanged when split across files.

### 2.11 Play review and Saves

**Play review** (Unplayed group; 1.1, not implemented): untouched content, 12 §3.

**Saves** (Library group, after packs) is a GUI page (`saves.js`, `view.SavesRows`, `view.SaveDetailOf`, `view.SavePlayOf`, `view.SaveContent`, `API.SavesRead` / `SaveDetail` / `SaveContent` / `SaveFix`). The left and middle cards come from the save heads (L0); the right card, Over time, the in-game days, the grouping by world and the consequences in Can it load? (12 §4.6) come from the full read (L1). Rules, data and actions are in 12 §1.7 and §4; the chosen draft is `docs/design/saves-drafts/b.html`. Three cards fill the window (00 §6 D20); the gaps between them drag.

- **Left: colonies and their saves.** The search is a card of its own above the tree (`/`, `esc` clears; no icon; focused, its border lights up in place, the card's size and corners): it matches colony and save names, not Mods, and expands the colonies it finds. Below it is the colonies card, with colonies by last played. A colony row shows only its name and save count; clicking it expands its saves underneath as a tree and selects the latest, and clicking the open current colony folds it. A save row shows only its name (RimSaves prefix removed, 12 §4.1) and in-game day. The left card has no status icons, descriptions or warnings.
- **Middle: the selected save.** The header has the save name (no icon) and Rename, Copy, Back up, Make a list, Recycle (12 §4.4), then only three facts: game (version and environment), list or pack, and location (folder and file, with Open location). **Can it load?** (12 §4.3) checks the save against what the Launch page applied (the current game and its current list, or the applied pack, §2.3) and lists only what needs attention: a quick-fix bar with the verdict and at most one primary action, then the rows under **the file**, **the last load**, **game changes** and **Mod list changes**, each with its consequence and its own fix button. Passed checks are not listed. **Over time** (12 §4.5): the colony's timeline, whose points open their saves, with zoom. **Mod changes**: only how the list the save is checked against (usually the current list) differs from the save's list (12 §4.3): the list's Mods the save lacks green with +, the save's Mods the list lacks red with −, load order ignored; long changes fold, and the whole list unfolds on request. A save with no list or pack shows its whole list folded instead.
- **Right: the colony and its content.** Colony name (with Rename), day and date, storyteller, difficulty and played time (the biome is not read, 12 §1.7); then **Content in this save**: the Defs the save references by the Mod providing them and by content category (12 §1.4, §1.5, §2).
- **Loading.** The left card, the middle header and the Mod list come from the save head at once (12 §1.7 L0). Consequences, play facts and grouping by world wait for the full read (L1) and show skeletons meanwhile; progress appears in the status line and in background tasks (§2.16).
- **Keys.** `/` search; ↑↓ move through visible saves; ←→ fold and unfold the current colony; `enter` runs the quick-fix bar's action; `F2` renames; `1`–`3` the colonies, the save and the colony's content, numbered as other pages number their cards (the search has no number).
- While the game runs (09 §4), Rename and Recycle are disabled with the reason. A file written in the last 5 seconds shows "being written" instead of a verdict.
- TUI: no page; the `saves` commands run through `:` (§9.1).

In detail:

- **Reading.** Opening the page shows its structure, then `API.SavesRead` lists the saves on the page's own reader in the background and sends a `saves` event (a newer request drops an older one). The reader keeps the head cache (12 §1.7), so coming back stats each save instead of reading it; leaving the page drops the listing (17 §7.3). Rescan reads again. Selecting a save runs `app.CheckSave` against its list as it is now (`API.SaveDetail`).
- **Full read** (12 §1.7 L1; `gui/saves_read.go`). After a listing that has saves not read yet, the background task "read the saves" (kind `saves`, RimArcho queue, one run at a time, stoppable) runs `archo saves index --progress <selected save>` as a child process; closing the window ends it, and each save it read stays stored. Its progress (`n/total` and the save) goes to the task record and, while the page is open, to the status line unless that shows a failure or an undo. The page hears of the run through `saves-read` events (§2.16.1 G20): the saves read, the progress, and, at most once a second and at the end, the listing again, so rows get their in-game day and colonies regroup by world while the selection and the open colonies stay; when the selected save is among those read, its cards are asked for again. A selected save that is not read yet never waits for the run: `SaveDetail` answers at once with skeletons in the right card and reads that one save on its own read session in a goroutine (one at a time; a newer selection replaces one that waits), then sends `saves-read` with it. The run may read the same save again, which only rewrites its cache row. The page keeps the facts of the selected save only (dropped on leaving); listings carry only summaries.
- **Left.** A save row shows its in-game day once it is read, with the date it was saved as its hover text; until then it shows the date. Search matches colony and save names on the page, marks the matches and opens the colonies found; `esc` clears it.
- **Can it load?** The save is checked against what the Launch page applied (`API.SaveDetail`, `appliedTarget`: the current game's current list, or its applied pack, `view.AppliedPack`). When that is the save's own game and list or pack (`app.SameTarget`), or the save matches none, the heading names it: "against the current list X" (or "against pack X"). When the save matched another game, list or pack, the bar starts with a line for those (`SaveDetail.Switch`): "with <game> and list X: loads as it is" (or "content will be lost", "will not load cleanly", from a second check against them), green, amber or red, and **Switch and launch**, which applies them as clicking their row on the Launch page does (`home.applyItem`, `API.HomeApply`) and opens that page with its launch button focused; then "with the current <game> and list Y", whose verdict bar and rows follow. The game starts only from the Launch page: no button here launches it. The bar's verdict drops "loads, but" (warnings read **content will be lost**) and says when what the Mods own could not be checked ("assemblies not analysed yet", or "Defs and assemblies" when the Defs were not either, 12 §4.6). Its one action: Recycle… for a file that cannot load; while something could not be checked, **Make a list from this save to analyse its assemblies** (`API.SaveNewList` with analyze: the list is made as below, then analysed as a background task while the page stays, and the save is checked again when the `analyze` event says it is done; the analysis indexes the save's own Mods, which is all the check needs); else Launch, or Make a list from this save for a save matching no list. There is no Fix and launch: each row has its fix. Launch (the save loads with its own list, which is the applied one) opens the Launch page with its button focused; `enter` runs Switch and launch when that line shows, else the bar's action. Rows by group, in this order: **the file** (unreadable, cut off, malformed), **the last load** ("the last load logged N errors and M warnings", omitting zero counts and using singular nouns for one, with when, the first message and how many kinds (12 §4.3); Open the game log selects that cluster on the game log page), **game changes** ("the game version changed since this save (1.6… → 1.7…)"), **Mod list changes**. Each row has a sign (− missing, + added, ↕ order), its heading, its consequence and its fixes. The Mods that are not installed are **one row** naming them (6 at most, then how many more), whose consequence is what they lose together (`SaveCheck.GoneOwns`: what nothing installed provides is counted once, not once per Mod) and says when the database has no data on them; its fix subscribes and enables the ones with a Workshop page; **View** opens under it each Mod with its packageId and Workshop page (or that it has none) and what is lost by kind: colonists by race, factions, classes and Defs by type, the most used 100 names of each. An installed Mod not in the list is a row headed by its name (the hover text says "installed but not in the list") with **Enable**; past 4 such rows the rest fold into one row with one fix for all of them. The Mods added since the save are one row naming them (8, then how many more) with **Disable**; the reordered ones one row with Use the save's order. A cut-off save gets Recycle… and opens the colony's previous readable save.
- **Fixes.** Every Mod fix is `API.SaveFix`: one undoable edit to the list the save is checked against (the applied list; the matched one when they are the same), which opens in the editor without becoming current (07 §1.3); the status line's undo undoes it and checks the save again. Workshop Mods added by a fix are then subscribed through the Steam / SteamCMD choice that missing Mods use. A pack's save, or one matching no list, offers no Mod fix. `archo saves fix --launch` (12 §4.4) fixes and also launches; the page does not offer that.
- **Mod changes** (`SaveDetail.Changes`, `Mods[].Change`). The heading says what the save is checked against, as Can it load? does ("against the current list X", "against list X", "against pack X"); under it the counts ("3 added", "1 removed"), then one 24 px row per change: the list's Mods the save lacks first (+, green, in the list's order), then the save's Mods the list lacks (−, red, in load order), each with the sign (its hover text says which side has it), the name and "not installed" when it is not (never for a pack's Mod). A name whose Mod is in the Mod library (`Library`: the installed copy this environment resolves the packageId to) links to it there (its packageId and "show in the mod library" as hover text). Past 12 changes the rest fold behind Show all N changes; Show fewer folds them again. Show the full list (N Mods) unfolds the save's whole list in load order, rows numbered, the changes marked with their sign and colour, ↕ on Mods in another order in the list, then the added Mods; Show only the changes folds it. The choice holds while the save stays selected. No change says "the list has the same Mods as this save". A save with no list or pack has no changes: the heading says "this save's N Mods" and the whole list is folded behind Show the full list (Show fewer folds it). Only the rows in view and 8 on each side are mounted as the card scrolls (§11 A18), each a list item with its position. Make a list (header) takes the path of All lists' "from a save" (`view.NewPlan`), names the list after the colony, and opens it. Selecting a save from Can it run's last save (§2.4) opens the page on it (`save:<ref>`).
- **Colony name** (12 §4.1). Rename in the right card's header, or a double-click on the colony name, edits it in place (at most 80 characters): `enter` or leaving saves (`API.ColonyRename`), `esc` cancels, an empty name gives back the saves' name, which is the placeholder. The saves' name is the hover text of the colony's tree row and of its name in the right card, and the search finds the colony by it too. Save files keep their names.
- **Files.** Rename (`F2` or double-click the name) edits the name in place; a taken name is refused while typing; `enter` or leaving the field saves, `esc` cancels. Copy selects the copy. Back up and Recycle show an inline confirmation in the middle card listing the files and sizes and where copies go; `esc` cancels. While the game runs, Rename and Recycle are disabled with the reason.
- **Over time** (middle card, between Can it load? and Mod changes; `view.SavePlayOf`'s `timeline`, 12 §4.5). This save's own wealth and colonist records from day 0 to its day (thinned to 120 values each), a mark per death letter, and one point per read save of the colony at its day, on the wealth line where the line reaches it and on the axis after it; a point opens its save, and the chart reads as one image (the tree reaches every save by keys). The legend names the dead. A long colony's saves sit pixels apart, so the chart zooms: −, + and Fit in its heading, `ctrl`+wheel around the pointer, and `+`, `-`, `0` while the section has the focus, from 1× (the card's width) to 64×; zoomed, it scrolls sideways (drag, `shift`+wheel or its scrollbar), the axis labels its days about every 90 px (1, 2, 5, 10, 20, 50… days apart), and the selected save is scrolled into view. The zoom is kept per colony while the page is open (each colony its own; opening the page starts at 1×); picking another save of the colony keeps it. The section is drawn on its own (`fillTime`), so the full read's news redraws it without the rest of the card and a rename in progress stays. While the save is read it shows skeletons; a save with no timeline has no section.
- **Right** (the colony and its content). The header (`view.SavePlayOf`) has the colony name, the in-game day and date (the game's quadrum names; the date may be a day off, 12 §1.7), the storyteller and difficulty by their in-game names for the vanilla Defs (a Mod's by Def name; commitment mode added) and the real play time; a malformed save's note says the facts come from before the break. **Content in this save** (`API.SaveContent`, `view.SaveContent`; asked for after the check, so the cards above never wait for it): the heading counts the Defs and their Mods; chips give each content category over all Mods (12 §2.2) with its count, `*` and a hover text on categories that may be underestimated, how many factions are hidden, and the uses; clicking a chip filters the Mods to that category and shows its Def names under each, clicking it again clears the filter. Then one row per Mod with Defs in the save, in the save's load order: name, Def count and its categories ("12 weapons, 3 factions"); opening a row shows each category's Def names (most used first, at most 100, then how many more) and Show in the mod library when it is installed. Past 40 Mods the rest fold behind Show all N Mods. **Source not found** is the last row: Defs no installed Mod of the save defines (12 §1.5), with a hover text explaining why. A note names the save's installed Mods whose Def facts lack the category fields ("not analysed yet"): what they add is left out, not counted as source not found, and the note's Make a list from this save and analyse it does what Make a list does with analyse (above), after which the card fills in. A Mod that is not installed is not in this note: its Defs are source not found. and another counts the save's Mods with no Def in it (code, interface and patch Mods leave none, 12 §3.3). A note says a Def means only that it was present, and a list under it says what this version cannot see in a save (`SaveContent.Limits`: Defs added by patches, terrain and biomes, content left only in history, the scenario; 12 §2). A name that several Def types define counts once per type (12 §1.5), so the categories may add up to more than the Def count. The section is redrawn on its own (`redrawContent`: the reply, a chip, opening a Mod), so a colony name being typed in the header stays. It shows skeletons while the save is read, and while a save cached by an older parser is read again for its content (`stale`, 12 §1.7); a note when it is not read in full; no number is made up.
- **Keys.** Besides the keys above, `1`–`3` focus the cards, each with its number before its heading. Saves has no `shift+` number: `shift+1`–`8` stay on the other eight entries (§3.5).
- **Size.** The page's accessibility tree and mounted rows follow §11 A18 and the targets in §10; measured: 18 §2 (Saves page full read) and §11 A18.
