### 2.17 All lists (formerly List management)

The page was defined on 2026-10-23 and is implemented in the GUI. The prototype is `docs/design/all-lists-drafts/` (the second A draft; the three-column B draft was rejected). It explains which lists exist, which game versions each supports, which collections each follows, and how to share them. Content editing remains in the editor (§2.5).

**Entry and location**: All lists is the first child under Lists in the sidebar, above recent lists (since 2026-10-26). The sidebar shows at most 4 lists; the remainder appear only here. Clicking Lists itself opens the current list (§2.1). The breadcrumb is Library / Lists / All lists. With top navigation, All lists is the last subpage button.

**Heading** (changed 2026-10-25): show no description (§7.3), only the primary new / import button at the right (`n`). Creating and importing already share one form, so they have no separate entries; `i` still opens import mode directly. If a draft exists, the button resumes it. While creation is in progress, the button is no longer solid.

**Left card**: by default, the left card occupies 38% of the page width and the right card 62%, with a minimum width of 270px. The gap between them is draggable; store the split in `ui.gui.plans.side`, and reset it on double-click (§7). All lists are shared across games (07 §1.7), with no game groups. Show the current game's current list first, then the others in creation order. When a list is made current, animate its row from the old position to the new one, as in the sidebar (§2.1). Lists whose allowed versions exclude the current game remain visible; the secondary version text already explains this (07 §1.6). Each row has two layers:
- The top shows the name in bold and the markers: a green dot if the list is currently written in the game, or an amber dot for external changes that have not been adopted. These follow the sidebar rules (§2.5).
- The muted bottom layer shows the allowed versions, N Mods, and the last-play date, or Never played.
- At the right (changed 2026-10-26, replacing the linked-collection Steam icon), the current list has a current pill. Other lists show make current on hover or selection. This sets the launch list without writing game files (07 §1.3).
- The row under the cursor has the selected background and an accent-colored name.

**Right card**: this card shows the selected list's details:
- **Header** (2026-10-25): show the name and markers. Current / make current moved to the right of each left-card row on 2026-10-26. A muted facts line below shows the Mod count, last-play date, creation date, and origin (the v1 note, such as copied from default v4). Show game currently uses v18 in green only when applicable. Four buttons appear directly, without an overflow menu: Rename (`F2`), Duplicate (`D`), Delete (`Delete`, requiring confirmation and disabled for the last list), and the primary Edit ↵, which opens the editor.
  - **Inline rename**: double-clicking the name, pressing `F2`, or clicking Rename turns the name into an input with all text selected. Check for duplicate names while typing. `enter` or leaving the input saves; `esc` cancels. No dialog opens.
  - **Duplicate**: immediately copy the current load order and allowed versions, starting an independent history. Name the copy `<name> copy`, adding a suffix if the name already exists. Select the copy and activate rename. Undo in the status deletes the copy. Duplicate in the sidebar context menu behaves identically.
- **Game versions** (07 §1.6): show small buttons from 1.0 through the current game version, displaying only version numbers. Allowed versions are raised and use the accent color; the current version has a dot. Hover text says that N Mods do not declare 1.7 support or that all Mods declare 1.6 support. Clicking adds or removes the version, retaining at least one. If the player has changed the defaults, show reset to default at the right, with the defaults in its hover text; otherwise add nothing. Do not add explanatory prose here. Readiness identifies Mods that do not support the current game. After a change, the status says Main colony allows 1.5–1.7 and offers Undo.
- **Follow Steam collections** (07 §7.6): show the linked count at the right of the heading. Each collection has a card:
  - The first line shows the Steam icon, title, and muted item count. At the right are the Open in Steam icon and Unlink.
  - A muted second line shows the last check, such as Today 14:02, 4 not installed, and Subscribe on Workshop. Do not show the URL itself.
  - If the collection has changed, show an amber-tinted line with 3 added and 1 removed and Show diff, and Sync collection at the right. Expand the diff inline, with green `+`, red `−`, and one Mod per line. If unchanged, show ✓ Matches collection.
  - The final row says On sync and has two segments: Add new only / Also disable removed.
  - Below the cards, show an input for pasting a collection link and Link. If no collections are linked, show muted No linked collections above the input.
  - Sync is one undoable edit. The status says Main colony synced Vanilla Expanded collection: 3 enabled and offers Undo.
- **Share**: show the last pack created from the list in one row with its name, size, and date. Open at the right goes to the pack page. Below are Export… (`e`, opening a subpage) and Create pack… (`B`, §2.6).

**Export subpage**: the breadcrumb is Library / Lists / <list> / Export. The sidebar stays on All lists, or on the originating list when opened from the editor. The heading has no description. Cancel at the right (`esc`) returns to the origin. The left card contains one radio choice per format (07 §7.3), with a name, extension, and sentence: RimArcho list (recommended), RimCrow share code, text list, ModsConfig.xml, RimWorld Mod list (.rml), RimCrow ModList.xml, and Workshop links. The right card shows N Mods and the allowed versions, followed by the full export in monospace (`loadout export --format`). Below it are Save to file… (a save dialog that never overwrites an existing file) and Copy. A share code has only Copy share code. Persist the selected format in `ui.gui.export.format`.

**new / import** (`n`, inline creation since 2026-10-24, simplified 2026-10-25): do not open a dialog (§3.1 rule 7). The breadcrumb is Library / Lists / All lists / New list. A named Draft row appears at the top of the left card and is not counted as a real list. The form at the right first asks for New list name, checks duplicates live, and defaults to New list. Then Start from offers Empty (default), Copy list, Save, and Import. Empty explains that Mods are added in the editor. Copy offers Source list (any list for the current game) and Version. The default is Current editing content (including unsaved changes); the other choices are all copyable history entries, showing the version, date, time, and Mod count. Changing the source resets the version to current content; stale reads cannot overwrite a later selection. Copy the current load order and allowed versions, starting an independent history.

The form has only one primary button, fixed at the bottom of the visible area. Its hover text says that no game files are written. Even a long preview must not require scrolling to find it. In Import mode, the button says Preview before a preview exists and Create and edit afterward; other modes always say Create and edit. Creation opens the editor without making the new list current (07 §1.3). `enter` in the name field or `ctrl+enter` in the textarea activates the button; `enter` in the textarea inserts a newline. Duplicate-name, read, and submission failures retain the input. Disable the form during submission to prevent duplicates. There are no Back to management, Continue later, or Create only actions. Leave through the sidebar, another list, or `esc`, which closes the form. Asynchronous reads of suggested names or source lists update inline; they never redraw the form and swallow a click in progress.

**Drafts**: retain drafts per game for the current app session. On leaving the form (esc, another list or page, or Back), discard drafts whose names are still the default or an unchanged import suggestion; the unchanged name indicates no intended creation. Renamed drafts remain in the left card. Clicking the draft or new / import restores its name and all source inputs. When esc leaves a retained draft, the status says Draft retained. The retained draft form adds a quiet Discard draft link; discarding is undoable. Drafts are not restored after a restart.

**Import within creation**: switch modes within the same form and retain the name. If the player has not edited it, suggest the source title or filename. A muted guide lists the supported imports: RimSort, RimCrow, RimWorld, and RimArcho lists, saves, share codes, and Steam collections. It explains that the player previews installed and missing Mods before creation. The dashed area has Choose file…, opening the native dialog and immediately reading and previewing the file; development falls back to the browser picker. Show the selected path and Clear according to §3.1 rule 12, or a drop-file hint if none is selected. There is no manual path field. Dropping a file anywhere on the form switches to import and reads it. Below, an Or paste textarea accepts a share code, collection link, Rentry link, or copied list. Read this input only on Preview; links use the network. Reuse import analysis to show the source, version differences, installed Mods, and missing Mods. Steam collections offer Follow this collection. Input changes invalidate the preview and restore Preview as the button label. Submission validates the preview identity and game. Preview alone changes no list.

**Missing Mods** (2026-10-25): below Not installed: N, explain that subscribed Mods return automatically to their list positions after download. Subscribe all (M) at the right first asks the player to choose Steam subscription / SteamCMD download, then queues the M Mods with known Workshop pages as one task (`subscribe workshop <id…>`, §2.16). For unknown pages, say that N Mods have no known Workshop pages and must be found manually. Each row retains Subscribe or Not on Workshop. After download and scanning, `loadout.Registry.Heal` replaces missing entries with the installed Mods in place. The editor import subpage shares this block. Readiness aggregates uninstalled Mods in the list into one item (§5).

**Import subpage** (editor `i`, onboarding, or a file dropped outside the import area; no dialog): `i` on All lists uses the creation import described above; the editor retains a separate destination flow. The breadcrumb is Library / Lists / Import, the sidebar stays on All lists, and Cancel (`esc`) is at the right. A text input accepts a share code, Steam collection link, Rentry link, or package name, with Choose file beside it. After reading, show the preview (07 §7.1): the name, source, game version (amber if it differs from the current game), installed and missing Mod counts with Workshop subscription for missing Mods, and suggested allowed versions. Below are three destinations: a new list, replace the selected list with added, removed, and moved counts, or add missing only. A Steam collection adds Follow this collection, checked by default. The Import button's hover text says that no game files are written. After import, return to All lists and select the imported list.

**Keys**: `↑↓` selects a list; `enter` opens the editor; `n` opens new / import (there are no Mods here, so it does not mean note, §3.5); `i` opens import mode; `F2` renames inline; `D` duplicates; `Delete` deletes with confirmation; `e` exports; `B` creates a pack; and `tab` enters the right-side controls. In the form, `esc` closes it. The hint lists selection, edit, new, rename, duplicate, export, and help. The form hint says enter Preview / Create and edit, esc Close.

**Loading cost**: between Game versions and Follow Steam collections, show Estimated loading cost. Display resident RAM and VRAM including Core and DLC, and the loading RAM budget. Resident means stable main-menu private bytes; loading means peak private bytes from startup to the main menu. Neither means working set. What is included expands the categories, the top five Mods for RAM and for VRAM, and the estimate boundaries. Measure in the background after rendering the page; discard stale results when the list or game changes. Data comes from `app.PlanLoadCost`, `loadcost.Estimate` / `Baseline` / `LoadingBudget` / `Spill`, and `view.PlanLoadCost`; the CLI command is `archo plan cost [<list>] [--mods] [--json]`. The model code is the sole source of coefficients. Unity 1.6 estimates use the vanilla baseline, per-Mod overhead and texture curve calibrated in the 2026-10-31 and 2026-11-01 VM measurements. Combined texture and DDS payloads were measured up to 7.5 GiB; larger payloads remain extrapolated. The VM's graphics adapter has no dedicated VRAM, so those private bytes include the driver's copy of every texture: 1.2 bytes per payload byte (`Coef.TextureGPU16`) and 0.66 GiB for vanilla. The model reports that share as VRAM and the rest of the curve as RAM. `loadcost.Spill` returns to RAM the 1.6 VRAM beyond `Coef.UsableVRAM` (90%) of the dedicated capacity, or all of it when no dedicated VRAM is reported (VM, integrated GPU, unreadable adapter); resident RAM, the loading budget and the §2.4 comparison include it and say how much it is. Without dedicated VRAM every estimate equals the VM curve; on a real graphics card the split is inferred, not measured. Loading budgets estimate startup peak private bytes from the payload and follow the same curve. Coefficients are owned by `loadcost.Coef`, `Baseline` and `LoadingBudget`; see [Unity 1.6 heavy-texture memory](../../research/2026-11-01_unity16-heavy-texture-memory.md) and [Unity 1.6 texture memory breakdown](../../research/2026-11-01_unity16-texture-memory-breakdown.md) for evidence and limits. The 1.7 loading reserve remains uncalibrated. Saves, maps, AssetBundles, and Mod allocations may exceed the scope. Changes to the per-Mod raw measurement format invalidate the file-fingerprint cache; model changes invalidate estimate totals. All lists use the selected game environment, or an explicit version override, to choose coefficients and LoadFolders, rather than the version saved in list history. An unknown version prompts a rescan. See §2.4 for hardware comparisons and levels.

**Data**: `view.BuildPlanManage` provides rows, selected details, allowed versions, and the number of Mods that do not declare support for each version. `view.PlanCollections` provides linked collections and changes from the cache, with network checks queued as background tasks (§2.16). `view.ExportPreview` provides the full export. The GUI APIs `PlanVersions`, `PlanFollow`, `PlanUnfollow`, `PlanSync`, and `PlanExport` share the CLI app functions (07 §1.6, §7.6). In the TUI, add Versions and Collections to `P` list switching (§9.1); export retains the command palette (**pending**).
