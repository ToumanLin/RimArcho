### 2.5 方案编辑器

方案页就是编辑器。已实现，包括多个方案（暂存和历史挂在方案上，04 §1、§2.2、§3）。新建（空、复制当前、复制某个版本、导入）、改名（输入时检查重名）、删除（确认，不能删最后一个）在列表管理页（§2.17）、方案页的“⋯”菜单、侧栏右键、`P` 和命令面板里。游戏的 ModsConfig.xml 里现在是哪个方案（写入记录，04 §1.3）不再写在状态行上：有两个以上方案时，那个方案的侧栏子项旁有一个绿色小点（悬停写“游戏里现在是：<方案> v<n>”），首页不再标（大卡片就是现在应用的那一项）；只有一个方案时不标。有未载入的外部版本时，侧栏条目、方案页和首页那一行带琥珀色标记。窄于 1100 像素时，顶栏的撤销、编译成整合包和按键提示收起。

**页面头**（2026-10-22 起和其他页面一样，§2.2）：面包屑下面一行淡色的“启用了 34 个”，右端依次是动作：外部版本的提示、未写入 N、撤销、导入 / 导出、编译成整合包、写入游戏、⋯（方案菜单）、启动游戏。自动排序在已启用区的表头（“排序 S”），它只作用于那个列表。
- 撤销 = `u`；导入 / 导出 = `i` / `e`（去导入、导出子页，§2.17，04 §9；原来的导入导出面板去掉）；自动排序 = `S`（直接排好，状态行写“已排序：移动了 N 个，排好的强要求 K 条”，只有弱要求没满足时写“只有较弱的顺序要求没满足”，后面是“撤销”）；预览排序（命令面板）里多一段 `why`：当前顺序违反的每条要求，写明强 / 弱 / 无害，强的在前（04 §5.3）；编译成整合包 = 去子页（§2.6）；写入游戏 = `w`（写 ModsConfig.xml 但不启动，给从 Steam 等其他途径开游戏的玩家，08 §2）。
- **启动游戏**（按钮和 `L`，命令面板的“启动”在编辑器里也一样）**不直接启动**：它打开启动页（§2.3），当前方案成为现在应用的那一项（平常本来就是；在启动页应用过整合包时换回当前方案），焦点在 ▶ 启动游戏 上，再按 `L` 或 `enter` 才启动（2026-10-22 定：启动键只在启动页）。CLI / MCP 的 `launch` 不变；TUI 没有启动页，编辑器里的 `L` 仍直接启动（§9.1）。
- 三个动作都是一次点击、一个键，没有确认步骤（§6）；被拒绝时（有游戏在运行、有未载入的外部修改、没有用户数据目录……）状态行写原因，带命令的拒绝另开一个只读的弹窗列出命令。想先看会写入什么、会建删哪些链接，用命令面板的“预览排序 / 预览写入 / 预览启动”（`view.DryRun`），或 `archo … --dry-run`。
- 导入、导出列表（04 §9）也在动作菜单和命令面板里（`i` / `e`，见 §3.5）。导出打开这个列表的导出子页，导入打开和列表管理页相同的导入子页（§2.17）。

**四个区**（TUI 是四栏；GUI 是三栏：未启用 | 已启用 | 详情，暂存和历史是第三栏里详情下方可折叠的两段）：

| 区 | 内容 | TUI 宽度（160 列终端） |
| --- | --- | --- |
| 1 未启用 | 已安装但没启用的 Mod，按名称排序 | 约 30 |
| 2 已启用 | 加载顺序 | 约 40 |
| 3 暂存 / 历史 | TUI：暂存有内容时上方是暂存，下方是“这个方案的历史”；暂存为空时整栏是历史。GUI：详情下方的“暂存”和“历史”两段 | 约 26 |
| 4 详情 | 光标所在 Mod 的详情（§4） | 其余，至少 40 |

数据：`view.BuildBoard`（三列和计数）、`view.HistoryItems`（历史）、`view.LoadDetail`（详情）。

**筛选栏**（2026-10-22 定，和 Mod 库存 › 全部是同一个组件，§2.9）：在“未启用”上方，是一张单独的卡片（不和“未启用”合成一张，两张卡片之间是 `--card-gap`，4px，§7；这条缝就是拖动分配的地方），一行：搜索框（§3.7 的查询和灰色补全）、生效的筛选（可去掉的小块）、“筛选”开关（`\`）。它同时筛选“未启用”和“已启用”：两列的标题写 `已启用 6 / 34`。默认收起；点“筛选”或按 `\` 展开（2026-10-22 玩家画图确认）：筛选栏在自己这一栏里向下长，占满“未启用”一栏，“未启用”缩成底部的一条标题，写着标题和个数（“未启用 42 / 1317”，样子同暂存、历史的标题条；点它或再按 `\`、`esc` 收起筛选栏，焦点回到列表）。筛选栏和下面的列表之间有一条可以拖动的缝，玩家拖它来分配这一栏（筛选栏至少 120 像素，下面至少留标题和几行；拖到底就回到“筛选占满”），双击恢复占满；键盘在筛选栏里 `ctrl+↑↓` 每次移动 40 像素。分配按页面存在设置 `ui.gui.filter.split:plan`、`ui.gui.filter.split:library`。展开时筛选一直作用于两个列表；焦点一离开筛选栏（点到列表、`tab` 走、`esc`）它就收起，生效的条件留在收起的那一行里（§3.1 规则 8，2026-10-23 改；以前在列表里移动光标不会收起它）。展开时每组先列 24 个值，其余在输入框里找。展开后一组一块，组内的值折行排列：标签、来源（工坊 / 本地 / 官方 / 副本 / git / SteamCMD）、版本（当前游戏的版本排第一并标“当前游戏”）、内容（带 DLL / 只有 XML / 语言包）、有（问题 / 报错 / 备注 / 别名）。每行先列用得最多的值和个数，行尾是“还有 N 个…”输入框，打字找其余的值。左键保留、右键去掉、再点一次恢复；同一组内是“或”，不同组之间是“且”，和 Mod 库存相同。数据：`view.FilterBoard`（每组的个数不算这一组自己的选择）。暂存保留自己的搜索框（`/` 在暂存区聚焦它）。

- 键盘：`/`、`ctrl+f` 聚焦搜索框；`\` 展开并把焦点放在第一个值上，`↑↓` 换组、`←→` 换值、`enter` / `space` 保留、`x` 去掉、直接打字进入这一组的输入框、`esc` 或 `\` 收起；搜索框为空时 `backspace` 去掉最后一个筛选。
- 有筛选时的移动：位置总是整张加载顺序里的位置。`m` 的数字和“在它之后 / 之前”都按完整列表（§3.6，候选也包括没显示的 Mod）；`space` 启用到建议位置（`App.SuggestAt`，与筛选无关）；拖到某一行上放到那一行的序号。`J` / `K` 越过下一个**显示的**行：被移动的行和它在筛选后的邻居交换位置，在完整列表里落在那个邻居的紧后面（`J`）或紧前面（`K`）；`alt+J` / `alt+K` 越过 10 个显示的行。没有筛选时就是原来的移动 1 位、10 位（`view.StepAt`，测试见 `TestStepAt`）。

GUI 的第三栏从上到下：详情卡片（占剩下的高度）、暂存、历史（暂存保留，2026-10-22 定）。暂存和历史各是一张可折叠的卡片，标题栏是“3 暂存 N”“历史  N 步”，右侧的小箭头打开时转向下；折叠时只剩标题栏。打开时按内容的高度，最多占这一栏的 38%。暂存默认在有 Mod 时打开、空时折叠；历史默认折叠；玩家点过之后按他的选择（存在浏览器里）。按 `3` 或 `←→` 聚焦到暂存时它会打开。拖放到暂存（包括折叠时它的标题栏）仍然是暂存；`t`、`space`、`T` 不变。

**行**（§7 的图标）：


- 只有四样东西：序号（淡色，右对齐，仅“已启用”有）、来源图标、名称、状态图标（靠列右边缘）。
- 名称用别名（如果有）；中文按显示宽度截断，不切半个字。
- 与上次写入游戏不同的行，在名称后加强调色的 `●`。
- 不可加载的 Mod 整行淡色。
- 行里不显示标签（任何一栏都不显示）：标签在详情里看和改（§4.1），用 `tag:` 搜索（§3.7）。
- 状态图标只标在能不能跑可操作项涉及的 Mod 上，所以图标和角标数字一致（§5）。

**暂存**（规则见 04 §2.2）：持久保存、不写入游戏的列表。两种用途：
- **准备区**：新订阅的 Mod 先放进来，想好了再启用；
- **排查区**：把一批 Mod 从“已启用”移到暂存来排查问题，排查完一键放回原位置。
- 每个从“已启用”放进暂存的 Mod 记住原位置和一个锚点：它前面的那个 Mod。锚点越过在它之前、已经被暂存的 Mod 向前移，所以分批暂存的顺序不影响放回。放回时沿着仍在暂存里的 Mod 追溯锚点链，找不到时用原位置。
- `add` 和 `restore` 各是一步撤销。被暂存的 Mod 以任何方式重新启用（撤销、启用、载入版本）都会离开暂存。暂存列表本身不进撤销栈。
- 命令：`archo stage list|add|drop|restore`（05 §4）。每个方案一份（meta 表的 `stage:<方案 ID>`）。
- 放回：`T`（全部放回原位置）、在暂存区按 `t` 或 `space`（放回这一个）。

**历史**（第三栏下方；暂存为空时占满第三栏）：
- **这次的修改**：撤销栈的每一步，最新在上，一行一步（“启用 Harmony  第 2 位”）。步骤文字由前后两份列表算出（`view.StepText`）。光标指向“现在”；重做的步骤在“现在”上方淡色显示。`u` / `ctrl+r` 让“现在”上下移动；点一步（TUI：光标移到这一步按 `enter`）立即回到那一步，之后仍可 `u` / `ctrl+r`。
- **版本**：方案的版本列表（写入游戏、启动、外部修改、导入等，标注来源，04 §3）。选中显示与当前列表的差异，`enter` 或“回到这一版”直接载入（`loadout checkout`），不确认：载入前的列表留在历史里，`u` 可以拿回来（§6）。现在 GUI 还弹确认对话框，**待改**。
- GUI：历史在第三栏最下方，是一段可折叠的“历史  N 步”，点开展开，与暂存是否有内容无关。键盘：`H` 把历史（每一步和各版本）列成一个选择框，`↑↓` `enter` 去那一步。TUI：暂存有内容、或暂存区在搜索时不显示历史。
- 焦点在第 3 区且显示历史时，`↑↓` `g` `G` `Home` `End` 在历史里移动，`enter` 去那一步。

**列宽与换行**：
- 三个列表区的宽度可以调整。TUI：`<` `>` 缩小 / 放大聚焦区，每次 2 格；`=` 恢复默认宽度（不改换行设置）。GUI：三栏之间有两条分隔线（未启用 | 已启用、已启用 | 第三栏），拖动调整，双击恢复默认（1 : 1.2 : 1.5）；键盘同 TUI：`<` `>` 每次 24 像素，`=` 恢复。

- TUI 名称换行：`z` 切换聚焦区的“名称换行”，按区保存。开启后长名称按显示宽度折成多行；续行从名称下方开始，选中时续行也是同样的淡底；序号、来源图标、状态图标只在第一行；`●` 在最后一行；换行的行不显示标签；光标所在行总是完整显示。

### 2.6 编译成整合包

方案的子页（当前方案），已实现（GUI `packs.js`，`API.BuildPage` → `view.BuildPageOf`；`archo pack build`，08 §5.2）。入口：方案编辑器顶栏的“编译成整合包”、整合包页的同名动作（`B`）。面包屑“库 / 方案 / <方案> / 编译成整合包”，侧栏停在这个方案上；右上“取消”（`esc`）回到编辑器。布局照原型（`RimArcho 新界面设计.html` 的“编译成整合包”），颜色用现在的视觉。
- **左侧**：“基本信息”卡片：名字（默认“<方案名> <日期>”，不合法或重名时在下面说明，`API.PackNameCheck`）。（2026-10-22 去掉了“完整包 / 轻包”的类型选择：包总是带文件，只分享列表时在包页“导出列表”，§2.7。）“编译时会做的事”卡片，五行，每行编号、粗体标题和一句话：1 检查能不能跑（有 error 级问题时编号变成红色“!”，写“还有 N 个会出错的问题”，列出问题，右侧“去处理”去能不能跑；没有时说排序为这个包单独做、移动几项，以及没写支持当前版本的 Mod 数，琥珀色）、2 去掉用不到的（只留当前版本会加载的内容，几个 Mod 带着别的版本目录、省多少；空间不够或读不出的 Mod 时红色；问题没修好时淡色）、3 贴图（08 §5.2）、锁住版本、放好（写进整合包文件夹，用自己的存档和设置，方案的存档不受影响）。编译中这几行显示进度（完成的打勾、当前的呼吸圈；复制时“去掉用不到的”和“锁住版本”一起进行），下面是进度条和“停止”（`view.ProgressOf`，每行有 `Key`）。
- **贴图**一行（`view.textureStep`）：标题下是一个选择框，八个值：不转换（照原样复制 PNG，默认）、预转换（原尺寸）、精简到 80 / 75 / 60 / 50 / 40 / 25%（`view.PackTextureChoices`，存在 `B.tex`）；换一个值就重新测量整页（`API.BuildPage(tex)`：要转换的文件、编译后的大小、转换时的峰值都跟着变）。测量在后台做（§3.1 规则 9）：选择框立刻换成新值，大小那几处显示微光占位，“编译”在新结果到之前变灰；连续换值时只算最后一次，旧的测量停掉。下面一句话：不转换时说转成 DDS 的好处；转换时写“N 个 PNG 转成 DDS，包里不再带 PNG。显存约 A → B。编译后包约 X，转换时最多占 Y。”，保留 PNG 的个数（同名 DDS 或别的格式）和包会变大时（琥珀色）列在下面。空间按峰值检查；汇总的“大小”写转换后的。**没装 todds** 时这一行红色，写“没有安装 DDS 转换工具（todds）：在 库 › 贴图优化 安装”，右侧“去安装”去贴图优化页；“编译”禁用，下一行“先安装 todds，或者不转换贴图再编译 →”也去那里。这一页从不下载 todds。按键 `D` 换到下一个值（`?` 里有），选择框也能用 tab 到达、↑↓ 改。“先看清单”带上同样的 `--textures [--texture-scale N]`。
- **右侧汇总**：包名、环境、Mod 数、大小（编译前 → 编译后；问题修好后才算出）、存档（独立，第一次启动时是空的）、位置（`pack.dir`）；下面是“编译”（`B`，或在名字里按 enter）和“先看清单，不写磁盘”（`V`）。
- **“编译”禁用**（G14）：有 error 级问题时禁用，按钮下一行红字“先修好 N 个问题 →”，点击去能不能跑；空间不够、有读不出的 Mod、名字不能用、另一个包正在编译时同样禁用并写原因。
- **“先看清单，不写磁盘”**：在右侧汇总下面就地展开 `archo pack build --dry-run` 的文字（`API.PackDryRun`，不写磁盘），再按一次或 `esc` 收起；不弹窗（§3.1 规则 7）。
- **大小要遍历每个 Mod 的文件夹**：页面先显示，检查在锁内做，测量在锁外、在后台做（`PackPlan.Measure`），大小到了再填上。
- **没编译完的**（`view.UnfinishedRows`）列在下方：别的窗口在编译的显示进度和“停止”；中断的可以“重新编译”或“删除已复制的”（这是 RimArcho 自己没完成的产物，按 08 §5.2 直接删除，不进回收站）。
- 在子进程里编译，编译完打开这个包的页。

### 2.7 整合包

已实现（GUI `packs.js`；TUI 在命令面板“整合包”中显示为带命令的文本）。
- 列表（侧栏的“整合包”）：每个包一行，包名、Mod 数、大小、游戏版本、上次游玩时间（`view.PackRows`），点击或 `enter` 打开它的页；`↑↓` 移动；页面动作“编译成整合包”（`B`）；没编译完的在列表上方。
- 侧栏子项是每个包（`view.Nav`），像方案下的每个方案；`tab` / `shift+tab` 在包之间切换（同一个侧栏条目下的子页，§3.5）；在列表页上 `tab` 到第一个包。
- 每个包的页（`API.Pack` → `view.BuildPackPage`）：页面头写事实，“N 个 Mod、大小、能在哪些版本上运行、哪天在哪个环境编译、上次游玩”，用间距隔开；顶栏动作：导出（`e`，保存文件对话框，`pack export`）、导出列表（`E`，只写它的列表，成为 RimArcho 列表 `.archolist.json`，每个 Mod 带版本，用来分享；`pack export --list`，04 §9.3）、移到回收站（`Del`，确认，`pack remove`）、启动（`L`，实心，`archo pack launch`，08 §5.3）。下面是包里的 Mod，按加载顺序，每行写大小和省掉的版本目录（Core 和 DLC 写“来自游戏”），最后是文件夹位置。
- 导入包：首次向导的“打开”只把 `.archopack` 解开（`pack import`，08 §5.4）；列表文件（包括 RimArcho 列表）和合集链接走导入预览，RimArcho 列表在那里标出“版本不同”的 Mod（04 §9.1）。

### 2.8 环境

已实现（GUI 环境页，点环境药丸进入；TUI 的 `E` 切换和删除环境）。数据：`view.BuildEnvPage`、`view.EnvGroups`。
- 所有环境（名称、游戏版本、游戏目录、当前标记），点击切换。
- **删除环境**（2026-10-22）：每个环境一行末尾的“删除环境”，GUI 命令面板的环境选择器里按 `Delete`，TUI `E` 里按 `d`。先是预演（`app.EnvRemovePreview` → `view.EnvRemovalLines`），一次确认：RimArcho 忘掉它的方案、启动记录、从它的 `Data`/`Mods` 读到的 Mod 和它的历史；游戏目录、所有 Mod 和存档不动，共用的 Mod 文件夹和玩家给 Mod 记下的内容留着。那个游戏在运行时拒绝。删的是当前环境时先换到另一个；一个都不剩时 GUI 打开添加环境引导。CLI 是 `env remove <名>`（不带 `--yes` 是预演）。
- 当前环境的目录：游戏目录、用户数据目录（`env set --game|--user-data`，修改前检查 Mod 仍是同一批，提示重新绑定 `env rebind`，02 §3.2）、工坊目录、SteamCMD 与额外目录（可移除来源：RimArcho 忘掉这个目录，文件留在原处）；添加 SteamCMD 目录（那里的 Mod 可以启用，写入时链接进 `Mods/`，08 §3）、添加其他 Mod 目录。路径不用系统选择框，直接输入。
- 启动：方式（`steam` / `direct`，`env set --launch`）、附加参数（`env set --launch-args`，例如 `-popupwindow`；存在设置 `env:<id>:launch_args` 中）。
- 添加环境：走首次引导的第一步（§2.15）。
