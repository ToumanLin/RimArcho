### 2.5 方案编辑器

方案页就是编辑器。已实现，包括多个方案（暂存和历史挂在方案上，04 §1、§2.2、§3）。新建 / 导入（空、复制某个列表或版本、存档、导入，同一张表单）、改名（输入时检查重名；全部列表页上就地改名）、创建副本、删除（确认，不能删最后一个）在全部列表页（§2.17）、侧栏右键、`P` 和命令面板里。游戏的 ModsConfig.xml 里现在是哪个方案（写入记录，04 §1.3）不再写在状态行上：有两个以上方案时，那个方案的侧栏子项旁有一个绿色小点（悬停写“游戏里现在是：<方案> v<n>”），首页不再标（大卡片就是现在应用的那一项）；只有一个方案时不标。有未载入的外部版本时，侧栏条目、方案页和首页那一行带琥珀色标记。编辑器页面头的动作（2026-10-26 改）：有未载入的外部版本时的琥珀色标记、“N 项未保存”、改名、删除、“导入/导出”（打开全部列表并选中这个列表，导入、导出和分享都在那里，§2.17）、“保存修改”（没有改动时写“没有变化”并不可点，`w`）；最后是实心按钮：这个列表是当前列表时写“启动”（`L`，去启动页），不是时写“设为当前”（不写游戏文件）。不再有“启动的是 X / 设为当前”提示、“⋯”菜单和编译成整合包按钮（编译在整合包页）；环境 chip 在编辑器里不显示。撤销在“启用”列表头、排序的左边。窄于 1100 像素时按键提示收起。

**打开的列表和当前列表**（2026-10-25 定，04 §1.3）：从侧栏、命令面板或全部列表打开一个列表，编辑器显示和编辑它，但当前列表（启动页的大标题、启动和 CLI 用的那个）不变；能不能跑、Mod 库存和编译成整合包跟着打开的列表。打开的不是当前列表时，页面头最前面有一行淡色字“启动的是 <当前列表>”和链接“设为当前”（窄于 1280 像素时只留链接）。在这个列表里保存，或点启动游戏，它就成为当前列表。

**页面头**（2026-10-22 起和其他页面一样，§2.2）：面包屑下面一行淡色的“启用了 34 个”，右端依次是动作：外部版本的提示、N 项未保存、撤销、导入 / 导出、编译成整合包、保存、⋯（方案菜单）、启动游戏。自动排序在已启用区的表头（“排序 S”），它只作用于那个列表。
- 撤销 = `u`；导入 / 导出 = `i` / `e`（去导入、导出子页，§2.17，04 §9；原来的导入导出面板去掉）；自动排序 = `S`（直接排好，状态行写“已排序：移动了 N 个，排好的强要求 K 条”，只有弱要求没满足时写“只有较弱的顺序要求没满足”，后面是“撤销”）；预览排序（命令面板）里多一段 `why`：当前顺序违反的每条要求，写明强 / 弱 / 无害，强的在前（04 §5.3）；编译成整合包 = 去子页（§2.6）；保存 = `w`（写 ModsConfig.xml 但不启动，给从 Steam 等其他途径开游戏的玩家，08 §2）。
- **启动游戏**（按钮和 `L`，命令面板的“启动”在编辑器里也一样）**不直接启动**：它打开启动页（§2.3），这个列表成为当前列表和现在应用的那一项（平常本来就是；打开的是别的列表时先把它设为当前；在启动页应用过整合包时换回当前方案），焦点在 ▶ 启动游戏 上，再按 `L` 或 `enter` 才启动（2026-10-22 定：启动键只在启动页）。CLI / MCP 的 `launch` 不变；TUI 没有启动页，编辑器里的 `L` 仍直接启动（§9.1）。
- 三个动作都是一次点击、一个键，没有确认步骤（§6）；被拒绝时（有游戏在运行、有未载入的外部修改、没有用户数据目录……）状态行写原因，带命令的拒绝另开一个只读的弹窗列出命令。想先看会写入什么、会建删哪些链接，用命令面板的“预览排序 / 预览保存 / 预览启动”（`view.DryRun`），或 `archo … --dry-run`。
- 导入、导出列表（04 §9）也在动作菜单和命令面板里（`i` / `e`，见 §3.5）。导出打开这个列表的导出子页，导入打开和全部列表页相同的导入子页（§2.17）。

**四个区**（TUI 是四栏；GUI 是三栏：筛选 / 详情 / 历史 | 已启用 | 未启用 / 暂存，默认宽度 38 : 31 : 31）：

| 区 | 内容 | TUI 宽度（160 列终端） |
| --- | --- | --- |
| 1 未启用 | 已安装但没启用的 Mod，按名称排序 | 约 30 |
| 2 已启用 | 加载顺序 | 约 40 |
| 3 暂存 / 历史 | TUI：暂存有内容时上方是暂存，下方是“这个方案的历史”；暂存为空时整栏是历史。GUI：暂存在右栏未启用下方，历史在左栏详情下方 | 约 26 |
| 4 详情 | 光标所在 Mod 的详情（§4） | 其余，至少 40 |

数据：`view.BuildBoard`（三列和计数）、`view.HistoryItems`（历史）、`view.LoadDetail`（详情）。

后端同时返回按 Mod 归属的问题数、最高级别、简短说明及可直接执行的修复动作；列表级问题与能不能跑共用缓存，编辑结果／事件带回更新摘要。接口合同见 [8.7](8-GUI技术.md#87-列表问题与-needs-缓存-api)。

版本提醒的行提示、汇总、已忽略数和恢复入口见 §5；即使已忽略全部版本提醒，问题面板仍可打开查看并恢复。

**筛选栏**（2026-10-25，和 Mod 库存 › 全部共用组件）：位于左栏最上方，下面是详情和列表历史。收起时一行搜索框、清空按钮和“筛选”开关（`\`）；条件直接写在搜索文本中，例如点“本地”写入 `source:local`，不生成常驻小块。点击搜索框、`/` 或 `ctrl+f` 打开框下的小悬浮窗：展示可用键，输入后按当前词切换到匹配的键或值；灰字预览候选补全，`↑↓` 选择、`tab` 接受，`enter` 结束输入。悬浮窗不显示 Mod 数，不重复显示相同值，固定说明经本地化，作者、标签、自定义目录名保持原文（§3.7）。

点“筛选”或 `\` 展开，只列标签、来源、内容三组；其他键从搜索框补全进入。来源按目录角色显示工坊、SteamCMD、本地、锁定库、官方和其他目录；自定义目录还列目录名，对应稳定的 `source:<目录别名>`。不提供原始路径候选，路径仍可在详情复制（02 §0.2）。每组先列最多 24 个常用值和个数，其余以可点击的“还有 N 个…”展开，展开后可点击“收起”；不再显示组内搜索输入框，查找统一使用上方查询框；左键 / `enter` / `space` 保留、右键 / `x` 排除、再次选择撤回。同组“或”、跨组“且”，手输和点击使用相同规则。

展开默认占左栏高度的 35%（至少 120px），其余留给详情和历史；卡片间的缝可拖动分配，拖到底仍可占满，双击恢复 35%；`ctrl+↑↓` 每次 40 像素。设置仍为 `ui.gui.filter.split:plan`、`ui.gui.filter.split:library`。焦点离开立刻折叠，查询文本保留。`↑↓` 换组、`←→` 换值（包括展开 / 收起按钮），直接打字进入上方查询框并带入当前组的键，`esc` / `\` 收起；暂存继续使用自己的搜索框。

- 有筛选时的移动：位置总是整张加载顺序里的位置。`m` 的数字和“在它之后 / 之前”都按完整列表（§3.6，候选也包括没显示的 Mod）；`space` 启用到建议位置（`App.SuggestAt`，与筛选无关）；拖到某一行上放到那一行的序号。`J` / `K` 越过下一个**显示的**行：被移动的行和它在筛选后的邻居交换位置，在完整列表里落在那个邻居的紧后面（`J`）或紧前面（`K`）；`alt+J` / `alt+K` 越过 10 个显示的行。没有筛选时就是原来的移动 1 位、10 位（`view.StepAt`，测试见 `TestStepAt`）。

GUI 左栏从上到下是筛选、简略详情、可折叠历史；中栏是已启用；右栏是未启用和可折叠暂存。暂存默认有内容时打开、空时折叠，历史默认折叠；玩家选择按浏览器保存。历史展开默认占左栏高度的 25%（至少 72px），暂存展开仍按内容高度、最多占父栏 38%；拖动后的自定义高度优先。相邻卡片间可拖动分配高度。`3` 聚焦暂存时展开，拖到暂存标题同样有效，`t`、`space`、`T` 不变。`←→` 按空间顺序在详情、已启用、未启用间导航；数字 `1`–`4` 仍对应未启用、已启用、暂存、详情。

**暂存**（规则见 04 §2.2）：持久保存在 RimArcho 中、不会保存到游戏的列表。两种用途：
- **准备区**：新订阅的 Mod 先放进来，想好了再启用；
- **排查区**：把一批 Mod 从“已启用”移到暂存来排查问题，排查完一键放回原位置。
- 每个从“已启用”放进暂存的 Mod 记住原位置和一个锚点：它前面的那个 Mod。锚点越过在它之前、已经被暂存的 Mod 向前移，所以分批暂存的顺序不影响放回。放回时沿着仍在暂存里的 Mod 追溯锚点链，找不到时用原位置。
- `add`、`drop` 和 `restore` 各是一步撤销，包括只改暂存、没有改变启用列表的操作。撤销 / 重做同时还原启用列表与暂存条目、顺序、原位置和锚点。被暂存的 Mod 以任何方式重新启用（撤销、启用、载入版本、导入）都会在该编辑中持久离开暂存；旧历史兼容规则见 04 §2.2。
- 命令：`archo stage list|add|drop|restore`（05 §4）。每个方案一份（meta 表的 `stage:<方案 ID>`）。
- 放回：`T`（全部放回原位置）、在暂存区按 `t` 或 `space`（放回这一个）。

**历史**（GUI 左栏详情下方；TUI 第三栏，暂存为空时占满）：
- **这次的修改**：撤销栈的每一步，最新在上，一行一步（“启用 Harmony  第 2 位”）。步骤文字由前后两份列表算出（`view.StepText`）。光标指向“现在”；重做的步骤在“现在”上方淡色显示。`u` / `ctrl+r` 让“现在”上下移动；点一步（TUI：光标移到这一步按 `enter`）立即回到那一步，之后仍可 `u` / `ctrl+r`。
- **版本**：方案的版本列表（保存、启动、外部修改、导入等，标注来源，04 §3）。选中显示与当前列表的差异，`enter` 或“回到这一版”直接载入（`loadout checkout`），不确认：列表改变时，载入前的列表留在历史里，`u` 可以拿回来（§6）；与当前列表相同时只写“没有变化”，不显示撤销提示，来源和历史不变（04 §3.2）。
- GUI：历史在左栏详情下方，是一段可折叠的“历史  N 步”，点开展开，与暂存是否有内容无关。键盘：`H` 把历史（每一步和各版本）列成一个选择框，`↑↓` `enter` 去那一步。TUI：暂存有内容、或暂存区在搜索时不显示历史。
- 焦点在第 3 区且显示历史时，`↑↓` `g` `G` `Home` `End` 在历史里移动，`enter` 去那一步。

**列宽与换行**：
- 三个列表区的宽度可以调整。TUI：`<` `>` 缩小 / 放大聚焦区，每次 2 格；`=` 恢复默认宽度（不改换行设置）。GUI：三栏之间有两条分隔线（左栏 | 已启用、已启用 | 右栏），拖动调整，双击恢复默认（38 : 31 : 31）；键盘同 TUI：`<` `>` 每次 24 像素，`=` 恢复。

### 2.6 编译成整合包

方案的子页（当前方案），已实现（GUI `packs.js`，`API.BuildPage` → `view.BuildPageOf`；`archo pack build`，08 §5.2）。入口：方案编辑器顶栏的“编译成整合包”、整合包页的同名动作（`B`）。面包屑“库 / 方案 / <方案> / 编译成整合包”，侧栏停在这个方案上；右上“取消”（`esc`）回到编辑器。布局照原型（`RimArcho 新界面设计.html` 的“编译成整合包”），颜色用现在的视觉。
- **左侧**：“基本信息”卡片：名字（默认“<方案名> <日期>”，不合法或重名时在下面说明，`API.PackNameCheck`）。（2026-10-22 去掉了“完整包 / 轻包”的类型选择：包总是带文件，只分享列表时在包页“导出列表”，§2.7。）“编译时会做的事”卡片，五行，每行编号、粗体标题和一句话：1 检查能不能跑（有 error 级问题时编号变成红色“!”，写“还有 N 个会出错的问题”，列出问题，右侧“去处理”去能不能跑；没有时说排序为这个包单独做、移动几项，以及没写支持当前版本的 Mod 数，琥珀色）、2 去掉用不到的（只留当前版本会加载的内容，几个 Mod 带着别的版本目录、省多少；空间不够或读不出的 Mod 时红色；问题没修好时淡色）、3 贴图（08 §5.2）、锁住版本、放好（写进整合包文件夹，用自己的存档和设置，方案的存档不受影响）。编译中这几行显示进度（完成的打勾、当前的呼吸圈；复制时“去掉用不到的”和“锁住版本”一起进行），下面是进度条和“停止”（`view.ProgressOf`，每行有 `Key`）。
