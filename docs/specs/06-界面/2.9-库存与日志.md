### 2.9 Mod 库存、订阅与更新

移库、删除/退订的既有确认预览列出所有受影响游戏、链接完整路径、原目标与摘除/重建动作；重复项搬移使用同一预览，不额外询问。管理目录移动在原对话框展示同一入链计划，再确认执行。未完成台账操作在“能不能跑”显示恢复项，沿用链接修复的一次确认入口（08 §3），打开页面不写文件。

副本详情的动作区不重复放“打开文件夹”“打开工坊页面”“Steam 页面”按钮；使用字段列表中的位置和工坊入口（§4.1），右键菜单和快捷键仍可打开。

**不列为副本**（2026-10-23）：Mod / 副本详情增加同名按钮，全屏详情的“副本”区对选中的那一份提供；公共整理菜单也能操作。只对同组还有其他在本机实例的单份提供，批量选择不提供。点击后将这一份拆成独立 Mod，复制别名、标签和 Mod 备注，保留副本备注；刷新后继续显示拆出的这一份，按钮消失。身份变更全局生效；同包名的实际加载冲突仍然检查。此动作不加入方案撤销历史（02 §6）。

**全部**（已实现：GUI `library.js`，TUI 命令面板“Mod 库存”；数据 `app.Library` → `view.BuildLibrary`）：回答“我手上有哪些 Mod、各有几份、放在哪、用在哪、占多少”。只管已经在本机的 Mod，不负责获取 Mod（不做工坊浏览和搜索，01 §3）。

**布局：两块，和方案编辑器同一个思路（2026-10-22 玩家画图确认）。** 左边一栏约和编辑器左栏接近：上面是可收起的筛选栏（和编辑器的是同一个组件，一张单独的卡片），下面隔一条缝是另一张卡片：常驻的 Mod / 副本详情，占满这一栏剩下的高度；右边宽的一块是表格。也就是两页都是“左上筛选，下面接一栏”。左栏默认 `clamp(280px, 26%, 440px)`，拖动分隔线改宽度（存在设置 `ui.gui.library.side`），双击恢复。页面和窗口一样宽（没有居中的最大宽度），表格的列随窗口变宽：名称列拿走多出来的宽度，玩家调过或移过的列保持保存的宽度。窗口窄于 900 像素时只剩筛选栏在表格上方，详情用 `enter` 盖在表格上。表格像文件管理器的“详细信息”视图：一行一个 Lineage（02 §6），点击展开它的每一份 Instance。

| 名称 | 大小 | 状态 | 来源 | 用在 |
| --- | --- | --- | --- | --- |
| Vanilla Expanded Framework（点击展开） | 合计大小 | 最要紧的一个状态 | 工坊  锁定库  本地 | 2 个方案 |
| └ 工坊 | 43 MB | 被其它管理器隐藏 | 工坊 | — |
| └ 锁定版本 2026/10/21 14:27 | 42 MB | 上游有更新 | 锁定版本 2026/10/21 14:27 | 主力殖民地 |

- **筛选栏**：与编辑器共用 §2.5、§3.7 的输入、浮窗、灰字和 `tab` 补全、失焦折叠。条件只在搜索文本中存在，不另生成小块；只展开标签、来源、内容三组，版本、状态、用在、更新日期、有、名称、作者、包名从浮窗输入。条件仍匹配同一份 Instance，不能用一份的来源和另一份的版本凑成匹配。来源按目录角色和稳定别名筛选，不显示可复制的原始路径。展开默认占左栏高度的 35%，缝可拖动，双击恢复默认比例，拖到底仍可占满并让详情缩成标题；每组常用值可显示个数，搜索浮窗不显示个数。TUI 的原有输入行和键盘补全保留。
- **表格**：
  - 列：默认显示名称、大小、状态、来源、用在；右键表头可以再打开更新日期、版本、作者、标签、上次游玩，或关掉默认列（名称总在），也可以“恢复默认列”。
  - 点表头按这一列排序，再点反过来，箭头标出方向（名称、来源、作者、标签从 A 到 Z 开始；大小从大到小；日期和版本从新到旧；状态从要紧到不要紧；用在从多到少）。拖表头移动列，拖表头的右边缘改宽度。列的顺序、宽度、显示哪些记在设置 `ui.gui.library.columns`；列加起来比卡片宽时表格横向滚动。
  - 名称格只写名称：Lineage 行写 Mod 名，展开后的 Instance 行与编辑器共用抽象标识（工坊、本地、锁定版本带创建时间、SteamCMD、自定义目录名），不再用原始文件夹名或工坊 ID。来源列使用同一标识，路径和 ID 在详情字段中查看、复制，标签不在行里（在详情和搜索里）。只有一份 Instance 的 Lineage 不需要展开，直接是那份的行。
  - 状态列只写要处理的状态（下表“行里显示”一列）：一行最多一个，最要紧的那个；详情里列全。
- **副本详情**：左栏筛选栏下面，常驻，跟着光标：光标所在的那一份（Lineage 行上是当前方案用的那份，否则第一份），停下约 90 毫秒后加载。标题右侧“查看完整详情 Enter ↵”和 `enter` 打开全屏详情（§4.2，和方案编辑器同一页），`esc` 回来；窗口窄时按 `→` 让这里的详情盖满表格，`enter` 或 `esc` 回来；在一份上按 `→` 把焦点交给详情（`↑↓` `PgUp` `PgDn` 滚动，`←` 回到表格）。窗口窄于 900 像素时不显示，`enter` 打开盖满的详情。从上到下：副本备注（下面）、动作（只列这一份能做的）、字段列表（§4.1，库存多出状态、用在、大小、支持的版本、更新日期、上次游玩几行）、Mod 的图、名字、简介和历史。不再另列一块“实例”信息。
- 多选后底部出现动作条（不只放在右键菜单里），每个按钮带它的键。
- 行菜单、详情动作和多选动作条只提供库动作；加入 / 启用 / 停用、移动位置、暂存、换用副本和从所有方案拿掉留在方案编辑器。库存不改 About.xml，也不绑定 `space`、`m`、`t`、`x` 或方案撤销 / 重做键。

**状态**（只在不正常时出现）：

| 状态 | 什么时候 | 行里显示 | 动作 |
| --- | --- | --- | --- |
| 加载不了 | 没有可读的 About.xml 等（`mod.unloadable`） | 是 | 打开文件夹 |
| 订阅了但不在磁盘上 | ACF 里有订阅，磁盘上没有文件夹 | 是 | 打开网页 |
| 游戏会忽略这一份 | `Mods/` 里有同包名的另一份排在前面（04 §4.2、`pkg.duplicate-installed`） | 是 | 备份锁定版本 |
| 退订残留 | 工坊文件夹还在，但已不再订阅 | 是 | 删除、重新订阅 |
| 被其它管理器隐藏 | About.xml 被改成 About.xml.disabled（08 §6） | 是 | 恢复、删除 |
| 上游有更新 | 锁定版本的上游变了（04 §7.3） | 是 | 查看差异、更新锁定版本 |

前四个也算“要处理”：加载不了、不在磁盘上、被忽略的那份都需要玩家做点什么。“不支持当前游戏版本”和“不在任何方案里”不是状态（0.9.0 起删掉，筛选栏、`state:` 的值和补全、CLI / MCP 都没有）：它们是常态，一千多个 Mod 里大半如此，写在行里或当筛选项都只是噪音。支持的版本在“支持的游戏版本”一组和字段列表里，没人用的副本用“用在 › 不在任何方案里”（`used:none`）找。

**动作**：副本详情里的六个，只在适用时出现，顺序固定：
1. **恢复**（`unhide`）：被其它管理器隐藏的那份恢复给游戏。
2. **退订**（工坊那份）/ **删除**（自己的那份）：“退订”经正在运行的 Steam 客户端真的退订（08 §10），Steam 随后删掉这个工坊文件夹，所以和删除一样先显示 `--dry-run` 的文字（会删哪个文件夹）再确认；游戏正在运行时拒绝。已启用、仍有方案在用时不拒绝，也不要求先去列表里拿掉：确认框里警告它在哪些列表里，玩家确认后照样执行，那些列表里的条目随后显示为缺失（批量时每一项都这样）。Steam 没在运行、游戏目录里没有 `steam_api64.dll` 或加载不了时，才退回到打开工坊页面，状态行说“连不上 Steam（原因）：已打开工坊页面，请在页面上退订”。“删除”把文件夹移到回收站（`trash`，08 §7），只对 `Mods/` 里和锁定库里 RimArcho 自己的那份、SteamCMD 下载的那份（没有订阅会把它下回来），以及退订残留、被隐藏的工坊文件夹出现；已启用或仍有方案在用时同样只警告是哪些方案；它本身是链接（`_Link_*` 之类）时拒绝，不去动链接指向的地方。先显示 `--dry-run` 的文字再确认。
3. **重新订阅**（工坊原件，含退订残留）：工坊 ID 为数字、副本自身不是链接或锁定版本时提供，先预览再确认。已订阅的先退订，Steam 确认成功后由 RimArcho 把原文件夹移到回收站，确认原路径已不存在才再订阅；清理失败的项不订阅并报告原因。预览明确说明 RimArcho 会先把文件夹移到回收站，再由 Steam 重新下载，其中的本地修改会丢失。已启用或有列表在用仍可执行，游戏运行时拒绝；原路径、工坊 ID、实例和 Lineage 身份保留，列表继续引用它。退订残留跳过退订和清理。确认订阅后（含残留项）主动请求 Steam 下载并等到文件落盘，后台任务显示逐项下载进度；停滞会提示检查 Steam；连不上 Steam 时同样退回到打开工坊页面。具体调用规则见 08 §10。
4. **备份锁定版本**（= 收进锁定库，下面）：`Mods/` 里多出来的那份。
5. **打开文件夹**。
6. **打开网页**（有工坊 ID 时）。

右键菜单和多选动作条还提供标签、副本备注、不列为副本、锁定这个版本、更新锁定版本、解除锁定（04 §7）及订阅来源的检查 / 更新 / 移除。单份不提供“转换贴图为 DDS”；已有转换贴图时保留“清除转换的贴图”，批量转换仍在贴图优化页（08 §5.2）。所有动作来自 `view.OpTable`（代码、名字、键、菜单分组），`view.CopyOps` 按页面和副本状态只给适用的代码；名字和键随页面数据只发一次。

**副本备注**（已实现，schema v13 `instance_note`）：每一份 Instance 自己的一段话，写在详情最上面。玩家没写时显示 RimArcho 写的第一版（灰色），例如“该锁定版本创建于 10 月 21 日，为方案「测试」创建，自从创建后上游有 2 次更新，原因：新版改了存档格式”。不是 RimArcho 做的副本也有第一版，说它从哪来、哪天首次发现，和工坊那份并存的再说之后工坊那份更新了几次：“工坊订阅，10 月 19 日首次发现”“放在游戏的 Mods 文件夹，10 月 19 日首次发现，之后工坊那份更新了 2 次”“已退订，Steam 留下了文件夹，…”；订阅了但没有文件夹的没有：
- RimArcho 在创建这一份时记下来历（`made`：锁定版本、更新锁定版本、收进锁定库；时间；为哪些方案；玩家给的原因 `--reason`），文字每次现算，所以“之后上游有几次更新”（同一 Lineage 的工坊那份在这之后的更新次数）一直是对的。
- 点一下就改，从现在显示的文字开始改；`enter` 保存，`shift+enter` 换行，`esc` 不改。写空就回到 RimArcho 写的那版。TUI 在 Mod 库存里按 `n`（多份时先选哪一份）。
- CLI `archo note <引用> <文字> --copy`（`--clear` 清掉），`archo pin … --reason`、`library move-to-locked … --reason`；MCP `set_player_data` 的 `copy_note`，`pin_mod`、`manage_library` 的 `reason`（05）。`archo library --lineage` 每份下面列出 `note:`。
- 和 Mod 的备注（`archo note <引用>`，§4.1 的“备注”，搜索的 `has:note`）的关系：Mod 的备注写在 Lineage 上，所有副本、所有方案共用，说的是“这个 Mod”；副本备注只属于这一份，说的是“为什么留着这一份”。`has:note` 仍只看 Mod 的备注；库存的搜索两种都搜。

**收进锁定库**（已实现，`archo library move-to-locked`）：同一个 Lineage 的备用版本都放在锁定库里，`Mods/` 里每个包名最多留一份，用哪份由方案决定（04 §7）。`Mods/` 里多出来的副本（手动复制的、其他管理器留下的）可以在这里收进锁定库：玩家确认后移动，同一个卷上改名，跨卷先复制、逐个文件核对，再把原目录移到回收站。它在 Lineage 里的身份和各方案的引用不变：移动后 RimArcho 先把这个 Instance 指到新位置再扫描（按来源和路径对上，R1），ID、Lineage、历史都不变，游戏下次写入或启动时经 `_Archo_` 链接看到它。没有 `.rimarcho/origin.json` 时写一份：上游是同 Lineage 的工坊那份（没有就是它自己），`origin_snapshot` 是这份自己的快照，所以“上游有更新”表示工坊那份的内容和它不同。只移 `Mods/` 里、同一 Lineage 还有别的副本（或本来就带 `origin.json`）的文件夹；里面有指向文件夹外的链接时拒绝（同卷改名也拒绝）。`pin --move-to-library` 用同一个移动，规则仍只认带 `origin.json` 的旧副本（04 §7.4）。写文件清单见 01 §4。


**订阅与更新**（数据见 02 §3.4；2026-10-24 改成一张列表加详情，草案 `docs/design/subscriptions-drafts/c.html`）：玩家来这里是为了两件事：更新 RimArcho 管的订阅、看 Steam 自己更新了什么。两件事在同一张列表里，先“等你更新”，再“已经更新”；添加订阅是另一个子页（下文）。原来的“来源”区去掉：来源的信息增量小，只留一行摘要。

自动检查（§2.16）的结果进入现有“等你更新”和来源摘要，发现待更新项时发安静通知；打开页面只读已有结果。SteamCMD、Git、下载页的检查记录随共享订阅保存，切换游戏仍可见，兼容读取旧的按环境记录。现有“更新全部”仍需玩家确认；下载页按原流程选择文件，任一登记游戏运行时拒绝更新。

- **左栏上面一条范围栏**：`列表「<当前列表>」` / `所有 Mod`（`a`），旁边写起点（“上次游玩 10月22日 以来”，从没玩过时“上次扫描以来”；所有 Mod 时同样写起点）。范围同时作用于“等你更新”和“已经更新”：只看列表时，只有别的列表才用到的待更新项藏起来，写“别的列表还有 N 个”加“看所有 Mod”。只看一个 Mod 时（下文），范围栏换成可去掉的条件“只看 <名字> ×”。
- **左栏列表**（区 `1`），从上到下：
  1. **等你更新**：已经知道有新版本、还没装上的那些，一份一行：名称、来源（Git、下载页、SteamCMD、工坊）、已装 → 可用（版本 / 短提交 / 日期）；下载页的那份另有标签“要选文件”。标题右边“全部更新”（`U`）作用于列出来的每一项，下载页的那份跳过并在状态行说要先选文件。都是最新的时写一句“都是最新的”。本地无来源的不列。
  2. **已经更新**：变化记录（下文）：一个 Mod 一行，名称和一句话，层级标签在行尾；然后是“新订阅 N 个，不见了 N 个”一行；然后“更早”，每天一行，`enter` 在列表里展开那天的行。
  - 列表底下一行来源摘要：“14:02 检查过 4 个来源 ▾”，有失败时右边一个琥珀色计数（“工坊 2 个已找不到”）。点开在列表底部就地展开（§3.1 规则 7），每个来源一行：Mod 数、上次检查的时间和结论（没检查过写“还没检查”）、SteamCMD 和 LoversLab 的账户短状态（§2.14，附“账户 →”）、“检查”按钮（排进后台任务，§2.16；本地来源只扫描文件）。工坊错误映射为短原因（9 = 工坊里已找不到，被删除或设为私有），同样的原因合成计数，可展开逐项。打开这一页只读本机状态，不联网。
- **右栏详情**（区 `2`），跟着左栏的光标：
  - 等你更新的一项：名称；来源、已装 → 可用（各自的时间）、跟踪（分支 / 标签 / 提交）；“更新”（`u`）先显示 `--dry-run` 的文字再确认，游戏运行时拒绝；工坊客户端的由 Steam 下载。下载页的那份：LoversLab 文件页读出文件列表（要先在设置 › 账户登录），选一个，站点有下载协议时先显示协议、玩家同意后才下载，下载后预览再安装；不是 LoversLab、没登录或站点要求手动下载时写原因，给“打开下载页”和“选下载好的 zip / 文件夹…”。另有“打开来源页”（Git 仓库在 GitHub / GitLab 上时打开两次提交的对比页，下载页打开页面，工坊打开更新说明）、“锁定现在这个版本”（想留着旧版时，先显示 `pin --dry-run`）、“在 Mod 库打开”，以及“用在”哪些列表（当前列表强调）。
  - 已经更新的一行：层级和一句话、按类分组的文件摘要和其余事实、“逐个文件”（`i`）、行的动作（下文），`ctrl+o` 打开文件夹。
  - 新订阅和不见了：逐个列出；当前列表还在用的不见了的 Mod 写“会影响启动”。
- **页面头**：一句说明（“先是等你更新的，再是 Steam 已经更新的”），右边“检查更新”（`K`，所有来源的检查各排一个后台任务）和“添加订阅”（`+`，去添加订阅子页）。`R` 仍是重新扫描。

**GUI 实现说明**：每行同高，只画看得到的行（真实数据 1284 个 Lineage，滚动一次约 4 ms，一次筛选往返约 20 ms）。筛选值只列个数大于 0 或已选中的，每组先列 6 个，其余“还有 N 个”。只有一份的 Lineage 直接是那份的行；筛选只命中部分副本时，Lineage 自动展开给出命中的那几份。会改文件的动作（锁定版本、更新锁定版本、解除锁定、恢复、备份锁定版本、退订、删除）先显示 CLI 的 `--dry-run` 文字再确认；`space` `m` `t` `x` 和从所有方案里拿掉是方案编辑，状态行带撤销，`u` 撤销的就是当前方案的这一步。每一份只带它的动作代码，文件夹路径和工坊网址留在 Go 里（详情按需取字段，打开文件夹和网页按 Instance），1284 个 Lineage 的页面数据从 1.47 MB 降到 0.77 MB。这一页讲的是整台机器上的副本，顶栏不显示环境标签（方案编辑器照常显示）；页面按钮只写“重新扫描”。TUI 的列表用同样的默认列（名称、大小、状态、来源、用在），不能改列。按键是 §3.5 的同一张表；本页另有：`→` 展开 Lineage（在一份上是去详情），`←` 收起或回到 Lineage，`s` 表头的菜单（按某列排序、移动或加宽当前排序列、显示或隐藏列、恢复默认列），`C` 这个 Mod 的变化，`R` 重新扫描。表头的拖动、右键都在 `s` 里有键盘的做法（§3.1 规则 6）。

参考 RimCrow 的“库存枢纽 › 全库数据管理”：一行对应磁盘上的一份、同来源重复和跨来源同项分开说、订阅了但不在磁盘上的“幽灵”项、删除默认进回收站、每个确认框说清后果，这些照做；它把操作都放在右键菜单、详情只在悬停时出现、搜索只看名称和包名、体积默认不算，这些不照做。

**变化记录**（订阅与更新列表里的“已经更新”；GUI `subscriptions.js`，TUI `c`；CLI `archo changes`、MCP `list_changes` 不变。历史数据来自 `internal/modchanges`，三段页面来自 `view.BuildSubscriptions`）：回答“我上次玩之后，我用的 Mod 变了什么、要不要管”。

- **一个 Mod 一行**：把它在时间范围里的所有变化事件合成一行，写成“名称  一句话说这意味着什么”，层级用一个小标签显示：**会影响启动** / **留意** / **只是内容**。按层级、再按名称排序。
  - 会影响启动（只在这个 Mod 在当前方案里时）：新增的依赖没装或没启用；不再支持当前环境的游戏版本；新增与一个已启用 Mod 的不兼容；包名变了。
  - 留意：代码（`.dll`）、Defs、Patches 或 LoadFolders.xml 改了；加载顺序规则变了；支持的版本变了；锁定的版本落后于工坊。版本号的变化跟着 Defs / Patches / 代码一起出现时才算留意。
  - 只是内容：只改了贴图、音效、翻译或其他文件；改名、换作者、文件夹换了位置也在这一层。
- **只用已有的数据，不做新的分析**。一句话最多三件事，取最要紧的；展开后先是按类分组的文件摘要，再是一句话里放不下的事和工坊的更新时间：
  - 支持的版本新增或去掉了哪些，是当前环境的版本（`st.GameMM()`）时标出“（当前游戏）”。
  - `About.xml` 的 `modVersion` 前后。
  - 依赖（基础的加上当前版本的 `modDependenciesByVersion`）新增或去掉了哪些，写成名称，带“未安装 / 未启用”（同 `view.Deps`）。
  - 两个快照的 `decl_blob` 里 `incompatibleWith`、`loadBefore` / `loadAfter`（含 `forceLoad*` 和按版本的形式）的差异；`load-rules-changed` 事件本身不带 detail（02 §5.3），所以从声明里比。
  - 文件按类分组：代码（`.dll`）、Defs、Patches、About/LoadFolders、贴图（`Textures/`）、音效（`Sounds/`）、翻译（`Languages/`）、其他。比较两个快照的 `snapshot_file`：有哈希的（语义文件）比哈希，其他比大小；贴图和音效写大小差，多于一类时再写总的大小差。例：“Defs 改了 4 个、新增 1 个，贴图 +3.2 MB，共 +3.4 MB”。About.xml 自己的变化由上面几项说，不另写“改了”。
  - 工坊的更新时间（`acf_time_updated`）。
  - 锁定的版本（04 §7）：方案用的是锁定版本时，它的上游也在范围里；上游更新了就写“锁定的版本落后 N 次更新”（`Store.UpdatesSince`，从 `origin.json` 的复制时间算）。
  - 第二阶段（**待做**）：“新增了 N 个 Def”“这个补丁现在会失败”这类说法要每个版本的分析摘要，现在没有存，不做。
- **范围和时间**：
  - 默认看**当前方案的 Mod**（加上它用的锁定版本的上游），可以切到**整个库存**（GUI 左栏上面的范围栏，`a`；CLI `--library`，MCP `library`）。
  - 默认时间是**当前方案上次游玩以来**（`Store.LastPlanLaunch`，启动记录，08 §1）；从没玩过时是上次扫描的那些变化。CLI / MCP 的 `--since scan:<n>|<天>d|YYYY-MM-DD` 改起点。
  - 更早的变化收在下面“更早”里，按天分组（起点之前的 10 次扫描），每天一行，展开后同样一个 Mod 一行。
  - 环境的第一次扫描发现的 Mod 不算变化。新出现和不见了的 Mod 合成一行摘要（“新订阅 2 个，不见了 1 个”），展开列出每一个；方案还在用的不见了的 Mod 算会影响启动。
  - 只看一个 Mod：详情“历史”下的“在变化记录查看全部”（TUI：`C`）只看它的 Lineage（每一份副本），列出它的每一次变化，按扫描分组（同一天先被发现、后来又更新的不会合成一行）。顶部是可去掉的条件“只看 <名字> ×”，点 × 或按 `esc` 回到所有 Mod；从侧栏或 `c` 进来总是所有 Mod。
- **行的动作**（适用时才有，展开后是按钮，也都有键）：打开网页（工坊的更新说明页，`ctrl+w`）、看依赖（新依赖会影响启动时，去能不能跑，`D`）、排序（依赖或加载规则变了、Mod 在方案里时，`S`）、锁定这个版本（工坊 Mod 更新了、在方案里、还没锁定时，`p`；先显示 `pin --dry-run` 再确认，TUI 按两次 `p`）。`ctrl+o` 打开文件夹。
- **按键**：`↑↓` 移动，GUI 的光标行在右栏显示详情、`enter` 展开更早的某一天（TUI：`enter` 展开 / 收起行、新增和不见了的那一行、更早的某一天），`i` 原始文件列表（`+` 新增、`~` 改了、`-` 删了，带大小差，最多 300 行），`a` 当前方案 / 整个库存，GUI 的 `tab` / `shift+tab` 到字段与按钮，TUI 切到另一个子页（全部），`R` 重新扫描，`esc` 去掉“只看”条件。`a` 和 `p` 是这一页新加的键，要并进共用的键表。
- 扫描后状态行仍是一句话：`✓ 扫描完成，12 个 Mod 有更新，1 个改了包名，按 c 查看`（`view.ChangeSummary`）。
- 需要玩家判断的身份问题不在这里，在能不能跑 › 要你确认。

### 2.10 游戏日志

已实现（GUI“日志 › 游戏日志”；TUI 在能不能跑里按 `l` 选择日志）。数据：`view.LogFiles`、`view.BuildLogPage`（伴生日志区 `view.MonitorOf`、`view.LiveMonitor`）；GUI 另有 `LogCluster`（展开一个聚类的证据）、`SelectLog`、`LogMonitor`、`AddMonitor`。
- 选择日志文件：一个安静的下拉按钮（“Player.log  10 月 21 日 17:55 ⌄”），菜单里每份 Player.log 下面缩进列出它这次运行的伴生日志（`ArchoMonitor.log`、`ArchoMonitor-prev.log`，没有时 RimCrow 的；配对按 03 §6.7.4，`LogFile.Of` 指向所属的 Player.log）。选伴生日志 = 打开它的 Player.log 并切到伴生日志区。标出属于哪次启动见 03 §6.4。
- 下拉按钮右边一行淡色事实：游戏版本、行数（不再写时间，下拉按钮已经写了）。
- 日志的聚类列表：每条一句话 + 归因的 Mod + 次数，展开看证据和样本。
- 聚类的详情（右侧详情卡，`archo log --cluster` 的文字）：完整的消息（最多 1200 字节）、续行（`also`）、首次出现前后的其他日志消息（`nearby`，03 §6.3）、归因和置信度。
- **Archo 日志分析**（范式卡片，`API.LogPattern` → `view.PatternCard`，03 §6.8）：聚类匹配到错误范式时，右侧在日志原文**上方**多一张卡片，小标题“3 Archo 日志分析”（数字键 3 聚焦）。卡片内容按主次排：
  - 第一行是**严重程度**：一个带颜色的词和一句影响（`PatternCard.Level` / `LevelText` / `Impact`，由范式的阶段和第一种修法定）。严重（红）= 和存档有关：可能读不了档，或丢东西；中等（琥珀）= 加载时出错：它说到的内容可能缺失或不起作用 / 游戏进行中出错：可能反复报错、卡顿或让某个功能失效；轻微（灰）= 阶段是 noise，或第一种修法是“通常可以不管”：通常不影响游戏。
  - 然后是要点：“这类报错通常是：…”（正文色、13px），“先试：…”（强调色的淡底，不用左边竖线，§7 原则 4）；来源 Mod 有自己的已知错误时多一句（琥珀色）。
  - 次要的在一条发丝线下面，12px、淡色：常见原因、修法。最后两行最淡：出现次数和重复上传证据（“40,326 份分享的 1.6 日志里有 22,998 份见过  …”），以及“来自玩家分享的日志，不是对你的列表的结论”。
  - 没匹配到（或只匹配到回退范式）时这张卡片不出现，日志原文占满右侧。CLI 文字里英文的 `pattern:` 小节不再重复显示（`view.WithoutPatternBlock`）。伴生日志区的条目对上聚类时，显示的就是那个聚类的证据和卡片。TUI 的文字版（`PatternCard.Lines`）在标题行下面先写“严重程度  影响”。
- **三张卡片之间的间隙可以拖**：列表和右侧之间左右拖改列表宽度，Archo 日志分析和日志原文之间上下拖改分析卡片高度；记在设置 `ui.gui.log.left`、`ui.gui.log.ana`，双击回到默认（列表略宽于右侧，分析卡片按内容、最多占右侧一半）。窄窗口（900px 以下）三张卡片上下排，不能拖。
- **伴生日志区**（这份 Player.log 有伴生日志时）：列表卡片顶上两个小标签“Player.log  24”“Archo Monitor  16”（RimCrow 的写“RimCrow Companion  16”），←→ 切换。
  - 区头一行淡色事实，取自 session 和 exit 行：开始–结束时间（游戏版本上面已经写了，Monitor 自己的版本不写）（没有 exit 行：“17:51 起，没有退出记录（崩溃或被强制关闭）”；游戏还在运行：“17:51 起”加一个绿点；写满 32 MiB 时注明）。
  - 每个条目一行（文件里的顺序）：时间、级别图标、`inferredType` 的短中文名（补丁错误、Def 配置错误、交叉引用错误、XML 加载错误、程序集冲突、Tick 异常、绘制异常、空引用、内存不足、贴图缺失；`view.MonitorKind`）、消息第一行、×次数（大于 1 时）、相关 Mod（名称；没装的写 packageId）、相关文件（在某个 Mod 目录里时写“Mod › 相对路径”）。INFO 且没有类型的条目不列。
  - 点一行展开 `details`（等宽、限高可滚动），并给出“Player.log 里的 E3 →”，点它切到聚类列表并选中那个聚类；右侧详情卡同时显示那个聚类的证据。对不上任何聚类的 ERROR / WARNING 写“只在 ArchoMonitor.log 里：游戏当时已不再写 Player.log”。

- 当前方案没有 Archo Monitor 时，文件选择下面一行淡色说明“这个方案没有 Archo Monitor：报错不会说明当时在加载哪个文件、哪个 Def”和小按钮“加入 Archo Monitor”（`App.AddMonitor`：把已安装的最新版本放到 Harmony 后面，一步可撤销，04 §1.5 的默认插入；玩家删掉过也能再加）。没安装时只写一行说明和 `archo monitor install`，没有按钮。所看的这次运行有伴生日志时两者都不显示（伴生日志区就在下面）。
- **日志文字用游戏自己的颜色**（聚类列表和伴生日志区的那一行都一样）：级别决定整行颜色，取自游戏日志窗口（`LudeonTK.EditWindow_Log` 画 `Verse.LogMessage.Color`）：Error `ColorLibrary.LogError` = `#ff6666`，Warning `Color.yellow` = `#ffeb04`（1.7 的 UnityStubs 是 1, .922, .016），Message 白色。浅色主题只为对比度调整、色相不变：Error `#eb0000`、Warning `#7e7400`，Message 用主题文字色（`view.GameLogColors`、`view.LightLogColors`，`style.css` 的 `--log-*`）。级别取日志自己的（Waylith 的 Player.log、伴生日志），1.6 的 Player.log 没有级别时按行的状态。
  - Mod 自己的颜色：消息里的 Unity 富文本由 Go 解析成片段（`logs.RichSpans` → `view.LogSpans`，TUI 用同一份片段映射到终端色）：认 `<color=#rgb[a]|#rrggbb[aa]|名称>`、`<b>`、`<i>`，可嵌套；`<size>` 一类改变大小或嵌入东西的标签去掉、保留里面的字；没打开过的结束标签去掉，没关的开始标签一直到行尾。其他看起来像标签的（`<li Class="…"/>`、`<script>`）照原样作为文字显示，和游戏里一样（消息里常有 XML，删掉会丢信息）。界面只把片段当文字放进去，颜色只接受 `#rrggbb`。
  - 一个 Mod 颜色和卡片底色对比度不到 4.5 时，保持色相和饱和度，调亮度到够为止（深色主题变亮，浅色主题变暗）；每个片段带深色、浅色两个值。
