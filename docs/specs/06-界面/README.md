# 06 · 界面

> 状态：2026-10-21 重写。GUI（窗口）和 TUI（终端）两个界面：信息架构、页面、交互规则、详情、视觉和各自的技术实现。方案编辑器、能不能跑、详情、设置、历史区、GUI 的侧栏、顶栏、首页、首次引导、Mod 库存 › 全部、方案页（多个方案，§2.17）、TUI 的页面映射（§9.1）已实现；存档管理、Archo 面板待实现（1.1）。2026-10-23 加后台任务（§2.16）和交互规则 7、8、表格（§3.9）；同日加全部列表（§2.17，GUI 已实现；TUI 的版本、合集两项待做）。2026-10-23 按章节拆成本文件夹，章节号不变。同日加界面规则：§3.1 规则 7–10（弹窗、折叠、后台不卡前台、可拖的缝）、§3.9 数据表的范围、§7.3 视觉规则；代码已按这些规则改完（01 §5.1 第 15 步）。2026-10-30 TUI 不再自带 WezTerm 终端、不再画图片，`:` 命令行加了补全和历史（§9.2–9.4）。
> 依据：00（定位、三个问题、原则）、00a（架构）、01（范围）、03（问题与日志）、04（方案与排序）、05（命令）、08（启动与整合包）、09（Archo）、10（没玩到与值得玩）。

设计原则：不让玩家沿着一条复杂路径完成操作，而是让玩家**随时知道自己在哪里、可以去哪里、怎么回去**，并以**最少的步骤**完成任务。“怎么回去”有两层：界面上，每个弹层和二级界面都能用 `esc` 或面包屑回到上一级（§3.1 规则 5）；数据上，每次修改都能在方案的历史里看到并撤回（§2.5 第三栏、04 §3）。
