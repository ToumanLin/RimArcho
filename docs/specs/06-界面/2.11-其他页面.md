### 2.15 首次引导

已实现（GUI，`guide.js`）。三步，每步可以返回上一步：
1. **找到环境**，两种方式切换：
   - **已有的游戏**：自动探测（02 §2.2）列出找到的游戏（可勾选多个），或输入路径、用“选择…”打开文件夹对话框；名字预填为游戏版本（`1.6`，重名时 `1.6-2`）。
   - **下载一个版本**（08 §11）：没有 SteamCMD 时说明从 Valve 下载它（显示大小和位置），玩家点“下载 SteamCMD”才下载；然后列出 SteamCMD 读到的分支（当前正式版、测试版、各旧版本，带 Steam 的说明和日期）、游戏目录（默认 `<盘>\Games\RimWorld <版本>`，可选择）和可选的 Steam 账户名覆盖项。默认匿名；留空使用设置，显式 anonymous 覆盖已保存的账户；说明密码和 Steam 令牌只在 SteamCMD 自己的窗口输入。下载时显示阶段（启动、登录、下载、校验）、进度条和 SteamCMD 的最后一行；失败时用平常话说原因并可重试；成功后和已有的游戏一样加入环境，进入第 2 步。
2. **读取 Mod**：扫描（子进程，显示进度，§8.4）。共用的 Mod 文件夹已经读过时只读新游戏的 `Data`、`Mods`（`scan --game-only`，02 §4.1），行里说“Data 和 Mods 里有 N 个 Mod”。
3. **从哪里开始**：游戏当前列表（导入 ModsConfig.xml 为第一个方案）/ 从 RimSort、RimCrow 搬过来（导入列表和玩家数据，04 §8、§9）/ 打开整合包或 Steam 合集（`pack import`、`archo collection`）。

导入走 `view.ReadImport` → `view.PreviewImport`（先显示预览）→ `view.ApplyImport`。环境页的“添加环境”从第 1 步开始。

### 2.16 后台任务

2026-10-23 定（玩家从三个候选里选了“任务与它的每一项”，原型 `spikes/bgtasks-v2/c.html`）。回答“RimArcho 刚才在后台做了什么、做到哪了、哪几项没成、为什么”。它是一个**页面**，和其他页面平级，**不是弹窗**（§3.1 规则 7）：任务在跑时玩家照常去别的页面，回来再看。

**什么是任务**：玩家点一下之后要做一阵子、做的时候不该卡住界面的事。每个任务属于一条队列：

| 队列 | 任务 | 怎么跑 |
| --- | --- | --- |
| 文件 | Mod 库里会动文件的动作：移到回收站、移入锁定库、取消隐藏、锁定这个版本、更新锁定版本、解除锁定（§2.9） | 一次一个任务，按提交顺序。移到回收站和取消隐藏整批做：先逐项检查，再同时移 8 个文件夹，全部做完只扫描一次；锁定、移入锁定库每项之后要扫描才认得新的那份，仍一项一项做 |
| Steam | 退订、重新订阅（经 Steam 客户端，08 §10） | 一次一个任务；先逐项检查，再每 50 个交给 Steam 一次 |
| RimArcho | 扫描、检查能不能跑、创建整合包、转换贴图、还原贴图、下载游戏（SteamCMD）、下载 SteamCMD 和 todds、更新社区数据、清除缓存、备份和压缩数据库、清理墓碑 | 原来各自的方式（子进程或协程，§8.4），同一种一次一个，不同种可以同时 |

- **速度**（2026-10-23）：以前每移一个文件夹就整库扫描一次、每退订一个就启动一次 Steam 程序，几百项要很久。现在批量做：内存不是这类任务要省的东西，速度优先。停止在检查时和每个文件夹、每批 Steam 之间生效。
- 文件和 Steam 两条队列是这次新加的：这些动作以前在 Mod 库里同步执行，一项失败就停在那里（“做了 2 个，然后：……”）。现在它们排进队列，**一项失败不停**，接着做下一项，每一项都记下结果。会改文件、RimArcho 撤不回的动作仍在提交前先预览再确认（§6）；确认之后就是后台任务，状态行写“移到回收站：14 个 Mod 已排进文件队列”，做完时状态行再写一句结果（“移到回收站：12 个完成，2 个失败，去后台任务查看”）。
- 不是任务但也在后台的：计算大小（编译页、贴图优化）、切换游戏时读数据、页面读取。它们不卡界面（§3.1 规则 9），进行中只显示在所在的地方，不进这一页。
- 方案编辑（启用、停用、暂存、切换版本、在所有列表里停用）不是任务：它们一下就完成，一步撤销（§3.1 规则 2）。写入游戏、启动也不是任务（§6）。
- 文件队列和扫描互斥：扫描在跑时文件任务排着等；文件任务在跑时扫描等它做完当前这一项。
- 发起者：现在都是玩家。Archo（1.1，09）发起的任务以后在行里带它的头像，详情里写“Archo 发起，你确认过”。

**记录**：每个任务一条记录：种类、对象（“14 个 Mod”“主力殖民地 10-22”）、状态、开始时间、用时、结果一句话，有逐项结果的再带每一项（名称、实例引用、结果、原因、大小）。进行中的在内存里，结束的写进 `<数据目录>/tasks.json`（最近 200 个任务；超过时去掉最旧的已完成任务，失败和部分完成的留得更久），下次打开窗口还在。关掉窗口时还在排队或进行中的任务记为“已停止（窗口关闭）”：RimArcho 不常驻后台（00 §4 原则 6）。

**状态**：进行中、排队中、失败、部分完成（有成有败）、已停止、完成。逐项的结果：完成、失败、正在做、等着、没动（停止后剩下的）。

**入口**：
- 侧栏底部常驻的一行（§2.1，在游戏运行状态上面）：平时是“后台任务”；有任务进行中或排队时是“◔ 后台 2 项  54%”（一个随总进度填满的小圆环），有没看过的失败或部分完成时右边是红色角标（个数）。点它打开这一页；打开这一页时，当时已结束的失败算看过了。
- `ctrl+j` 从任何页面打开、再按一次回到原来的页面；命令面板“后台任务”。
- 状态行里任务结果后面的“去后台任务查看”。
- 顶部导航时，这一行在横栏右端、设置齿轮旁边，只是图标、圆环和角标。

**布局**（同 Mod 库存的“左上筛选，下面接一栏”，§2.9）：面包屑“后台任务”，页面头没有说明文字，只有页面动作“清除已完成”（`C`）。
- **左栏**（默认 `clamp(270px, 25%, 380px)`，拖动分隔线改宽度，存在设置 `ui.gui.tasks.side`，双击恢复）：
  - `1` **筛选栏**（§2.5 的同一个组件）：搜索任务名、对象、结果和每一项的名字；分组：状态、队列、时间（现在 / 今天 / 昨天 / 更早）。
  - `2` **任务**：按“进行中 / 排队中 / 今天 / 昨天 / 更早”分组（分组标题淡色带个数），每组里新的在前，排队的按将要执行的顺序。每个任务两行：第一行粗体种类和淡色对象，右端开始时间；第二行进行中是小进度条、“10 / 14”和现在在做什么（“正在移 RocketMan”“等 Steam 处理第 2 批”“第 4 步  锁住版本”），排队中是“排在文件队列，等前一项做完”，结束的是状态词（失败红、部分完成琥珀、完成带绿色 ✓、已停止淡色）和结果一句话。完成和已停止的名称不加粗。
- **右栏**，两张卡片，中间的缝上下拖动（`ui.gui.tasks.split`，双击恢复）：
  - **概要卡**：15px 的种类和对象；一句话（“进行中  10 / 14  正在移 RocketMan”“部分完成  12 个完成，2 个失败”）；进行中、已停止、部分完成时一条进度条；有步骤的任务（创建整合包）是一排步骤标记（✓、当前的强调色圆点、等着的淡色序号，同 §2.6）；动作按钮，每个带键；最下一行淡色的队列（“文件  一次一项，按顺序做”）、开始、用时。
  - `3` **每一项**：这个任务碰过的每一项，一张表（§3.9 的表格规则）。列：项目（名称，总在）、结果、原因（失败的原因，人话，经 `view.Humanize`）、大小；右键表头还有位置（文件夹或工坊 ID）。默认按结果排序，失败在前。标题行右端写“完成 12  失败 2”。没有逐项结果的任务（扫描、检查、下载游戏）这张卡片只写一句结果，和“按 o 去变化页”这样的去处。
- 窗口窄于 900 像素时只剩左栏，`enter` 让右栏盖满，`esc` 回来（同 Mod 库存）。

**动作**（适用时才出现；按钮、右键菜单、键都是同一张表，作用于选中的任务，否则是光标所在的）：

| 键 | 动作 | 什么时候 |
| --- | --- | --- |
| `x` | 停止后续：做完当前这一项就停，做完的留着，剩下的记为“没动”；排队中的是“取消排队”，什么都没动过 | 进行中、排队中 |
| `r` | 重试失败的 N 项（新任务，只含失败的项）；已停止的是“继续剩下的”（只含没动的项）；没有逐项结果的是“再试一次” | 失败、部分完成、已停止 |
| `J` `K` | 往后 / 往前排一位；也可以拖动行 | 排队中 |
| `o` | 去它改动的页面：Mod 库（筛选成这个任务碰过的项）、变化、能不能跑、这个整合包、贴图优化 | 都有 |
| `ctrl+o` | 打开文件夹（每一项上是那一项的文件夹） | 文件队列的任务、每一项 |
| `Del` | 从记录里去掉（文件不受影响；状态行带“撤销”，`ctrl+z`） | 已结束的 |
| `C` | 清除已完成（只去掉“完成”的，失败、部分完成、已停止留着；同样可以撤销） | 页面动作 |

- 停止、重试、去掉记录都**不确认**：停止只是不再做后面的项；重试是新的任务，失败的项本来就没动；去掉记录可以撤销（§6）。
- 每一项上：`o` 在 Mod 库里看这一份（光标停在它上面）、`ctrl+o` 打开文件夹、失败的项 `r` 只重试这一项、`ctrl+c` 复制名字。
- 从回收站放回（移到回收站的任务）**待做**：要 08 §7 先有从回收站按原路径恢复的功能。

**按键**：`1` `2` `3` 聚焦三个区（§3.5）；`↑↓` `PgUp` `PgDn` `Home` `End` 移动；在任务上 `enter` 或 `→` 去每一项，`←` 回来；`shift+↑↓`、`ctrl+space`、`ctrl+a` 多选任务；`s` 每一项的表头菜单，`<` `>` `=` 列宽；菜单键 / `shift+F10` 行菜单；`/` `ctrl+f` 搜索，`\` 筛选；`?` 全部按键。提示行：`↑↓ 移动  enter 每一项  x 停止后续  r 重试失败的  o 去 Mod 库  ? 全部按键`（随光标所在任务能做的动作变）。

**动效**：进行中的进度条和侧栏的圆环用 `--t-layout` 平滑前进；进度条上的流光同 §7.1 的“加载中”；任务换组（进行中 → 今天）时行用 FLIP 滑过去。`prefers-reduced-motion` 时都不动。

**数据与实现**：`internal/app/tasks.go`（任务、队列、记录文件；文件和 Steam 两条队列的执行，每一项调用 Mod 库原来的单项动作）；`internal/view/tasks.go`（`BuildTasks`：分组、行文字、概要、每一项、动作表，文案在 `view.Text`）；GUI `API.Tasks` / `TaskAct` 和事件 `tasks`（有变化时推送，最多每 250 毫秒一次），页面 `js/tasks.js`。扫描、分析、创建整合包、贴图、下载游戏的原有进度事件不变，同时各记一个任务。CLI 和 MCP 不读这份记录：它们的命令本来就在前台执行完（05）。TUI 暂不做这一页（**待做**）。

### 2.17 列表管理

2026-10-23 定，GUI 已实现。原型：`docs/design/plan-manage-drafts/`（A 第二稿；三栏的 B 稿不用）。这一页回答“我有哪些列表、每个能在哪些版本上玩、跟着哪个合集、怎么分享出去”。编辑列表的内容仍在编辑器里（§2.5）。

**入口与位置**：侧栏“列表”下的第一个子项“管理”，取代原来的“+ 新列表”；点“列表”本身也打开它，和点 Mod 库打开“全部”一样（§2.1）。面包屑“库 / 列表 / 管理”。顶部导航时，“管理”是子页按钮的第一个。

**页面头**：没有说明文字（§7.3），只有右端的导入为新列表（`i`，安静按钮）和新列表（`n`，实心）。已有草稿时写“继续新列表”；正在创建时不再把它画成实心主操作。

**左栏**（一张卡片，宽 270–340px，和右栏之间的缝可以拖动，§7）：当前游戏的所有列表，不分组，顺序和侧栏一样。别的游戏的列表不在这里，在启动页（§2.3）。每行两层：
- 上层是名称（粗体）和标记：“当前”药丸、游戏里现在是它时的绿色小点、有没采用的外部修改时的琥珀色小点，规则同侧栏（§2.5）。
- 下层淡色：“允许的版本  N 个 Mod  上次游玩的日期”（没玩过时写“没玩过”）。
- 右侧：关联了合集时有一个 Steam 图标，合集有变化时变成琥珀色。
- 光标所在的行是选中底色，名称用强调色。

**右栏**（一张卡片）是选中列表的详情：
- **头部**：名称和标记；下面一行淡色事实，写 Mod 数、上次游玩、创建日期和出处（版本 v1 的备注，例如“复制自 default v4”）、“游戏里现在是 v18”（绿色，只在是它时出现）。右端直接露出“复制成新列表…”和主操作“编辑 ↵”（去编辑器），以及“设为当前”（不是当前列表时才有；只切换当前列表，不写游戏文件）、“⋯”（改名、复制成新列表、删除列表…）。
- **游戏版本**（04 §1.6）：一排小按钮，1.0 到当前游戏版本，按钮上只写版本号。允许的版本是凸起的、强调色；现在的游戏版本后面加一个小点。悬停写“现在的游戏有 N 个 Mod 没写支持 1.7”或“所有 Mod 都写了支持 1.6”。点按钮加入或去掉这个版本，至少留一个。玩家改过时右边多一个“恢复默认”（悬停写默认值），没改过时什么都不加。这里不写解释文字；哪些 Mod 不支持现在的游戏，由“能不能跑”提示。改了以后，状态行写“主力殖民地 允许 1.5–1.7”，带“撤销”。
- **跟着 Steam 合集**（04 §9.6）：小标题右边写关联了几个。每个合集是一张小卡片：
  - 第一行：Steam 图标、合集标题、条目数（淡色）；右端是“在 Steam 打开”图标和“取消关联”。
  - 第二行淡色：“上次检查 今天 14:02  4 个没装  在工坊订阅”。不写链接本身。
  - 有变化时，下面是一条琥珀色浅底：“合集有变化：新增 3 个、移除 1 个，看差异”，右端是“跟上合集”。“看差异”就地展开，`+` 绿、`−` 红，一行一个 Mod。没变化时写“✓ 和合集一致”。
  - 最后一行：“跟上时：”加一个两段切换，“只加入新增的 / 也停用移除的”。
  - 卡片下面是输入框“粘贴 Steam 合集链接，让这个列表跟着它”和“关联”。还没关联任何合集时，输入框上方淡色写“还没有关联合集”。
  - 跟上合集是一步可撤销的编辑，状态行写“主力殖民地 跟上「Vanilla Expanded 全系列」：启用 3 个”，带“撤销”。
- **分享**：这个列表上次创建的整合包（一行：包名、大小、创建日期，右端“打开”去整合包页），下面两个按钮：“导出…”（`e`，去导出子页）和“创建整合包…”（`B`，去 §2.6 的子页）。

**导出子页**：面包屑“库 / 列表 / <列表> / 导出”，侧栏停在“管理”上（从编辑器进来时停在那个列表上）。页面头没有说明文字，右端“取消”（`esc`，回到来的地方）。左边一张卡片是格式（04 §9.3），每行一个单选项，写名称、扩展名和一句话：RimArcho 列表（推荐）、RimCrow 分享码、文本列表、ModsConfig.xml、RimWorld Mod 列表（.rml）、RimCrow ModList.xml、工坊链接。右边一张卡片写“N 个 Mod  允许的版本”，内容就是要导出的全文（`loadout export --format` 的输出，等宽字），下面是“保存为文件…”（保存对话框，不覆盖已有文件）和“复制”；分享码只有“复制分享码”。选的格式记在 `ui.gui.export.format`。

**新列表**（`n`，2026-10-24 调整为就地创建）：不弹窗（§3.1 规则 7）。面包屑“库 / 列表 / 管理 / 新列表”，左栏最上面多一行带名称的“草稿”，不计入正式列表。右栏表单先填“新列表名称”（输入时检查重名），再选“从哪里开始”：复制列表（默认）、空列表、从存档、导入。复制时分别选择“来源列表”和“基于哪个版本”：来源是当前游戏的任意列表；版本默认“当前编辑内容（含尚未写入游戏的修改）”，其余列出所有可复制的历史版本，显示版本号、日期时间和 Mod 数。更换来源时重置为当前编辑内容，过时读取不覆盖后来的选择。当前内容复制加载顺序和允许的游戏版本，副本从自己的历史开始。详情的“复制成新列表…”预选该列表并建议“名称 副本”，已有草稿时恢复草稿而不覆盖输入。

表单底部显示创建后成为当前列表、写入或启动时才更新游戏文件。主操作“创建并编辑”（名称框 `enter`），创建后进入编辑器；次操作“仅创建”，留在管理页选中新列表，状态行带创建撤销。两种都沿用新列表成为当前列表的规则。键盘 Enter 在文本域中保留换行，在原生选择器中保留选择行为。重名、读取失败或提交失败保留输入，提交期间禁用表单，防止重复创建。

草稿按游戏在本次应用会话内分别保留；“返回管理”、`esc`、查看另一列表、普通换页及前进后退都只切换视图。左栏草稿和“继续新列表”恢复名称与各来源输入；“稍后继续”返回管理；明确的“丢弃草稿”才清除，并提供撤销丢弃。重启不恢复草稿。

**新建中的导入**：与其他来源在同一表单内切换，名称始终保留，不再进入导入子页或重复选择目的地。支持粘贴、原生文件选择、输入文件路径，以及把文件拖到导入输入区；就地预览复用现有导入分析，显示来源、版本差异、已安装和缺失项及订阅入口。Steam 合集可勾选“以后跟着这个合集”。输入改动后旧预览失效，确认时校验预览标识和所属游戏，避免其他导入流程覆盖后误用内容。仅预览不修改任何列表。

**导入子页**（编辑器的 `i`、首次引导或在导入输入区外把文件拖进窗口；不弹窗）：管理页的 `i` 改为上述新建中的导入，编辑器保留独立的目的地流程。面包屑“库 / 列表 / 导入”，侧栏停在“管理”上，右端“取消”（`esc`）。上面一个文本框，粘贴分享码、Steam 合集链接、Rentry 链接或包名，旁边有“选择文件…”。读到内容后，下面显示预览（04 §9.1）：名称、来源、游戏版本（和现在的游戏不同时琥珀色写出）、Mod 数（已安装、没装各几个，没装的带“在工坊订阅”）、建议允许的版本。再下面是三选一的去向：导入为新列表、替换选中的列表（写出新增、移除、移动各多少）、只加入缺少的。来源是 Steam 合集时多一个勾选框“以后跟着这个合集”（默认勾上）。按钮是“导入”，悬停写“不写游戏文件”。导入后回到列表管理，选中导入的那个列表。

**按键**：`↑↓` 选列表；`enter` 去编辑器；`n` 新列表（这一页没有 Mod，所以 `n` 不是备注，§3.5）；`i` 导入；`e` 导出；`B` 创建整合包；`F2` 改名；`Delete` 删除列表（确认）；`tab` 进入右栏的控件。提示行：`↑↓ 选列表  enter 编辑  n 新列表  i 导入  e 导出  B 创建整合包  ? 全部按键`。

**加载占用**（2026-10-24，已实现）：右栏“游戏版本”和“跟着 Steam 合集”之间一段“加载占用（估算）”，一行“内存约 A–B  显存约 C–D”（含原版和 DLC），下一行淡色写其中原版和 DLC、Mod 各多少。页面画出来后才在后台测量（§3.1 规则 9），测量时是微光占位，第一次写“已读 n / N 个 Mod”；换选中的列表就丢掉旧结果。“算了什么”展开：分类表（贴图、DDS、音效、Def、Patch、程序集：文件数、磁盘大小、内存和显存范围）、内存和显存各前五的 Mod、几句说明（1.7 的贴图系数是实测的，按需上传、小显卡显存更少；1.6 只按规则；内存指专用内存，任务管理器的“内存”通常更少；不算存档和游戏中的增长）。范围大约两倍宽，不给单个数字。数据：`app.PlanLoadCost`（`internal/loadcost`，逐 Mod 缓存），`view` 的 `PlanLoadCost`；CLI `archo plan cost [<列表>] [--mods] [--json]`。模型和实测见 docs/research/2026-10-24_小文件读取与加载占用.md。

**数据**：`view.BuildPlanManage`（每个列表的行、选中列表的详情、允许的版本和每个版本有几个 Mod 没写支持）、`view.PlanCollections`（关联的合集和变化，读缓存，联网检查放在后台任务里，§2.16）、`view.ExportPreview`（导出全文）。GUI 的 API 是 `PlanVersions`、`PlanFollow`、`PlanUnfollow`、`PlanSync`、`PlanExport`，背后和 CLI 是同一套 app 函数（04 §1.6、§9.6）。TUI：`P`（§9.1）的列表切换里加“版本”和“合集”两项，导出沿用命令面板（**待做**）。
