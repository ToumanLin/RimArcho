### 2.13 Archo 面板

**贴图优化**（GUI `textures.js`，`view.TexturePage`；TUI 是命令面板和 `shift+7` 的文本面板）：库下的一页，和别的页面一样是页面头加右端的动作（下载 todds、转换、停止、全部还原），下面是当前方案（或全部 Mod）的 PNG 贴图、估计的大小和进度（08 §5.2）。统计由玩家决定（2026-10-24）：打开页面只读编码器和范围里的 Mod 数（`API.TexturesInfo`），不读贴图；底部一行写“还没统计”，右边“扫描统计”和“开始转换”。点“扫描统计”才在后台读（`API.Textures`，§3.1 规则 9）：列表先出来，大小一行行填上，统计时两个下拉菜单变灰，按钮换成“停止统计”（停下后回到上一次的结果）。换范围或缩放不重新统计：上一次的数字留着，底部写“选项改过了……点「扫描统计」重新统计”；转换或全部还原之后写“贴图之后有变化……”。没统计也能转换（只转新增或变了的 PNG），确认框里这样写；统计过且没有要转的时“开始转换”变灰。按 Mod 的贴图路径、大小、修改时间指纹及选项缓存摘要；再次打开先核对元数据，未变时直接填数，未扫描的文件变更也会使缓存失效。结果按 100 毫秒轮询合批，未变的行保留原节点和微光。设置里只留编码器 todds 的位置。

- **账户**：`view.AccountGroup` 每服务一行，只显示服务名、单行状态和“登录”；已登录改为“重新登录”“退出账号”。不常驻账户名字段、应用或验证按钮。SteamCMD 登录就地展开小字段，已知账户名预填，`enter` 登录、`esc` 取消并恢复按钮焦点；密码与 Guard 仍由 SteamCMD 自己的控制台输入。关闭后自动验证与游戏许可判断，语义见 08 §11。退出确认说明：离线或 Steam 退出失败时，自动忘记此受管 SteamCMD 所有账户的本地缓存。外部副本只写“使用外部 SteamCMD，登录由它自己管理”，不提供按钮。
- 单行状态：SteamCMD 未登录“下载Mod可用，未登录”；登录后“下载Mod可用，下载游戏可用/不可用，登录账号：<名>”。LoversLab 未设置账户时只保留登录入口，不显示状态，也不在订阅、自动检查说明或 CLI/MCP 摘要里显示账户状态；启用后，可用时“可用，Cookie 到期时间：<日期或 N/A>”，需要登录时说明原因，账户行附上次检查时间。英文使用相同语义；设置与订阅来源行共用短状态。
- LoversLab 首次“登录”才确认成人内容、站点规则、自有账号及本机加密保存会话；无需单独启用，以后登录不重复说明。独立原生窗口保留站点 Remember me 选项，不保存密码；“退出账号”仅忘记本机会话。打开设置只读本地状态；续期及需要重新登录的提前提醒由 §2.16 的自动检查负责，账户行显示待确认状态。文件选择就地列实际文件名、大小、日期，无元数据才退回按钮文字；原站声明仍逐次由玩家确认，失败保留手动 zip 入口。
- 外部工具组标题下淡色写上次检查，各工具行显示“有新版本：<版本>”；更新仍使用原来的“更新工具”。尚未兼容的 todds 新版本只提示，不提供安装按钮。工具使用中拒绝更新或移除；具体边界见 07 §2.1。

- **启动页背景**（GUI 设置 › 外观内，2026-10-24；存在 GUI 设置 `ui.gui.home.bg`，一个 JSON：图、暗化、模糊、画面焦点、轮换、打星的图、玩家自己的图）。
  - 上半：左边是启动页的缩小版（左侧列表和右下启动键的示意，图上压着和启动页一样的暗化），下面一行写图名和“来自 <Mod 名>”；右边是暗化（0–80%，默认 30%）、模糊（0–20，默认 0）、画面焦点（左 / 居中 / 右，图被裁时保留哪边）、轮换（每次打开窗口从打星的图里随机选一张；没打星时提示按 `*`）。拖动滑块时预览跟着变，松手保存；其他改动立即保存。
  - 下半：按来源分组的标签页，每组一格格缩略图，选中的有强调色边框和 ✓，打星的右上角有 ★。分组：
    - **游戏自带**（2026-10-24）：读当前环境游戏的 `Data/Core/Defs/Misc/ExpansionDefs/ExpansionDefs.xml` 确定名称和背景包；Core 始终可用，DLC 只在当前游戏有 `Data/<defName>` 目录时列出，不因共享缓存或别的游戏有 DLC 而增加。所有安装共用每个 packageId 的一对菜单 JPEG；只有缺失或损坏的包才按该来源游戏 ExpansionDef 的 `backgroundPath` 提取：
      - **1.7**：有 `Assets.zip` 时，从其中唯一的 `Resources/Textures/<backgroundPath>.*.dds` 或 `.*.dds.split` 读取（不分大小写；两种后缀合起来有多条也视为不唯一）。`.dds.split` 支持 DX10 BC7：按完整 mip 链的块数解析命令表和分组的端点 / 索引流，校验命令、记录边界、字段和完整长度，再逐块还原给 DDS 行解码器；其他 split 格式回退到预览图。候选缺失、不唯一或格式不支持时，日志指出资源路径、候选条目和预览图回退。
      - **1.6 及更早、没有 `Assets.zip`**：只读 `RimWorldWin64_Data/resources.assets` 的 SerializedFile 元数据与 Texture2D 对象，从 `globalgamemanagers` 的 ResourceManager 读取 `textures/<backgroundPath>` → 外部文件 / 对象 ID 映射，精确解析到 `resources.assets`；映射不可用时才按不分大小写的唯一纹理名匹配，重名不猜。像素来自对象内嵌数据，或 `m_StreamData` 指定的 `resources.assets.resS` 范围；只读第 0 级 mip，按 Unity 的倒置存储翻转。支持 Unity 2018–2022 的已知 Texture2D 布局，其他布局走下述回退。DLC 只在当前游戏 `Data/<defName>` 目录存在时列出；实测 1.6 的 Core 和五个 DLC 菜单图全在该 `.resS`，无需读取 DLC AssetBundle。若其他版本将图放进 AssetBundle，当前跳过提取并使用预览图。
      - 每张图优先用成功提取的菜单图；资源缺失、条目不唯一、布局不支持、解码或校验失败时，恢复该官方 Mod 的 `About/Preview.png` 回退（沿用普通图片缓存）。两者都没有时不列出该图，选中的图不可用时按默认图 → 纯色兜底；提取来源可以是其他已登记游戏，但预览图回退仍取当前游戏。
      - 每张可用的图一格，菜单图名称取 ExpansionDef 的 `label`；中文界面从游戏 Languages 的简体中文目录或 `.tar` 读 `ExpansionDef` 翻译，缺失时用 `defName`。预览图名称沿用官方 Mod 名。Core 星球图仍是默认。后台先发布当前游戏可用的共享缓存，再补缺失的包，不阻塞页面，也不进后台任务页（§3.1 规则 9）。补图从已登记安装中按 `Version.txt` 的版本从新到旧尝试，当前安装也参与；新版本缺图或提取失败时继续尝试旧版本。缓存命中不打开 `Assets.zip`、Unity 文件或构建纹理目录；无可用图时先用纯色，补图后仅在列表变化时推送刷新。沿用 `game:<packageId>` key，已有选择、收藏和轮换自动对应到可用图。最后一格仍是“纯色”（不用图，跟随主题）。
    - **每个背景 Mod 一组**：名字里带 “background”（不分大小写）的 Mod，不用加进方案，装了就列出。读它写的 `VBE.BackgroundImageDef`（Vanilla Backgrounds Expanded 的格式，Shella Backgrounds 等也用）：名称取 `label`，图是任意 `Textures/` 下的 `<path>.png/.jpg`；图找不到的那条跳过。没有这种 Def 的，列出它 `Textures/` 下宽 ≥ 1280 的横图（只读文件头）。只看名字匹配的这几个 Mod 的文件夹，不搜其他 Mod。打包在 `Assets.zip` 或只有 `.dds` 的图暂不支持。
    - **自定义**：玩家自己加的 PNG / JPG（“添加图片…”打开系统的打开文件对话框）；悬停出现 ×，只从列表里移除，不删文件。其他名字不带 background 的 Mod 里的图也从这里加。
  - 按键：`tab` 进到缩略图，方向键选，`Enter` 用这张（在“添加图片…”上是添加），`*` 打星，`[` `]` 换分组，`Delete` 移除自定义图。
  - 选中的图找不到了（Mod 退订、文件移走）时用默认图；默认图也没有时用纯色。
  - **缓存与内存**（2026-10-24）：原图每张只解码一次，一次只解一张，缩成 1920 宽（启动页）和 480 宽（缩略图、预览）两份 JPEG，放在 `cache/backgrounds/`。普通图片按路径、大小、修改时间命名；游戏菜单图以小写 packageId 的 SHA-256 前 12 字节和格式版本命名为 `menu-shared-v1-<hash>-1920.jpg` / `-480.jpg`，与安装路径、游戏版本、ZIP / Unity 指纹和界面语言无关，每个包只存一对。缓存 JPEG 有大小、尺寸及完整解码校验；同一进程按路径、大小和修改时间记住校验结果，未改变时只做文件状态检查。缺失、损坏或尺寸不配套时重提取该包，不重做其他包。旧的 `menu-<stamp hash>-*.jpg` 忽略并保留，不删除玩家文件。游戏更新不自动使共享缓存失效；需要换成更新后的美术时，关闭 RimArcho，仅删除 `cache/backgrounds/menu-shared-v1-*.jpg` 后重新打开（可只删目标包的一对）；外部浏览器使用强制刷新。补图期间仍校验源文件指纹，变化或取消时丢弃暂存文件，不替换已有成员；JPEG 通过临时文件原子替换。游戏 ZIP 支持 zstd（方法 93）和 deflate，校验完整条目的大小与 CRC-32；DDS / Unity 支持 BC7、BC1、BC3，Unity 另支持 RGBA32，每次只解 4 行并直接盒式缩放。ZIP 条目上限 128 MiB；split 先验证 DDS 尺寸（单边 ≤ 16384、像素数 ≤ 4000 万）、mip 数和由块数推导的负载范围，再分配与声明长度相同的一份 split 负载缓冲（命令表直接引用该缓冲），校验 ZIP 大小与 CRC 后按需还原 16 字节块；不分配完整还原 DDS 或全尺寸像素。缩略图生成后仍遍历余下 mip 的记录以检查字段，失败不发布 JPEG。普通 DDS 不使用整条目缓冲。Unity 元数据有大小上限，像素用文件范围读取，不把整个 `.resS` 读入内存；不分配或保存全尺寸 RGBA、还原 DDS 或 PNG，每张做完 `debug.FreeOSMemory`。其他图片直接从解码结果缩放，不另复制全尺寸位图，一批解码停下 2 秒后把内存还给系统。缩略图在滚到眼前时才加载。`/bg` 只提供当前环境列表里有的图，不按任意路径读文件；URL 带图片路径版本；共享菜单图跨游戏使用同一 URL，普通图片沿用各自的缓存版本。

### 2.16 后台任务

**自动检查与数据更新**：GUI 和交互式 TUI 打开期间，`app.AutomaticLoop` 用同一个计时器调度四项工作；窗口就绪后延迟 20 秒首次检查，之后每分钟查看是否到期，关闭时取消请求，不常驻，也不更新 RimArcho 本身。每轮使用独立连接、按顺序执行，结束释放库存和数据索引；网络不持有页面锁。GUI 有正在进行或排队的任务时让玩家的操作先做。

- 设置只有 `updates.auto` 总开关（默认开）和 `updates.interval`（常规 / 缩短一半 / 延长一倍）。常规间隔由 `app.AutomaticInterval` 定义：Mod 和社区数据每天、工具每周、已启用的 LoversLab 会话每四小时；另外两个选择统一缩放。说明用自然间隔：每天 / 每周 / 每 4 小时；缩短一半为每 12 小时 / 每周两次 / 每 2 小时，延长一倍为每 2 天 / 每 2 周 / 每 8 小时。英文使用对应的 daily、weekly 等表达。
- SQLite meta `automatic:<类别>` 在联网前记录检查尝试，完成后记结果、完成时间和待处理数；同库的多个窗口以条件更新领取同一次检查。重启和失败都不立即重复检查。手动更新社区数据、手动验证账户也满足对应的检查间隔。CLI / MCP 只读取状态，不启动计时器（05 §4.2）。
- Mod 只检查 SteamCMD 公开工坊元数据、Git 跟踪引用、下载页版本；LoversLab 有已启用的会话时使用它读文件页。检查不下载 Mod、不检出 Git 新提交；结果沿用 §2.9 的“等你更新”，玩家确认才更新，任一登记游戏运行时拒绝更新。Steam 客户端订阅由 Steam 自己更新，不加入自动检查。离线保留已知更新。
- 工具检查和 LoversLab 会话协议分别由 07 §2.1、§3.1 定义；社区数据的下载、条件请求和替换由 04 §6.3 定义。
- 发现待处理数变化且非零时，仅发一条安静通知；同一个数量不反复提醒。LoversLab 需要重新登录的通知用警告标记（GUI ⚠、TUI `!`），更新数量用完成标记。社区数据失败保留旧文件，不发失败通知。GUI 每次检查记成后台任务，自动失败不产生未读红角标；TUI 显示安静通知，暂不提供任务页。结果在订阅与更新、设置的外部工具 / 社区数据 / 账户各处查看（§2.14）。订阅和后台任务的成功结果说“都是最新的”或“N 个有更新”，不说“检查完成”；失败保留原来的原因。

**Steam credit 询问**：导入页全部订阅、关注合集和需要处理页的批量 subscribe，都先选择“从 Steam 订阅（慢，但订阅能给作者带来订阅数，由 Steam 管理）”或“从 SteamCMD 下载（快，但不计入作者的订阅数，由 RimArcho 管理）”，对应请求都传 `batch:true`。使用 SteamCMD 的批次达到三次游戏会话后，在窗口就绪、游戏退出或窗口回到前台时查询 `CreditPrompt()`（assets/js/credit.js `checkCredit`）；非空时弹一次“要在 Steam 上订阅，给作者带来订阅数吗？”，两个选项是“在后台逐步把这批 SteamCMD Mod 换成 Steam 订阅”和“不用了”。显示本次合并的 Mod 数量、少量名字，回答整个 `batchIDs`。前端合并并发查询；已有其它弹窗时不打开，留到下次查询。Esc 关闭或回答请求失败都不算回答，下次查询会再问。`null` 表示推迟，不标为已读；没有第三个隐式 Dismiss 动作。批次规则由 02 §3.4 定义，签名、JSON、事件与文案 key 见 [API 合同](../../api/steam-credit.md)。

**逐步替换任务**：接受后进入任务页中的 RimArcho 队列，种类 `steam-credit-replace`，沿用 `tasks` 变化/结束事件；进度显示已处理数 / 总数，逐项显示等待、已替换、保留副本的原因或不可恢复订阅错误。等待 Steam 或游戏退出期间仍可停止；停止保留已完成订阅和未完成义务，可从任务页继续，重启也继续。历史显示可以清理，SQLite 的义务不能随之丢弃。历史和撤销跟随客户端副本，不造成重复副本；保留原因包括任一可加载旧副本的环境无法加载新副本（整项保留，注明环境）、损坏暂存数据（注明列表）、固定整合包、入链或未交接的游戏部署。备注合并到新副本；DDS 台账不直接迁移，任务结果提示重新优化工坊副本。启动遇交接锁最多等待十秒，Go 提供“等待后台替换完成”提示（`launch-wait` 事件），超时才报错；扫描不占交接锁。重叠批次已交接的项显示“已由另一批替换为工坊里的这一份”。等待扫描/文件任务不增加失败次数；关闭窗口取消 Steam worker，最多等待替换 runner 三秒，下次续跑。结束 `done` 可包含上述原因保留的副本，`part` / `fail` 表示存在不可恢复失败；此类失败不自动重试。


2026-10-23 定（玩家从三个候选里选了“任务与它的每一项”，原型 `spikes/bgtasks-v2/c.html`）。回答“RimArcho 刚才在后台做了什么、做到哪了、哪几项没成、为什么”。它是一个**页面**，和其他页面平级，**不是弹窗**（§3.1 规则 7）：任务在跑时玩家照常去别的页面，回来再看。

**什么是任务**：玩家点一下之后要做一阵子、做的时候不该卡住界面的事。每个任务属于一条队列：

| 队列 | 任务 | 怎么跑 |
| --- | --- | --- |
| 文件 | Mod 库里会动文件的动作：移到回收站、移入锁定库、取消隐藏、锁定这个版本、更新锁定版本、解除锁定（§2.9） | 一次一个任务，按提交顺序。移到回收站和取消隐藏整批做：先逐项检查，再同时移 8 个文件夹，全部做完只扫描一次；锁定、移入锁定库每项之后要扫描才认得新的那份，仍一项一项做 |
| Steam | 退订、重新订阅（经 Steam 客户端，08 §10） | 一次一个任务；先逐项检查，再每 50 个交给 Steam 一次 |
| RimArcho | 扫描、检查能不能跑、创建整合包、转换贴图、还原贴图、下载游戏（SteamCMD）、下载 SteamCMD 和 todds、更新社区数据、清除缓存、备份和压缩数据库、清理墓碑 | 原来各自的方式（子进程或协程，§8.4），同一种一次一个，不同种可以同时 |

- **速度**（2026-10-23）：以前每移一个文件夹就整库扫描一次、每退订一个就启动一次 Steam 程序，几百项要很久。现在批量做：内存不是这类任务要省的东西，速度优先。停止在检查时和每个文件夹、每批 Steam 之间生效；重新订阅的下载等待可在批内停止，关闭 worker。
- **重新订阅的下载进度**：订阅确认后主动下载并等待文件落盘（08 §10）。任务阶段显示“Steam 正在下载 3 / 14”，每项显示“等 Steam 开始下载”或“下载中 45%”；任务百分比计入运行项的字节比例，完成计数只在逐项结束后增加。任务变化事件每秒最多两次，完成事件立即发送。持久记录 `app.TaskItem` 的 `got` / `size` 是已下载 / 总字节；页面 `view.TaskItemRow` 使用 `got` / `downloadSize` 数字与翻译后的 `stateText`，原有 `size` 格式化文字与 `bytes` 文件大小不变。停止或关闭窗口终止下载等待，未完成项留作继续；Steam 本身可能继续下载。
- **全部订阅的下载任务**：一次操作只显示一个任务、一条总进度，不显示内部下载分包或重试轮次；预检、分包和失败分类由 02 §3.4 定义。运行中显示已处理数 / 总数、当前正在下载的 Mod 名；每条 SteamCMD Success / ERROR 立即更新记录，进度跨分包和重试单调推进。有公开 `file_size` 时按字节加权，未知大小使用已知大小的平均权重，全部未知时按条目计数；运行中的百分比最多 99%，成功结束为 100%。可重试失败在同一任务内自动重试，重试结束前不计入已完成进度，耗尽后才作为最终失败展示。
- **订阅任务的结果文本**：左侧第一行“订阅 N 个 Mod”，单个用“订阅 Mod 名”；第二行只有一行汇总，例如“完成 36，失败 4：已不在创意工坊”。右侧概要按原因分组，每个原因一行，例如“4 个 Mod 已不在创意工坊（作者删除或设为私有）”，不重复逐项原因、不放 URL。逐项表名称用预检的 title，取不到才回退到 Workshop ID；原因列只放短语（“已不在创意工坊”“连接失败或超时”等），没有 `failed:` 前缀；每项菜单保留“打开工坊页面”。任务项持久记录 `failureKind` 和 `permanent`，不可重试的行不提供重试。
- **订阅任务的取消与恢复**：运行中显示“取消”，沿用任务 stop 动作。已完成的保留，剩余行显示“已取消”；结束后显示“继续 N 个”，沿用原任务行、总数、已完成项和进度，只提交剩余项。自动重试后仍失败的可重试项显示“重试 N 个”；永久失败不计入数量，没有可重试项就不显示重试按钮，此时主按钮为“前往订阅与更新”。内部实现和进程归属见 02 §3.4。
- 文件和 Steam 两条队列是这次新加的：这些动作以前在 Mod 库里同步执行，一项失败就停在那里（“做了 2 个，然后：……”）。现在它们排进队列，**一项失败不停**，接着做下一项，每一项都记下结果。会改文件、RimArcho 撤不回的动作仍在提交前先预览再确认（§6）；确认之后就是后台任务，状态行写“移到回收站：14 个 Mod 已排进文件队列”，做完时状态行再写一句结果（“移到回收站：12 个完成，2 个失败，去后台任务查看”）。
- 不是任务但也在后台的：计算大小（编译页、贴图优化）、切换游戏时读数据、页面读取。它们不卡界面（§3.1 规则 9），进行中只显示在所在的地方，不进这一页。
- 方案编辑（启用、停用、暂存、切换版本、在所有列表里停用）不是任务：它们一下就完成，一步撤销（§3.1 规则 2）。保存、启动也不是任务（§6）。
- 文件队列和扫描互斥：扫描在跑时文件任务排着等；文件任务在跑时扫描等它做完当前这一项。
- 发起者：玩家或上述自动检查。Archo（1.1，09）发起的任务以后在行里带它的头像，详情里写“Archo 发起，你确认过”。

**记录**：每个任务一条记录：种类、对象（“14 个 Mod”“主力殖民地 10-22”）、状态、开始时间、用时、结果一句话，有逐项结果的再带每一项（名称、实例引用、结果、原因、大小）。进行中的在内存里，结束的写进 `<数据目录>/tasks.json`（最近 200 个任务；超过时去掉最旧的已完成任务，失败和部分完成的留得更久），下次打开窗口还在。关掉窗口时还在排队或进行中的任务记为“已停止（窗口关闭）”：RimArcho 不常驻后台（00 §4 原则 6）。

**状态**：进行中、排队中、失败、部分完成（有成有败）、已停止、完成。逐项的结果：完成、失败、正在做、等着、没动（停止后剩下的）。

**入口**：
- 侧栏底部常驻的一行（§2.1，在游戏运行状态上面）：平时是“后台任务”；有任务进行中或排队时是“◔ 后台 2 项  54%”（一个随总进度填满的小圆环），有没看过的失败或部分完成时右边是红色角标（个数）。点它打开这一页；打开这一页时，当时已结束的失败算看过了。
- `ctrl+j` 从任何页面打开、再按一次回到原来的页面；命令面板“后台任务”。
- 状态行里任务结果后面的“去后台任务查看”。
- 顶部导航时，这一行在横栏右端、设置齿轮旁边，只是图标、圆环和角标。

**布局**（同 Mod 库存的“左上筛选，下面接一栏”，§2.9）：面包屑“后台任务”，页面头没有说明文字，只有页面动作“清除已完成”（`C`）。
- **左栏**（默认 `clamp(270px, 25%, 380px)`，拖动分隔线改宽度，存在设置 `ui.gui.tasks.side`，双击恢复）：
  - `1` **筛选栏**（§2.5 的同一个组件）：搜索任务名、对象、结果和每一项的名字；分组：状态、队列、时间（现在 / 今天 / 昨天 / 更早）。
  - `2` **任务**：按“进行中 / 排队中 / 今天 / 昨天 / 更早”分组（分组标题淡色带个数），每组里新的在前，排队的按将要执行的顺序。每个任务两行：第一行粗体种类和淡色对象，右端开始时间；第二行进行中是小进度条、“10 / 14”和现在在做什么（“正在移 RocketMan”“等 Steam 处理第 2 批”“第 4 步  锁住版本”），排队中是“排在文件队列，等前一项做完”，结束的是状态词（失败红、部分完成琥珀、完成带绿色 ✓、已停止淡色）和结果一句话。完成和已停止的名称不加粗。
- **右栏**，两张卡片，中间的缝上下拖动（`ui.gui.tasks.split`，双击恢复）：
  - **概要卡**：15px 的种类和对象；一句话（“进行中  10 / 14  正在移 RocketMan”“部分完成  12 个完成，2 个失败”）；进行中、已停止、部分完成时一条进度条；有步骤的任务（创建整合包）是一排步骤标记（✓、当前的强调色圆点、等着的淡色序号，同 §2.6）；动作按钮，每个带键；最下一行淡色的队列（“文件  一次一项，按顺序做”）、开始、用时。
  - `3` **每一项**：这个任务碰过的每一项，一张表（§3.9 的表格规则）。列：项目（名称，总在）、结果、原因（失败的原因，人话，经 `view.Humanize`）、大小；右键表头还有位置（文件夹或工坊 ID）。默认按结果排序，失败在前。标题行右端写“完成 12  失败 2”。没有逐项结果的任务（扫描、检查、下载游戏）这张卡片只写一句结果，和“按 o 去订阅与更新”这样的去处。
- 窗口窄于 900 像素时只剩左栏，`enter` 让右栏盖满，`esc` 回来（同 Mod 库存）。

**动作**（适用时才出现；按钮、右键菜单、键都是同一张表，作用于选中的任务，否则是光标所在的）：

| 键 | 动作 | 什么时候 |
| --- | --- | --- |
| `x` | 停止后续：做完当前这一项就停，做完的留着，剩下的记为“没动”；排队中的是“取消排队”，什么都没动过 | 进行中、排队中 |
| `r` | 重试可重试的失败项（新任务，只含这些项）；已停止的是“继续剩下的”（只含没动的项）；没有逐项结果的是“再试一次” | 有可重试失败、部分完成、已停止 |
| `J` `K` | 往后 / 往前排一位；也可以拖动行 | 排队中 |
| `o` | 去它改动的页面：Mod 库（筛选成这个任务碰过的项）、订阅与更新、能不能跑、这个整合包、贴图优化 | 都有 |
| `ctrl+o` | 打开文件夹（每一项上是那一项的文件夹） | 文件队列的任务、每一项 |
| `Del` | 从记录里去掉（文件不受影响；状态行带“撤销”，`ctrl+z`） | 已结束的 |
| `C` | 清除已完成（只去掉“完成”的，失败、部分完成、已停止留着；同样可以撤销） | 页面动作 |

- 停止、重试、去掉记录都**不确认**：停止只是不再做后面的项；重试是新的任务，失败的项本来就没动；去掉记录可以撤销（§6）。
- 每一项上：`o` 在 Mod 库里看这一份（光标停在它上面）、`ctrl+o` 打开文件夹、可重试的失败项 `r` 只重试这一项、`ctrl+c` 复制名字。
- 从回收站放回（移到回收站的任务）**待做**：要 08 §7 先有从回收站按原路径恢复的功能。

**按键**：`1` `2` `3` 聚焦三个区（§3.5）；`↑↓` `PgUp` `PgDn` `Home` `End` 移动；在任务上 `enter` 或 `→` 去每一项，`←` 回来；`shift+↑↓`、`ctrl+space`、`ctrl+a` 多选任务；`s` 每一项的表头菜单，`<` `>` `=` 列宽；菜单键 / `shift+F10` 行菜单；`/` `ctrl+f` 搜索，`\` 筛选；`?` 全部按键。提示行：`↑↓ 移动  enter 每一项  x 停止后续  r 重试失败的  o 去 Mod 库  ? 全部按键`（随光标所在任务能做的动作变）。

**动效**：进行中的进度条和侧栏的圆环用 `--t-layout` 平滑前进；进度条上的流光同 §7.1 的“加载中”；任务换组（进行中 → 今天）时行用 FLIP 滑过去。`prefers-reduced-motion` 时都不动。

**数据与实现**：`internal/app/tasks.go`（任务、队列、记录文件；文件和 Steam 两条队列的执行，每一项调用 Mod 库原来的单项动作）；`internal/view/tasks.go`（`BuildTasks`：分组、行文字、概要、每一项、动作表，文案在 `view.Text`）；GUI `API.Tasks` / `TaskAct` 和事件 `tasks`（有变化时推送，最多每 250 毫秒一次），页面 `js/tasks.js`。扫描、分析、创建整合包、贴图、下载游戏的原有进度事件不变，同时各记一个任务。CLI 和 MCP 不读这份记录：它们的命令本来就在前台执行完（05）。TUI 暂不做这一页（**待做**）。

### 2.17 全部列表（原“列表管理”）

2026-10-23 定，GUI 已实现。原型：`docs/design/plan-manage-drafts/`（A 第二稿；三栏的 B 稿不用）。这一页回答“我有哪些列表、每个能在哪些版本上玩、跟着哪个合集、怎么分享出去”。编辑列表的内容仍在编辑器里（§2.5）。

**入口与位置**：侧栏“列表”下的第一个子项“全部列表”，置顶在最近使用的列表之上（2026-10-26 起；侧栏最多列 4 个列表，其余只在这一页；点“列表”本身打开当前列表，§2.1）。面包屑“库 / 列表 / 全部列表”。顶部导航时，“全部列表”是子页按钮的最后一个。

**页面头**（2026-10-25 改）：没有说明文字（§7.3），只有右端一个“新建 / 导入”（`n`，实心）：新建和导入本来就是同一张表单，不再分两个入口（`i` 仍直接打开表单的导入方式）。有草稿时点它回到草稿；正在创建时它不再画成实心。

**左栏**（一张卡片，默认占页面宽度的 38%、右栏 62%，至少 270px；和右栏之间的缝可以拖动，存在设置 `ui.gui.plans.side`，双击恢复，§7）：所有列表（所有游戏共用，04 §1.7），不按游戏分组，当前游戏的当前列表在最前，其余按创建顺序。设为当前后，行按新顺序从原位置滑到新位置（和侧栏一样，§2.1）。允许的版本不含当前游戏的列表照常列出，下层的版本文字已经说明（04 §1.6）。每行两层：
- 上层是名称（粗体）和标记：游戏里现在是它时的绿色小点、有没采用的外部修改时的琥珀色小点，规则同侧栏（§2.5）。
- 下层淡色：“允许的版本  N 个 Mod  上次游玩的日期”（没玩过时写“没玩过”）。
- 右侧（2026-10-26 改，原来是关联合集的 Steam 图标，已去掉）：当前列表是“当前”药丸；其他列表是“设为当前”链接，鼠标移上或选中该行时出现（它成为启动的那个列表，不写游戏文件，04 §1.3）。
- 光标所在的行是选中底色，名称用强调色。

**右栏**（一张卡片）是选中列表的详情：
- **头部**（2026-10-25 改）：名称和标记（“当前”/“设为当前”在 2026-10-26 移到左栏每行右侧）。下面一行淡色事实，写 Mod 数、上次游玩、创建日期和出处（版本 v1 的备注，例如“复制自 default v4”）、“游戏里现在是 v18”（绿色，只在是它时出现）。右端四个按钮直接露出，没有“⋯”：改名（`F2`）、创建副本（`D`）、删除（`Delete`，确认；只剩一个列表时禁用）、主操作“编辑 ↵”（去编辑器）。
  - **改名就地进行**：双击名称、`F2` 或“改名”，名称变成输入框（全选），输入时检查重名；`enter` 或离开输入框时保存，`esc` 放弃。不弹窗。
  - **创建副本**：立刻复制这个列表现在的内容（加载顺序和允许的版本，副本从自己的历史开始），名为“<名称> 副本”（重名时加序号），选中它并把名称放进改名输入框；状态行带“撤销”（删掉副本）。侧栏右键菜单的“创建副本”相同。

  - 第一行：Steam 图标、合集标题、条目数（淡色）；右端是“在 Steam 打开”图标和“取消关联”。

  - 最后一行：“跟上时：”加一个两段切换，“只加入新增的 / 也停用移除的”。

**导出子页**：面包屑“库 / 列表 / <列表> / 导出”，侧栏停在“全部列表”上（从编辑器进来时停在那个列表上）。页面头没有说明文字，右端“取消”（`esc`，回到来的地方）。左边一张卡片是格式（04 §9.3），每行一个单选项，写名称、扩展名和一句话：RimArcho 列表（推荐）、RimCrow 分享码、文本列表、ModsConfig.xml、RimWorld Mod 列表（.rml）、RimCrow ModList.xml、工坊链接。右边一张卡片写“N 个 Mod  允许的版本”，内容就是要导出的全文（`loadout export --format` 的输出，等宽字），下面是“保存为文件…”（保存对话框，不覆盖已有文件）和“复制”；分享码只有“复制分享码”。选的格式记在 `ui.gui.export.format`。

**新建 / 导入**（`n`，2026-10-24 就地创建，2026-10-25 简化）：不弹窗（§3.1 规则 7）。面包屑“库 / 列表 / 全部列表 / 新列表”，左栏最上面多一行带名称的“草稿”，不计入正式列表。右栏表单先填“新列表名称”（输入时检查重名，默认“新列表”），再选“从哪里开始”：空列表（默认）、复制列表、从存档、导入。空列表下一行淡色说明列表从空开始、在编辑器里添加 Mod。复制时分别选择“来源列表”和“基于哪个版本”：来源是当前游戏的任意列表；版本默认“当前编辑内容（含未保存的修改）”，其余列出所有可复制的历史版本，显示版本号、日期时间和 Mod 数。更换来源时重置为当前编辑内容，过时读取不覆盖后来的选择。当前内容复制加载顺序和允许的游戏版本，副本从自己的历史开始。

表单底部只有一个主按钮（悬停写“不写游戏文件”），固定在可见区域底部，预览再长也不用滚动去找：导入还没预览时它是“预览”，预览之后换成“创建并编辑”；其他方式一直是“创建并编辑”。创建后进入编辑器（新列表不自动成为当前列表，04 §1.3）。名称框 `enter`、文本域 `ctrl+enter` 等于点它；文本域里 `enter` 保留换行。重名、读取失败或提交失败保留输入，提交期间禁用表单，防止重复创建。没有“返回管理”“稍后继续”“仅创建”：要离开就点侧栏、左栏的另一个列表或按 `esc`（关闭表单）。异步读取（建议的名称、来源列表）只就地更新，不重画表单，免得吞掉进行中的点击。

**草稿**：按游戏在本次应用会话内保留。离开表单（`esc`、点另一个列表、换页、后退）时，名称还是给的默认名（或导入时按来源建议的名字）的草稿直接丢掉：玩家没改任何东西，说明不想要；改过名字的草稿留在左栏，点它或“新建 / 导入”回到它，恢复名称和各来源输入，`esc` 离开时状态行写“草稿已保留”。留下的草稿表单里多一个“丢弃草稿”（安静链接），丢弃可撤销。重启不恢复草稿。

**新建中的导入**：与其他方式在同一表单内切换，名称保留（玩家没改过名字时，用导入内容的标题或文件名作建议名）。上面一行淡色引导：能导入什么（RimSort、RimCrow、RimWorld 或其他 RimArcho 的列表、存档、分享码、Steam 合集），创建前先预览看哪些 Mod 已经有了。下面是虚线框：“选择文件…”（窗口里是系统打开对话框，选完立刻读取并预览；开发环境回退为浏览器文件选择），旁边写选中的文件名和“清除”，没选时写“或把文件拖到这里”；不再有手填路径的输入框。文件拖到表单任何地方都切到导入并读取。再下面“或者粘贴”一个文本域：分享码、合集链接、Rentry 链接或复制的列表，点“预览”才读（链接会联网）。预览复用现有导入分析，显示来源、版本差异、已安装和缺失项。Steam 合集可勾选“以后跟着这个合集”。输入改动后旧预览失效、主按钮变回“预览”，确认时校验预览标识和所属游戏。仅预览不修改任何列表。

**缺失的 Mod**（2026-10-25）：预览的“没有安装：N”下面一行写“订阅的 Mod 下载完后会自动回到列表里的位置”，右端“全部订阅（M 个）”：先选“用 Steam 订阅 / 用 SteamCMD 下载”，再把有工坊页的 M 个作为一个后台任务订阅（`subscribe workshop <id…>`，§2.16）。没有已知工坊页的写“N 个没有已知的创意工坊页面，需要自己找”，每行仍有单独的“订阅”或“不在工坊列表里”。下载、扫描后，列表里的缺失项自动换成装好的 Mod，位置不变（`loadout.Registry.Heal`）。编辑器的导入子页用同一段。能不能跑里，列表里没装的 Mod 合成一项（§5）。

**导入子页**（编辑器的 `i`、首次引导或在导入输入区外把文件拖进窗口；不弹窗）：全部列表页的 `i` 改为上述新建中的导入，编辑器保留独立的目的地流程。面包屑“库 / 列表 / 导入”，侧栏停在“全部列表”上，右端“取消”（`esc`）。上面一个文本框，粘贴分享码、Steam 合集链接、Rentry 链接或包名，旁边有“选择文件…”。读到内容后，下面显示预览（04 §9.1）：名称、来源、游戏版本（和现在的游戏不同时琥珀色写出）、Mod 数（已安装、没装各几个，没装的带“在工坊订阅”）、建议允许的版本。再下面是三选一的去向：导入为新列表、替换选中的列表（写出新增、移除、移动各多少）、只加入缺少的。来源是 Steam 合集时多一个勾选框“以后跟着这个合集”（默认勾上）。按钮是“导入”，悬停写“不写游戏文件”。导入后回到全部列表，选中导入的那个列表。

**按键**：`↑↓` 选列表；`enter` 去编辑器；`n` 新建 / 导入（这一页没有 Mod，所以 `n` 不是备注，§3.5）；`i` 直接打开导入方式；`F2` 改名（就地）；`D` 创建副本；`Delete` 删除列表（确认）；`e` 导出；`B` 创建整合包；`tab` 进入右栏的控件；表单里 `esc` 关闭表单。提示行：`↑↓ 选列表  enter 编辑  n 新建 / 导入  F2 改名  D 创建副本  e 导出  ? 全部按键`；表单里是 `enter 预览 / 创建并编辑  esc 关闭`。

**加载占用**（2026-10-24，已实现）：右栏“游戏版本”和“跟着 Steam 合集”之间一段“加载占用（估算）”，一行“内存约 A–B  显存约 C–D”（含原版和 DLC），下一行淡色写其中原版和 DLC、Mod 各多少。页面画出来后才在后台测量（§3.1 规则 9），测量时是微光占位，第一次写“已读 n / N 个 Mod”；换选中的列表就丢掉旧结果。“算了什么”展开：分类表（贴图、DDS、音效、Def、Patch、程序集：文件数、磁盘大小、内存和显存范围）、内存和显存各前五的 Mod、几句说明（1.7 的贴图系数是实测的，按需上传、小显卡显存更少；1.6 只按规则；内存指专用内存，任务管理器的“内存”通常更少；不算存档和游戏中的增长）。范围大约两倍宽，不给单个数字。数据：`app.PlanLoadCost`（`internal/loadcost`，逐 Mod 缓存），`view` 的 `PlanLoadCost`；CLI `archo plan cost [<列表>] [--mods] [--json]`。模型和实测见 docs/research/2026-10-24_小文件读取与加载占用.md。

**数据**：`view.BuildPlanManage`（每个列表的行、选中列表的详情、允许的版本和每个版本有几个 Mod 没写支持）、`view.PlanCollections`（关联的合集和变化，读缓存，联网检查放在后台任务里，§2.16）、`view.ExportPreview`（导出全文）。GUI 的 API 是 `PlanVersions`、`PlanFollow`、`PlanUnfollow`、`PlanSync`、`PlanExport`，背后和 CLI 是同一套 app 函数（04 §1.6、§9.6）。TUI：`P`（§9.1）的列表切换里加“版本”和“合集”两项，导出沿用命令面板（**待做**）。
