### 2.16.1 定时行为总表

本表记录当前 `internal/`、`cmd/` 和 GUI 前端的调度、轮询、延迟、防抖、重试及按时间到期的行为。自动检查的授权、任务记录和通知规则见 §2.16；性能门槛及实测仍见 §10、07 §6。本表不改变这些行为。

- **触发与间隔分开看**：固定间隔只在对应窗口、页面、任务或子进程存活时有效；按需到期检查没有独立计时器。循环若在一次工作结束后才重新计时，表中间隔不包括工作耗时。
- **界面**表示实际入口；CLI / MCP 的按需操作不等于它们启动了自动维护。联网列指该行为可能发起的外部请求；前端调用本机 API、读文件或检查进程不算联网。Steam 回调和下载标“是（Steam）”。
- **设置**列的“否”表示没有玩家可改的间隔设置；代码中供测试注入的时钟、等待和轮询参数不算设置。`updates.auto` 默认 `on`，`updates.interval` 默认 `normal`；四类维护共享这两个键，没有独立开关。
- **代码位置**以 `internal/` 为根；`JS/` 是 `internal/surface/gui/assets/js/`。函数内的回调归在所属函数名下。表中编号只用于定位行为。
- 单次 HTTP / 外部程序的超时、反编译预算、历史保留天数不是周期任务；下表另记录直接创建计时器的等待，以及参与调度和定期整理的到期条件。测试文件、`internal/testkit`、`spikes/`、文档原型和依赖库内部的渲染 / GC 调度不计入。
