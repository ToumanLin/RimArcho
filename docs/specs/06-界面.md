# 06 · 界面

> 状态：2026-10-21 重写。GUI（窗口）和 TUI（终端）两个界面：信息架构、页面、交互规则、详情、视觉和各自的技术实现。方案编辑器、能不能跑、详情、设置、历史区、GUI 的侧栏、顶栏、首页、首次引导已实现；方案页（多个方案）、Mod 库 › 全部、TUI 的页面映射、存档管理、Archo 面板待实现。
> 依据：00（定位、三个问题、原则）、00a（架构）、01（范围）、03（问题与日志）、04（方案与排序）、05（命令）、08（启动与整合包）、09（Archo）、10（没玩到与值得玩）。

设计原则：不让玩家沿着一条复杂路径完成操作，而是让玩家**随时知道自己在哪里、可以去哪里、怎么回去**，并以**最少的步骤**完成任务。“怎么回去”有两层：界面上，每个弹层和二级界面都能用 `esc` 或面包屑回到上一级（§3.1 规则 5）；数据上，每次修改都能在方案的历史里看到并撤回（§2.5 第三栏、04 §3）。

## 1. 分层与共享视图模型

```
surface/tui   (Bubble Tea)        surface/gui   (Wails 服务 + assets/*.html|css|js)
      │  只做：布局、绘制、按键/鼠标映射      │  只做：把 view 模型序列化给前端、事件推送
      └──────────────┬──────────────────────┘
                internal/view     界面无关的视图模型
                     │
                internal/app      业务
```

- TUI 用 Bubble Tea + Bubbles + Lip Gloss；GUI 用 Wails v3 + 原生 HTML/CSS/JavaScript（§8）。GUI 不是把 TUI 渲染进窗口，也不调用 CLI 再解析文字。
- `internal/view` 不依赖 Bubble Tea、Lip Gloss、Wails。输入是 `*app.App` 的状态，输出是普通 Go 结构（可以直接 JSON 化）。

`internal/app` 给界面提供类型化接口：`SetTags` / `SetAlias` / `SetNote`、身份问题回答、日志选择、`ChildScan`（扫描子进程，不弹控制台窗口）、每个 Mod 的 Def / Patch / Harmony 小结。界面不拼 CLI 参数做编辑。`cmds.Execute` 只留给本来就是文字的只读场景：排序 / 写入 / 启动的预览（CLI 的 `--dry-run` 文字）、“查看”类操作和全屏详情的 Def / 补丁 / Harmony 子区，以及玩家自己在命令行输入框里输入的 archo 命令。

规则：
1. 业务规则只能写在 `app` 或 `view` 中。界面层出现“如果是工坊 Mod 就……”这类判断即为缺陷。
2. 两个界面的同一操作调用同一个函数。同一个状态下，TUI 和 GUI 拿到的 `Needs`、`Board`、详情数据完全相同（G1）。
3. 文案只有一份（`view.Text`），GUI 通过一次调用拿到当前语言的整张表。
4. 每个会写磁盘的动作都满足三条：先预览（`--dry-run` 或界面预览），要玩家确认，能撤回或说明为什么不能撤回（01 §4）。

### 2.2 顶栏、状态行、提示行

**GUI 顶栏**（已实现）：收起侧栏按钮 + 面包屑（如“在玩 / 方案 / 主力殖民地”）+ 环境 chip（如“Steam · 1.7”）+ 当前页动作（右侧）。面包屑的每一级都可点击返回。

**TUI 顶栏**（已实现）：品牌 · 当前环境（药丸）· 能不能跑 N · 未写入 N，右侧是位置行（§3.2）和 `L 启动`（空间不够时先去掉它）。进入二级界面时左侧换成面包屑：`RimArcho › 能不能跑`、`RimArcho › 已启用 › Combat Extended`。游戏运行时顶栏显示“游戏运行中”和本次运行的报错数。

两个界面的底部都是：
- **状态行**：一句话。`✓`（绿）完成、`✗`（红）失败、`…`（次要色）进行中。下一次按键时清除。GUI 在状态行左侧显示位置（§3.2），能撤销的结果后面带“撤销”链接。
- **提示行**：当前对象此刻能用的动作，`键 说明 · 键 说明`，最多 7 项，最后一项是 `? 全部按键`。按键用文字色，说明用次要色，分隔点用淡色。`!` 不在提示行上（顶栏或侧栏已经显示数字），但仍然可用，`?` 会列出它。

“未写入 N”：方案的编辑即时持久化（04 §1），不存在“未保存”。这个数字和行上的 `●` 表示“与上次写入游戏的列表不同、启动或写入游戏时才会写进去”的条目数，只是提示，不阻止启动（08 §2）。界面文字现在还是“需要处理 N · 未保存 N”，改名**待实现**。

### 2.5 方案编辑器

方案页就是编辑器。已实现，包括多个方案（暂存和历史挂在方案上，04 §1、§2.2、§3）。新建（空、复制当前、复制某个版本、导入）、改名（输入时检查重名）、删除（确认，不能删最后一个）在方案页的“⋯”菜单、侧栏右键、`P` 和命令面板里。状态栏显示“游戏里现在是：<方案> v<n>”；有未载入的外部版本时，侧栏条目、方案页和首页那一行带标记。窄于 1100 像素时，顶栏的撤销、编译成整合包和按键提示收起。

**右上动作**：撤销 · 自动排序 · 编译成整合包 · 写入游戏，旁边是启动。
- 撤销 = `u`；自动排序 = `S`（先显示差异，确认后生效）；编译成整合包 = 去子页（§2.6）；写入游戏 = `w`（写 ModsConfig.xml 但不启动，给从 Steam 等其他途径开游戏的玩家，08 §2）；启动 = `L`（写入并启动，08 §2）。
- 写入游戏前显示确认：差异和版本改写说明（04 §4.1）。启动前显示预览：会写入什么、会建删哪些链接（`view.DryRun("launch")`）。
- 导入、导出列表（04 §9）放在动作菜单和命令面板里（`i` / `e`，见 §3.5）。

**暂存**（规则见 04 §2.2）：持久保存、不写入游戏的列表。两种用途：
- **准备区**：新订阅的 Mod 先放进来，想好了再启用；
- **排查区**：把一批 Mod 从“已启用”移到暂存来排查问题，排查完一键放回原位置。
- 每个从“已启用”放进暂存的 Mod 记住原位置和一个锚点：它前面的那个 Mod。锚点越过在它之前、已经被暂存的 Mod 向前移，所以分批暂存的顺序不影响放回。放回时沿着仍在暂存里的 Mod 追溯锚点链，找不到时用原位置。
- `add` 和 `restore` 各是一步撤销。被暂存的 Mod 以任何方式重新启用（撤销、启用、载入版本）都会离开暂存。暂存列表本身不进撤销栈。
- 命令：`archo stage list|add|drop|restore`（05 §4）。每个方案一份（meta 表的 `stage:<方案 ID>`）。
- 放回：`T`（全部放回原位置）、在暂存区按 `t` 或 `space`（放回这一个）。

**历史**（第三栏下方；暂存为空时占满第三栏）：
- **这次的修改**：撤销栈的每一步，最新在上，一行一步（“启用 Harmony · 第 2 位”）。步骤文字由前后两份列表算出（`view.StepText`）。光标指向“现在”；重做的步骤在“现在”上方淡色显示。`u` / `ctrl+r` 让“现在”上下移动；点一步（TUI：光标移到这一步按 `enter`）立即回到那一步，之后仍可 `u` / `ctrl+r`。
- **版本**：方案的版本列表（写入游戏、启动、外部修改、导入等，标注来源，04 §3）。选中显示与当前列表的差异，确认后载入（`loadout checkout`；GUI 用确认对话框，TUI 按两次 `enter`）。载入前的列表留在历史里，`u` 可以拿回来。
- GUI：暂存有内容时，历史折叠成暂存下方的一条“▸ 历史 · N 步”，点开展开。TUI：暂存有内容、或暂存区在搜索时不显示历史。
- 焦点在第 3 区且显示历史时，`↑↓` `g` `G` `Home` `End` 在历史里移动，`enter` 去那一步。

**列宽与换行**：
- 三个列表区的宽度可以调整。TUI：`<` `>` 缩小 / 放大聚焦区，每次 2 格；`=` 恢复默认宽度（不改换行设置）。GUI：拖动区之间的分隔线，双击分隔线恢复默认。

## 3. 交互规则

本章的规则对方案编辑器完整成立，其他页面按同样的原则（方向键只导航、动作是按钮或动词键、`esc` 回上一级）。GUI 和 TUI 的键盘按键相同，例外在 §8.5 和 §9.1 写明。

### 3.1 五条规则

1. **方向键只导航，永不改动数据。** 在任何状态下，`↑↓←→` 都只移动光标、焦点或滚动位置，不移动 Mod、不启用、不打标签。GUI 中单击和滚轮同样不改数据。
2. **动作是动词键，立即生效，`u` 撤销。** 动作作用于“对象”：有选中时是选中的实例，否则是光标所在行。动作不进入任何模式，没有“放下 / 取消”这一步。每个动词是一次 app 编辑，所以是一步撤销。
3. **位置始终可见。** 位置行随时说明：焦点在哪个区域、光标是第几个、选中了几个、当前打开了什么弹层（§3.2）。
4. **可去哪里始终可见。** 提示行只列出当前对象此刻能用的动作（最多 7 个），`?` 列出全部，`ctrl+k` 可以从任何地方去任何地方。
5. **弹层最少。** 只有命令面板、标签候选行、位置输入、确认、帮助五种。每个弹层都有标题并显示在位置行中，`esc` 关闭，不嵌套。另外两个输入框给进阶使用：`:` 命令行和 `r` 规则输入，只在 `?` 中列出。

**基态**：当前页、无选择、无弹层（方案编辑器里还要求聚焦的列表没有搜索）。任何状态下最多按 3 次 `esc` 回到基态（T20、G5）：
- `esc` 先关弹层，再清除搜索和选择；
- 在二级界面（全屏详情、技术页、能不能跑某项的展开视图、TUI 的整合包 / 设置文本）里 `esc` 回到打开它的页面；技术页里 `esc` 关闭整叠技术页（`backspace` 才是退一页），所以从任何深度都满足 3 次；
- `esc` 不在侧栏页面之间后退：页面是平级的，换页用侧栏、面包屑或 `ctrl+k`。

### 3.2 位置

方案编辑器有四个焦点区：`1` 未启用、`2` 已启用、`3` 暂存 / 历史、`4` 详情。数字键直接跳到对应区；区标题前显示这个数字（淡色）。

- 聚焦区：标题用强调色，光标所在行加一层很淡的整行底色（TUI `#1A1C24`）。非聚焦区的光标只把名称变成文字色，不加底色，不显示 `▸`。焦点在详情时，列表都画成非聚焦，所以屏幕上永远只有一处“最亮的地方”。
- 详情区有标题行 `4 详情`（滚动后变成 `▲ 名称`），焦点在详情时用强调色；内容从下一行开始，和列表第一行对齐。
- 位置行（TUI 在顶栏右侧，GUI 在状态行左侧）：
  - 列表区：`已启用 · 322 / 488 · 已选 3`。位置按可见（搜索后）的行数计算，有搜索时加 `已筛选`。
  - 详情区：`详情 · Combat Extended · 简介 40%`。小节取当前顶行上方的小标题（概要、简介、历史、技术信息）加上滚动了多少。
  - 弹层打开时在后面追加，例如：`已启用 · 322 / 488 › 标签`。搜索显示为 `› 搜索`，等待第二次按键的确认显示为 `› 确认`。
  - 全屏详情：`已启用 › Combat Extended（322 / 488）› Harmony`。
  - 其他页面（全屏、技术页、能不能跑、变化）：位置行就是面包屑。

### 3.3 方向键

| 状态 | `↑↓` | `←→` |
| --- | --- | --- |
| 列表区 | 移动光标 | 切换焦点区 |
| 详情区 | 滚动详情 | 切换焦点区 |
| 全屏详情 | 滚动内容 | 上一个 / 下一个 Mod（仍是导航） |
| 弹层（面板、标签行、位置输入） | 在弹层的选项中移动 | 在弹层的选项中移动 |

- `PgUp` / `PgDn` 和鼠标滚轮在任何区域都滚动详情，不改变焦点，所以读简介不需要先切到详情区。滚轮在指针所在的任何位置都滚动详情，不移动列表光标；列表用按键或单击滚动。
- `←` 从详情回到它所显示 Mod 所在的列表（不是第 3 区）：130 列宽时暂存不在屏幕上，而从“已启用”过来时第 3 区会显示另一个 Mod。从暂存（第 3 区）按 `→` 仍到第 4 区。`←→` 不循环。`tab` / `shift+tab` 在所有区（含详情）之间循环。
- `j` `k` 等于 `↓` `↑`，`h` `l` 等于 `←` `→`（TUI）。`Home` / `End`（TUI 也可 `g` / `G`）到列表首尾。
- 详情中简介默认只显示前 12 行；一旦详情被滚动（任何地方按 `PgDn`）或聚焦，就显示全文，所以 `PgDn` `PgDn` 能读完。详情还没加载时按的 `PgDn` 会保留到加载完成。

### 3.4 选择

- `shift+↑↓`：从光标处扩展连续选择。
- `ctrl+space`（TUI 也可 `v`）：切换光标所在行的选中状态。普通的 `↑↓` 和 `ctrl+↑↓` **不会**清除选择，所以“移动光标 → `ctrl+space`”就能间断多选。
- 鼠标：单击移动光标，`shift+单击` 范围选择，`ctrl+单击` 切换选中。在同一个列表里单击保留选择（和 `↑↓` 一样只移动光标）；单击另一个列表会清除选择。
- `esc`：清除选择。切换到另一个列表区时选择也会清除，提示行事先说明：`←→ 换列表会取消选择`。
- 选中的行行首有强调色的 `▌`。有选中时，提示行变为：`已选 3 · space 停用 · t 暂存 · m 移动 · # 标签 · esc 取消选择`。这只是提示行，不是悬浮窗，也不是模式。
- 动作之后：`#` 保留选择（可以再按 `#`）；`space`、`t` 清除选择（行离开了这个列表）；`J` / `K` 和在“已启用”内的 `m` 保留选择。

**命令面板**（`ctrl+k`）：
- 样式同 magpie 的筛选选择器：顶部 `❯` 输入行，下面是结果列表。
- 内容：所有命令（中文名加英文别名，例如“自动排序 sort”；`view.Commands`，现在 24 个）、所有 Mod（直接跳转）、其他环境（切换）。侧栏的每个页面和每个方案作为“去 …”命令加入（**待实现**）。
- 打分：前缀 4 > 子串 3 > 子序列 2 > 说明文字 1（说明里写着按键，所以按按键也能找到）。同分时命令在前，其次是 Mod，然后是环境，再其次是较短的名称。输入为空时只列命令和其他环境。
- 按键：输入即筛选；`↑↓`（或 `tab`、`ctrl+n` / `ctrl+p`）选择；`enter` 执行；`esc` 或再按 `ctrl+k` 关闭；`ctrl+u` 清空输入。
- 选中 Mod 后跳到它所在的列并选中它；那一列的搜索把它隐藏时，清除搜索。

### 3.6 位置输入（`m`）

```
 移动 3 个到 ❯ harm▌
   之后  Harmony                       （第 1 位）
   之后  Harmony Patches for VFE        （第 212 位）
   第 352 位（建议位置）
   最前 · 最后
```

- 输入数字表示“移到第 N 位”；输入 Mod 名，模糊匹配后最多显示 5 个候选（排序：前缀、子串、字母顺序），默认是“放在它之后”，`tab` 切换为“放在它之前”并保持选中的行。
- 不输入、直接 `enter`，就移到建议位置。建议位置（`App.SuggestAt`）用排序器的约束边：紧跟在必须排在它前面的最后一个已启用 Mod 之后；只有“排在之前”的约束时，放在其中第一个 Mod 之前；没有约束时放末尾；官方内容优先这条边忽略。对已经启用的 Mod，先把它们从列表里拿出来再算，所以 `m` 也能为移动建议位置。
- 选项是一个列表，每项一行，只有 `最前 · 最后` 共用一行；两对方向键都能在选项间移动。位置按“去掉要移动的 Mod 之后”的列表计数（`MoveBlock` 和 `Enable` 用的就是它）；名字旁的“（第 N 位）”是那个 Mod 现在的序号。
- 对象在“未启用”或“暂存”中时，`m` 等于“启用并放到所选位置”；从暂存移多个时启用并移出暂存，是一步撤销。
- 输入框位于列表下方，占用列表的最后几行，所以缩略图不会盖住它。数据：`view.PosOptions`、`view.Place`。

### 3.7 搜索（`/`）

- 筛选聚焦的列表区，结果即时显示；`enter` 结束输入，筛选保留在这一列，直到在这一列按 `esc` 清除。列标题显示 `已启用 12/485`，后面是淡色的查询文本。GUI 每列标题下有搜索框。
- 输入时状态行显示 `其他区：未启用 2 · 暂存 0 · tab 跳到下一个匹配的区`（是状态行，不是列标题下多一行，否则每行都要下移），所以不用先想“它在哪一列”。
- 输入时按 `tab`：把查询移到右边下一个有匹配的列表（循环），光标放在第一个匹配上，并结束输入（这样 `/` 名字 `tab` `space` 只要 3 键，否则 `space` 会输入空格）。离开的列表清除查询。

查询由空格分隔的词组成，全部词都要满足（AND）：

| 写法 | 含义 |
| --- | --- |
| `词` | 名称、别名或作者包含它（不分大小写）；整个查询都没有结果时，自由词再按名称的字母顺序匹配（`hsl` 找到 “Hair Style Lib”） |
| `name:词` / `author:词` / `tag:词` | 只看名称（含别名）/ 作者 / 标签；`tag:` 要求标签等于这个词 |
| `id:值` | 包名包含它、工坊 ID 等于它，或者是 `#引用` |
| `type:值` | 来源 `official` `workshop` `local` `copy` `git` `steamcmd`；内容 `assembly`（带 DLL）、`xml`（没有 DLL，也可写 `xml-only`）、`language`（只有语言文件，也可写 `language-pack`） |
| `has:problem` / `has:error` | 有能不能跑的可操作项 / 有会导致加载失败的问题；还有 `has:tag` `has:note` `has:alias` |
| `-词`、`-tag:x` | 取反 |
| `"带 空格"` | 引号内是一个词 |

内容类型（`type:assembly` 等）来自对当前快照文件列表的一次 GROUP BY，在第一次用到时加载，数据库变化前一直保留（`view.ContentCache`）。

### 3.8 标签

- 详情中显示 Mod 的标签；列表中名称后面用淡色显示标签。
- 标签属于 Mod 的 Lineage（04 §8），对应 CLI `tag add|remove <引用> <标签…> --mod <引用>…`、MCP `set_player_data`。
- 标签不进撤销：它是玩家数据，不是列表编辑，`u` 不撤销它，GUI 状态行也不给标签修改显示“撤销”。

`#` 在提示行（或详情）下方打开一行候选，不是输入框：

```
 ✎ 输入…   [框架]  [美化]  [服装]  [种族]  [武器]  [建筑]  [QoL]  [测试中] …
           ▲ 初始选中第一个候选
```

- `←→`（或 `↑↓`）移动选择；`enter` 应用；`esc` 关闭。`enter` 后候选行关闭，选择保留，可以再按 `#`。
- 第一个候选左边是“✎ 输入…”：从第一个候选按 `←` 就到达它，此时可以直接打字，`enter` 创建并应用新标签。在任何候选上直接打字也会跳到输入处。
- 已经挂在**全部**对象上的标签显示为 `[✓框架]`，`enter` 把它从这些对象上移除；只挂在部分对象上的显示为 `[~框架]`，`enter` 补齐到全部。
- 候选顺序：常用标签（`archo config set tags.pinned "框架,美化,…"`，`,` 和 `，` 都可分隔）在前，然后按使用次数排序的已有标签。放不下时向右滚动。数据：`view.TagCandidates`、`view.PinnedTags`。
- 预置常用标签是 `tags.pinned` 的默认值（不在首次运行时写进数据库，`config get` 能看到，`config set` 整体替换）：框架、美化、服装、种族、武器、建筑、家具、QoL、平衡、剧情、性能、语言包、测试中、待删除。
- 没有选择时，候选行代替状态行。

### 4.3 简介来源与渲染

**测量**（2026-10-19，玩家环境，1274 个有 About.xml 的工坊 Mod，只读；工坊描述用 Steam 公开接口 `ISteamRemoteStorage/GetPublishedFileDetails/v1`，无需 key，13 次批量请求取回 1264 个）。按去掉 BBCode 和图片后的纯文本长度：

| 长度 | About.xml | 工坊页面 |
| --- | --- | --- |
| 空 | 25 | 1 |
| 1–79 字 | 355 | 19 |
| 80–299 | 376 | 108 |
| 300–999 | 276 | 345 |
| ≥ 1000 | 242 | 791 |

- About.xml 为空或不到 80 字的占 30%（380 个）；其中 305 个的工坊页面有 300 字以上。两边都只有一两句、也没有图片的只有 18 个。工坊描述 300 字以上的占 90%，About.xml 只占 41%。
- 504 个 Mod 的两边开头是同一段文字（作者复制了一份）。只有 5 个用了 `descriptionsByVersion`。
- 工坊描述 55%（696 个）带图片，共 7981 张；139 个以图片为主（≥ 3 张、每张不到 100 字的文字）。几乎全是图文混排：文字不到 80 字、只有图片的只有 1 个。
- 图片格式：PNG 7351、GIF 323、无扩展名 244、JPEG 55、WebP 6。图床：i.imgur.com 72%，其次 raw.githubusercontent.com、img.litet.net、i.postimg.cc、Steam 自己的 images.steamusercontent.com。
- 出现最多的 BBCode：`img` `*`（列表项）`url` `b` `h1` `list` `h2` `td` `h3` `i` `tr` `hr` `th` `u` `table` `code` `nl` `strike` `olist` `quote`。

**规则：**

1. **来源。** About.xml 的 `description`（若有当前游戏版本的 `descriptionsByVersion` 条目则用它）随时可读，从磁盘按需读取，不存进数据库。工坊页面描述在线获取。
2. **选哪个。** 有工坊描述时：About.xml 不到 300 字，或者两边开头相同（忽略图片），只显示工坊描述（标题“简介 · 工坊页面”）；两边都长且不同，先显示 About.xml，再显示工坊描述（两个小标题）。没有工坊描述（本地 Mod、离线、获取失败）时显示 About.xml，并在小标题后淡色注明原因（`view.DescNote`）。
3. **何时获取。** 只为选中的 Mod 按需获取：光标在一个工坊 Mod 上停留 400 毫秒后，在后台发一次单个 ID 的请求，不预取整个列表。结果缓存在 `<数据目录>/cache/workshop/<工坊 ID>.json`。缓存里的 `time_updated` 不早于本地 appworkshop 清单中的 `timeupdated` 时视为最新，不再联网；没有清单时间时，缓存 7 天有效。全屏详情里按 `r` 强制刷新。
4. **离线开关。** `archo config set workshop.fetch on|off`（默认 on）；`workshop.images on|off`（默认 on）单独关闭图片下载。关闭后只用缓存和 About.xml。联网只访问 Steam 的这个公开接口，以及工坊描述里出现的图片地址。请求带 RimArcho 的 User-Agent。
5. **BBCode 渲染**（按显示宽度换行，遵守 §7 的原则）：`h1`–`h3` 粗体文字色并前后空一行；`b` 粗体；`i` `u` 照常显示（不用斜体和下划线）；`strike` 淡色；`list` / `olist` 用 `•` 和序号、按层级缩进两格；`url` 显示链接文字，WezTerm 中用 OSC 8 做成可点击，兼容模式在文字后面淡色显示域名；`quote` `code` 缩进两格、次要色；`table` 按列对齐、放不下的列截断；`hr` 变成空行；`nl` 换行；`noparse` 原样；未知标签去掉、保留内容。GUI 由 Go 端解析成块结构，前端渲染为标题、列表、表格、引用、代码、链接、图片元素（§8.3）。
6. **图片里的文字（OCR）**：界面不做。用视觉模型识别，放在 Archo 的任务里（09 §5）。

### 4.4 图片

- **缩略图来源**：Mod 的 `About/Preview.png`（文件名大小写不敏感；内容是 JPEG 也接受）。缩放到宽 360 像素（不放大）的 PNG，按快照哈希缓存为 `<数据目录>/cache/previews/<快照哈希>.png`。只读 Mod 目录。
- **描述图片**：在需要时才下载；解码、缩放到 720 像素宽后缓存为 PNG（`<数据目录>/cache/workshop-img/`）。`imgur.com/x.png` 这样的链接直接改成 `i.imgur.com`。GIF 只显示第一帧；WebP 和解码失败的显示占位。
- **简略详情不内嵌描述图片**：只显示缩略图和文字，描述中的图片在第一张图片的位置合成一行淡色占位 `[图片 ×3 · enter 在全屏中查看]`（TUI 兼容模式下是 `[图片 ×3]`）。描述图片只在全屏详情中显示；全屏详情在兼容模式下逐张列成文字占位 `[图片 · i.imgur.com]`。
- `ui.previews off` 整体关闭界面里的图片；`workshop.images off` 只关闭描述图片的下载。
- GUI 直接用 `<img>` 显示、按比例缩放，描述图片 `loading="lazy"`，进入可视区域时才请求；图片只经 `/img/` 处理器从本地缓存读出（§8.3）。TUI 的绘制规则见 §9.4。
- 图片画廊、大图浏览等功能只在 GUI 做：终端图片协议有先天限制（ConPTY 的光标问题、按整格对齐、无法部分裁剪），TUI 的图片只是锦上添花。

## 5. 能不能跑的写法

**每一项**由问题集合和环境的待确认项生成：分组、一句由 Mod 名组成的话、作用于它的动作（`view.Action`）、是否计数。问题代码、`#引用`、`pkg:`、`p:` 等 CLI 引用形式从不出现在页面上，它们只在技术信息、CLI 和 MCP 里。

| 内部代码 | 玩家看到的 | 一键操作（TUI 键） | 分组 |
| --- | --- | --- | --- |
| `official.order` | Core 和 DLC 要排在最前面 | `S` 自动排序 | 会让游戏出错 |
| `order.violated` | 只有一条时：A 应该排在 B 之后；多条时合并成一项：10 个 Mod 的顺序不对（数的是需要挪动的 Mod），`enter` 展开逐条列出 | `S` 自动排序 | 会让游戏出错 |
| `order.cycle` | 3 个 Mod 的顺序要求互相矛盾 | `enter` 用人话查看各条要求，`x` 忽略建议的那一条（加忽略规则，这一项消失） | 会让游戏出错 |
| `pkg.duplicate-active` | 同一个 Mod 启用了两份 | `space` 选择保留哪一份 | 会让游戏出错 |
| `entry.missing` | 列表里有 X，但没有安装它 | `o` 在工坊搜索（订阅在 1.2）、`space` 从列表中移除 | 会让游戏出错 |
| `mod.unloadable` | A 已启用，但游戏无法加载它 | `space` 停用 | 会让游戏出错 |
| `mod.replaced`（社区数据 replacements） | A 有维护中的替代品：B | B 已安装：`space` 启用 B、停用 A；未安装：`o` 在工坊打开 B | 会让游戏出错 |
| `version.unsupported`（汇总） | 293 个 Mod 没有标明支持 1.7（其中 288 个支持 1.6） | `enter` 查看列表 | 会让游戏出错 |
| 列表为旧版本写入 | 列表是为 1.5 写的，游戏启动时会重置它，写入一次就好 | `w` 写入游戏 | 会让游戏出错 |
| `dep.missing` | A 需要 B，但没有安装 B | `o` 在工坊打开 B（声明的 URL，否则工坊搜索） | 会让游戏出错 |
| `dep.inactive` | A 需要 B，但 B 没有启用 | `space` 启用 B | 会让游戏出错 |
| `patch.no-match`（目标未启用） | A 的部分内容没有生效（它针对的 B 没有启用） | `space` 启用 B，或 `enter` 查看 | 会让游戏出错 |
| `def.parent-missing` | A 的部分内容继承的定义不存在，可能缺少前置 Mod | `enter` 查看 | 会让游戏出错 |
| `incompat.active` | A 与 B 不兼容 | `space` 选择停用哪一个 | 会让游戏出错 |
| `log.*` | 上次运行时 A 报了 12 次错 | `enter` 查看日志与证据（技术页） | 上次运行的报错 |
| 实时日志 | 本次运行中 A 报错（新的在前） | `enter` 查看 | 上次运行的报错 · 本次运行 |
| 身份待确认 | X 和 Y 是同一个 Mod 吗？ | `s` / `c` / `u` 回答（两次确认） | 要你确认 |
| ModsConfig.xml 外部修改冲突 | ModsConfig.xml 在 RimArcho 之外被改了，而这个方案之后也改过 | 看差异 / `L` 载入（两次确认，会替换这个方案现在的列表）/ `I` 忽略 | 要你确认 |
| `mod.pinned`（上游有更新） | A 锁定了版本，工坊那份之后更新过 | 查看差异（`mod <工坊实例> --diff <副本>`）、更新锁定版本（`pin --update`）、解除锁定（`unpin`，确认） | 隐藏的 Mod |
| `mod.hidden-residue` | A 被隐藏、已经退订，文件夹还留着 | 移到回收站（`trash`，确认） | 隐藏的 Mod |
| `mod.hidden` | A 被隐藏了（大概是别的 Mod 管理器做的） | 保持隐藏（忽略问题）、恢复（`unhide`，确认）、移到回收站（确认） | 隐藏的 Mod |

- 动作类型（`view.Action.Kind`）：`sort`、`save`、`enable`、`disable`、`choose-disable`（从选项中选一个停用）、`open-url`、`view`（只读命令文字）、`list`（显示标题和行）、`fold`（展开 / 收起合并项）、`ignore-rule`、`load-external`、`dismiss-conflict`、`answer`、`unhide`、`unpin`、`trash`、`ignore`。`Action.Key` 是 TUI 的键，GUI 显示为按钮，按钮文字就是动作（“启用 B”“自动排序”“在工坊打开”）。
- `patch.no-match` 只有在它针对的 Mod 已安装但未启用时（target-inactive）才出现；目标根本不存在、版本路由错误等情况玩家无法处理，留在技术信息。`def.abstract-collision` 同样只在技术信息里。
- `version.unsupported` 只有在其中有 Mod 连上一个版本都不支持（warning）时才出现；全部只是支持上一版本时按 info 处理，不出现。
- **合并规则**：同一种问题如果一个键就能全部解决，就合并成一项，`enter` 展开逐条显示；目前只有 `order.violated`（`S` 一次排好）。缺失的列表条目、未启用的依赖、日志等每条要单独处理，不合并。
- **计数**：角标和顶栏的数字 = 这个页面上可以操作的项数（折叠的旧日志那一行不算），合并后的一项算 1，所以数字反映的是要做几件事，而不是有几条发现。列表行上的状态图标也只标在这些项涉及的 Mod 上。
- **不出现在这里的**：
  - info 级别（Def 覆盖、补丁争用、共享 Harmony 目标等）：只在详情的技术信息里，以及 CLI 和 MCP 中；
  - 没有日志证据的 Harmony 警告：归入技术信息，玩家无法据此行动；
  - 旧日志（不属于当前方案最近一次启动，或来自另一个游戏版本，03 §6.4）：折叠成一行淡色 `更早的日志 · 9 月 29 日 · 1.6`，不计数。

## 6. 确认与反馈

- **预览**：排序、写入游戏、启动先显示预览（`view.DryRun`，CLI 的 `--dry-run` 文字），确认后执行（`view.Apply`）。写入游戏的确认显示差异和版本改写说明（04 §4.1）。
- **不能撤销的动作要确认**。能用 `u` 撤销的操作不需要确认。
  - TUI 用“再按一次”：第一次按在状态行显示 `✗ 再按一次 L 载入，会替换现在的列表`，再按同一个键执行，按其他键取消（“已取消”）。
  - GUI 用确认对话框，对话框显示 `view.Action.Warn`。
  - 目前用于：载入外部修改的 ModsConfig.xml（`L`）、回答身份问题（`s` `c` `u`，合并或拆分 Lineage 不能用 `u` 撤销）、载入历史版本、`unhide`、`unpin`、`trash`、整合包移到回收站、设置页里带确认的命令。
- **回收站和改名**动作（`unhide`、`unpin`、`trash`）先显示预览（`--dry-run`）再确认（08 §6、§7）。
- **结果文字**由界面写成人话（“启用了 Beta”“Harmony 现在是第 3 个”）；命令的错误经过 `view.Humanize`，把实例引用换成 Mod 名。
- **长任务**不阻塞界面，进度在状态行（§8.4）。
- **变化不弹窗**：扫描结果、新的游戏报错只更新状态行和数字。

## 7. 视觉

**原则**（magpie / Linear 式精致极简）：
1. **零边框（TUI）。** 区域之间只用空白、两格缩进、淡色小标题来分隔，不画方框和分割线。GUI 用 magpie 的卡片：一层安静的底面，内容放在带细边框、12px 圆角的卡片上。
2. **一种强调色。** 只有强调色、成功绿、错误红，加上一个用于警告的琥珀色。强调色只给“正在操作的东西”：光标、选中名称、聚焦区的标题、输入提示符。
3. **大部分文字是灰的。** 多数字符是次要色或淡色，只有你要操作的那一项是亮的。
4. **选中是小标记加变色，不是整行色块。** `▸` 加上粗体强调色名称；选择是行首的 `▌`。实心背景只用于“药丸”（当前环境、聚焦的筛选项）和聚焦区光标行的淡底色。
5. **粗体只表示身份**（Mod 名称、标题），不用斜体、下划线和反色。
6. **不显示开发者术语。** 界面上不出现问题代码、`#id`、`decl`、`lineage` 等词，它们只在技术信息和 CLI / MCP 中出现。例外：包名在详情中默认显示。
7. **静止的界面。** TUI 没有动画和转圈；进行中的工作在状态行用 `…` 表示。GUI 只有页面进入和视图切换的短过渡，`prefers-reduced-motion` 时关闭。
8. **TUI 每一行只占一行**，没有行间距。放不下就截断加 `…`，并告诉玩家藏了多少（`还有 12 个`）。详情文字换行（§4.1）。

**TUI 色板**（深色）：

## 8. GUI 技术

### 8.1 交付

同一份源码，链接两次：

| 文件 | 子系统 | 双击 | 用途 |
| --- | --- | --- | --- |
| `archo.exe` | 控制台 | WezTerm 中的 TUI（§9.2） | CLI、`archo mcp`、`archo tui`；`archo gui` 启动 GUI |
| `RimArcho.exe` | Windows GUI（`-H windowsgui`，没有控制台黑框） | GUI | 给玩家双击的入口（可带 `--env <名称>`）；带命令参数时按 CLI 执行，供 GUI 的扫描和分析子进程使用 |

- 两个 exe 共用数据目录和数据库，可以同时打开（SQLite WAL 支持多进程）。GUI 窗口获得焦点时比较 `Stamp()`（数据库状态，`ChangeKey`），变了就重新加载；在旧视图上的编辑不覆盖对方的修改（G8）。
- `archo gui`：同目录下有 `RimArcho.exe` 就启动它并立即返回；没有就在当前进程中运行 GUI。
- 发布包含两个 exe（体积见 07 §6）。

### 8.2 前端

- Wails `v3.0.0-beta.28`（v3 仍是 beta，锁定这个版本，升级单独验证）。不需要 CGO（`CGO_ENABLED=0`）。
- 纯 HTML + CSS + 原生 JavaScript（ES modules）。**不用框架、不用 npm、没有构建步骤**。文件放在 `internal/surface/gui/assets/`（`index.html`、`style.css`、`js/` 下 `api.js` `state.js` `lists.js` `detail.js` `screens.js` `popups.js` `exchange.js` `icons.js` `shell.js` `home.js` `guide.js` `main.js`），用 `go:embed` 打进 exe。
- 调用 Go：手写的 `api.js` 用 `import { Call } from "/wails/runtime.js"` 和 `Call.ByName`，用 `Proxy` 拼出方法全名 `github.com/ToumanLin/RimArcho/internal/surface/gui.API.<方法>`。不使用 `wails3` 生成的绑定，构建只需要 `go build`。
- `internal/surface/gui`：`api.go`（Wails 服务，每个方法只调用 view）、`gui.go`（窗口、`/preview/`、`/img/` 本地图片处理器、CSP、图标路由）、`exchange.go`（导入导出对话框）、`text.go`。
- Go → 前端：Wails 事件（`scan` 扫描结束、`analyze` 分析进度与结束、`pack` 编译进度）。游戏运行状态由前端每 2 秒调用 `Live` 轮询。
- 列表虚拟滚动：只创建可见行。
- 样式表首行 `[hidden]{display:none !important}`：弹层容器的 `display:flex` 会盖过 `hidden` 属性，形成一层看不见的遮罩吃掉所有点击。
- WebView2 用户数据放在 `<数据目录>/webview2`，不放 `%APPDATA%\RimArcho.exe`。
- `spikes/guidev`：开发用，在 127.0.0.1 上用同一个 API 驱动页面，便于在浏览器里调试；不进发布包。

### 8.3 安全

- 页面的 Content-Security-Policy：`default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'`。`script-src 'self'` 下 Wails 运行时正常工作，不需要 `unsafe-eval`。
- 工坊简介和图片都是外部内容：简介由 Go 端解析成 BBCode 块结构后传给前端，前端用 `textContent` 和元素构建，**从不把外部文字当 HTML 插入**；图片只经过 `/img/` 处理器从本地缓存读出，不直接加载远程地址。
- 链接用系统浏览器打开；`OpenURL` 拒绝非 http(s) 链接。
- Wails 在 Windows 上用 WebView2 的资源拦截，不开任何 TCP 端口。
- 设置页只运行 `view.SettingCommand` 允许的命令（§2.14）。

### 8.4 长任务

- 扫描和分析在子进程中运行（`archo scan`、`archo analyze`，`app.ChildScan` / `ChildAnalyze`，子进程带 `CREATE_NO_WINDOW`）。进度通过事件推到状态行，界面不阻塞。TUI 同样如此（`:` 里输入 `scan` 也交给子进程）。
- 启动时：有索引就立即显示列表，然后在后台增量扫描；从没扫描过时自动开始扫描。
- 整合包编译在后台进行，进度推到编译页，可以停止（§2.6）。

### 8.5 鼠标

方案编辑器里的鼠标操作是动词的另一种触发方式：

| 操作 | 键盘 | 鼠标 |
| --- | --- | --- |
| 移动光标 / 切换区 | `↑↓` / `←→`、`1`–`4` | 单击 |
| 选择 | `shift+↑↓`、`ctrl+space`、`esc` 清除 | `shift+单击` 范围、`ctrl+单击` 切换 |
| 启用 / 停用 | `space` | 双击；拖到另一列 |
| 暂存 / 放回 | `t` | 拖到暂存列 / 拖出 |
| 调整顺序 | `J` `K`、`m` 位置输入 | 在“已启用”内拖动；落点线旁显示“第 N 位” |
| 标签 | `#` | 右键菜单 › 标签 |
| 撤销 / 重做 | `u` / `ctrl+r`、`ctrl+z` / `ctrl+y` | 状态行里的“撤销”链接 |
| 排序 / 写入 / 启动 | `S` / `w` / `L` | 右上按钮 |
| 搜索 | `/`、`ctrl+f` | 每列标题下的搜索框 |

- **拖放规则**：从“未启用”或暂存拖到“已启用”的某一行上 = 放到那一行的序号；拖到最后一行下方 = 放到末尾；在“已启用”内拖 = 移动；拖到暂存 = 暂存；“已启用”拖到“未启用” = 停用；暂存拖到“未启用” = 移出暂存、不启用（`view.Unstage`）。按下和松开在同一行是单击。拖动中状态行说出落点；拖动中按 `esc` 取消。松手即生效，可以 `u` 撤销。
- **右键菜单**列出当前对象此刻能用的动作，和提示行是同一份数据。
- 方向键、滚轮、单击永不改动数据（§3.1 规则 1）。只有双击、拖放、按钮和动词键会改动数据。
- TUI 的鼠标：单击移动光标、`ctrl+单击` 加选、`shift+单击` 范围选择、拖动列之间的空白调整列宽、单击详情区聚焦、滚轮滚动详情。TUI 不做拖动移 Mod 和框选。

### 8.6 图标与 Windows 资源

- **图形**：`internal/icon/portrait.svg`（80×80，矢量），放在圆角深色底（`#1B1D23`，圆角半径为边长的 0.22）上。48px 及以上显示整幅；40px 及以下只显示脸部（视框 x 20–64、y 24–68），任务栏上仍能认出。渲染用 `internal/icon/svgr.go` 的小型 SVG 渲染器（路径、圆、椭圆、填充、描边、线性渐变、不透明度），不加依赖。
- **不提交二进制**：仓库公开，不放二进制。`icon.PNG(size)` 抗锯齿光栅化（每像素超采样），供窗口图标和资源使用；`icon.SVG(size)` 是同一构图的矢量版，页面的 favicon 用 `/icon.svg`（256）和 `/icon-small.svg`（16），由它生成。

- **没有资源时**（开发构建、`spikes/guidev`），窗口用 `application.Options.Icon` 的 PNG（256 px）作后备。

### 9.2 WezTerm 宿主

图标和缩略图都依赖终端能力，而玩家的终端五花八门（例如 Windows Terminal 默认字体 Cascadia Mono 没有 Nerd Font 图标）。因此 RimArcho 自带一个受控的显示环境。

**启动流程**（`internal/host`）。只有不带参数的 `archo` 会走到这里；`archo tui`、`archo --here`（强制在当前终端运行）、CLI 子命令和 `archo mcp` 从不触发（`wantsHost`）。检查顺序：

```
双击 archo.exe（或在任意终端里运行 archo）
  ├─ 已经运行在 WezTerm 中（TERM_PROGRAM=WezTerm）→ 在这里运行，完整模式
  ├─ terminal.host none → 在这里运行
  ├─ 找到了 WezTerm：PATH 中的 wezterm-gui，然后 %ProgramW6432% / %ProgramFiles% / %LOCALAPPDATA%\Programs 下的 WezTerm\，然后 <数据目录>/wezterm/
  │    → 写 <数据目录>/wezterm.lua，启动 wezterm-gui --config-file <数据目录>/wezterm.lua start -- archo tui [--env x]，本进程退出
  │      （--config-file 是全局参数，必须写在 start 之前）
  └─ 没找到，且有控制台可问 → 询问：
       “下载 WezTerm 便携版（约 66 MB）以显示图标和 Mod 预览图？[Y/n]”
       Y：下载、校验、解压到 <数据目录>/wezterm/，设 terminal.host wezterm，然后按上一行启动
       n：设 terminal.host none，在当前终端以兼容模式运行，并说明怎么改
```

- 下载只在玩家同意后进行，不静默下载。`archo config set terminal.host auto|wezterm|none`：auto（默认）表示还没问过，没找到 WezTerm 时询问一次；none 以后在当前终端运行；wezterm 表示总是用宿主。
- 下载来源：WezTerm 官方 GitHub Releases 的最新稳定版（`/repos/wezterm/wezterm/releases/latest`），取 `WezTerm-windows-*.zip` 和同名 `.sha256`。边下载到 `.part` 文件边计算哈希，校验不符则不解压、不启动，回到当前终端。解压前检查每个条目都在 `<数据目录>/wezterm/` 之内，有一个越界就整体拒绝。
- 没有控制台可问时（输出被重定向、管道），不询问，直接在当前终端运行。
- 任何失败（下载、校验、启动）都说明原因，然后在当前终端运行 TUI。

**wezterm.lua**（`internal/wezterm` 生成，每次启动重写，手改会丢失）：

| 项 | 设置 |
| --- | --- |
| 字体 | **随 RimArcho 自带** Maple Mono NF CN（Regular、Bold；SIL OFL 1.1，许可证文件一并分发），放在 `<程序目录>/fonts/`，通过 `font_dirs` 加载，不安装到系统。它同时包含 Nerd Font 图标和中文字形，所以图标、中英文的宽度和风格完全受控。回退顺序为 Symbols Nerd Font Mono（WezTerm 内置）、Cascadia Mono、Segoe UI Symbol；不能设 `font_locator = 'ConfigDirsOnly'`，否则 Maple 没有的字形（如 `⬥`、`⇣`）会显示成方框。字号 11 |
| 配色 | 与 §7 色板一致的深色方案：前景 `#E6E6E6`、背景 `#0E0F12`、光标 `#A5B4FC`、选区 `#2C2E4A` |
| 窗口 | 无标签栏、无滚动条，标题为 “RimArcho”，初始 160×46，内边距左右 8、上下 6 |
| 图片 | iTerm2 内联图片协议（WezTerm 原生支持）；关闭 kitty 图形协议 |
| 宽度 | `treat_east_asian_ambiguous_width_as_wide = false`，`unicode_version = 14`，与 RimArcho 的宽度计算一致 |
| 退出 | `exit_behavior = 'CloseOnCleanExit'`：archo 正常退出时关窗；出错退出时保留窗口，错误信息可读 |
| 内存 | `front_end = 'OpenGL'`（WebGpu 内存高得多，以后的 WezTerm 可能把它设为默认，所以固定）；`line_state_cache_size`、`line_quad_cache_size`、`line_to_ele_shape_cache_size` 都降到 128（默认 1024，浏览 Mod 会显示大量不同的行，大多是 CJK，每行都被缓存；128 仍能容纳最大化窗口的行，CPU 不变）；`glyph_cache_image_cache_size = 16`（图片由 archo 自己的 LRU 保存）；`scrollback_lines = 0`（TUI 在备用屏幕上运行） |
| 其他 | 关闭响铃、关闭字体连字（`harfbuzz_features = { 'calt=0', 'clig=0', 'liga=0' }`）、关闭更新检查和更新窗口、关闭配置热加载、关闭窗口时不确认 |

- WezTerm 是独立进程，有自己的 GPU 和内存开销（实测见 07 §6）。§10 的 archo 目标只约束 archo 进程本身。
- WezTerm 在 Windows 上总会在 `%USERPROFILE%\.local\share\wezterm\` 写 GUI 套接字和日志，这个位置不能通过配置改变；README 和卸载说明要提到它。
- 脚本驱动 WezTerm 时注意：`WEZTERM_UNIX_SOCKET` 为空时，`wezterm cli` 会退回默认套接字，可能是玩家自己的窗口。测量脚本找不到自己的 `gui-sock-<pid>` 时必须停止。

**自带字体的打包**：`scripts/release.ps1 -MapleTag v7.9`（固定版本）从 github.com/subframe7536/maple-font 的发布页下载 `MapleMono-NF-CN.zip` 和 `.sha256`，校验哈希，取 `MapleMono-NF-CN-Regular.ttf` 和 `-Bold.ttf`；`OFL.txt` 取自同一标签的仓库，脚本检查它是 SIL OFL。全部放在发布 zip 的 `fonts/` 下。下载缓存在 `dist/cache/`（不进 git）。仓库里没有字体文件。

### 9.3 兼容模式

在其他终端中运行时（RimArcho 无法控制别的终端用什么字体）：
- 图标换成 §7 表格中的 Unicode 备用字符。`ui.icons auto|nerd|compat`：auto（默认）在 `TERM_PROGRAM=WezTerm` 时用 Nerd Font 图标，否则用兼容字符；玩家自己的终端已经在用 Nerd Font 时可以设 `nerd`。
- 不显示缩略图，也不预留缩略图区，名称顶格。
- 链接不可点击，在文字后面淡色显示域名；描述图片显示为文字占位。
- 其余布局和交互完全相同。

### 9.4 缩略图

- **绘制**：bubbletea 渲染完一帧后，用 iTerm2 内联图片协议（OSC 1337），在详情区预留的矩形里单独绘制图片。做法：包装输出 writer，在同一次写入中帧后追加清除或绘制；绘制时必须临时显示光标（ConPTY 在光标隐藏时不转发定位）。
- **尺寸由 RimArcho 决定，不交给终端**：图片按比例缩放到 18×9 格以内，取能放下它的最少行数 N，用透明像素补成恰好 18×N 格的比例，以 `width=18;height=N;preserveAspectRatio=0` 发送，所以图片覆盖的正好是这 18×N 格（16:9 占 5 行，正方形 8 行，竖图 9 行）。不能用 `preserveAspectRatio=1`：WezTerm 会保持宽度、按比例推算高度，竖图会超出预留区，清除后留下残条。
- **预留区**：宽度固定 18 格；高度等于图片的行数，尺寸还不知道时按 16:9，没有 Preview.png 时是一行，居中显示淡色的“无预览”。名称、作者、事实写在预留区右边。右边剩不到 16 格文字时不显示预留区。全屏详情中预留 36×18 格，规则相同。
- **清除**：选中项变化时，图片在下一帧消失，并在同一次写入中对图片自己占的那几行逐行执行 `ECH 18`。文字覆盖和 bubbletea 的整行重写都不能擦掉图片格子，不能依赖它们；也不擦整个 9 行（会把短图片下面没变的文字擦掉）。
- **不等待**：选中项变化时立即绘制。为了不让快速滚动卡顿：
  - 在后台预取光标上下各 10 个 Mod 的缩略图。可见图片和预取各用一个加载槽、每槽一张，所以当前行的未命中不会排在预取后面；加载完成时即使光标已经离开也保留，留作以后的预取。
  - 编码好的图片序列放在内存 LRU 里，上限 64 张（缩略图已是 360 像素宽，64 张只占几 MB）；屏幕上的和正在加载的从不被逐出。
  - 命中缓存时立刻画；未命中时立刻开始解码，解码完如果光标还在这一行就画，否则不画。
  - 每帧重画已经显示的图片（这一帧可能写过它们），最多再加一张新图片；其余每隔 16 毫秒画一张，不需要新帧。简略详情里只有缩略图，这条主要影响全屏详情。
- `ui.preview_dwell_ms`（默认 0，范围 0–5000）：光标停留多少毫秒后才画缩略图，玩家觉得闪烁时可以调大。`ui.previews off` 整体关闭图片。
- **描述图片**（只在全屏详情中）：在原位置占一块区域，宽度为列宽和 60 格中较小者，行数按图片比例算、最多 20 行；用与缩略图相同的方法绘制（补成整格比例、`preserveAspectRatio=0`、离开时 ECH 清除）。只有完全进入可见区域时才画，部分可见时显示占位行；加载中占一行。
