# 06 · 界面

> 状态：2026-10-21 重写。GUI（窗口）和 TUI（终端）两个界面：信息架构、页面、交互规则、详情、视觉和各自的技术实现。方案编辑器、能不能跑、详情、设置、历史区、GUI 的侧栏、顶栏、首页、首次引导、Mod 库存 › 全部已实现；方案页（多个方案）、TUI 的页面映射、存档管理、Archo 面板待实现。
> 依据：00（定位、三个问题、原则）、00a（架构）、01（范围）、03（问题与日志）、04（方案与排序）、05（命令）、08（启动与整合包）、09（Archo）、10（没玩到与值得玩）。

设计原则：不让玩家沿着一条复杂路径完成操作，而是让玩家**随时知道自己在哪里、可以去哪里、怎么回去**，并以**最少的步骤**完成任务。“怎么回去”有两层：界面上，每个弹层和二级界面都能用 `esc` 或面包屑回到上一级（§3.1 规则 5）；数据上，每次修改都能在方案的历史里看到并撤回（§2.5 第三栏、04 §3）。

## 1. 分层与共享视图模型

```
surface/tui   (Bubble Tea)        surface/gui   (Wails 服务 + assets/*.html|css|js)
      │  只做：布局、绘制、按键/鼠标映射      │  只做：把 view 模型序列化给前端、事件推送
      └──────────────┬──────────────────────┘
                internal/view     界面无关的视图模型
                     │
                internal/app      业务
```

- TUI 用 Bubble Tea + Bubbles + Lip Gloss；GUI 用 Wails v3 + 原生 HTML/CSS/JavaScript（§8）。GUI 不是把 TUI 渲染进窗口，也不调用 CLI 再解析文字。
- `internal/view` 不依赖 Bubble Tea、Lip Gloss、Wails。输入是 `*app.App` 的状态，输出是普通 Go 结构（可以直接 JSON 化）。

`internal/app` 给界面提供类型化接口：`SetTags` / `SetAlias` / `SetNote`、身份问题回答、日志选择、`ChildScan`（扫描子进程，不弹控制台窗口）、每个 Mod 的 Def / Patch / Harmony 小结。界面不拼 CLI 参数做编辑。`cmds.Execute` 只留给本来就是文字的只读场景：排序 / 写入 / 启动的预览（CLI 的 `--dry-run` 文字）、“查看”类操作和全屏详情的 Def / 补丁 / Harmony 子区，以及玩家自己在命令行输入框里输入的 archo 命令。

规则：
1. 业务规则只能写在 `app` 或 `view` 中。界面层出现“如果是工坊 Mod 就……”这类判断即为缺陷。
2. 两个界面的同一操作调用同一个函数。同一个状态下，TUI 和 GUI 拿到的 `Needs`、`Board`、详情数据完全相同（G1）。
3. 文案只有一份（`view.Text`），GUI 通过一次调用拿到当前语言的整张表。
4. 每个会写磁盘的动作都满足三条：能预览（`--dry-run`，界面上命令面板的“预览…”），能撤回或在执行前说明为什么不能撤回，结果写在状态行（01 §4）。只有 RimArcho 的撤销管不到的动作才先确认（§6）。

底部：

### 2.2 顶栏、状态行、提示行

**GUI 顶栏**（2026-10-22 改）：只有面包屑（如“库 / 方案 / 主力殖民地”，15px，最后一级加粗）和紧挨着页面名的 chip（环境，如“main · 1.7”；能不能跑写“方案 · 环境”；首页跨环境，不显示）。**顶栏没有按钮**，每一页都一样：收起侧栏的按钮在侧栏顶部（§2.1），启动键只在启动页（§2.3、§2.5）。面包屑的每一级都可点击返回。页面没有另外的大标题（面包屑就是标题）；面包屑下方第一行是一句淡色的说明，写这一页是做什么的，**页面级动作在这一行的右端**（`.page-head` 的 `.page-acts`；没有说明的页面动作也在这一行）。页面级动作是安静的“图标 + 文字”按钮，没有边框，只有主操作是实心按钮。方案编辑器也有这一行（§2.5）。

**TUI 顶栏**（已实现）：品牌 · 当前环境（药丸）· 能不能跑 N · 未写入 N，右侧是位置行（§3.2）和 `L 启动`（空间不够时先去掉它）。进入二级界面时左侧换成面包屑：`RimArcho › 能不能跑`、`RimArcho › 已启用 › Combat Extended`。游戏运行状态不在顶栏，在状态行右端（§9.1）。

两个界面的底部都是：
- **状态行**：一句话。`✓`（绿）完成、`✗`（红）失败、`…`（次要色）进行中。下一次按键时清除。GUI 在方案编辑器和全屏详情里于状态行左侧显示位置（§3.2）；其他页面不显示（面包屑已经说了在哪），状态行也不再显示“游戏里现在是”（见 §2.5）。能撤销的结果后面带“撤销”链接。
- **提示行**：当前对象此刻能用的动作，`键 说明 · 键 说明`，最多 7 项，最后一项是 `? 全部按键`。按键用文字色，说明用次要色，分隔点用淡色。能不能跑不在提示行上（顶栏或侧栏已经显示数字），用 `shift+2` 去，`?` 会列出它。

“未写入 N”：方案的编辑即时持久化（04 §1），不存在“未保存”。这个数字和行上的 `●` 表示“与上次写入游戏的列表不同、启动或写入游戏时才会写进去”的条目数，只是提示，不阻止启动（08 §2）。界面文字已改为“未写入”。

### 2.3 启动（原首页）

已实现（GUI，`home.js`，2026-10-22 改为“游戏主菜单”式布局）。页面铺一张背景图（§2.14），图从顶栏下面一直铺到状态行上面；左侧一列是所有方案和整合包，左下是动态，右下是启动键。
- 列出**所有环境**的方案和整合包（`view.AddOtherEnvs`：另一个环境的方案用 `app.PlansIn`，不加载那个环境）。没有页面说明、没有页面动作、列表上方也没有小标题（重新扫描在 Mod 库 › 变化，新方案 / 导入在方案页）。
- **左侧一列**，每项一行两层：上层是类型标签（[方案] / [整合包]，放在最左边，两种标签同宽，名称从同一条线开始）和名称；下层是淡色的“能运行的游戏版本 · N 个 Mod · 玩过的日期”，和名称左对齐（版本：方案是它所在环境的游戏版本，如“1.7”；整合包是它带的 Mod 的 supportedVersions 的交集，如“1.5–1.6”，`view.PackVersions`；悬停写环境）。
  - 第一行是**现在应用的**那一项（`view.PickFeatured`：当前环境的当前方案；在这里对整合包按过“应用”、并且此后当前方案没变时，是那个整合包），整行是凸起的淡底色，没有左侧竖线；右边常驻“编辑 ↵”，去方案编辑器或整合包页。
  - 其余按最近游玩排序（启动记录，08 §2）；从没启动过的排在后面，按名称。键盘所在的行和鼠标下的行是更淡的底色，右边出现“应用 ↵”。
  - **应用**：让这一项成为现在应用的那一项（它移到第一行）：先切换到它的环境（如果不是当前环境），方案成为当前方案，整合包记在 GUI 设置 `ui.gui.home.pack`（环境、包名、当时的当前方案）里。不写任何游戏文件（`API.HomeApply`）。
  - 单击一行只是选中；双击或按钮执行编辑 / 应用。列表比窗口长时这一列自己滚动。
- **左下**两行文字，各是一个链接（只有有内容时才显示那一行）：
  - **上次游戏**：只写结果，“上次游戏 · 10 月 21 日 · 3 个错误 →”（没有报错时“没有报错”，去游戏日志；有报错去能不能跑；游戏在运行时写“游戏运行中 · N 个错误”）。页面打开或窗口重新得到焦点时，`Player.log` 比上次读过的新就自动读一遍（`app.NewLog`，读一次很便宜）。从没有过游戏记录时这一行不显示。

**暂存**（规则见 04 §2.2）：持久保存、不写入游戏的列表。两种用途：
- **准备区**：新订阅的 Mod 先放进来，想好了再启用；
- **排查区**：把一批 Mod 从“已启用”移到暂存来排查问题，排查完一键放回原位置。
- 每个从“已启用”放进暂存的 Mod 记住原位置和一个锚点：它前面的那个 Mod。锚点越过在它之前、已经被暂存的 Mod 向前移，所以分批暂存的顺序不影响放回。放回时沿着仍在暂存里的 Mod 追溯锚点链，找不到时用原位置。
- `add` 和 `restore` 各是一步撤销。被暂存的 Mod 以任何方式重新启用（撤销、启用、载入版本）都会离开暂存。暂存列表本身不进撤销栈。
- 命令：`archo stage list|add|drop|restore`（05 §4）。每个方案一份（meta 表的 `stage:<方案 ID>`）。

### 2.6 编译成整合包

方案的子页（当前方案），已实现（GUI `packs.js`，`API.BuildPage` → `view.BuildPageOf`；`archo pack build`，08 §5.2）。入口：方案编辑器顶栏的“编译成整合包”、整合包页的同名动作（`B`）。面包屑“库 / 方案 / <方案> / 编译成整合包”，侧栏停在这个方案上；右上“取消”（`esc`）回到编辑器。布局照原型（`RimArcho 新界面设计.html` 的“编译成整合包”），颜色用现在的视觉。
- **左侧**：“基本信息”卡片：名字（默认“<方案名> <日期>”，不合法或重名时在下面说明，`API.PackNameCheck`）、类型（完整包 / 轻包，`--light`，两个单选块，`T` 切换）。“编译时会做的事”卡片，四行（完整包五行，多一行“贴图”），每行编号、粗体标题和一句话：1 检查能不能跑（有 error 级问题时编号变成红色“!”，写“还有 N 个会出错的问题”，列出问题，右侧“去处理”去能不能跑；没有时说排序为这个包单独做、移动几项，以及没写支持当前版本的 Mod 数，琥珀色）、2 去掉用不到的（只留当前版本会加载的内容，几个 Mod 带着别的版本目录、省多少；空间不够或读不出的 Mod 时红色；轻包和问题没修好时淡色）、3 贴图（只有完整包有，08 §5.2）、锁住版本、放好（写进整合包文件夹，用自己的存档和设置，方案的存档不受影响）。编译中这几行显示进度（完成的打勾、当前的呼吸圈；复制时“去掉用不到的”和“锁住版本”一起进行），下面是进度条和“停止”（`view.ProgressOf`，每行有 `Key`）。
- **贴图**一行（`view.textureStep`）：标题下是一个选择框，八个值：不转换（照原样复制 PNG，默认）、预转换（原尺寸）、精简到 80 / 75 / 60 / 50 / 40 / 25%（`view.PackTextureChoices`，存在 `B.tex`）；换一个值就重新测量整页（`API.BuildPage(light, tex)`：要转换的文件、编译后的大小、转换时的峰值都跟着变）。下面一句话：不转换时说转成 DDS 的好处；转换时写“N 个 PNG 转成 DDS，包里不再带 PNG。显存约 A → B。编译后包约 X，转换时最多占 Y。”，保留 PNG 的个数（同名 DDS 或别的格式）和包会变大时（琥珀色）列在下面。空间按峰值检查；汇总的“大小”写转换后的。**没装 todds** 时这一行红色，写“没有安装 DDS 转换工具（todds）：在 库 › 贴图优化 安装”，右侧“去安装”去贴图优化页；“编译”禁用，下一行“先安装 todds，或者不转换贴图再编译 →”也去那里。这一页从不下载 todds。按键 `D` 换到下一个值（`?` 里有），选择框也能用 tab 到达、↑↓ 改。“先看清单”带上同样的 `--textures [--texture-scale N]`。
- **右侧汇总**：包名、环境、Mod 数、大小（编译前 → 编译后；问题修好后才算出）、存档（独立，第一次启动时是空的）、位置（`pack.dir`）；下面是“编译”（`B`，或在名字里按 enter）和“先看清单，不写磁盘”（`V`）。
- **“编译”禁用**（G14）：有 error 级问题时禁用，按钮下一行红字“先修好 N 个问题 →”，点击去能不能跑；空间不够、有读不出的 Mod、名字不能用、另一个包正在编译时同样禁用并写原因。
- **“先看清单，不写磁盘”**：弹出 `archo pack build --dry-run` 的文字（`API.PackDryRun`，不写磁盘）。
- **大小要遍历每个 Mod 的文件夹**：页面先显示，检查在锁内做，测量在锁外做（`PackPlan.Measure`）；切到轻包不测量。
- **没编译完的**（`view.UnfinishedRows`）列在下方：别的窗口在编译的显示进度和“停止”；中断的可以“重新编译”或“删除已复制的”（这是 RimArcho 自己没完成的产物，按 08 §5.2 直接删除，不进回收站）。
- 完整包在子进程里编译，编译完打开这个包的页；轻包立即写好并打开。

**动作**：副本详情里的六个，只在适用时出现，顺序固定：
1. **恢复**（`unhide`）：被其它管理器隐藏的那份恢复给游戏。
2. **退订**（工坊那份）/ **删除**（自己的那份）：“退订”经正在运行的 Steam 客户端真的退订（08 §10），Steam 随后删掉这个工坊文件夹，所以和删除一样先显示 `--dry-run` 的文字（会删哪个文件夹）再确认；已启用、仍有方案在用、游戏正在运行时拒绝。Steam 没在运行、游戏目录里没有 `steam_api64.dll` 或加载不了时，才退回到打开工坊页面，状态行说“连不上 Steam（原因）：已打开工坊页面，请在页面上退订”。“删除”把文件夹移到回收站（`trash`，08 §7），只对 `Mods/` 里和锁定库里 RimArcho 自己的那份、SteamCMD 下载的那份（没有订阅会把它下回来），以及退订残留、被隐藏的工坊文件夹出现；已启用或仍有方案在用时拒绝并说出是哪些方案；它本身是链接（`_Link_*` 之类）时拒绝，不去动链接指向的地方。先显示 `--dry-run` 的文字再确认。
3. **重新订阅**（退订残留）：同样经 Steam 客户端订阅，一点就做（不删东西，不需要确认），Steam 在后台下载，下次扫描时它不再是退订残留；连不上 Steam 时同样退回到打开工坊页面。
4. **备份锁定版本**（= 收进锁定库，下面）：`Mods/` 里多出来的那份。
5. **打开文件夹**。
6. **打开网页**（有工坊 ID 时）。

另外还有方案的动作（和编辑器的同一套，§3.5）：`space` 加入当前方案并启用 / 从当前方案拿掉 / 放回（在暂存里），同一 Mod 的另一份在当前方案里时是“换成这一份”（`x`）；`m` 启用到… / 移动到…；`t` 暂存；`x` 换成另一份；从所有方案里拿掉（可撤销）；锁定这个版本、更新锁定版本、解除锁定（04 §7）。它们在右键菜单和多选动作条里。所有动作来自一张表（`view.OpTable`：代码、名字、键、菜单分组），每一份只带适用的代码（`view.CopyOps`）；名字和键随页面数据只发一次。

**副本备注**（已实现，schema v13 `instance_note`）：每一份 Instance 自己的一段话，写在详情最上面。玩家没写时显示 RimArcho 写的第一版（灰色），例如“该锁定版本创建于 10 月 21 日，为方案「测试」创建，自从创建后上游有 2 次更新，原因：新版改了存档格式”。不是 RimArcho 做的副本也有第一版，说它从哪来、哪天首次发现，和工坊那份并存的再说之后工坊那份更新了几次：“工坊订阅，10 月 19 日首次发现”“放在游戏的 Mods 文件夹，10 月 19 日首次发现，之后工坊那份更新了 2 次”“已退订，Steam 留下了文件夹，…”；订阅了但没有文件夹的没有：
- RimArcho 在创建这一份时记下来历（`made`：锁定版本、更新锁定版本、收进锁定库；时间；为哪些方案；玩家给的原因 `--reason`），文字每次现算，所以“之后上游有几次更新”（同一 Lineage 的工坊那份在这之后的更新次数）一直是对的。
- 点一下就改，从现在显示的文字开始改；`enter` 保存，`shift+enter` 换行，`esc` 不改。写空就回到 RimArcho 写的那版。TUI 在 Mod 库存里按 `n`（多份时先选哪一份）。
- CLI `archo note <引用> <文字> --copy`（`--clear` 清掉），`archo pin … --reason`、`library move-to-locked … --reason`；MCP `set_player_data` 的 `copy_note`，`pin_mod`、`manage_library` 的 `reason`（05）。`archo library --lineage` 每份下面列出 `note:`。
- 和 Mod 的备注（`archo note <引用>`，§4.1 的“备注”，搜索的 `has:note`）的关系：Mod 的备注写在 Lineage 上，所有副本、所有方案共用，说的是“这个 Mod”；副本备注只属于这一份，说的是“为什么留着这一份”。`has:note` 仍只看 Mod 的备注；库存的搜索两种都搜。

**收进锁定库**（已实现，`archo library move-to-locked`）：同一个 Lineage 的备用版本都放在锁定库里，`Mods/` 里每个包名最多留一份，用哪份由方案决定（04 §7）。`Mods/` 里多出来的副本（手动复制的、其他管理器留下的）可以在这里收进锁定库：玩家确认后移动，同一个卷上改名，跨卷先复制、逐个文件核对，再把原目录移到回收站。它在 Lineage 里的身份和各方案的引用不变：移动后 RimArcho 先把这个 Instance 指到新位置再扫描（按来源和路径对上，R1），ID、Lineage、历史都不变，游戏下次写入或启动时经 `_Archo_` 链接看到它。没有 `.rimarcho/origin.json` 时写一份：上游是同 Lineage 的工坊那份（没有就是它自己），`origin_snapshot` 是这份自己的快照，所以“上游有更新”表示工坊那份的内容和它不同。只移 `Mods/` 里、同一 Lineage 还有别的副本（或本来就带 `origin.json`）的文件夹；里面有指向文件夹外的链接时拒绝（同卷改名也拒绝）。`pin --move-to-library` 用同一个移动，规则仍只认带 `origin.json` 的旧副本（04 §7.4）。写文件清单见 01 §4。

**数据**：大小来自扫描快照（逐个文件读过，记下字节数，不另开开关）；用在来自所有方案的工作区和整合包的 `pack.json`；上次游玩来自启动记录（08 §1）；订阅来自工坊 ACF。命令：`archo library [--search <词>] [--include <键:值>]… [--exclude <键:值>]… [--sort <列>] [--lineage <引用>] [--facets] [--all]`（`--sort` 取 name、size、changed、played、state、source、used、updated、version、author、tags，前面加 `-` 反过来）、`library remove-from-plans <引用…>`、`library move-to-locked <引用> [--dry-run]`；MCP 只读工具 `list_library`，写工具 `manage_library`（05 §1.2、§5.2）。筛选的键：`tag`、`source`（workshop / local / locked / steamcmd / extra / monitor）、`version`、`state`（unloadable / missing / ignored / residue / hidden / updated）、`used`（`plan:<名>`、`pack:<名>`、`none`）。“用在”包括同一个游戏目录的所有环境的方案（另一个环境的写成 `<环境>/<方案>`）和整合包；“从所有方案里拿掉”也作用于它们，每个方案一步撤销。大小：快照表本来就有 `total_size`（扫描时逐个文件累加，`.git`、`.rimarcho` 不算），不需要迁移；没有快照的写“—”。“游戏会忽略这一份”只出现在 `Mods/` 里同包名的两份之间：工坊那份同包名时游戏以 `_steam` 加载它（04 §4.1），不算被忽略。

**GUI 实现说明**：每行同高，只画看得到的行（真实数据 1284 个 Lineage，滚动一次约 4 ms，一次筛选往返约 20 ms）。筛选值只列个数大于 0 或已选中的，每组先列 6 个，其余“还有 N 个”。只有一份的 Lineage 直接是那份的行；筛选只命中部分副本时，Lineage 自动展开给出命中的那几份。会改文件的动作（锁定版本、更新锁定版本、解除锁定、恢复、备份锁定版本、退订、删除）先显示 CLI 的 `--dry-run` 文字再确认；`space` `m` `t` `x` 和从所有方案里拿掉是方案编辑，状态行带撤销，`u` 撤销的就是当前方案的这一步。每一份只带它的动作代码，文件夹路径和工坊网址留在 Go 里（详情按需取字段，打开文件夹和网页按 Instance），1284 个 Lineage 的页面数据从 1.47 MB 降到 0.77 MB。这一页讲的是整台机器上的副本，顶栏不显示环境标签（方案编辑器照常显示）；页面按钮只写“重新扫描”。TUI 的列表用同样的默认列（名称、大小、状态、来源、用在），不能改列。按键是 §3.5 的同一张表；本页另有：`→` 展开 Lineage（在一份上是去详情），`←` 收起或回到 Lineage，`s` 表头的菜单（按某列排序、移动或加宽当前排序列、显示或隐藏列、恢复默认列），`C` 这个 Mod 的变化，`R` 重新扫描。表头的拖动、右键都在 `s` 里有键盘的做法（§3.1 规则 6）。

参考 RimCrow 的“库存枢纽 › 全库数据管理”：一行对应磁盘上的一份、同来源重复和跨来源同项分开说、订阅了但不在磁盘上的“幽灵”项、删除默认进回收站、每个确认框说清后果，这些照做；它把操作都放在右键菜单、详情只在悬停时出现、搜索只看名称和包名、体积默认不算，这些不照做。

**变化**（已实现：GUI Mod 库存 › 变化，`screens.js`；TUI 的 `c` 界面；CLI `archo changes`、MCP `list_changes`。数据都来自 `internal/modchanges`，界面用 `view.T` 写中文，CLI / MCP 写英文，所以三者说的是同一件事）：回答“我上次玩之后，我用的 Mod 变了什么、要不要管”。

- **一个 Mod 一行**：把它在时间范围里的所有变化事件合成一行，写成“名称 · 一句话说这意味着什么”，层级用一个小标签显示：**会影响启动** / **留意** / **只是内容**。按层级、再按名称排序。
  - 会影响启动（只在这个 Mod 在当前方案里时）：新增的依赖没装或没启用；不再支持当前环境的游戏版本；新增与一个已启用 Mod 的不兼容；包名变了。
  - 留意：代码（`.dll`）、Defs、Patches 或 LoadFolders.xml 改了；加载顺序规则变了；支持的版本变了；锁定的版本落后于工坊。版本号的变化跟着 Defs / Patches / 代码一起出现时才算留意。
  - 只是内容：只改了贴图、音效、翻译或其他文件；改名、换作者、文件夹换了位置也在这一层。
- **只用已有的数据，不做新的分析**。一句话最多三件事，取最要紧的；展开后先是按类分组的文件摘要，再是一句话里放不下的事和工坊的更新时间：
  - 支持的版本新增或去掉了哪些，是当前环境的版本（`st.GameMM()`）时标出“（当前游戏）”。
  - `About.xml` 的 `modVersion` 前后。
  - 依赖（基础的加上当前版本的 `modDependenciesByVersion`）新增或去掉了哪些，写成名称，带“未安装 / 未启用”（同 `view.Deps`）。
  - 两个快照的 `decl_blob` 里 `incompatibleWith`、`loadBefore` / `loadAfter`（含 `forceLoad*` 和按版本的形式）的差异；`load-rules-changed` 事件本身不带 detail（02 §5.3），所以从声明里比。
  - 文件按类分组：代码（`.dll`）、Defs、Patches、About/LoadFolders、贴图（`Textures/`）、音效（`Sounds/`）、翻译（`Languages/`）、其他。比较两个快照的 `snapshot_file`：有哈希的（语义文件）比哈希，其他比大小；贴图和音效写大小差，多于一类时再写总的大小差。例：“Defs 改了 4 个、新增 1 个，贴图 +3.2 MB · 共 +3.4 MB”。About.xml 自己的变化由上面几项说，不另写“改了”。
  - 工坊的更新时间（`acf_time_updated`）。
  - 锁定的版本（04 §7）：方案用的是锁定版本时，它的上游也在范围里；上游更新了就写“锁定的版本落后 N 次更新”（`Store.UpdatesSince`，从 `origin.json` 的复制时间算）。
  - 第二阶段（**待做**）：“新增了 N 个 Def”“这个补丁现在会失败”这类说法要每个版本的分析摘要，现在没有存，不做。
- **范围和时间**：
  - 默认看**当前方案的 Mod**（加上它用的锁定版本的上游），可以切到**整个库存**（GUI 顶部两个按钮，`a`；CLI `--library`，MCP `library`）。
  - 默认时间是**当前方案上次游玩以来**（`Store.LastPlanLaunch`，启动记录，08 §1）；从没玩过时是上次扫描的那些变化。CLI / MCP 的 `--since scan:<n>|<天>d|YYYY-MM-DD` 改起点。
  - 更早的变化收在下面“更早”里，按天分组（起点之前的 10 次扫描），每天一行，展开后同样一个 Mod 一行。
  - 环境的第一次扫描发现的 Mod 不算变化。新出现和不见了的 Mod 合成一行摘要（“新订阅 2 个 · 不见了 1 个”），展开列出每一个；方案还在用的不见了的 Mod 算会影响启动。
  - 只看一个 Mod：详情“历史”下的“在变化页查看全部”（TUI：`C`）只看它的 Lineage（每一份副本），列出它的每一次变化，按扫描分组（同一天先被发现、后来又更新的不会合成一行）。顶部是可去掉的条件“只看 <名字> ×”，点 × 或按 `esc` 回到所有 Mod；从侧栏或 `c` 进来总是所有 Mod。
- **行的动作**（适用时才有，展开后是按钮，也都有键）：打开网页（工坊的更新说明页，`ctrl+w`）、看依赖（新依赖会影响启动时，去能不能跑，`D`）、排序（依赖或加载规则变了、Mod 在方案里时，`S`）、锁定这个版本（工坊 Mod 更新了、在方案里、还没锁定时，`p`；先显示 `pin --dry-run` 再确认，TUI 按两次 `p`）。`ctrl+o` 打开文件夹。
- **按键**：`↑↓` 移动，`enter` 展开 / 收起（行、新增和不见了的那一行、更早的某一天），`i` 原始文件列表（`+` 新增、`~` 改了、`-` 删了，带大小差，最多 300 行），`a` 当前方案 / 整个库存，`tab` / `shift+tab` 切到另一个子页（全部），`R` 重新扫描，`esc` 去掉“只看”条件。`a` 和 `p` 是这一页新加的键，要并进共用的键表。
- 扫描后状态行仍是一句话：`✓ 扫描完成 · 12 个 Mod 有更新 · 1 个改了包名 · 按 c 查看`（`view.ChangeSummary`）。
- 需要玩家判断的身份问题不在这里，在能不能跑 › 要你确认。

### 2.10 游戏日志

已实现（GUI“日志 › 游戏日志”；TUI 在能不能跑里按 `l` 选择日志）。数据：`view.LogFiles`、`view.BuildLogPage`（伴生日志区 `view.MonitorOf`、`view.LiveMonitor`）；GUI 另有 `LogCluster`（展开一个聚类的证据）、`SelectLog`、`LogMonitor`、`AddMonitor`。
- 选择日志文件：一个安静的下拉按钮（“Player.log · 10 月 21 日 17:55 ⌄”），菜单里每份 Player.log 下面缩进列出它这次运行的伴生日志（`ArchoMonitor.log`、`ArchoMonitor-prev.log`，没有时 RimCrow 的；配对按 03 §6.7.4，`LogFile.Of` 指向所属的 Player.log）。选伴生日志 = 打开它的 Player.log 并切到伴生日志区。标出属于哪次启动见 03 §6.4。
- 下拉按钮右边一行淡色事实：游戏版本 · 行数（不再写时间，下拉按钮已经写了）。
- 日志的聚类列表：每条一句话 + 归因的 Mod + 次数，展开看证据和样本。
- 聚类的详情（右侧详情卡，`archo log --cluster` 的文字）：完整的消息（最多 1200 字节）、续行（`also`）、首次出现前后的其他日志消息（`nearby`，03 §6.3）、归因和置信度。
- **Archo 日志分析**（范式卡片，`API.LogPattern` → `view.PatternCard`，03 §6.8）：聚类匹配到错误范式时，右侧在日志原文**上方**多一张卡片，小标题“3 Archo 日志分析”（数字键 3 聚焦）。卡片内容按主次排：
  - 第一行是**严重程度**：一个带颜色的词和一句影响（`PatternCard.Level` / `LevelText` / `Impact`，由范式的阶段和第一种修法定）。严重（红）= 和存档有关：可能读不了档，或丢东西；中等（琥珀）= 加载时出错：它说到的内容可能缺失或不起作用 / 游戏进行中出错：可能反复报错、卡顿或让某个功能失效；轻微（灰）= 阶段是 noise，或第一种修法是“通常可以不管”：通常不影响游戏。
  - 然后是要点：“这类报错通常是：…”（正文色、稍大），“先试：…”（左边一条强调色竖线）；来源 Mod 有自己的已知错误时多一句（琥珀色）。
  - 次要的在一条细线下面，字小、淡色：常见原因、修法。最后两行最淡：出现次数和重复上传证据（“6,734 份分享的 1.6 日志里有 3,706 份见过 · …”），以及“来自玩家分享的日志，不是对你的列表的结论”。
  - 没匹配到（或只匹配到回退范式）时这张卡片不出现，日志原文占满右侧。CLI 文字里英文的 `pattern:` 小节不再重复显示（`view.WithoutPatternBlock`）。伴生日志区的条目对上聚类时，显示的就是那个聚类的证据和卡片。TUI 的文字版（`PatternCard.Lines`）在标题行下面先写“严重程度 · 影响”。
- **三张卡片之间的间隙可以拖**：列表和右侧之间左右拖改列表宽度，Archo 日志分析和日志原文之间上下拖改分析卡片高度；记在设置 `ui.gui.log.left`、`ui.gui.log.ana`，双击回到默认（列表略宽于右侧，分析卡片按内容、最多占右侧一半）。窄窗口（900px 以下）三张卡片上下排，不能拖。
- **伴生日志区**（这份 Player.log 有伴生日志时）：列表卡片顶上两个小标签“Player.log · 24”“Archo Monitor · 16”（RimCrow 的写“RimCrow Companion · 16”），←→ 切换。
  - 区头一行淡色事实，取自 session 和 exit 行：开始–结束时间（游戏版本上面已经写了，Monitor 自己的版本不写）（没有 exit 行：“17:51 起 · 没有退出记录（崩溃或被强制关闭）”；游戏还在运行：“17:51 起”加一个绿点；写满 32 MiB 时注明）。
  - 每个条目一行（文件里的顺序）：时间、级别图标、`inferredType` 的短中文名（补丁错误、Def 配置错误、交叉引用错误、XML 加载错误、程序集冲突、Tick 异常、绘制异常、空引用、内存不足、贴图缺失；`view.MonitorKind`）、消息第一行、×次数（大于 1 时）、相关 Mod（名称；没装的写 packageId）、相关文件（在某个 Mod 目录里时写“Mod › 相对路径”）。INFO 且没有类型的条目不列。
  - 点一行展开 `details`（等宽、限高可滚动），并给出“Player.log 里的 E3 →”，点它切到聚类列表并选中那个聚类；右侧详情卡同时显示那个聚类的证据。对不上任何聚类的 ERROR / WARNING 写“只在 ArchoMonitor.log 里：游戏当时已不再写 Player.log”。

## 3. 交互规则

本章的规则对方案编辑器和 Mod 库存 › 全部完整成立（两页是同一套界面：同一个筛选栏、同一张按键表、同一个右键菜单，2026-10-22 定），其他页面按同样的原则（方向键只导航、动作是按钮或动词键、`esc` 回上一级）。GUI 和 TUI 的键盘按键相同，例外在 §8.5 和 §9.1 写明。

### 3.1 六条规则

1. **方向键只导航，永不改动数据。** 在任何状态下，`↑↓←→` 都只移动光标、焦点或滚动位置，不移动 Mod、不启用、不打标签。GUI 中单击和滚轮同样不改数据。
2. **动作是动词键，立即生效，`u` 撤销。** 动作作用于“对象”：有选中时是选中的实例，否则是光标所在行。动作不进入任何模式，没有“放下 / 取消”这一步。每个动词是一次 app 编辑，所以是一步撤销。
3. **位置始终可见。** 位置行随时说明：焦点在哪个区域、光标是第几个、选中了几个、当前打开了什么弹层（§3.2）。
4. **可去哪里始终可见。** 提示行只列出当前对象此刻能用的动作（最多 7 个），`?` 列出全部，`ctrl+k` 可以从任何地方去任何地方。
5. **弹层最少。** 只有命令面板、标签候选行、位置输入、确认、帮助五种。每个弹层都有标题并显示在位置行中，`esc` 关闭，不嵌套。另外两个输入框给进阶使用：`:` 命令行和 `r` 规则输入，只在 `?` 中列出。
6. **鼠标能做的，键盘都能做**（2026-10-22 定，为了 TUI）。每个页面上的点击、右键、拖动、双击都有按键或键盘焦点能到：行的动作有自己的键，没有键的在右键菜单里，而菜单键和 `shift+F10` 在光标所在行打开同一个菜单（`↑↓` 选、`enter` 执行、`esc` 关，菜单里显示的键也直接执行）。筛选栏、表头（`s`）、历史（`H`）、列宽（`<` `>` `=`）、详情里的链接（`C`、`ctrl+o`、`ctrl+w`、`g`、`n`）同样。新功能先给键再给鼠标；测试 `TestOpsReachable`（view）和 `TestOpsRunnable`（GUI）检查每个动作有键或菜单、两页都能执行。

**基态**：当前页、无选择、无弹层或菜单、筛选栏收起（方案编辑器里还要求聚焦的列表没有搜索）。筛选栏收起后仍生效的筛选是页面自己的状态，不算离开基态（再按一次 `esc` 清掉）。任何状态下最多按 3 次 `esc` 回到基态（T20、G5）：
- `esc` 先关弹层和菜单（GUI 里用鼠标打开、焦点不在菜单上的右键菜单和 `⋯` 菜单也一样），再一级一级退：详情（盖满的详情、详情焦点）→ 选择 → 筛选栏（焦点在行上时一次清掉并收起；焦点在筛选栏里时只收起）；
- 在二级界面（全屏详情、技术页、能不能跑某项的展开视图、TUI 的整合包 / 设置文本）里 `esc` 回到打开它的页面；技术页里 `esc` 关闭整叠技术页（`backspace` 才是退一页），所以从任何深度都满足 3 次；
- `esc` 不在侧栏页面之间后退：页面是平级的，换页用侧栏、面包屑或 `ctrl+k`。

### 3.2 位置

方案编辑器有四个焦点区：`1` 未启用、`2` 已启用、`3` 暂存 / 历史、`4` 详情。数字键直接跳到对应区；区标题前显示这个数字（淡色）。

- 聚焦区：标题用强调色，光标所在行加一层很淡的整行底色（TUI `#1A1C24`）。非聚焦区的光标只把名称变成文字色，不加底色，不显示 `▸`。焦点在详情时，列表都画成非聚焦，所以屏幕上永远只有一处“最亮的地方”。
- 详情区有标题行 `4 详情`（滚动后变成 `▲ 名称`），焦点在详情时用强调色；内容从下一行开始，和列表第一行对齐。
- 位置行（TUI 在顶栏右侧，GUI 在方案编辑器和全屏详情的状态行左侧）：
  - 列表区：`已启用 · 322 / 488 · 已选 3`。位置按可见（搜索后）的行数计算，有搜索时加 `已筛选`。
  - 详情区：`详情 · Combat Extended · 简介 40%`。小节取当前顶行上方的小标题（概要、简介、历史、技术信息）加上滚动了多少。
  - 弹层打开时在后面追加，例如：`已启用 · 322 / 488 › 标签`。搜索显示为 `› 搜索`，等待第二次按键的确认显示为 `› 确认`。
  - 全屏详情：`已启用 › Combat Extended（322 / 488）› Harmony`。
  - 其他页面（全屏、技术页、能不能跑、变化）：位置行就是面包屑。

### 3.4 选择

- `shift+↑↓`：从光标处扩展连续选择。
- `ctrl+space`（TUI 也可 `v`）：切换光标所在行的选中状态。`ctrl+a`：选中显示的全部（筛选后就是筛选出的行）。普通的 `↑↓` 和 `ctrl+↑↓` **不会**清除选择，所以“移动光标 → `ctrl+space`”就能间断多选。
- 鼠标：单击移动光标，`shift+单击` 范围选择，`ctrl+单击` 切换选中。在同一个列表里单击保留选择（和 `↑↓` 一样只移动光标）；单击另一个列表会清除选择。
- `esc`：清除选择。切换到另一个列表区时选择也会清除，提示行事先说明：`←→ 换列表会取消选择`。
- 选中的行行首有强调色的 `▌`。有选中时，提示行变为：`已选 3 · space 停用 · t 暂存 · m 移动 · g 标签 · esc 取消选择`。这只是提示行，不是悬浮窗，也不是模式。
- 动作之后：`g` 保留选择（可以再按 `g`）；`space`、`t` 清除选择（行离开了这个列表）；`J` / `K` 和在“已启用”内的 `m` 保留选择。

### 3.6 位置输入（`m`）

```
 移动 3 个到 ❯ harm▌
   之后  Harmony                       （第 1 位）
   之后  Harmony Patches for VFE        （第 212 位）
   第 352 位（建议位置）
   最前 · 最后
```

- 输入数字表示“移到第 N 位”；输入 Mod 名，模糊匹配后最多显示 5 个候选（排序：前缀、子串、字母顺序），默认是“放在它之后”，`tab` 切换为“放在它之前”并保持选中的行。
- 不输入、直接 `enter`，就移到建议位置。建议位置（`App.SuggestAt`）用排序器的约束边：紧跟在必须排在它前面的最后一个已启用 Mod 之后；只有“排在之前”的约束时，放在其中第一个 Mod 之前；没有约束时放末尾；官方内容优先这条边忽略。对已经启用的 Mod，先把它们从列表里拿出来再算，所以 `m` 也能为移动建议位置。
- 选项是一个列表，每项一行，只有 `最前 · 最后` 共用一行；两对方向键都能在选项间移动。位置按“去掉要移动的 Mod 之后”的列表计数（`MoveBlock` 和 `Enable` 用的就是它）；名字旁的“（第 N 位）”是那个 Mod 现在的序号。
- 对象在“未启用”或“暂存”中时，`m` 等于“启用并放到所选位置”；从暂存移多个时启用并移出暂存，是一步撤销。
- 输入框位于列表下方，占用列表的最后几行，所以缩略图不会盖住它。数据：`view.PosOptions`、`view.Place`。

### 3.7 搜索（`/`）

- 搜索是筛选栏的一部分（§2.5）：一次筛选“未启用”和“已启用”两列，结果即时显示；`enter` 结束输入，筛选保留，直到按 `esc` 清除。列标题显示 `已启用 12 / 485`。暂存区有自己的搜索框，规则相同。
- 原来的“tab 跳到下一个有匹配的列表”不再需要（两列一起筛选），`tab` 只接受灰色补全。

查询由空格分隔的词组成，全部词都要满足（AND）：

| 写法 | 含义 |
| --- | --- |
| `词` | 名称、别名或作者包含它（不分大小写）；整个查询都没有结果时，自由词再按名称的字母顺序匹配（`hsl` 找到 “Hair Style Lib”） |
| `name:词` / `author:词` / `tag:词` | 只看名称（含别名）/ 作者 / 标签；`tag:` 匹配标签中任一单词的开头（`tag:facial` 找到 Facial Hair 和 Facial Animation，`tag:animation` 找到 Facial Animation，`tag:"facial hair"` 只找前者） |
| `id:值` | 包名包含它、工坊 ID 等于它，或者是 `#引用` |
| `type:值` | 来源 `official` `workshop` `local` `copy` `git` `steamcmd`；内容 `assembly`（带 DLL）、`xml`（没有 DLL，也可写 `xml-only`）、`language`（只有语言文件，也可写 `language-pack`） |
| `has:problem` / `has:error` | 有能不能跑的可操作项 / 有会导致加载失败的问题；还有 `has:tag` `has:note` `has:alias` |
| `version:1.6` | 声明支持这个游戏版本 |
| `-词`、`-tag:x` | 取反 |
| `"带 空格"` | 引号内是一个词 |

补全：光标在末尾、当前词已有两个字母时，搜索框里用灰字显示补全（`au` → `author:`）；`tag:` `type:` `has:` 后面补值，标签值取当前列表里标签的单词，用得多的在前。`tab`（GUI 也可 `→`）接受补全。`version:` 后面补这台机器上 Mod 支持的版本。

内容类型（`type:assembly` 等）来自对当前快照文件列表的一次 GROUP BY，在第一次用到时加载，数据库变化前一直保留（`view.ContentCache`）。

### 3.8 标签

- 详情的字段列表里显示 Mod 的标签（§4.1，旁边是“编辑”）；列表的行里不显示标签（名字长时它挤掉名字，一千多行里也读不过来），找带某个标签的 Mod 用 `tag:` 搜索（§3.7）或 Mod 库存的标签筛选（§2.9）。
- 标签属于 Mod 的 Lineage（04 §8），对应 CLI `tag add|remove <引用> <标签…> --mod <引用>…`、MCP `set_player_data`。
- 标签不进撤销：它是玩家数据，不是列表编辑，`u` 不撤销它，GUI 状态行也不给标签修改显示“撤销”。

`g` 在提示行（或详情）下方打开一行候选，不是输入框：

```
 ✎ 输入…   [框架]  [美化]  [服装]  [种族]  [武器]  [建筑]  [QoL]  [测试中] …
           ▲ 初始选中第一个候选
```

- `←→`（或 `↑↓`）移动选择；`enter` 应用；`esc` 关闭。`enter` 后候选行关闭，选择保留，可以再按 `g`。
- 第一个候选左边是“✎ 输入…”：从第一个候选按 `←` 就到达它，此时可以直接打字，`enter` 创建并应用新标签。在任何候选上直接打字也会跳到输入处。
- 已经挂在**全部**对象上的标签显示为 `[✓框架]`，`enter` 把它从这些对象上移除；只挂在部分对象上的显示为 `[~框架]`，`enter` 补齐到全部。
- 候选顺序：常用标签（`archo config set tags.pinned "框架,美化,…"`，`,` 和 `，` 都可分隔）在前，然后按使用次数排序的已有标签。放不下时向右滚动。数据：`view.TagCandidates`、`view.PinnedTags`。
- 预置常用标签是 `tags.pinned` 的默认值（不在首次运行时写进数据库，`config get` 能看到，`config set` 整体替换）：框架、美化、服装、种族、武器、建筑、家具、QoL、平衡、剧情、性能、语言包、测试中、待删除。
- 没有选择时，候选行代替状态行。

### 4.3 简介来源与渲染

**测量**（2026-10-19，玩家环境，1274 个有 About.xml 的工坊 Mod，只读；工坊描述用 Steam 公开接口 `ISteamRemoteStorage/GetPublishedFileDetails/v1`，无需 key，13 次批量请求取回 1264 个）。按去掉 BBCode 和图片后的纯文本长度：

| 长度 | About.xml | 工坊页面 |
| --- | --- | --- |
| 空 | 25 | 1 |
| 1–79 字 | 355 | 19 |
| 80–299 | 376 | 108 |
| 300–999 | 276 | 345 |
| ≥ 1000 | 242 | 791 |

- About.xml 为空或不到 80 字的占 30%（380 个）；其中 305 个的工坊页面有 300 字以上。两边都只有一两句、也没有图片的只有 18 个。工坊描述 300 字以上的占 90%，About.xml 只占 41%。
- 504 个 Mod 的两边开头是同一段文字（作者复制了一份）。只有 5 个用了 `descriptionsByVersion`。
- 工坊描述 55%（696 个）带图片，共 7981 张；139 个以图片为主（≥ 3 张、每张不到 100 字的文字）。几乎全是图文混排：文字不到 80 字、只有图片的只有 1 个。
- 图片格式：PNG 7351、GIF 323、无扩展名 244、JPEG 55、WebP 6。图床：i.imgur.com 72%，其次 raw.githubusercontent.com、img.litet.net、i.postimg.cc、Steam 自己的 images.steamusercontent.com。
- 出现最多的 BBCode：`img` `*`（列表项）`url` `b` `h1` `list` `h2` `td` `h3` `i` `tr` `hr` `th` `u` `table` `code` `nl` `strike` `olist` `quote`。

**规则：**

1. **来源。** About.xml 的 `description`（若有当前游戏版本的 `descriptionsByVersion` 条目则用它）随时可读，从磁盘按需读取，不存进数据库。工坊页面描述在线获取。
2. **选哪个。** 有工坊描述时：About.xml 不到 300 字，或者两边开头相同（忽略图片），只显示工坊描述（标题“简介 · 工坊页面”）；两边都长且不同，先显示 About.xml，再显示工坊描述（两个小标题）。没有工坊描述（本地 Mod、离线、获取失败）时显示 About.xml，并在小标题后淡色注明原因（`view.DescNote`）。
3. **何时获取。** 只为选中的 Mod 按需获取：光标在一个工坊 Mod 上停留 400 毫秒后，在后台发一次单个 ID 的请求，不预取整个列表。结果缓存在 `<数据目录>/cache/workshop/<工坊 ID>.json`。缓存里的 `time_updated` 不早于本地 appworkshop 清单中的 `timeupdated` 时视为最新，不再联网；没有清单时间时，缓存 7 天有效。全屏详情里按 `r` 强制刷新。
4. **离线开关。** `archo config set workshop.fetch on|off`（默认 on）；`workshop.images on|off`（默认 on）单独关闭图片下载。关闭后只用缓存和 About.xml。联网只访问 Steam 的这个公开接口，以及工坊描述里出现的图片地址。请求带 RimArcho 的 User-Agent。
5. **BBCode 渲染**（按显示宽度换行，遵守 §7 的原则）：`h1`–`h3` 粗体文字色并前后空一行；`b` 粗体；`i` `u` 照常显示（不用斜体和下划线）；`strike` 淡色；`list` / `olist` 用 `•` 和序号、按层级缩进两格；`url` 显示链接文字，WezTerm 中用 OSC 8 做成可点击，兼容模式在文字后面淡色显示域名；`quote` `code` 缩进两格、次要色；`table` 按列对齐、放不下的列截断；`hr` 变成空行；`nl` 换行；`noparse` 原样；未知标签去掉、保留内容。GUI 由 Go 端解析成块结构，前端渲染为标题、列表、表格、引用、代码、链接、图片元素（§8.3）。
6. **图片里的文字（OCR）**：界面不做。用视觉模型识别，放在 Archo 的任务里（09 §5）。

### 4.4 图片

- **缩略图来源**：Mod 的 `About/Preview.png`（文件名大小写不敏感；内容是 JPEG 也接受）。缩放到宽 360 像素（不放大）的 PNG，按快照哈希缓存为 `<数据目录>/cache/previews/<快照哈希>.png`。只读 Mod 目录。
- **描述图片**：在需要时才下载；解码、缩放到 720 像素宽后缓存为 PNG（`<数据目录>/cache/workshop-img/`）。`imgur.com/x.png` 这样的链接直接改成 `i.imgur.com`。GIF 只显示第一帧；WebP 和解码失败的显示占位。
- **简略详情不内嵌描述图片**：只显示缩略图和文字，描述中的图片在第一张图片的位置合成一行淡色占位 `[图片 ×3 · enter 在全屏中查看]`（TUI 兼容模式下是 `[图片 ×3]`）。描述图片只在全屏详情中显示；全屏详情在兼容模式下逐张列成文字占位 `[图片 · i.imgur.com]`。
- `ui.previews off` 整体关闭界面里的图片；`workshop.images off` 只关闭描述图片的下载。
- GUI 直接用 `<img>` 显示、按比例缩放，描述图片 `loading="lazy"`，进入可视区域时才请求；图片只经 `/img/` 处理器从本地缓存读出（§8.3）。TUI 的绘制规则见 §9.4。
- 图片画廊、大图浏览等功能只在 GUI 做：终端图片协议有先天限制（ConPTY 的光标问题、按整格对齐、无法部分裁剪），TUI 的图片只是锦上添花。

## 5. 能不能跑的写法

**每一项**由问题集合和环境的待确认项生成：分组、一句由 Mod 名组成的话、作用于它的动作（`view.Action`）、是否计数。问题代码、`#引用`、`pkg:`、`p:` 等 CLI 引用形式从不出现在页面上，它们只在技术信息、CLI 和 MCP 里。

| 内部代码 | 玩家看到的 | 一键操作（TUI 键） | 分组 |
| --- | --- | --- | --- |
| `official.order` | Core 和 DLC 要排在最前面 | `S` 自动排序 | 会让游戏出错 |
| `order.violated`（强要求，warning） | 只有一条时：A 应该排在 B 之后（说明写“强要求（依赖或 loadBefore）”）；多条时合并成一项：10 个 Mod 的顺序不对（数的是需要挪动的 Mod），`enter` 展开逐条列出 | `S` 自动排序 | 会让游戏出错 |
| `order.violated`（弱或无害，info，04 §5.3） | 合成淡色的一项，不计数：5 条较弱的顺序要求没满足（loadAfter 和社区规则，分享的日志里违反它们并没有多出错） | `S` 自动排序，`f` 展开 | 会让游戏出错 |
| `order.cycle` | 3 个 Mod 的顺序要求互相矛盾（info：淡色，不计入数字，03 §4.3.1） | `enter` 用人话查看各条要求，`x` 忽略建议的那一条（加忽略规则，这一项消失） | 会让游戏出错 |
| `pkg.duplicate-active` | 同一个 Mod 启用了两份 | `space` 选择保留哪一份 | 会让游戏出错 |
| `entry.missing` | 列表里有 X，但没有安装它 | `o` 在工坊搜索（订阅在 1.2）、`space` 从列表中移除 | 会让游戏出错 |
| `mod.unloadable` | A 已启用，但游戏无法加载它 | `space` 停用 | 会让游戏出错 |
| `mod.replaced`（社区数据 replacements） | A 有维护中的替代品：B | B 已安装：`space` 启用 B、停用 A；未安装：`o` 在工坊打开 B | 会让游戏出错 |
| `version.unsupported`（汇总） | 293 个 Mod 没有标明支持 1.7（其中 288 个支持 1.6） | `enter` 查看列表 | 会让游戏出错 |
| 列表为旧版本写入 | 列表是为 1.5 写的，游戏启动时会重置它，写入一次就好 | `w` 写入游戏 | 会让游戏出错 |
| `dep.missing` | A 需要 B，但没有安装 B | `o` 在工坊打开 B（声明的 URL，否则工坊搜索） | 会让游戏出错 |
| `dep.inactive` | A 需要 B，但 B 没有启用 | `space` 启用 B | 会让游戏出错 |
| `dep.observed-missing`（日志语料，warning） | A 似乎需要 B（分享的日志里见过），B 没有安装 / 没有启用 | 已安装：`space` 启用 B；未安装：`o` 在工坊打开 B | 会让游戏出错 |
| `combo.known-bad`（日志语料，warning） | A 和 B 一起时常报错（分享的日志里见过）；或：这个版本的 A 常报错，其他版本没有 | `space` 选择停用哪一个；版本：`space` 停用 A | 会让游戏出错 |
| `mod.known-error`（日志语料，info） | 淡色的一行，不计数：A 有一个已知错误：这是 Mod 自己的问题（下一行淡色：不是你的列表的问题，更新它可能就好了；淡色项也显示这一行说明） | `enter` 看这个错误 | 会让游戏出错 |
| `patch.no-match`（目标未启用） | A 的部分内容没有生效（它针对的 B 没有启用） | `space` 启用 B，或 `enter` 查看 | 会让游戏出错 |
| `def.parent-missing` | A 的部分内容继承的定义不存在，可能缺少前置 Mod | `enter` 查看 | 会让游戏出错 |
| `incompat.active` | A 与 B 不兼容 | `space` 选择停用哪一个 | 会让游戏出错 |
| `log.*` | 上次运行时 A 报了 12 次错 | `enter` 查看日志与证据（技术页） | 上次运行的报错 |
| 实时日志 | 本次运行中 A 报错（新的在前） | `enter` 查看 | 上次运行的报错 · 本次运行 |
| 身份待确认 | X 和 Y 是同一个 Mod 吗？ | `s` / `c` / `u` 回答（两次确认） | 要你确认 |
| ModsConfig.xml 外部修改冲突 | ModsConfig.xml 在 RimArcho 之外被改了，而这个方案之后也改过 | 看差异 / `L` 载入（两次确认，会替换这个方案现在的列表）/ `I` 忽略 | 要你确认 |
| `mod.pinned`（上游有更新） | A 锁定了版本，工坊那份之后更新过 | 查看差异（`mod <工坊实例> --diff <副本>`）、更新锁定版本（`pin --update`）、解除锁定（`unpin`，确认） | 隐藏的 Mod |
| `mod.hidden-residue` | A 被隐藏、已经退订，文件夹还留着 | 移到回收站（`trash`，确认） | 隐藏的 Mod |
| `mod.hidden` | A 被隐藏了（大概是别的 Mod 管理器做的） | 保持隐藏（忽略问题）、恢复（`unhide`，确认）、移到回收站（确认） | 隐藏的 Mod |

- 动作类型（`view.Action.Kind`）：`sort`、`save`、`enable`、`disable`、`choose-disable`（从选项中选一个停用）、`open-url`、`view`（只读命令文字）、`list`（显示标题和行）、`fold`（展开 / 收起合并项）、`ignore-rule`、`load-external`、`dismiss-conflict`、`answer`、`unhide`、`unpin`、`trash`、`ignore`。`Action.Key` 是 TUI 的键，GUI 显示为按钮，按钮文字就是动作（“启用 B”“自动排序”“在工坊打开”）。
- `patch.no-match` 只有在它针对的 Mod 已安装但未启用时（target-inactive）才出现；目标根本不存在、版本路由错误等情况玩家无法处理，留在技术信息。`def.abstract-collision` 同样只在技术信息里。
- 日志语料层的三项（`dep.observed-missing` 在缺少的前置一类，`combo.known-bad` 在冲突一类，`mod.known-error`）的凭据 chip 是“社区日志”，来源写实测比例（§2.4）。
- `version.unsupported` 只有在其中有 Mod 停在上一个版本（warning）时才出现；全部只写了更早的版本时按 info 处理，不出现（日志语料 G8 把两者的严重度对调了，03 §4.3.1）。
- **合并规则**：同一种问题如果一个键就能全部解决，就合并成一项，`enter` 展开逐条显示；目前有 `order.violated`（`S` 一次排好）、同一个 Mod 的 `def.parent-missing`（“X 的 34 处内容可能缺少前置”，一个“查看”看全部）、同一个 Mod 针对同一个未启用目标的 `patch.no-match`（“X 的 6 个补丁不会生效”，启用目标一次解决）。合并项的展开键是 `f`（`order.violated` 是 `enter`），GUI 在 `⋯` 菜单里。缺失的列表条目、未启用的依赖、日志等每条要单独处理，不合并。
- **计数**：角标和顶栏的数字 = 这个页面上可以操作的项数（折叠的旧日志那一行不算），合并后的一项算 1，所以数字反映的是要做几件事，而不是有几条发现。列表行上的状态图标也只标在这些项涉及的 Mod 上。
- **不出现在这里的**：
  - info 级别（Def 覆盖、补丁争用、共享 Harmony 目标等）：只在详情的技术信息里，以及 CLI 和 MCP 中；
  - 没有日志证据的 Harmony 警告：归入技术信息，玩家无法据此行动；
  - 旧日志（不属于当前方案最近一次启动，或来自另一个游戏版本，03 §6.4）：折叠成一行淡色 `更早的日志 · 9 月 29 日 · 1.6`，不计数。

## 6. 确认与反馈

- **排序、写入游戏、启动直接执行**（`view.Run`）：一次点击或一个键，结果写在状态行（`view.Outcome.Text`）；排序能用 `u` 撤销，状态行带“撤销”（TUI 写“u 可撤销”）。被拒绝时（有游戏在运行、有未载入的外部修改、没有用户数据目录、找不到 Steam……）不弹确认：状态行写原因，`Outcome.Refused` 有命令时，GUI 开一个只读弹窗、TUI 开一个面板，列出能解决它的命令（看差异 / 载入 / 忽略等）。
- **预览**照样可以看，但不在动作前面拦一道：命令面板的“预览排序 / 预览写入 / 预览启动”（`view.DryRun`，CLI 的 `--dry-run` 文字）只读，没有“继续”按钮；CLI 是 `archo sort|save|launch --dry-run`。
- **一步可撤销的动作不确认**：除了排序，还有载入历史版本、载入外部修改的 ModsConfig.xml（`L`）。两者都是工作区的一步编辑，被替换的列表留在历史里，状态行带“撤销”（`view.Action.Undo`）。
- **RimArcho 撤销不了的动作要确认**。
  - TUI 用“再按一次”：第一次按在状态行显示 `✗ 再按一次 R：……`，再按同一个键执行，按其他键取消（“已取消”）。
  - GUI 用确认对话框，对话框显示 `view.Action.Warn`。
  - 目前用于：删除方案；回答身份问题（`s` `c` `u`，合并或拆分 Lineage 不能用 `u` 撤销）；`unhide`、`unpin`（改名 Mod 文件夹里的 About.xml）；`trash`、整合包移到回收站、删除未完成编译复制的文件；设置页里的忘掉文件夹、下载社区数据（约 50 MB）、`gc`。
- **回收站和改名**动作（`unhide`、`unpin`、`trash`）先显示预览（`--dry-run`）再确认（08 §6、§7）。
- **卸载 RimArcho** 不用确认对话框：它的页面就是预览，页面最下面的按钮是唯一的一次确认（§2.14，01 §4.1）。
- **结果文字**由界面写成人话（“启用了 Beta”“Harmony 现在是第 3 个”）；命令的错误经过 `view.Humanize`，把实例引用换成 Mod 名。
- **长任务**不阻塞界面，进度在状态行（§8.4）。
- **变化不弹窗**：扫描结果、新的游戏报错只更新状态行和数字。

## 7. 视觉

**原则**（magpie / Linear 式精致极简）：
1. **零边框（TUI）。** 区域之间只用空白、两格缩进、淡色小标题来分隔，不画方框和分割线。GUI 用 magpie 的卡片：一层安静的底面，内容放在带细边框、12px 圆角的卡片上。
2. **一种强调色。** 只有强调色、成功绿、错误红，加上一个用于警告的琥珀色。强调色只给“正在操作的东西”：光标、选中名称、聚焦区的标题、输入提示符。
3. **大部分文字是灰的。** 多数字符是次要色或淡色，只有你要操作的那一项是亮的。
4. **选中是小标记加变色，不是整行色块。** `▸` 加上粗体强调色名称；选择是行首的 `▌`。实心背景只用于“药丸”（当前环境、聚焦的筛选项）和聚焦区光标行的淡底色。
5. **粗体只表示身份**（Mod 名称、标题），不用斜体、下划线和反色。
6. **不显示开发者术语。** 界面上不出现问题代码、`#id`、`decl`、`lineage` 等词，它们只在技术信息和 CLI / MCP 中出现。例外：包名在详情中默认显示。界面上每个概念叫什么见 §7.2。
7. **静止的界面。** TUI 没有动画和转圈；进行中的工作在状态行用 `…` 表示。GUI 的动效只用来说明“什么变了、东西去了哪里”（§7.1），都很短，`prefers-reduced-motion` 时全部关闭。
8. **TUI 每一行只占一行**，没有行间距。放不下就截断加 `…`，并告诉玩家藏了多少（`还有 12 个`）。详情文字换行（§4.1）。

**TUI 色板**（深色）：

| 角色 | 值 | 用途 |
| --- | --- | --- |
| 背景 | `#0E0F12` | WezTerm 宿主的背景 |
| 文字 | `#E6E6E6` | 名称、值、按键字母 |

| 淡色 | `#4A4F5A` | 序号、小标题、分隔点 `·`、未聚焦区的内容 |

**字体**：TUI 在 WezTerm 宿主中用自带的 Maple Mono NF CN（§9.2）。GUI 用系统界面字体（`Segoe UI Variable Text`、`Segoe UI`、`Microsoft YaHei UI`），序号用等宽数字，代码用 `Cascadia Mono`；GUI 不依赖附带的 Maple Mono。

**文案**：

### 7.1 动效（GUI）

三个时长，定义在 `style.css` 的 `:root`，缓动统一用 `--ease`（`cubic-bezier(.2, .8, .2, 1)`）：

| 变量 | 时长 | 用于 |
| --- | --- | --- |
| `--t-press` | 120ms | 悬停、按下、颜色的淡入淡出 |
| `--t-enter` | 180ms | 出现：页面进入、弹层、状态行 |
| `--t-layout` | 260ms | 位置变化：列表行换位、侧栏高亮滑动、数字跳动 |

动效清单（`js/motion.js` 和 `style.css` 的 motion 一节）：
- **页面进入**：新打开的页面淡入并上移 4px；同一页重绘（动作之后、切换子视图）不动。
- **侧栏高亮**：当前条目的底色是一块滑动的高亮（像视图切换的 thumb），换页时从旧条目滑到新条目；尺寸直接变，只有位置动。子项有自己的一块高亮，在同一条目的子项之间滑动。
- **侧栏子项展开 / 收起**：子项所在的格子的行高从 `0fr` 过渡到 `1fr`（`--t-layout`），同时淡入（`--t-enter`），条目名称后的小箭头转 90°。换条目时旧的收起、新的展开一起进行，下面的条目跟着平滑移动，不跳。高亮直接滑向目标条目动画结束时的位置（`motion.js` 按正在展开、收起的子项算出终点）。收起的子项不在 tab 顺序里。
- **列表变化**（启用、停用、移动、排序、撤销、拖放）：动作前记下可见行（按 Mod）在屏幕上的位置，重绘后把仍可见的行从旧位置滑到新位置（FLIP）；被操作的行（不知道是哪些时，是换了位置或新进入这个列表的行）闪一下强调浅底，约 600ms 淡出。只处理虚拟列表已经画出来的行（几十行），一批行只触发一次样式计算。
- **数字**：侧栏角标和个数、列表标题的数目、能不能跑各区的计数、“N 项未写入”，数字变了时轻轻放大一下。
- **状态行**：新的一句从下方滑入。
- **加载中**：按需加载的部分（游戏日志、日志详情、全屏详情的分页）显示几条微光闪动的占位条，不写“加载中…”；屏幕阅读器读到的是原来的文字。
- **卡片和弹层**：保持原来的轻微缩放淡入。

规则：
- 会持续或会移动的动画只动 `opacity` 和 `transform`（WebView2 合成，不重新布局、不重绘）；闪一下用一层淡出的覆盖层，不对背景色做动画；微光和进度条的流光是移动的渐变层。例外：120ms 的悬停颜色过渡（一次性，不是持续动画），和侧栏子项展开时格子的行高（只有几行，一次 260ms）。
- 不用 `backdrop-filter` 模糊（WebView2 每一帧都重绘它）。
- `prefers-reduced-motion: reduce` 时：CSS 把所有动画和过渡的时长设为 0，`motion.js` 不做 FLIP、闪烁、跳动和滑入。
- 滚动不触发任何动画：1341 行的列表连续滚动 400 次，没有动画在运行，每次重绘可见行中位数 0.5ms（开发环境实测）。

### 7.2 界面用词

2026-10-22 定。界面（TUI、GUI 的中文）用玩家的说法；代码、CLI、MCP 和规格书保留原来的名字（方案、环境、Instance……），所以规格书里写“方案”的地方，界面上写“列表”。

检查：`internal/surface/cli` 的 `TestWording`（`view.WordingProblems`）读程序里所有的翻译表和命令面板，有“不写”一列的词就失败；同一个英文键在两张表里译法不同也失败（后注册的覆盖前一个，前一个就丢了）。确实需要这个词的个别文字记在 `wordingExempt`（例如“反编译”）。

| 概念（规格书里的名字） | 界面上写 | 不写 |
| --- | --- | --- |
| 方案（plan、loadout） | **列表**：当前列表、新列表、列表历史 | 方案、工作区 |
| 方案里启用的部分 | 已启用 | 启用列表 |
| 编辑器的三栏 | 区：已启用、未启用、暂存区 | 列表（和“列表”混淆） |
| 加入方案 / 从方案拿掉（编辑器和 Mod 库是同一个动作） | **启用 / 停用**；从所有方案里拿掉 = 在所有列表里停用 | 加入当前方案、拿掉、移出方案 |
| 暂存、`stage restore` | 放进暂存 / 放回列表 | — |
| `save` | **写入游戏**；没写进去的修改 = 还没写入游戏；版本 = 写入过的版本 | 保存到游戏、未保存、已保存的版本 |
| `checkout` | 回到这一版（历史里的一步叫“回到旧版”） | 载入版本、载入列表 |
| 载入外部修改（ModsConfig.xml 在外面改过） | 采用外部修改 | 载入到列表 |
| 环境（Environment） | **游戏**；`env remove` = 移除游戏（不动文件） | 环境、删除环境 |
| 来源（Source） | 设置里叫 Mod 文件夹；筛选和详情里写来源（工坊、本地……） | — |
| Instance | 这一份、另一份、N 份 | 实例、Instance |
| Lineage | 同一个 Mod 的几份 | Lineage |
| 副本 | 只指 RimArcho 复制出来的（锁定库里的、整合包里的） | 把工坊原版叫副本 |
| `pin` / `unpin` / `pin --update` | **锁定这个版本** / 解除锁定 / 更新锁定版本（旧的那份保留）；来源一栏写“锁定版本” | 固定（别的工具做的固定也叫锁定） |
| 锁定之后上游有更新 | **有新版本**；改用工坊版 | 上游、原版有更新、改用原版（“原版”是 Core 和 DLC） |
| `library move-to-locked` | 移入锁定库 | 收进锁定库、备份锁定版本 |
| `swap` | **切换版本…** | 换成另一份副本、替换实例 |
| `unhide` | 取消隐藏 | 恢复给游戏 |
| `trash` | 移到回收站 | 删除（“删除”只用于真的删掉的东西：列表、DDS、卸载） |
| Mod 库存 | **Mod 库** | 库存 |
| 编译整合包 | **创建整合包**、重新创建、没创建完的整合包 | 编译 |

完整包 / 轻包暂时照旧：轻包改成“导出列表”的一种格式之后，界面上只剩“整合包”（另一个分支）。

## 8. GUI 技术

### 8.1 交付

同一份源码，链接两次：

| 文件 | 子系统 | 双击 | 用途 |
| --- | --- | --- | --- |
| `archo.exe` | 控制台 | WezTerm 中的 TUI（§9.2） | CLI、`archo mcp`、`archo tui`；`archo gui` 启动 GUI |
| `RimArcho.exe` | Windows GUI（`-H windowsgui`，没有控制台黑框） | GUI | 给玩家双击的入口（可带 `--env <名称>`）；带命令参数时按 CLI 执行，供 GUI 的扫描和分析子进程使用 |

- 两个 exe 共用数据目录和数据库，可以同时打开（SQLite WAL 支持多进程）。GUI 窗口获得焦点时比较 `Stamp()`（数据库状态，`ChangeKey`），变了就重新加载；在旧视图上的编辑不覆盖对方的修改（G8）。
- `archo gui`：同目录下有 `RimArcho.exe` 就启动它并立即返回；没有就在当前进程中运行 GUI。
- 发布包含两个 exe（体积见 07 §6）。

### 8.2 前端

- Wails `v3.0.0-beta.28`（v3 仍是 beta，锁定这个版本，升级单独验证）。不需要 CGO（`CGO_ENABLED=0`）。
- 纯 HTML + CSS + 原生 JavaScript（ES modules）。**不用框架、不用 npm、没有构建步骤**。文件放在 `internal/surface/gui/assets/`（`index.html`、`style.css`、`js/` 下 `api.js` `state.js` `lists.js` `detail.js` `screens.js` `popups.js` `exchange.js` `icons.js` `shell.js` `home.js` `guide.js` `plans.js` `motion.js` `main.js`），用 `go:embed` 打进 exe。
- 调用 Go：手写的 `api.js` 用 `import { Call } from "/wails/runtime.js"` 和 `Call.ByName`，用 `Proxy` 拼出方法全名 `github.com/ToumanLin/RimArcho/internal/surface/gui.API.<方法>`。不使用 `wails3` 生成的绑定，构建只需要 `go build`。
- `internal/surface/gui`：`api.go`（Wails 服务，每个方法只调用 view）、`gui.go`（窗口、`/preview/`、`/img/` 本地图片处理器、CSP、图标路由）、`exchange.go`（导入导出对话框）、`text.go`。
- Go → 前端：Wails 事件（`scan` 扫描结束、`analyze` 分析进度与结束、`pack` 编译进度）。游戏运行状态由前端每 2 秒调用 `Live` 轮询。
- 列表虚拟滚动：只创建可见行。
- 样式表首行 `[hidden]{display:none !important}`：弹层容器的 `display:flex` 会盖过 `hidden` 属性，形成一层看不见的遮罩吃掉所有点击。
- WebView2 用户数据放在 `<数据目录>/webview2`，不放 `%APPDATA%\RimArcho.exe`。
- `spikes/guidev`：开发用，在 127.0.0.1 上用同一个 API 驱动页面，便于在浏览器里调试（`-assets <目录>` 直接读磁盘上的页面文件，改了刷新就能看到）；不进发布包。

### 8.3 安全

- 页面的 Content-Security-Policy：`default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'`。`script-src 'self'` 下 Wails 运行时正常工作，不需要 `unsafe-eval`。
- 工坊简介和图片都是外部内容：简介由 Go 端解析成 BBCode 块结构后传给前端，前端用 `textContent` 和元素构建，**从不把外部文字当 HTML 插入**；图片只经过 `/img/` 处理器从本地缓存读出，不直接加载远程地址。
- 链接用系统浏览器打开；`OpenURL` 拒绝非 http(s) 链接。
- Wails 在 Windows 上用 WebView2 的资源拦截，不开任何 TCP 端口。
- 设置页只运行 `view.SettingCommand` 允许的命令（§2.14）。

### 8.4 长任务

- 扫描和分析在子进程中运行（`archo scan`、`archo analyze`，`app.ChildScan` / `ChildAnalyze`，子进程带 `CREATE_NO_WINDOW`）。进度通过事件推到状态行，界面不阻塞。TUI 同样如此（`:` 里输入 `scan` 也交给子进程）。
- 启动时：有索引就立即显示列表，然后在后台增量扫描；从没扫描过时自动开始扫描。
- 整合包编译在后台进行，进度推到编译页，可以停止（§2.6）。

### 8.5 鼠标

方案编辑器里的鼠标操作是动词的另一种触发方式：

| 操作 | 键盘 | 鼠标 |
| --- | --- | --- |
| 移动光标 / 切换区 | `↑↓` / `←→`、`1`–`4` | 单击 |
| 选择 | `shift+↑↓`、`ctrl+space`、`esc` 清除 | `shift+单击` 范围、`ctrl+单击` 切换 |
| 启用 / 停用 | `space` | 双击；拖到另一列 |
| 暂存 / 放回 | `t` | 拖到暂存列 / 拖出 |
| 调整顺序 | `J` `K`、`m` 位置输入 | 在“已启用”内拖动；落点线旁显示“第 N 位” |
| 标签 | `g` | 右键菜单 › 标签 |
| 撤销 / 重做 | `u` / `ctrl+r`、`ctrl+z` / `ctrl+y` | 状态行里的“撤销”链接 |
| 排序 / 写入 / 启动 | `S` / `w` / `L` | 右上按钮 |
| 搜索、筛选 | `/`、`ctrl+f`、`\` | 筛选栏（未启用上方）；暂存的搜索框 |
| 右键菜单 | 菜单键、`shift+F10` | 右键 |
| 列宽 | `<` `>` `=` | 拖动分隔线、双击恢复 |
| 历史 | `H`、`u` / `ctrl+r` | 点历史里的一步 |

- **拖放规则**：从“未启用”或暂存拖到“已启用”的某一行上 = 放到那一行的序号；拖到最后一行下方 = 放到末尾；在“已启用”内拖 = 移动；拖到暂存 = 暂存；“已启用”拖到“未启用” = 停用；暂存拖到“未启用” = 移出暂存、不启用（`view.Unstage`）。按下和松开在同一行是单击。拖动中状态行说出落点；拖动中按 `esc` 取消。松手即生效，可以 `u` 撤销。
- **右键菜单**（方案编辑器和 Mod 库存相同，2026-10-22 定）：同样的分组和顺序，每项右边写它的键，只列适用的项（`view.RowOps` / `view.CopyOps`，名字和键来自 `view.OpTable`）：
  1. 方案：`space`（启用 / 停用 / 放回；Mod 库存是加入 / 拿掉 / 换成这一份）、`m`、`t`、`x`、从所有方案里拿掉；
  2. 整理：标签 `g`、备注 `n`；
  3. 打开：打开文件夹 `ctrl+o`、打开工坊页面 `ctrl+w`；
  4. 版本：锁定这个版本、更新锁定版本、解除锁定、备份锁定版本；
  5. 磁盘：恢复、重新订阅，最后是红色的退订 / 删除（`Del`）。

  组之间是一条细线。菜单键和 `shift+F10` 在光标所在行打开它，焦点在第一项；`↑↓`（或 `tab`）移动、`enter` 执行、`esc` 关闭，按菜单里写的键也直接执行。有多选时只列能作用于多个的项（文件夹、页面、备注、位置、换成另一份只对一个）。
- 方向键、滚轮、单击永不改动数据（§3.1 规则 1）。只有双击、拖放、按钮和动词键会改动数据。
- TUI 的鼠标：单击移动光标、`ctrl+单击` 加选、`shift+单击` 范围选择、拖动列之间的空白调整列宽、单击详情区聚焦、滚轮滚动详情。TUI 不做拖动移 Mod 和框选。

### 8.6 图标与 Windows 资源

- **图形**：`internal/icon/portrait.svg`（80×80，矢量），放在圆角深色底（`#1B1D23`，圆角半径为边长的 0.22）上。48px 及以上显示整幅；40px 及以下只显示脸部（视框 x 20–64、y 24–68），任务栏上仍能认出。渲染用 `internal/icon/svgr.go` 的小型 SVG 渲染器（路径、圆、椭圆、填充、描边、线性渐变、不透明度），不加依赖。
- **不提交二进制**：仓库公开，不放二进制。`icon.PNG(size)` 抗锯齿光栅化（每像素超采样），供窗口图标和资源使用；`icon.SVG(size)` 是同一构图的矢量版，页面的 favicon 用 `/icon.svg`（256）和 `/icon-small.svg`（16），由它生成。
- **窗口图标**：Wails 先取 exe 的图标组 ID 3，没有时才用传入的 PNG。所以发布版不画；开发版（没有 `.syso`）按系统大图标尺寸（`SM_CXICON`，100% 缩放下 32px）画一张，画完立即 `FreeOSMemory`。以前画 256px，要 43 MB 堆（4 倍超采样的 float64 缓冲 32 MB），只为得到一张 32px 的图标，Go 之后也不把这些内存还给系统。
- `go run ./scripts/winres`（发布脚本调用）写 `cmd/archo/rsrc_windows_amd64.syso`：一个 COFF 资源对象，含图标组和版本信息。`.syso` 不提交（`.gitignore`）。
- **图标组 ID 3**：Wails 窗口按 ID 3 取应用图标；资源管理器取第一个图标组，两者是同一个。尺寸 16、20、24、32、40、48、64、256，每个尺寸一张 PNG。
- **版本信息**：`FileVersion`、`ProductVersion` 取发布版本号，`ProductName` RimArcho，`FileDescription` 区分 `archo.exe`（RimArcho command line）和 `RimArcho.exe`（RimArcho）。两个 exe 由同一个包构建，发布脚本在两次构建之间各写一次 `.syso`。
- **没有资源时**（开发构建、`spikes/guidev`），窗口用 `application.Options.Icon` 的 PNG（256 px）作后备。

## 9. TUI

### 9.1 定位与页面映射

TUI 是**方案编辑器的键盘版**：默认打开当前方案的编辑器（§2.5），其他页面经命令面板到达，不画侧栏。TUI 和 GUI 用同一套 view 模型和同样的按键（§3）。

| Mod 库存 › 变化 | `c` 或命令面板（已实现） |
| Mod 库存 › 全部 | 命令面板“Mod 库存”、`shift+4`（`$`）：和 GUI 同一套界面（§2.9）：筛选栏、可展开的 Lineage 行、宽时右边是副本详情，按键和右键菜单同 §3.5、§8.5 |
| 游戏日志 | 在能不能跑里 `l` 选择日志；日志项 `enter` 打开技术页（已实现） |
| 整合包、设置 | 命令面板，显示为带命令的文本面板（已实现） |
| 环境 | `E` 切换环境（已实现）；目录和启动设置用 CLI `env set` |
| 导航在侧边 / 顶部（`ctrl+b`） | 没有侧栏，不适用 |
| 启动页、编译成整合包、游玩回顾、值得玩 | 不提供页面；对应的 CLI 命令可在 `:` 里运行。没有启动页，所以编辑器里的 `L`（和顶栏的 `L 启动`）仍然直接写入并启动，不像 GUI 那样先去启动页（§2.5）；状态行在“正在启动游戏”后面写最可能出事的问题（“留意：…”，`view.LaunchHint`），`shift+2` 去能不能跑 |
| Archo 面板 | 暂不支持（09 §6） |

- 游戏运行状态在**状态行右端**（对应 GUI 侧栏底部，§2.1）：游戏运行时是 `● 游戏运行中 · 14:05 起`，本次运行的报错数是后面的琥珀色数字；游戏退出后有新的 Player.log 时是 `● 分析本次日志  shift+2`（强调色）；都没有时什么都不显示。状态行的一句话在左边，两者同时出现时这一段留在右边。新错误到来时顶栏“能不能跑 N”更新，不弹窗（每 2 秒 `view.LiveTracker.Update`；文字是 `view.LiveText`）。
- 右键菜单的键：Bubble Tea v1.3.10 不认 xterm 的 `shift+F10`（`CSI 21;2 ~`），Windows 控制台送来的是不带 shift 的 F10，菜单键在 xterm 类终端里是 F16；所以 TUI 里 F10、`shift+F10`、F16 都打开菜单，右键在指针处打开。TUI 的筛选栏占整个宽度（“未启用”一列放不下筛选块）；Mod 库存的副本详情只有备注、动作、状态和字段，没有简介和图（**待实现**）；Mod 库存在最底层按 `esc` 回到编辑器（TUI 没有侧栏）。

- `archo tui` 进入 TUI，与不带参数相同，但不经过 WezTerm 宿主（§9.2）。界面上不出现 `#id`：结果由 TUI 写成人话，错误经 `view.Humanize`；保留 CLI 文字（带引用）的只有技术页和 `:` 的输出。
- 颜色：termenv 在 ConPTY 下无法查询终端、会退回无色，所以 `SetColors` 在终端声明支持 24 位色时强制 24 位色：`COLORTERM=truecolor|24bit`、`TERM_PROGRAM=WezTerm`，或有 `WT_SESSION`（Windows Terminal）。其他终端沿用 termenv 的检测。

### 9.2 WezTerm 宿主

图标和缩略图都依赖终端能力，而玩家的终端五花八门（例如 Windows Terminal 默认字体 Cascadia Mono 没有 Nerd Font 图标）。因此 RimArcho 自带一个受控的显示环境。

**启动流程**（`internal/host`）。只有不带参数的 `archo` 会走到这里；`archo tui`、`archo --here`（强制在当前终端运行）、CLI 子命令和 `archo mcp` 从不触发（`wantsHost`）。检查顺序：

```
双击 archo.exe（或在任意终端里运行 archo）
  ├─ 已经运行在 WezTerm 中（TERM_PROGRAM=WezTerm）→ 在这里运行，完整模式
  ├─ terminal.host none → 在这里运行
  ├─ 找到了 WezTerm：PATH 中的 wezterm-gui，然后 %ProgramW6432% / %ProgramFiles% / %LOCALAPPDATA%\Programs 下的 WezTerm\，然后 <数据目录>/wezterm/
  │    → 写 <数据目录>/wezterm.lua，启动 wezterm-gui --config-file <数据目录>/wezterm.lua start -- archo tui [--env x]，本进程退出
  │      （--config-file 是全局参数，必须写在 start 之前）
  └─ 没找到，且有控制台可问 → 询问：
       “下载 WezTerm 便携版（约 66 MB）以显示图标和 Mod 预览图？[Y/n]”
       Y：下载、校验、解压到 <数据目录>/wezterm/，设 terminal.host wezterm，然后按上一行启动
       n：设 terminal.host none，在当前终端以兼容模式运行，并说明怎么改
```

- 下载只在玩家同意后进行，不静默下载。`archo config set terminal.host auto|wezterm|none`：auto（默认）表示还没问过，没找到 WezTerm 时询问一次；none 以后在当前终端运行；wezterm 表示总是用宿主。
- 下载来源：WezTerm 官方 GitHub Releases 的最新稳定版（`/repos/wezterm/wezterm/releases/latest`），取 `WezTerm-windows-*.zip` 和同名 `.sha256`。边下载到 `.part` 文件边计算哈希，校验不符则不解压、不启动，回到当前终端。解压前检查每个条目都在 `<数据目录>/wezterm/` 之内，有一个越界就整体拒绝。
- 没有控制台可问时（输出被重定向、管道），不询问，直接在当前终端运行。
- 任何失败（下载、校验、启动）都说明原因，然后在当前终端运行 TUI。

**wezterm.lua**（`internal/wezterm` 生成，每次启动重写，手改会丢失）：

| 项 | 设置 |
| --- | --- |
| 字体 | **随 RimArcho 自带** Maple Mono NF CN（Regular、Bold；SIL OFL 1.1，许可证文件一并分发），放在 `<程序目录>/fonts/`，通过 `font_dirs` 加载，不安装到系统。它同时包含 Nerd Font 图标和中文字形，所以图标、中英文的宽度和风格完全受控。回退顺序为 Symbols Nerd Font Mono（WezTerm 内置）、Cascadia Mono、Segoe UI Symbol；不能设 `font_locator = 'ConfigDirsOnly'`，否则 Maple 没有的字形（如 `⬥`、`⇣`）会显示成方框。字号 11 |
| 配色 | 与 §7 色板一致的深色方案：前景 `#E6E6E6`、背景 `#0E0F12`、光标 `#A5B4FC`、选区 `#2C2E4A` |
| 窗口 | 无标签栏、无滚动条，标题为 “RimArcho”，初始 160×46，内边距左右 8、上下 6 |
| 图片 | iTerm2 内联图片协议（WezTerm 原生支持）；关闭 kitty 图形协议 |
| 宽度 | `treat_east_asian_ambiguous_width_as_wide = false`，`unicode_version = 14`，与 RimArcho 的宽度计算一致 |
| 退出 | `exit_behavior = 'CloseOnCleanExit'`：archo 正常退出时关窗；出错退出时保留窗口，错误信息可读 |
| 内存 | `front_end = 'OpenGL'`（WebGpu 内存高得多，以后的 WezTerm 可能把它设为默认，所以固定）；`line_state_cache_size`、`line_quad_cache_size`、`line_to_ele_shape_cache_size` 都降到 128（默认 1024，浏览 Mod 会显示大量不同的行，大多是 CJK，每行都被缓存；128 仍能容纳最大化窗口的行，CPU 不变）；`glyph_cache_image_cache_size = 16`（图片由 archo 自己的 LRU 保存）；`scrollback_lines = 0`（TUI 在备用屏幕上运行） |
| 其他 | 关闭响铃、关闭字体连字（`harfbuzz_features = { 'calt=0', 'clig=0', 'liga=0' }`）、关闭更新检查和更新窗口、关闭配置热加载、关闭窗口时不确认 |

- WezTerm 是独立进程，有自己的 GPU 和内存开销（实测见 07 §6）。§10 的 archo 目标只约束 archo 进程本身。
- WezTerm 在 Windows 上总会在 `%USERPROFILE%\.local\share\wezterm\` 写 GUI 套接字和日志，这个位置不能通过配置改变；README 和卸载说明要提到它。
- 脚本驱动 WezTerm 时注意：`WEZTERM_UNIX_SOCKET` 为空时，`wezterm cli` 会退回默认套接字，可能是玩家自己的窗口。测量脚本找不到自己的 `gui-sock-<pid>` 时必须停止。

**自带字体的打包**：`scripts/release.ps1 -MapleTag v7.9`（固定版本）从 github.com/subframe7536/maple-font 的发布页下载 `MapleMono-NF-CN.zip` 和 `.sha256`，校验哈希，取 `MapleMono-NF-CN-Regular.ttf` 和 `-Bold.ttf`；`OFL.txt` 取自同一标签的仓库，脚本检查它是 SIL OFL。全部放在发布 zip 的 `fonts/` 下。下载缓存在 `dist/cache/`（不进 git）。仓库里没有字体文件。

### 9.3 兼容模式

在其他终端中运行时（RimArcho 无法控制别的终端用什么字体）：
- 图标换成 §7 表格中的 Unicode 备用字符。`ui.icons auto|nerd|compat`：auto（默认）在 `TERM_PROGRAM=WezTerm` 时用 Nerd Font 图标，否则用兼容字符；玩家自己的终端已经在用 Nerd Font 时可以设 `nerd`。
- 不显示缩略图，也不预留缩略图区，名称顶格。
- 链接不可点击，在文字后面淡色显示域名；描述图片显示为文字占位。
- 其余布局和交互完全相同。

### 9.4 缩略图

- **绘制**：bubbletea 渲染完一帧后，用 iTerm2 内联图片协议（OSC 1337），在详情区预留的矩形里单独绘制图片。做法：包装输出 writer，在同一次写入中帧后追加清除或绘制；绘制时必须临时显示光标（ConPTY 在光标隐藏时不转发定位）。
- **尺寸由 RimArcho 决定，不交给终端**：图片按比例缩放到 18×9 格以内，取能放下它的最少行数 N，用透明像素补成恰好 18×N 格的比例，以 `width=18;height=N;preserveAspectRatio=0` 发送，所以图片覆盖的正好是这 18×N 格（16:9 占 5 行，正方形 8 行，竖图 9 行）。不能用 `preserveAspectRatio=1`：WezTerm 会保持宽度、按比例推算高度，竖图会超出预留区，清除后留下残条。
- **预留区**：宽度固定 18 格；高度等于图片的行数，尺寸还不知道时按 16:9，没有 Preview.png 时是一行，居中显示淡色的“无预览”。名称、作者、事实写在预留区右边。右边剩不到 16 格文字时不显示预留区。全屏详情中预留 36×18 格，规则相同。
- **清除**：选中项变化时，图片在下一帧消失，并在同一次写入中对图片自己占的那几行逐行执行 `ECH 18`。文字覆盖和 bubbletea 的整行重写都不能擦掉图片格子，不能依赖它们；也不擦整个 9 行（会把短图片下面没变的文字擦掉）。
- **不等待**：选中项变化时立即绘制。为了不让快速滚动卡顿：
  - 在后台预取光标上下各 10 个 Mod 的缩略图。可见图片和预取各用一个加载槽、每槽一张，所以当前行的未命中不会排在预取后面；加载完成时即使光标已经离开也保留，留作以后的预取。
  - 编码好的图片序列放在内存 LRU 里，上限 64 张（缩略图已是 360 像素宽，64 张只占几 MB）；屏幕上的和正在加载的从不被逐出。
  - 命中缓存时立刻画；未命中时立刻开始解码，解码完如果光标还在这一行就画，否则不画。
  - 每帧重画已经显示的图片（这一帧可能写过它们），最多再加一张新图片；其余每隔 16 毫秒画一张，不需要新帧。简略详情里只有缩略图，这条主要影响全屏详情。
- `ui.preview_dwell_ms`（默认 0，范围 0–5000）：光标停留多少毫秒后才画缩略图，玩家觉得闪烁时可以调大。`ui.previews off` 整体关闭图片。
- **描述图片**（只在全屏详情中）：在原位置占一块区域，宽度为列宽和 60 格中较小者，行数按图片比例算、最多 20 行；用与缩略图相同的方法绘制（补成整格比例、`preserveAspectRatio=0`、离开时 ECH 清除）。只有完全进入可见区域时才画，部分可见时显示占位行；加载中占一行。
