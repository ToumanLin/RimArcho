# 01 · MVP 范围

> 依据：[00-顶层设计](../00-顶层设计.md) 的 D1–D8。
> 本文定义 MVP 做什么、不做什么、怎样算完成。各模块细节见 02–07。

## 1. MVP 目标

玩家用一个 TUI 就能完成日常的 Mod 管理闭环：

**发现 Mod → 选择与排序 → 写入游戏 → 启动 → 看懂报错 → 追踪变化。**

同时，任何支持 MCP 的 agent 都能通过 `archo mcp` 查询同一套事实，替代现有的 `rim_mod_inspector.py` 和两个 skill（D7）。

## 3. 范围

### 3.1 MVP 包含

| 模块 | 内容 |
| --- | --- |
| 环境 | 单机多环境的数据模型；TUI 中可以切换环境；自动探测路径 |
| 采集 | 游戏本体和 DLC、本地 Mods、工坊目录、SteamCMD 目录（只读）、ModsConfig.xml、ACF、社区数据库、Player.log |
| 身份 | Instance 对账、Lineage、来源重新绑定、墓碑、变更事件（全部按 D8） |
| Loadout | 编辑、历史、撤销、diff、写入 ModsConfig.xml、导入和导出文本列表 |
| 排序 | 基于约束的拓扑排序：依赖、loadBefore/After、社区规则、用户规则；报告约束环 |
| 分析 | 声明层问题；Def 索引与覆盖；PatchOperation 命中与落空；交叉引用缺失；Harmony 元数据；日志归因 |
| 源码 | 按需调用 ilspycmd 反编译单个 Mod 并缓存；在缓存中搜索 |
| 本地副本 | copy-local：写入 `.rimarcho/origin.json`，可选初始化 git |
| 启动 | 直接启动游戏，或通过 Steam 启动 |
| 表面 | TUI、GUI（08，D9）、CLI、MCP（stdio） |
| 迁移 | 从 RimCrow 一次性导入别名、分组、用户规则 |

### 3.2 MVP 不包含

- ~~图形界面（GUI）。~~ 2026-10-20 改为纳入（D9，08）。
- 订阅、退订、下载。这些交给 Steam 客户端；RimArcho 只读 ACF 状态。（正式版修订：订阅走 Steam，退订由 RimArcho 发请求并删除本地文件，09 §3.1。）
- 工坊浏览和搜索、Git 来源订阅、SteamCMD 下载。
- 贴图优化、推荐清单导出、主题、多语言 UI（MVP 只做中文和英文）。
- 内置 LLM 调用、对话界面、API key 管理。（正式版修订：内置 AI 工作台，09 §5。）
- 权限和审批机制（D6，由 harness 负责）。
- AllComps 变更审计、图标材质审计。现有 inspector 中的这两个专项审计放到 MVP 之后，届时作为分析器加入。

## 5. 完成标准

### 5.1 功能

- U1–U14 的验收用例全部通过（见各规格文档的“验收”小节）。
- 用同一份真实 Mod 集合（≥ 300 个 Mod）回放现有 inspector 的典型诊断，至少包括：XML Patch 落空、交叉引用缺失、`Pawn.Tick` 堆栈。RimArcho 得出的结论与 inspector 一致，或者更准确。

### 5.2 性能与资源（测量环境：500 个 Mod，Windows，SSD）

| 指标 | 目标 | M0 实测（2026-10-19，见 07 §6.1） |
| --- | --- | --- |
| TUI 空闲常驻内存 | ≤ 80 MB | 500 行列表 16 MB + SQLite 写满 500 个 Mod 后 21.5 MB（分别测得），目标保持 |
| 冷启动到列表可交互 | ≤ 2 秒（命中索引时） | 未测（M1） |
| 首次全量扫描 | ≤ 60 秒 | 未测；500 个 Mod 的文件清单（13.7 万个文件）写入 SQLite 用时 1.8 秒，不含哈希 |
| 增量扫描（无变化） | ≤ 3 秒 | 未测（M1） |
| 全量 Def 与 Patch 分析 | ≤ 30 秒，峰值内存 ≤ 400 MB，在子进程中执行，结束即释放 | 482 个 Mod：7.8 秒（前提是 defName/@Name 索引快速路径，没有索引时 58 秒）。峰值内存 0.8–1.0 GB，**未达标**，见下方说明 |
| MCP 单次查询（索引已建好） | ≤ 500 毫秒 | 未测（M1） |

以上数字为初始目标，M0 测量后可以修正，修正结果记入本文。

**M0 修正：**
- Patch 层**必须**实现 defName/@Name 索引快速路径（03 §5.2），否则 30 秒目标无法达成。
- 峰值内存 400 MB 的目标暂时保留，条件是 Patch 层改用紧凑节点表示（07 §6.1）。M1 第一周复测；如果仍不达标，放宽为 ≤ 1 GB。分析在子进程中进行，所以这一项不影响 TUI 常驻内存。
- 新增参考：读取 575 个 Mod DLL 的 HarmonyPatch 元数据共用 0.12 秒，Harmony 层不构成性能瓶颈。

### 5.3 安全底线

- 不修改工坊目录下的任何文件。（正式版修订：仍不修改条目里的文件；只在玩家退订时整体删除该条目的文件夹，进回收站，09 §3.1。）
- 写入 ModsConfig.xml 前先备份，写入采用原子替换。
- （正式版新增，09 §8.2）只在 `Mods/` 中创建、删除以 `_Archo_` 开头的目录链接；不写入链接目标，不改动 `Mods/` 中的其他条目。
- 解压和复制时防止路径穿越；不跟随指向 Mod 目录以外的符号链接写入。
- 不开放任何网络端口。MCP 只走 stdio。
