# 06 · TUI

> 本文定义：MVP 的终端界面（D3）。界面只回答三个问题：现在装了什么、哪里有问题、发生了什么变化（00 §5）。
> 所有操作都对应 05 中的命令；TUI 不实现自己的业务逻辑。

## 1. 基本约束

| 项 | 要求 |
| --- | --- |
| 终端尺寸 | 推荐 ≥ 120×30；最小 80×24，此时隐藏详情栏 |
| 字符宽度 | 正确处理中文等宽字符，长名称按显示宽度截断 |
| 颜色 | 支持 256 色和真彩色；`NO_COLOR` 时退化为纯文本加符号 |
| 输入 | 键盘优先；鼠标可选（点击选中、滚轮滚动） |
| 语言 | 中文、英文，跟随配置 |
| 内存 | 空闲常驻 ≤ 80 MB（01 §5.2） |

## 2. 整体布局

```
┌ RimArcho ─ 环境: 正版 1.6 ─────────────── [1]列表 [2]问题 [3]变化 ─┐
│                                                                      │
│  主视图（随标签切换）                    │  详情栏（当前选中实体）   │
│                                          │                           │
│                                          │                           │
├──────────────────────────────────────────────────────────────────────┤
│ 启用 212/487 · 问题 5E 12W · 未保存 3 处 · 变化 4 · 待确认 1         │
│ : 命令行                                       ? 帮助   q 退出        │
└──────────────────────────────────────────────────────────────────────┘
```

- 顶部：当前环境和三个主视图的标签。按 `E` 切换环境（对应 `env use`）。
- 主视图：列表、问题、变化三选一。
- 详情栏：显示当前选中实体的摘要，内容与 `archo mod`、`archo def` 等命令的输出一致，只是加了颜色和链接。
- 状态栏：统计数字，点击或按快捷键可以跳到对应视图。
- 命令行：按 `:` 打开，可执行任意 CLI 命令。结果显示在弹出面板里。

## 3. 列表视图（U2、U3）

### 3.1 内容

一个列表，不分“启用”和“停用”两栏。

```
  #   名称                          来源   版本  问题
  1 ● Core                          官方   1.6
  2 ● Harmony                       工坊   1.6
 34 ● Combat Extended               工坊   1.6   ✖2 ▲3
  — ○ Yayo's Combat 3               工坊   1.6   ✖1
  — ○ Combat Extended (本地副本)    本地   1.6
```

- `●` 已启用，带顺序号；`○` 未启用。
- 默认排序：已启用的按加载顺序在上，未启用的按名称在下。
- 筛选：`/` 搜索；`f` 打开筛选（启用状态、来源、有问题、标签、Lineage）。
- 未保存的修改用标记显示在行首。

### 3.2 操作

| 按键 | 操作 | 对应命令 |
| --- | --- | --- |
| `space` | 启用或停用 | `enable` / `disable` |
| `J` / `K` | 下移 / 上移一位 | `move` |
| `m` | 移动到指定位置或某 Mod 前后 | `move` |
| `v` | 多选模式 | — |
| `S` | 自动排序：先显示 diff，确认后写入工作区 | `sort` |
| `w` | 保存到游戏 | `save` |
| `u` / `Ctrl+r` | 撤销 / 重做 | — |
| `L` | 启动游戏 | `launch` |
| `x` | 用同一 Lineage 的其他 Instance 替换 | `swap` |
| `enter` | 打开 Inspect | — |
| `r` | 为选中的 Mod 添加用户规则 | `rule add` |

## 4. 问题视图（U5、U6）

- 按严重度分组，然后按主体 Mod 分组。
- 每行：严重度、问题代码、一句话结论、主体。
- `enter` 展开证据；证据里的引用可以继续 `enter` 进入 Inspect。
- `i` 忽略（挂在 Lineage 上，Mod 更新后自动失效）。
- 建议命令以按钮形式列在展开区域，选中后回车执行。例如 `dep.inactive` 的建议是“启用 #b21c”。
- 日志：按 `l` 选择日志文件（默认最新的 Player.log），分析结果作为 `log.*` 问题并入此视图。

## 5. 变化视图（U7、U9）

- 按扫描批次倒序排列，每批内按事件类型分组。
- 事件行：类型、主体、前后差异摘要。例如 `package-id-changed  #a3f9  ceteam.ce → ceteam.combatextended`。
- `enter` 展开文件级差异（新增、删除、修改的语义文件）。
- **待确认项**置顶显示（02 §5.4），提供三个选项：是同一个、是副本、无关。
- 外部修改了 ModsConfig.xml 时，也作为一条变化显示，并提供“载入工作区 / 忽略”。

## 6. Inspect

- 以全屏面板打开任意引用：Mod、Def、Patch、Harmony 目标、日志簇、Lineage。
- 内容与对应 CLI 命令的输出一致，引用可以点击跳转。
- `backspace` 返回上一层，保留浏览历史。
- 在 Mod 的 Inspect 中可以切换子标签：概要、Def、Patch、Harmony、规则、历史快照。

## 7. 关键流程

### 7.1 首次启动（U1）

1. 自动探测环境（02 §2.2），列出结果供确认或修改。
2. 选择是否导入社区数据（需要联网，可跳过）。
3. 首次扫描，显示进度。
4. 发现 RimCrow 数据库时，询问是否导入（04 §7）。
5. 进入列表视图。

### 7.2 保存

1. 按 `w` 后，显示与上次保存版本的 diff 和当前的错误级问题。
2. 有错误级问题时提示，但允许继续保存。
3. 确认后写入，状态栏的“未保存”清零。

### 7.3 游戏结束后

检测到 Player.log 比上次启动时间新时，状态栏出现“新日志”。按一下键就会分析，并切换到问题视图。

## 8. 验收

| # | 场景 | 期望 |
| --- | --- | --- |
| T1 | 500 个 Mod 的列表连续滚动和搜索 | 无明显卡顿，每次按键响应 ≤ 50 毫秒 |
| T2 | 80×24 终端 | 详情栏自动隐藏，所有操作仍可完成 |
| T3 | 中文 Mod 名和别名 | 对齐正确，不错行 |
| T4 | 不看文档完成：启用、排序、保存、启动 | 新用户在 5 分钟内完成（可用性测试） |
| T5 | 空闲 10 分钟 | 常驻内存 ≤ 80 MB |
