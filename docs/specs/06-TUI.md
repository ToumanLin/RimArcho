# 06 · TUI（v2）

> 本文定义：RimArcho 的终端界面。v2 根据玩家试用反馈重写，取代 v1（v1 见 git 历史）。
> 所有操作仍然对应 05 中的命令；TUI 不实现自己的业务逻辑。
> 视觉语言参考 magpie（`C:\Users\Touman_Lin\Documents\AIRelay\magpie`）的 Linear 式精致极简风格。

## 0. v1 的问题与 v2 的回应

| 试用反馈 | v1 的问题 | v2 的做法 |
| --- | --- | --- |
| 缺乏美学 | 表格加边框，信息密、层次平 | 无边框、灰阶分层、单一强调色、图标代替文字（§2、§3） |
| `[1]list [2]problems [3]changes` 不是给人看的 | 按数据类型组织界面，用的是开发者术语 | 按任务组织：主界面就是“管 Mod”；问题改为“需要处理”，用人话、带一键操作；变化不再占顶栏（§4） |
| 列表信息太多 | `# ref name source ver flags` 六列 | 只留序号、来源图标、名称、状态图标（§5.2） |
| 详情没有主次、不换行 | CLI 输出原样搬进界面 | 按“它是什么 → 有没有问题 → 简介 → 关系 → 技术信息”分层，所有文字按显示宽度换行，带缩略图（§6） |
| 想要 RimCrow 的四列 | 单列表加详情栏 | 未启用 / 已启用 / 暂存 / 详情 四列（§5） |

这也修正了 00 §5 中“只有一个列表”的设想，以本文为准。

## 1. 运行环境：WezTerm 宿主

图标和缩略图都依赖终端能力，而玩家的终端五花八门。比如本机的 Windows Terminal 用的是默认字体 Cascadia Mono，没有 Nerd Font 图标。因此 RimArcho 自带一个受控的显示环境。

### 1.1 启动流程

```
双击 archo.exe（或在任意终端里运行 archo）
  ├─ 已经运行在 WezTerm 中（TERM_PROGRAM=WezTerm）→ 直接进入 TUI，完整模式
  ├─ 找到了 WezTerm（PATH、Program Files、<数据目录>/wezterm/）
  │    → 用 RimArcho 的配置启动：wezterm-gui --config-file <数据目录>/wezterm.lua start -- archo tui（`--config-file` 是全局参数，必须写在 `start` 之前）
  └─ 没找到 → 在当前控制台询问：
       “下载 WezTerm 便携版（约 66 MB）以显示图标和 Mod 预览图？[Y/n]”
       Y：从 WezTerm 的 GitHub Releases 下载 Windows 便携版 zip，校验发布页提供的 sha256，
          解压到 <数据目录>/wezterm/，然后按上一行启动
       n：记住选择，在当前终端以兼容模式运行（§1.3）
```

- 下载只在玩家同意后进行，不静默下载。可以用 `archo config set terminal.host auto|wezterm|none` 改变选择：auto（默认）表示还没问过，没找到 WezTerm 时询问一次；回答 n 记为 none，以后在当前终端运行；wezterm 表示总是用宿主。
- 下载来源：WezTerm 官方 GitHub Releases 的最新稳定版（`/repos/wezterm/wezterm/releases/latest`），取 `WezTerm-windows-*.zip` 和同名 `.sha256`，校验不符则不解压、不启动，回到当前终端。解压前检查每个条目都在 `<数据目录>/wezterm/` 之内。
- 没有控制台可问时（输出被重定向、管道），不询问，直接在当前终端运行。
- `archo --here` 强制在当前终端运行，不切换到 WezTerm。
- CLI 子命令和 `archo mcp` 永远不触发这个流程。

### 1.2 RimArcho 的 WezTerm 配置（`wezterm.lua`，由 RimArcho 生成）

| 项 | 设置 |
| --- | --- |
| 字体 | **随 RimArcho 自带** Maple Mono NF CN（Regular、Bold；SIL OFL 1.1，许可证文件一并分发），放在 `<程序目录>/fonts/`，通过 `font_dirs` 加载，不安装到系统。它同时包含 Nerd Font 图标和中文字形，所以图标、中英文的宽度和风格完全受控。回退顺序为 Symbols Nerd Font Mono（WezTerm 内置）、Cascadia Mono、Segoe UI Symbol；不能设 `font_locator = 'ConfigDirsOnly'`，否则 Maple 没有的字形（如 `⬥`、`⇣`）会显示成方框 |
| 配色 | 与 §2 的色板一致的深色方案；背景 `#0E0F12` |
| 窗口 | 无标签栏、无滚动条，标题为 “RimArcho”，初始 160×46 |
| 图片 | 启用 iTerm2 内联图片协议（WezTerm 原生支持） |
| 宽度 | `treat_east_asian_ambiguous_width_as_wide = false`，`unicode_version = 14`，与 RimArcho 的宽度计算一致 |
| 退出 | `exit_behavior = 'CloseOnCleanExit'`：archo 正常退出时关窗；出错退出时保留窗口，错误信息可读 |
| 其他 | 关闭响铃、关闭字体连字（`harfbuzz_features = { 'calt=0', 'clig=0', 'liga=0' }`）、关闭更新检查、关闭配置热加载、关闭窗口时不确认 |

### 1.3 兼容模式

在其他终端中运行时（RimArcho 无法控制别的终端用什么字体）：
- 图标换成 §3 表格中的 Unicode 备用字符；如果玩家自己的终端已经在用 Nerd Font，可以用 `archo config set ui.icons nerd` 打开图标；
- 不显示缩略图，也不预留缩略图区，名称顶格（§6.1；V3 裁定：与 §6.1 统一，不再加一行“无预览”）。WezTerm 中没有 Preview.png 的 Mod 在预留区中央显示淡色的“无预览”；
- 其余布局和交互完全相同。

### 1.4 资源

WezTerm 是独立进程，有自己的 GPU 和内存开销。V0 实测（07 §6.2）：承载 archo 空闲时 wezterm-gui 工作集约 91 MB，OpenConsole 约 12 MB；启动到窗口可见约 0.5 秒（首次约 1.2 秒）。01 §5.2 的“TUI ≤ 80 MB”仍然只约束 archo 进程本身。V3 实测（数据目录副本，依次停留 40 个 Mod 显示缩略图并打开一次全屏详情后空闲 60 秒）：archo 工作集 45.7 MB，峰值 53.5 MB；wezterm-gui 约 161 MB，比 V0 的 91 MB 高。V2.1 查明：主要不是图片，而是 WezTerm 按行缓存的渲染结果（默认每种 1024 行，浏览越多越大；关掉图片也涨 60 MB）。生成的 wezterm.lua 把三个行缓存降到 128 行并固定 OpenGL 前端（WebGpu 实测 383 MB），同一套操作从 209 MB 降到 152 MB，CPU 时间不变；空闲基线约 100 MB。

WezTerm 在 Windows 上总会在 `%USERPROFILE%\.local\share\wezterm\` 写 GUI 套接字和日志，这个位置不能通过配置改变；RimArcho 的说明和卸载说明要提到它。

## 2. 视觉语言

### 2.1 原则

1. **零边框。** 区域之间只用空白、两格缩进、淡色小标题来分隔，不画方框和分割线。
2. **一种强调色。** 只有强调色、成功绿、错误红，加上一个用于警告的琥珀色（§2.2）。强调色只给“正在操作的东西”：光标、选中名称、聚焦列的标题、输入提示符。
3. **大部分文字是灰的。** 界面上多数字符是次要色或淡色，只有你要操作的那一项是亮的。
4. **选中是小标记加变色，不是整行色块。** `▸` 加上粗体强调色名称。实心背景只用于“药丸”（当前环境、聚焦的筛选项）。
5. **粗体只表示身份**（Mod 名称、标题），不用斜体、下划线和反色。
6. **不显示开发者术语。** 界面上不出现问题代码、`#id`、`decl`、`lineage` 等词，它们只在“技术信息”和 CLI/MCP 中出现。例外：包名（packageId）在详情中默认显示，玩家用它在别的工具和论坛里找 Mod（试用反馈）。
7. **静止的界面。** 没有动画和转圈；进行中的工作在状态行用 `…` 表示。
8. **每一行只占一行**，没有行间距。放不下就截断加 `…`，并告诉玩家藏了多少（`还有 12 个`）。

### 2.2 色板（深色；浅色模式按 magpie 的对应值自动切换，V5 实现，见 decisions-tuiv2 §5）

| 角色 | 值 | 用途 |
| --- | --- | --- |
| 文字 | `#E6E6E6` | 名称、值、按键字母 |
| 次要 | `#7C8290` | 说明、按键提示文字、作者 |
| 淡色 | `#4A4F5A` | 序号、小标题、分隔点 `·`、未聚焦列的内容 |
| 强调 | `#A5B4FC` | 光标、选中名称、聚焦列标题、提示符 |
| 药丸底色 | `#2C2E4A` | 当前环境、聚焦的筛选项 |
| 成功 | `#7EE2A8` | `✓` 结果 |
| 警告 | `#F2C46D` | 警告图标（magpie 没有警告色；Mod 管理需要区分“会坏”和“可能有问题”） |
| 错误 | `#FF8A80` | 错误图标、失败结果 |

### 2.3 文案

- 中文界面用短句，动词开头：“启用 Vehicle Framework”，不写“执行启用操作”。
- 小标题用淡色短词：`已启用 485`、`简介`、`需要`。
- 空状态是一句话，并指出按哪个键：`暂存是空的 · 按 t 把选中的 Mod 放进来`。
- 未知值用淡色的 `—`，不写 unknown。

## 3. 图标

图标采用 Nerd Font 中的 Font Awesome 4 区段（码位 U+F000–U+F2E0），所有 Nerd Font 都包含这一段，WezTerm 内置的符号字体也包含。兼容模式下改用右栏的 Unicode 字符。右栏全部是东亚宽度为“中性”（N）的字符：无论 runewidth 是否开启 `EastAsianWidth`，宽度都是 1，并且 Windows 默认字体 Cascadia Mono 都有字形、按 1 格绘制（V0 实测，见 07 §6.2）。Nerd Font 码位属于私用区，东亚宽度是“不明确”（A），所以 RimArcho 计算宽度时必须关闭 `EastAsianWidth`，WezTerm 配置中也关闭 `treat_east_asian_ambiguous_width_as_wide`。

| 含义 | Nerd Font（码位） | 兼容模式 | 颜色 |
| --- | --- | --- | --- |
| 来源：官方（Core、DLC） | shield `U+F132` | `⬥` U+2B25 | 淡色 |
| 来源：工坊 | steam `U+F1B6` | `◉` U+25C9 | 淡色 |
| 来源：本地 | folder `U+F07B` | `▢` U+25A2 | 淡色 |
| 来源：本地副本（来自工坊） | clone `U+F24D` | `⬦` U+2B26 | 淡色 |
| 来源：Git | git `U+F1D3` | `∆` U+2206 | 淡色 |
| 状态：错误（会导致加载失败） | times-circle `U+F057` | `⨯` U+2A2F | 错误红 |
| 状态：警告（可能有问题） | exclamation-triangle `U+F071` | `!` | 警告琥珀 |
| 状态：上次运行报错 | bug `U+F188` | `◍` U+25CD | 错误红 |
| 状态：不可加载（被停用的残留） | ban `U+F05E` | `◌` U+25CC | 淡色 |
| 状态：无问题 | 不显示 | 不显示 | — |
| 修改未保存 | circle `U+F111` | `⬤` U+2B24 | 强调色 |
| 锁定（Core 不可移动） | lock `U+F023` | 不显示 | 淡色 |
| 有更新 / 有变化 | refresh `U+F021` | `⇣` U+21E3 | 次要 |
| 前置依赖 | link `U+F0C1` | `›` U+203A | 次要 |
| 暂存 | inbox `U+F01C` | `◫` U+25EB | 次要 |
| 启动游戏 | play `U+F04B` | `►` U+25BA | 文字 |
| 保存 | floppy `U+F0C7` | `↲` U+21B2 | 文字 |

规则：一行最多两个图标（来源和状态）；状态图标只有在有问题时才出现，“没有问题”就是没有图标。

两种模式共用的标记：选中 `▸`、成功 `✓`、提示符 `❯`（都是中性宽度）；失败在完整模式用 times-circle，兼容模式用 `⨯`（`✗` 在 Cascadia Mono 中没有字形）。`…` 和 `·` 的东亚宽度不明确，但在两种终端中都按 1 格绘制，继续使用（前提同上：宽度计算关闭 `EastAsianWidth`）。

## 4. 信息架构

### 4.1 按任务组织

玩家打开管理器要做的事，按频率排序：
1. 看看哪些 Mod 开着，调整一下，然后进游戏；
2. 新订阅了 Mod，把它放进列表合适的位置；
3. 游戏出问题了，弄清楚是哪个 Mod、怎么办；
4. 偶尔：看看什么更新了、整理旧 Mod。

所以主界面就是“管 Mod”的四列（§5），而问题和变化不是平级的页面：
- **问题 → “需要处理”**：附着在 Mod 上（列表里的状态图标、详情里的说明），并在顶栏汇总成一个数字，按一个键打开清单（§7）。
- **变化 → 状态行通知**：扫描后状态行显示一句话（`✓ 扫描完成 · 12 个 Mod 有更新 · 1 个改了包名`），按 `c` 查看；每个 Mod 的变化在详情的“历史”里。需要玩家判断的身份问题（“这是同一个 Mod 吗？”）作为一项“需要处理”出现。

### 4.2 屏幕结构

```
顶栏    品牌 · 当前环境（药丸）· 需要处理 N · 未保存 N                    启动 ▶
空行
四列    未启用 | 已启用 | 暂存 | 详情
空行
状态行  ✓ / ✗ / … 一句话
提示行  上下文相关的按键提示
```

顶栏没有页面标签。进入二级界面时，顶栏换成面包屑：`RimArcho › 需要处理`、`RimArcho › 已启用 › Combat Extended`。`esc` 一律返回上一级。

## 5. 四列

### 5.1 布局

| 列 | 内容 | 宽度（160 列终端） |
| --- | --- | --- |
| 未启用 | 已安装但没启用的 Mod，按名称排序 | 约 30 |
| 已启用 | 加载顺序 | 约 40 |
| 暂存 | 玩家临时放的 Mod（§5.4） | 约 26 |
| 详情 | 光标所在 Mod 的详情（§6） | 其余，至少 40 |

- 列之间留 3 格空白，不画竖线。
- 聚焦列的标题用强调色，其他列标题淡色；未聚焦列中的光标行只把名称变为文字色，不显示 `▸`。
- 终端宽度 < 140：隐藏暂存列；用 `←→` / `tab` 聚焦到暂存时，它占据第一列的位置（`t` 仍是放入 / 移出暂存）。宽度 < 110：详情列改为按 `enter` 打开的全屏界面。宽度 < 80：三列变成三个标签，用 `[` `]` 切换。
- 聚焦只在三个列表之间切换；详情列跟随光标，V2 中不可聚焦。

### 5.2 行

```
已启用 485
   1  ⛨  Harmony
   2  ⛨  Core                                   ⊗
  12  ♨  Vehicle Framework                      ▲
▸ 13  ♨  Better Cargo Interface for Vehicles
  14  ▢  [ISEGYE IDOL] Hair style 1.6     ●
```

（示意图中的符号代表 §3 中的图标。）

- 只有四样东西：序号（淡色，右对齐，仅“已启用”列有）、来源图标、名称、状态图标（靠列右边缘）。
- 名称用别名（如果有）；中文按显示宽度截断。
- 修改过但未保存的行，在名称后加强调色的 `●`。
- 不可加载的 Mod 整行淡色。

### 5.3 操作

| 按键 | 操作 |
| --- | --- |
| `↑↓` / `jk` | 移动光标 |
| `←→` / `hl` / `tab` | 切换聚焦列 |
| `space` | 启用 / 停用：在“未启用”中按下，加入“已启用”末尾（或排序后的建议位置）；在“已启用”中按下，移回“未启用” |
| `t` | 放入 / 移出暂存 |
| `J` `K` | 在“已启用”中上移 / 下移 |
| `m` | 移动到指定位置（输入序号或 Mod 名称） |
| `S` | 自动排序：先显示差异，确认后生效 |
| `w` | 保存到游戏 |
| `L` | 启动游戏 |
| `/` | 在聚焦列中搜索（§5.5） |
| `#` | 编辑选中 Mod 的标签（§5.6） |
| `T` | 把暂存中的 Mod 全部放回原位置（§5.4） |
| `v` | 多选；`space`、`t` 作用于选中的全部 |
| `i` | 展开 / 收起详情中的技术信息 |
| `[` `]` | 宽度 < 80 时切换列表 |
| `u` / `ctrl+r` | 撤销 / 重做 |
| `!` | 打开“需要处理”（V4 之前是旧版问题列表，其中 `l` 选择日志） |
| `c` | 查看最近变化 |
| `ctrl+k` | 命令面板（§8） |
| 鼠标 | 点击选中；在列之间拖动 = 启用、停用或暂存；在“已启用”内拖动 = 调整顺序 |

### 5.4 暂存

暂存是每个环境一个、持久保存、不写入游戏的列表。两种用途：
- **准备区**：新订阅的 Mod 先放进来，想好了再启用；
- **排查区**：把一批 Mod 从“已启用”移到暂存来排查问题，排查完一键放回原位置。暂存会记住每个 Mod 原来的位置。

放回时按 `T`（全部放回原位置）或逐个按 `space`。

### 5.5 搜索

`/` 在聚焦列中输入查询，结果即时显示；`enter` 结束输入，查询保留在这一列，直到在这一列按 `esc` 清除。列标题显示 `已启用 12/485`，后面是淡色的查询文本。

查询由空格分隔的词组成，全部词都要满足（AND）：

| 写法 | 含义 |
| --- | --- |
| `词` | 名称、别名或作者包含它（不分大小写）；整个查询都没有结果时，自由词再按名称的字母顺序匹配（`hsl` 找到 “Hair Style Lib”） |
| `name:词` / `author:词` / `tag:词` | 只看名称（含别名）/ 作者 / 标签；`tag:` 要求标签等于这个词 |
| `id:值` | 包名包含它、工坊 ID 等于它，或者是 `#引用` |
| `type:值` | 来源 `official` `workshop` `local` `copy` `git`；内容 `assembly`（带 DLL）、`xml`（没有 DLL，也可写 `xml-only`）、`language`（只有语言文件，也可写 `language-pack`） |
| `has:problem` / `has:error` | 有需要处理的问题 / 有会导致加载失败的问题；还有 `has:tag` `has:note` `has:alias` |
| `-词`、`-tag:x` | 取反 |
| `"带 空格"` | 引号内是一个词 |

### 5.6 标签

- 详情中显示 Mod 的标签；列表中名称后面用淡色显示标签，放不下就省略。
- `#` 对选中的 Mod（含 `v` 多选）编辑标签：输入行列出已有标签补全（`tab` 补全当前词），`词` 或 `+词` 添加，`-词` 删除，`enter` 应用。
- 标签属于 Mod 的家族（04 §7.1），对应 CLI `tag add|remove`、MCP `set_player_data`。

## 6. 详情

### 6.2 缩略图

- 来源：Mod 的 `About/Preview.png`（大小写不敏感）。
- 缓存：缩放到宽 360 像素的 PNG，按快照哈希存进 `<数据目录>/cache/previews/`。
- 绘制：bubbletea 渲染完一帧后，用 iTerm2 内联图片协议，在详情区预留的矩形里单独绘制图片；光标离开时清除。要求光标停留 150 毫秒后再绘制，避免快速滚动时闪烁。
- 与 bubbletea 渲染器的配合已在 V0 验证，做法见 07 §6.2：包装输出 writer，在同一次写入中帧后追加清除或绘制；绘制时必须临时显示光标（ConPTY 在光标隐藏时不转发定位）。
- 尺寸由 RimArcho 决定，不交给终端：图片按比例缩放到 18×9 格以内，取能放下它的最少行数 N，用透明像素补成恰好 18×N 格的比例，以 `width=18;height=N;preserveAspectRatio=0` 发送，所以图片覆盖的正好是这 18×N 格（16:9 占 5 行，正方形 8 行，竖图 9 行）。不能用 `preserveAspectRatio=1`：WezTerm 会保持宽度、按比例推算高度，竖图会超出预留区。
- 清除规则：选中项变化时，对 18×9 的整个预留区逐行执行 `ECH 18`。图片不会超出预留区，所以这样就清掉了它的全部像素。文字覆盖和 bubbletea 的整行重写都不能擦掉图片格子，不能依赖它们。
- 版面始终按 18×9 预留，不随图片的实际行数变化。

### 6.4 简介的来源（2026-10-19 调研）

**测量**（玩家环境，1274 个有 About.xml 的工坊 Mod，只读；工坊描述用 Steam 公开接口 `ISteamRemoteStorage/GetPublishedFileDetails/v1`，无需 key，13 次批量请求取回 1264 个）。按去掉 BBCode 和图片后的纯文本长度：

| 长度 | About.xml | 工坊页面 |
| --- | --- | --- |
| 空 | 25 | 1 |
| 1–79 字 | 355 | 19 |
| 80–299 | 376 | 108 |
| 300–999 | 276 | 345 |
| ≥ 1000 | 242 | 791 |

- About.xml 为空或不到 80 字的占 30%（380 个）；其中 305 个的工坊页面有 300 字以上。两边都只有一两句、也没有图片的只有 18 个。
- 504 个 Mod 的两边开头是同一段文字（作者复制了一份）。只有 5 个用了 `descriptionsByVersion`。
- 工坊描述 55%（696 个）带图片，共 7981 张；139 个以图片为主（≥ 3 张、每张不到 100 字的文字）。几乎全是图文混排：文字不到 80 字、只有图片的只有 1 个。
- 图片格式：PNG 7351、GIF 323、无扩展名 244、JPEG 55、WebP 6。图床：i.imgur.com 72%，其次 raw.githubusercontent.com、img.litet.net、i.postimg.cc、Steam 自己的 images.steamusercontent.com。
- 出现最多的 BBCode：`img` `*`（列表项）`url` `b` `h1` `list` `h2` `td` `h3` `i` `tr` `hr` `th` `u` `table` `code` `nl` `strike` `olist` `quote`。

**决定：**

1. **来源。** About.xml 的 `description`（若有当前游戏版本的 `descriptionsByVersion` 条目则用它）随时可读，从磁盘按需读取，不存进数据库。工坊页面描述在线获取。
2. **选哪个。** 有工坊描述时：About.xml 不到 300 字，或者两边开头相同，只显示工坊描述（标题“简介 · 工坊页面”）；两边都长且不同，先显示 About.xml，再显示工坊描述（两个小标题）。没有工坊描述（本地 Mod、离线、获取失败）时显示 About.xml，并在小标题后淡色注明原因。
3. **何时获取。** 只为选中的 Mod 按需获取：光标在一个工坊 Mod 上停留 400 毫秒后，在后台发一次单个 ID 的请求，不预取整个列表。结果缓存在 `<数据目录>/cache/workshop/<工坊 ID>.json`。缓存里的 `time_updated` 不早于本地 appworkshop 清单中的 `timeupdated` 时视为最新，不再联网；没有清单时间时，缓存 7 天有效。全屏详情里按 `r` 强制刷新。
4. **离线开关。** `archo config set workshop.fetch on|off`（默认 on）；`workshop.images on|off`（默认 on）单独关闭图片下载。关闭后只用缓存和 About.xml。联网只访问 Steam 的这个公开接口，以及工坊描述里出现的图片地址。
5. **BBCode 渲染**（按显示宽度换行，遵守 §2.1）：`h1`–`h3` 粗体文字色并前后空一行；`b` 粗体；`i` `u` 照常显示（不用斜体和下划线）；`strike` 淡色；`list`/`olist` 用 `•` 和序号、按层级缩进两格；`url` 显示链接文字，WezTerm 中用 OSC 8 做成可点击，兼容模式在文字后面淡色显示域名；`quote` `code` 缩进两格、次要色；`table` 按列对齐、放不下的列截断；`hr` 变成空行；`nl` 换行；`noparse` 原样；未知标签去掉、保留内容。
6. **图片。** 完整模式（WezTerm）：`[img]` 在原位置占一块区域，宽度为列宽和 60 格中较小者，行数按图片比例算、最多 20 行；下载、解码、缩放到 720 像素宽后缓存为 PNG（`<数据目录>/cache/workshop-img/`），用 §6.2 的 OSC 1337 方法绘制（补成整格比例、`preserveAspectRatio=0`、离开时 ECH 清除）。图片只有完全进入可见区域时才画，部分可见时显示占位行；图片在需要时才下载。GIF 只显示第一帧；WebP 和解码失败的显示占位。兼容模式：一行淡色占位 `[图片 · i.imgur.com]`。
7. **图片里的文字（OCR）**（2026-10-20 修订：要做，改用视觉模型，放进 AI 工作台，见 09 §5.2。下面是原结论）不做：Windows 自带 OCR 需要 WinRT 调用，对工坊横幅这类艺术字识别不可靠；而且测量显示只靠图片写简介的 Mod 只有 1 个。

## 7. 需要处理

### 7.1 内容

按“问题出在哪里”分组，每组是一个淡色小标题：

| 分组 | 包含 |
| --- | --- |
| 这个列表 | 官方内容顺序、加载顺序、顺序矛盾、同一个 Mod 启用了两份、列表为旧版本保存 |
| 缺少的前置 | 缺失或未启用的依赖 |
| 冲突 | 不兼容的 Mod 同时启用；有日志证据的补丁冲突 |
| 上次运行 | 当前列表下最近一次游戏日志中的错误，按 Mod 归并 |
| 需要你确认 | 身份待确认项（02 §5.4）、外部修改了列表 |

### 7.2 每一项的写法

| 内部代码 | 玩家看到的 | 一键操作 |
| --- | --- | --- |
| `dep.missing` | A 需要 B，但没有安装 B | `o` 在工坊打开 B |
| `dep.inactive` | A 需要 B，但 B 没有启用 | `space` 启用 B |
| `order.violated` | 只有一条时：A 应该排在 B 之后；多条时合并成一项：10 个 Mod 的顺序不对（数的是需要挪动的 Mod），`enter` 展开逐条列出 | `S` 自动排序 |
| `official.order` | Core 和 DLC 要排在最前面 | `S` 自动排序 |
| `order.cycle` | 3 个 Mod 的顺序要求互相矛盾 | `enter` 查看，`x` 忽略建议的那一条 |
| `incompat.active` | A 与 B 不兼容 | 选择停用哪一个 |
| `pkg.duplicate-active` | 同一个 Mod 启用了两份 | 选择保留哪一份 |
| `patch.no-match` | A 的部分内容没有生效（它针对的 B 没有启用） | `space` 启用 B，或 `enter` 查看 |
| `version.unsupported`（汇总） | 293 个 Mod 没有标明支持 1.7（其中 288 个支持 1.6） | `enter` 查看列表 |
| `log.*` | 上次运行时 A 报了 12 次错 | `enter` 查看日志与证据 |

补充（V4 裁定）：
- `patch.no-match` 只有在它针对的 Mod 已安装但未启用时（target-inactive）才出现，归入“缺少的前置”；目标根本不存在、版本路由错误等情况玩家无法处理，留在“技术信息”。
- `def.parent-missing`（错误）写成“A 的部分内容继承的定义不存在，可能缺少前置 Mod”，归入“缺少的前置”，`enter` 查看。
- `mod.unloadable`（已启用但游戏无法加载）写成“A 已启用，但游戏无法加载它”，`space` 停用；`entry.missing` 写成“列表里有 X，但没有安装它”，`o` 在工坊搜索、`space` 从列表中移除；列表为旧版本保存写成一项，`w` 保存。这三项都归入“这个列表”。
- `version.unsupported` 只有在其中有 Mod 连上一个版本都不支持（warning）时才出现；全部只是支持上一版本时，按 info 处理，不出现。
- 合并规则：同一种问题如果一个键就能全部解决，就合并成一项，`enter` 展开逐条显示；目前只有 `order.violated`（`S` 一次排好）。缺失的列表条目、未启用的依赖、日志等每条要单独处理，不合并。
- 顶栏的数字 = 这个页面上可以操作的项数（折叠的旧日志那一行不算），合并后的一项算 1，所以数字反映的是要做几件事，而不是有几条发现。列表行上的状态图标也只标在这些项涉及的 Mod 上，所以图标和数字一致。

### 7.3 什么不出现在这里

- info 级别（Def 覆盖、补丁争用、共享 Harmony 目标等）：只在详情的“技术信息”里，以及 CLI 和 MCP 中。
- 没有日志证据的 Harmony 警告：归入“技术信息”。玩家无法据此行动。
- 旧日志（早于当前列表，或来自另一个游戏版本）：折叠成一行 `更早的日志 · 9 月 29 日 · 1.6`。

## 9. 反馈与确认

- **状态行**：倒数第二行，一句话。`✓`（绿）表示完成、`✗`（红）表示失败、`…`（次要色）表示进行中。下一次按键时清除。

- **危险操作双击确认**：例如在详情中删除本地副本，第一次按显示 `✗ 再按一次 d 删除 XXX`，按其他键取消。目前用于：载入外部修改的 ModsConfig.xml（`L`，会替换未保存的修改）、回答身份问题（`s` `c` `u`，合并或拆分 Lineage 不能用 `u` 撤销）。能用 `u` 撤销的操作不需要双击。
- **保存前确认**：保存是写游戏文件的唯一动作，所以保留一个确认界面，显示差异和版本改写说明（04 §2.2）。

## 12. v2.1 交互修订（2026-10-20，玩家试用反馈）

### 12.1 列宽与换行

- 三个列表列（未启用、已启用、暂存）的宽度可以调整：
  - 键盘：`<` `>` 缩小 / 放大聚焦列，每次 2 格；`=` 恢复默认。
  - 鼠标：拖动列之间的空白分隔区。
  - 宽度按环境保存，下次启动沿用。详情列取剩余宽度，最少 40 格；不够时先压缩其他列。
- 名称换行：`z` 切换聚焦列的“名称换行”。开启后，长名称按显示宽度折成多行（遵守 §2.1 之外的这一例外），序号、来源图标、状态图标只出现在第一行。设置按列保存。

### 12.2 以实例为中心的“拾取”操作

操作分两步：**先拾取，再对拾取的实例下动作。** 拾取是选择，不改变任何东西；动作才改变列表。

**拾取（选择）**

| 输入 | 效果 |
| --- | --- |
| `↑↓` / `jk` | 移动光标（没有拾取时） |
| `shift+↑↓` | 从光标处开始或扩展连续拾取 |
| `ctrl+↑↓` | 移动光标，不改变拾取 |
| `ctrl+space` | 切换光标所在行的拾取（间断多选） |
| `space` | 没有拾取时：拾取光标所在的一行 |
| 鼠标单击 / `shift+单击` / `ctrl+单击` | 光标 / 范围拾取 / 切换拾取 |

拾取的行用强调色的 `▌` 标在行首，名称变为文字色。拾取只能在同一列内进行；切换列会清空拾取。

**拾取后的动作**

一旦有拾取，在拾取范围的旁边出现一个小悬浮窗（无边框，药丸底色 `#2C2E4A`，靠近拾取行，不遮住拾取行本身）：

```
 已拾取 3 个 · 已启用 #352–354
 ↑↓ 位置   ←→ 移到 未启用 / 暂存   # 标签   t 暂存   enter 放下   esc 取消
```

此时按键作用在**拾取的实例**上，不再移动光标：

| 按键 | 动作 |
| --- | --- |
| `↑↓` | 在“已启用”中整体上移 / 下移一位（保持拾取内部的相对顺序；间断拾取先收拢到第一个的位置）。在“未启用”和“暂存”中这两个键无效，悬浮窗里显示为淡色 |
| `shift+↑↓` | 整体移动 10 位 |
| `←→` | 移到左 / 右相邻列表（未启用 ↔ 已启用 ↔ 暂存）。移入“已启用”时，放在满足排序约束的建议位置（没有约束时放末尾），然后可以继续用 `↑↓` 调整；悬浮窗实时显示目标位置 |
| `#` | 打开标签候选行（§12.3），对全部拾取的实例生效 |
| `t` | 放入 / 移出暂存（等同于移到暂存列，但光标留在原列） |
| `enter` | 放下：结束拾取，保留所有改动 |
| `esc` | 取消：结束拾取，并撤销这次拾取期间做的全部移动 |

- 拾取期间的每一步都实时显示在列表里（预览即结果），但整次拾取只记为**一条**撤销记录。
- 光标跟随拾取的实例：放下后，光标停在第一个被拾取的实例上（它可能已经在另一列）。
- 没有拾取时，原来的单键操作（`J` `K`、`space` 启用 / 停用等）仍然可用，作为快捷方式。

鼠标框选和拖动放到 GUI 中实现，TUI 不做。

### 12.3 标签候选行

`#` 在悬浮窗（或详情）下方打开一行候选，不是输入框：

```
 ✎ 输入…   [框架]  [美化]  [服装]  [种族]  [武器]  [建筑]  [QoL]  [测试中] …
           ▲ 初始选中第一个候选
```

- `←→` 移动选择；`enter` 应用；`esc` 关闭。
- 第一个候选左边是“✎ 输入…”：从第一个候选按 `←` 就到达它，此时可以直接打字，`enter` 创建并应用新标签。因此手动输入的按法是 `#` `←` 然后输入。
- 已经挂在**全部**拾取实例上的标签显示为 `[✓框架]`，`enter` 会把它从这些实例上移除；只挂在部分实例上的显示为 `[~框架]`，`enter` 补齐到全部。
- 候选顺序：常用标签（可配置，`archo config set tags.pinned "框架,美化,…"`）在前，然后按使用次数排序的已有标签。候选行放不下时向右滚动。
- 预置常用标签（首次运行写入，玩家可以修改）：框架、美化、服装、种族、武器、建筑、家具、QoL、平衡、剧情、性能、语言包、测试中、待删除。

### 12.4 图片

- **缩略图不再等待。** 选中项变化时立即绘制。为了不让快速滚动卡顿：
  - 在后台预取光标上下各 10 个 Mod 的缩略图，缓存编码好的图片序列（内存 LRU，上限 64 张，约 6 MB）；
  - 命中缓存时立刻画；未命中时立刻开始解码，解码完如果光标还在这一行就画，否则丢弃；
  - 每帧最多绘制一张图片。
  `ui.preview_dwell_ms`（默认 0）保留为可配置项，玩家觉得闪烁时可以调大。
- **简略详情不再内嵌描述里的图片**：只显示缩略图和文字，描述中的图片显示为一行淡色占位 `[图片 ×3 · enter 在全屏中查看]`。描述图片只在全屏详情中绘制。
- TUI 的图片是“锦上添花”：终端图片协议有先天限制（ConPTY 的光标问题、按整格对齐、无法部分裁剪），所以图片画廊、大图浏览等功能留给 GUI。`ui.previews off` 可以整体关闭图片。

### 12.5 详情的滚动与切换

- **简略详情可以聚焦**：在已启用 / 暂存列按 `→`（没有拾取时），或鼠标点击详情列，焦点进入详情列；`↑↓` 滚动详情内容；`←` 或 `esc` 回到列表。焦点在详情列时，详情标题用强调色。
- **全屏详情**（`enter` 进入）：
  - `↑↓` / `PgUp` `PgDn` / 鼠标滚轮：滚动内容；
  - `←→`：切换到所在列表的上一个 / 下一个 Mod，滚动位置回到顶部；
  - `tab` / `shift+tab`：在子区（概要、Def、补丁、Harmony、规则、历史）之间切换；
  - `esc`：返回，光标停在最后查看的那个 Mod 上。

## 13. v3 交互模型（2026-10-20）

> 设计原则（玩家提出，2026-10-20 更新）：不让玩家沿着一条复杂路径完成操作，而是让玩家**随时知道自己在哪里、可以去哪里、怎么回去**，并以**最少的步骤**完成任务。
> “怎么回去”有两层：界面上，每个弹层和二级界面都能用 `esc` 或面包屑回到上一级（§13.2 规则 5、T20）；数据上，每次修改都能在修改历史里看到并撤回（见 08 §14 的历史区）。
> 本节**取代** §12.2（拾取会话与悬浮窗）和 §12.5 中“→ 进入详情”的特例；§5.3 中与本节冲突的按键以本节为准。§12.1（列宽、换行）、§12.3（标签候选行）、§12.4（图片）保留。

### 13.1 问题诊断（v2.1）

- 约 13 种状态：列表、筛选输入、拾取会话、标签行、命令面板、详情焦点、全屏详情、检查栈、需要处理、变化、排序差异确认、保存确认、帮助。
- 同一个键含义太多：`←→` 有 5 种含义（切列、把拾取的 Mod 移到相邻列表、标签选择、全屏切换 Mod、进入详情），`↑↓` 有 4 种。玩家必须先记住“我现在处在哪种状态”，才知道方向键会做什么。按错时，方向键甚至会移动 Mod。
- 拾取模式把“选择”和“动作”串成一条路径：拾取 → 移动 → 放下 / 取消。路径中途的状态只能从悬浮窗看出来。

### 13.2 五条规则

1. **方向键只导航，永不改动数据。** 在任何状态下，`↑↓←→` 都只移动光标、焦点或滚动位置，不移动 Mod、不启用、不打标签。
2. **动作是动词键，立即生效，`u` 撤销。** 动作作用于“对象”：有选中时是选中的实例，否则是光标所在行。动作不进入任何模式，没有“放下 / 取消”这一步。
3. **位置始终可见。** 顶栏的位置行随时说明：焦点在哪个区域、光标是第几个、选中了几个、当前打开了什么弹层。
4. **可去哪里始终可见。** 底部提示行只列出当前对象此刻能用的动作（最多 7 个），`?` 列出全部，`ctrl+k` 可以从任何地方去任何地方。
5. **弹层最少。** 只有命令面板、标签候选行、位置输入、确认、帮助五种。每个弹层都有标题并显示在位置行中，`esc` 关闭，不嵌套。

### 13.3 焦点区与位置

- 四个焦点区：`1` 未启用、`2` 已启用、`3` 暂存、`4` 详情。数字键直接跳到对应区；区标题前显示这个数字（淡色）。
- `←→` 在相邻焦点区之间移动，详情是最右边的第 4 区。
- 聚焦区：标题用强调色，光标所在行加一层很淡的整行底色（`#1A1C24`）。非聚焦区的光标只把名称变成文字色，不加底色。这样屏幕上永远只有一处“最亮的地方”。
- 顶栏右侧的位置行：
  - 列表区：`已启用 · 322 / 488 · 已选 3`
  - 详情区：`详情 · Combat Extended · 简介 40%`
  - 弹层打开时在后面追加，例如：`已启用 · 322 / 488 › 标签`
  - 全屏详情：`已启用 › Combat Extended（322 / 488）› Harmony`

### 13.4 方向键的含义（全部状态）

| 状态 | `↑↓` | `←→` |
| --- | --- | --- |
| 列表区 | 移动光标 | 切换焦点区 |
| 详情区 | 滚动详情 | 切换焦点区 |
| 全屏详情 | 滚动内容 | 上一个 / 下一个 Mod（仍是导航） |
| 弹层（面板、标签行、位置输入） | 在弹层的选项中移动 | 在弹层的选项中移动 |

另外：`PgUp` / `PgDn` 和鼠标滚轮在任何区域都滚动详情，不改变焦点，所以读简介不需要先切到详情区。

### 13.5 选择

- `shift+↑↓`：从光标处扩展连续选择。
- `ctrl+space`：切换光标所在行的选中状态。普通的 `↑↓` **不会**清除选择，所以“移动光标 → `ctrl+space`”就能间断多选。
- 鼠标：单击移动光标，`shift+单击` 范围选择，`ctrl+单击` 切换选中。
- `esc`：清除选择。切换到另一个列表区时，选择也会清除（底部提示行会先说明这一点）。
- 选中的行行首有强调色的 `▌`。有选中时，底部提示行变为：`已选 3 · space 停用 · t 暂存 · m 移动 · # 标签 · esc 取消选择`。这只是提示行，不是悬浮窗，也不是模式。

### 13.6 动词键

| 键 | 动作（作用于对象） |
| --- | --- |
| `space` | 启用 / 停用。启用时直接放到排序约束建议的位置；状态行说明 `✓ 已放在第 352 位 · m 改位置` |
| `t` | 放入暂存；在暂存区中则放回原来的位置 |
| `m` | 移动到…：打开位置输入（§13.7） |
| `J` / `K` | 在“已启用”中下移 / 上移 1 位；`shift+J` / `shift+K` 移动 10 位 |
| `#` | 标签候选行（§12.3） |
| `enter` | 全屏详情 |
| `o` | 打开工坊页面 |
| `S` / `w` / `L` | 自动排序 / 保存 / 启动（作用于整个列表） |
| `u` / `ctrl+r` | 撤销 / 重做（每个动作一步） |
| `!` | 需要处理 |
| `/` | 搜索（§13.8） |
| `ctrl+k` | 命令面板 |
| `?` | 全部按键 |

### 13.7 位置输入（`m`）

```
 移动 3 个到 ❯ harm▌
   之后  Harmony                       （第 1 位）
   之后  Harmony Patches for VFE        （第 212 位）
   第 352 位（建议位置）
   最前 · 最后
```

- 可以输入数字，表示“移到第 N 位”；也可以输入 Mod 名，模糊匹配后显示候选，候选默认是“放在它之后”，`tab` 切换为“放在它之前”。
- 不输入、直接 `enter`，就移到建议位置。
- 对象在“未启用”或“暂存”中时，`m` 等于“启用并放到所选位置”。

### 13.8 搜索（`/`）

- 筛选聚焦的列表区，语法同 §5.5（`name:`、`tag:`、`-` 等）。
- 输入框下面多一行：`其他区：未启用 2 · 暂存 0 · tab 跳到下一个匹配的区`，所以不用先想“它在哪一列”。
- `enter` 结束输入，筛选保留；`esc` 清除筛选。

### 13.9 常见任务的步数

“+ 名字”表示还要输入几个字符。

| 任务 | v2.1 | v3 |
| --- | --- | --- |
| 启用一个已知名字的 Mod，并放到合适位置（焦点在已启用区） | `←` `/` 名字 `enter` `space` `→` `enter`：6 键 + 名字 | `/` 名字 `tab` `space`：3 键 + 名字 |
| 把一个 Mod 挪到另一个 Mod 后面（相距 120 位） | `space`，`shift+↑` 约 12 次，`enter`：约 14 键 | `m` 名字 `enter`：2 键 + 名字 |
| 停用 3 个不相邻的 Mod | 用 `ctrl+↑↓` 移动加 3 次 `ctrl+space`，`←` `enter`：移动键 + 5 | 用 `↑↓` 移动加 3 次 `ctrl+space`，`space`：移动键 + 4 |
| 读完当前 Mod 的简介 | `→` `↓↓↓` `←`：5 键 | `PgDn` `PgDn`：2 键 |
| 给 5 个连续的 Mod 加一个常用标签 | `shift+↓` 4 次，`#` `→` `enter`：7 键 | 相同：7 键 |
| 把一半的 Mod 放进暂存来排查问题 | `shift+↓` N 次，`t`，`enter` | `shift+↓` N 次，`t` |
