### 2.9 Mod inventory, updates

The existing confirmation previews for moving copies to the library, deleting, and unsubscribing list every affected game, full link path, original target, and detach or rebuild action. Duplicate-copy moves use the same preview without another prompt. Moving a managed directory shows the same inbound-link plan in its existing dialog before confirmation. Unfinished ledger operations appear as recovery items in can it run, using link repair's single confirmation entry (08 §3). Opening a page writes no files.

The copy-detail action area does not repeat open the folder, Open Workshop page, or Steam page buttons. Use the location and Workshop entries in the fields (§4.1); context menus and shortcuts can still open them.

**do not list as a copy** (2026-10-23): this button appears in Mod and copy details, for the selected copy in the full-screen Copies section, and in the shared organization menu. It is available only for one copy that has another locally installed sibling, never for multiple selection. Clicking splits the copy into an independent Mod, copying its alias, tags, and Mod note while retaining the copy note. After refresh, keep displaying the separated copy, and remove the button. The identity change applies globally; actual loading conflicts between identical package IDs are still checked. This action does not enter plan undo history (02 §6).

**All** is implemented in GUI `library.js` and the TUI command panel's Mod inventory entry, using `app.Library` → `view.BuildLibrary`. It answers which Mods the player has, how many copies each has, where they are, where they are used, and how much space they occupy. It only manages Mods already installed locally, rather than acquiring Mods or browsing and searching the Workshop (01 §3).

**The layout has two parts and follows the plan editor's approach** (confirmed by the player's drawing on 2026-10-22). The left column is about as wide as the editor's left column. A collapsible filter bar, shared with the editor, occupies its own card at the top. Below a gap, another permanent Mod and copy detail card fills the remaining height. A wide table occupies the right. Both pages therefore have filters at the upper left with a column beneath them. The left width defaults to `clamp(280px, 26%, 440px)`. Drag the divider to resize it, saving to `ui.gui.library.side`; double-click resets it. The page fills the window without a centered maximum width. As the window widens, the name column takes the surplus width, while resized or reordered columns keep their saved widths. Below 900px, filters sit above the table, and `enter` overlays details. The table follows Explorer's Details view: one row per Lineage (02 §6), expandable to show each Instance.

Inventory does not edit `About.xml` or bind `space`, `m`, `t`, `x`, or plan undo and redo keys.

**States** appear only when something is abnormal:

| State | When | In row | Action |
| --- | --- | --- | --- |
| Cannot load | No readable `About.xml`, etc. (`mod.unloadable`) | Yes | open the folder |
| Subscribed but missing on disk | An ACF subscription has no folder on disk | Yes | Open webpage |
| Game ignores this copy | Another copy with the same package ID comes first in `Mods/` (04 §4.2, `pkg.duplicate-installed`) | Yes | Back up locked version |
| Unsubscribe residue | A Workshop folder remains after its subscription is removed | Yes | Delete or resubscribe |
| Hidden by another manager | `About.xml` was renamed About.xml.disabled (08 §6) | Yes | Restore or delete |
| Upstream updated | A locked version's upstream has changed (04 §7.3) | Yes | View the diff or update the locked version |

The first four also count as needing attention: unloadable, missing, and ignored copies require player action. Unsupported current game and unused are not states. They were removed in 0.9.0 from filters, `state:` values and completion, and CLI and MCP output. These are normal conditions affecting most of a library with more than a thousand Mods, so showing them in rows or filters adds noise. Supported versions belong in their facet and detail fields; find unused copies through Used in › No plans (`used:none`).

**Actions**: the six copy-detail actions appear only when applicable, in a fixed order:
1. **Restore** (`unhide`) makes a copy hidden by another manager visible to the game again.
2. **Unsubscribe** for a Workshop copy, or **Delete** for an owned copy: unsubscribe actually calls the running Steam client (08 §10). Steam then deletes the Workshop folder, so show `--dry-run` text naming the folder and confirm, as for deletion. Refuse while the game runs. An enabled copy or one used by a plan can still be removed without first editing the lists. The confirmation names the affected lists; after confirmation, execute the action and leave their entries marked missing, for each item in a batch. Only when Steam is unavailable, `steam_api64.dll` is missing from the game directory, or the DLL cannot load does the action fall back to opening the Workshop page. The status explains the Steam connection failure and asks the player to unsubscribe on the page. Delete moves the folder to the recycle bin (`trash`, 08 §7). It is available only for RimArcho's owned copies in `Mods/` or the lock library, SteamCMD copies without a subscription that would download them again, and unsubscribed residue or hidden Workshop folders. Used copies get the same list warning. Refuse if the copy itself is a link, such as `_Link_*`, without touching its target. Show the dry run before confirmation.
3. **Resubscribe** applies to Workshop originals, including residue, with a numeric Workshop ID, provided the copy is neither a link nor a locked version. Preview and confirm first. For a subscribed copy, unsubscribe first; after Steam confirms success, RimArcho recycles the original folder, verifies that the original path no longer exists, and subscribes again. Do not subscribe items whose cleanup failed; report the reason. The preview explicitly warns that RimArcho recycles the folder before Steam downloads it again, losing local changes. Enabled or used copies are allowed, but a running game causes refusal. Retain the original path, Workshop ID, Instance and Lineage identities, and list references. Residue skips unsubscribe and cleanup. After confirming the subscription, including for residue, explicitly request the Steam download and wait for files on disk, with per-item progress in background tasks. Stalls suggest checking Steam. If Steam is unavailable, use the same webpage fallback. See 08 §10 for call rules.
4. **Back up locked version**, meaning move into the lock library as below, applies to an extra `Mods/` copy.
5. **open the folder** opens its folder.
6. **Open webpage** is available when a Workshop ID exists.

The context menu and multiple-selection bar also offer tags, copy note, do not list as a copy, pin, update locked version, unpin (04 §7), and subscription-source check, update, and remove. A single copy has no Convert textures to DDS action. Keep Clear converted textures when converted files exist; batch conversion remains on texture optimization (08 §5.2). All actions come from `view.OpTable`, which defines their code, name, key, and menu group. `view.CopyOps` returns only applicable codes for the page and copy state. Names and keys are sent once with the page data.

**Copy note** (implemented, schema v13 `instance_note`): each Instance owns a paragraph at the top of details. If the player has not written one, show RimArcho's generated first version in gray. For example: this locked version was created on Oct 21 for the Test plan; its upstream has updated twice since; reason: the new version changed the save format. Copies not created by RimArcho also get a first version describing their origin and first discovery date, and later Workshop updates when both coexist. Examples include Workshop subscription, first seen Oct 19; game Mods folder, first seen Oct 19, Workshop updated twice since; and unsubscribed, Steam left the folder. A subscription without a folder has no generated note:
- Record provenance when creating the copy: `made` identifies pin, update pin, or move-to-library; also record the time, plans, and player's `--reason`. Recalculate the text on display so the count of subsequent same-Lineage Workshop updates remains correct.
- Clicking edits the currently displayed text. `enter` saves, `shift+enter` adds a newline, and `esc` cancels. Empty text restores the generated version. In TUI inventory, `n` edits the note, choosing a copy first if there are several.
- CLI uses `archo note <ref> <text> --copy` (`--clear` clears), `archo pin … --reason`, and `library move-to-locked … --reason`. MCP uses `copy_note` in `set_player_data` and `reason` in `pin_mod` and `manage_library` (05). `archo library --lineage` lists `note:` beneath each copy.
- The Mod note (`archo note <ref>`, §4.1 Note, search `has:note`) belongs to the Lineage and is shared across copies and plans; it describes the Mod. The copy note explains why this copy is retained. `has:note` still checks only the Mod note; inventory text search searches both.

**Move into lock library** (implemented, `archo library move-to-locked`): keep alternate versions of a Lineage in the lock library, leaving at most one copy per package ID in `Mods/`. The plan chooses which copy to use (04 §7). Extra copies left by manual copying or other managers can move here after confirmation. On the same volume, rename the folder. Across volumes, copy it, verify every file, and recycle the original. Retain its Lineage identity and plan references: before scanning, point the Instance to its new location so source and path reconciliation matches it (R1). Its ID, Lineage, and history remain unchanged; the next write or launch exposes it through an `_Archo_` link. If `.rimarcho/origin.json` is missing, create it with the same-Lineage Workshop copy as upstream, or itself if none exists. `origin_snapshot` is this copy's own snapshot, so Upstream updated means its content differs from the Workshop copy. Only move folders inside `Mods/` with another copy in the same Lineage or an existing `origin.json`. Refuse links inside the folder that point outside it, even for a same-volume rename. `pin --move-to-library` uses the same move but still only accepts old copies with `origin.json` (04 §7.4). See 01 §4 for file writes.

Each copy carries only action codes. Paths and Workshop URLs stay in Go, with detail fields fetched on demand and folders or pages opened by Instance. This reduced the 1284-Lineage payload from 1.47 MB to 0.77 MB. This page describes machine-wide copies, so its top bar has no environment label; the editor still has one. The page button only says Rescan. The TUI uses the same fixed default columns: name, size, state, source, and usage. It uses the shared §3.5 keys, plus → to expand a Lineage or focus copy details, ← to collapse or return to the Lineage, `s` for the header menu, C for this Mod's changes, and R to rescan. From RimCrow's Inventory hub › Full library data management, adopt physical-copy rows, the distinction between same-source duplicates and cross-source identity, subscribed-but-missing ghost entries, recycling by default, and explicit consequences in confirmations. **Changes** (already updated within subscriptions; GUI `subscriptions.js`, TUI `c`; CLI `archo changes` and MCP `list_changes` remain unchanged): this answers what changed in the player's used Mods since last play and whether it needs attention. History comes from `internal/modchanges`, and the three-section page from `view.BuildSubscriptions`.

- **One Mod per row** combines all its events in the time range into a name and one sentence explaining their meaning. A small tier badge shows **Affects launch** / **Worth a look** / **Content only**. Sort by tier, then name.
  - Affects launch applies only when the Mod is in the current plan: a new dependency is not installed or enabled, support for the current game's version was dropped, a new incompatibility involves an enabled Mod, or the package ID changed.
  - Worth a look covers changes to `.dll` code, Defs, Patches, LoadFolders.xml, load-order rules, or supported versions, and a locked version lagging behind the Workshop. A version-number change qualifies only when accompanied by Defs, Patches, or code changes.
  - Content only covers changes only to textures, audio, translations, or other files, as well as renames and changes to authors or folder locations.
- **Use existing data only, without new analysis.** The sentence contains at most three of the most urgent facts. Expansion starts with a file summary grouped by category, then facts that did not fit and the Workshop update time:
  - List added and removed supported versions, marking the current `st.GameMM()` version as current game.
  - Show the before and after `About.xml` `modVersion`.
  - Name added or removed dependencies, combining the base declarations with the current version's `modDependenciesByVersion`, and mark not installed or not enabled as in `view.Deps`.
  - Compare `incompatibleWith` and `loadBefore` / `loadAfter` in the two snapshots' `decl_blob`, including `forceLoad*` and versioned forms. The `load-rules-changed` event carries no detail itself (02 §5.3), so compare the declarations.
  - Group files as code (`.dll`), Defs, Patches, About/LoadFolders, textures (`Textures/`), audio (`Sounds/`), translations (`Languages/`), and other. Compare `snapshot_file` hashes when present for semantic files, otherwise sizes. Show size deltas for textures and audio, plus the total delta when multiple categories changed. For example: 4 Defs changed, 1 added, textures +3.2 MB, total +3.4 MB. The facts above already describe About.xml changes, so do not add a duplicate changed entry for it.
  - Show the Workshop update time, `acf_time_updated`.
  - For a locked version used by the plan (04 §7), include its upstream in scope. If upstream updated, report N updates behind, using `Store.UpdatesSince` from the copy time in `origin.json`.
  - Phase two is **pending**: claims such as N new Defs or this patch now fails require per-version analysis summaries, which are not stored yet and are therefore not produced.
- **Scope and time**:
  - Default to current-plan Mods, including the upstream of locked versions it uses. Switch to the full inventory through the GUI scope bar and a, CLI `--library`, or MCP `library`.
  - Default to since the current plan's last play (`Store.LastPlanLaunch`, launch records, 08 §1), or the last scan's changes if never played. CLI and MCP `--since scan:<n>|<days>d|YYYY-MM-DD` change the starting point.

**search files** (Mod library › search files, a sidebar child and command-panel entry; 2026-10-30, GUI `filesearch.js`, `view.FileSearch`): search text in Mod files as with `archo files search` (03 §5.5), or C# code as with `archo source search --in` (03 §5.4). There is no index; every search reads the files again.
- The first block is the search row: input, case sensitivity (`alt+c`), whole word (`alt+w`), regex (`alt+r`), and Def name (`alt+d`). Def mode determines case and whole-word behavior and disables those two switches. Two rows below select kind and scope. Kind is Files / C# code (`alt+1` / `alt+2`). Files offers Defs, Patches, and About by default, plus translations, textures, sounds, and assemblies. The default scope is the open list's enabled Mods, shown as a muted <list> enabled N Mods block. + Mod opens an inline name lookup with up to 6 candidates, as in sorting rules; named Mods have a removable ×. C# searches only named Mods. With none named, the status asks the player to add one first because decompiling a whole list takes many minutes; there is no `--active` option. Case, whole-word, and Def-name controls are absent for C#, which is always case-insensitive. The page does not expose CLI `--all-versions`, `--game`, `--lang`, `--mode`, or `--per-file`.
- Enter in the input starts a search. Changing options, kind, or scope reruns it when the query is nonempty. Each search invalidates the previous one: `API.BeginFileSearch` obtains a sequence number, old results are discarded, and Go cancels the old context. While running, the heading shows Searching, or decompilation progress for C#; polling and decompilation limits are in §2.16.1 G17. The only right-side action is Stop (`esc`). Leaving the page also stops it (`API.Leave("search")`).
- The Results block groups Mod → file → line. A Mod heading has a muted number, a name linking to full details, and its hit count. A file shows its relative path, which copies the full path on click (§3.1 rule 12), and the count of omitted lines. A result line shows the line number, muted Def-mode role and containing Def or XPath, and highlighted matches. The heading gives total hits, Mods, files, amount searched, and elapsed time. An empty result says Not found and identifies content excluded by the default scope. If named C# Mods have no assemblies, say so. Show at most 60 lines per page and 5 per file (`view.FileSearchPerPage`, `FileSearchPerFile`), with `[` `]` or bottom buttons to paginate. Unreadable files and incompletely decompiled assemblies appear muted below the results.
- The cursor only visits files and lines. Arrows, `j k`, `PgUp PgDn`, and `Home End` only navigate (§3.1 rule 1). Enter or ctrl+o opens the containing folder, restricted to this Mod's directory or the C# cache (`view.SearchFolder`, through `API.OpenSearchFolder` in the GUI). `ctrl+c` copies the full path. `/` or `ctrl+f` returns to input; `↓` in input enters results, and esc leaves input while retaining the text, or stops a running search. Esc from full details opened through results returns here.
- **TUI** (2026-10-31, `surface/tui/filesearch.go`): use the same `view.FileSearch` and two blocks, `1` search and `2` results. Enter from the command panel or Tab from add a subscription, using the GUI library subpage order. Kind and scope are blocks below the input. Up/down moves among the input and those two rows, left/right changes blocks, and Space toggles them. Switch keys match the GUI: alt+1, alt+2, alt+c, alt+w, alt+r, alt+d. + Mod opens inline name input, arrows select a candidate, and Enter accepts it; Del on a named Mod's block removes it. In results, [ ] paginates and Enter or ctrl+o opens the folder. The terminal has no click-to-copy or ctrl+c copying, since ctrl+c exits. Mod names do not link to full details; use the panel to jump to that Mod. Esc stops the search first, then leaves input, then returns to the editor. Any page change also stops the search (`fsLeft`).

### 2.10 Game logs

Game logs are implemented in GUI Logs › Game logs; the TUI uses `l` in can it run to choose a log. Data comes from `view.LogFiles` and `view.BuildLogPage`, with companion data in `view.MonitorOf` and `view.LiveMonitor`. The GUI also has `LogCluster` to expand cluster evidence, plus `SelectLog`, `LogMonitor`, and `AddMonitor`.
- A quiet dropdown chooses the log file, for example Player.log Oct 21 17:55 ⌄. Indent each run's companion logs below its Player.log: `ArchoMonitor.log` and `ArchoMonitor-prev.log`, or RimCrow logs if those are absent. Pairing follows 03 §6.7.4, with `LogFile.Of` pointing to the owning Player.log. Choosing a companion opens its Player.log and switches to the companion area. See 03 §6.4 for launch identification.
- Muted facts to the dropdown's right show the game version and line count, without repeating the timestamp already in the dropdown.
- At the heading's right, if this is the selected problem log, show muted errors included in Needs attention. If the game is still writing it (`LogPage.Live`), say the game is still writing and its errors will be included after exit, without a button (03 §6.4; a live log is not the problem log). Otherwise, offer Add its errors to Needs attention (`SelectLog`).
- Each cluster row contains one sentence, its attributed Mod, and a count. Expand it to inspect evidence and samples.
- With explicit phase markers (03 §6.7.3–4), Player.log clusters follow first-occurrence order, while Archo Monitor entries follow file order. When adjacent rows belong to different phases, insert a quiet separator before the next row, such as Main menu 09:47, Loading Colony1.rws 09:48, or Playing 09:49. Show times and save names only when recorded. Place a cluster at its first phase, retaining its per-phase counts in details. Companion entries count anew in each phase, so returning to the menu or loading again can produce another separator. Do not show empty-phase separators. Each separator shares the next data row's `virtualRows` measurement container, takes no cursor position, and does not count toward tab row counts. Expansion, refresh, and tab changes retain the existing scroll behavior. Without phase data, add no separators and keep the original Player.log severity-and-count order.
- Open game log from can it run opens the referenced Player.log, which may be Player-prev.log, selects the Player.log area, and selects and scrolls an attributed cluster for that Mod into view. Other clusters remain browsable. An unattributed item opens the full log. Sidebar entry retains the normal selection rules.
- The right-side cluster detail card shows `archo log --cluster` text: the full message up to 1200 bytes, continuation lines (`also`), messages around the first occurrence (`nearby`, 03 §6.3), attribution, and confidence.
- **Archo log analysis**, the pattern card from `API.LogPattern` → `view.PatternCard` (03 §6.8), appears **above** raw evidence when the cluster matches an error pattern. Its heading is 3 Archo log analysis, with 3 focusing it. Order the contents by importance:
  - **Severity** comes first, as a colored word and impact sentence (`PatternCard.Level`, `LevelText`, `Impact`, derived from the phase and first remedy). Severe is red and concerns saves that may not load or may lose content. Moderate is amber: loading errors may leave content missing or nonfunctional; runtime errors may repeat, cause stutter, or break a feature. Minor is gray: the phase is noise or the first remedy says it can usually be ignored, generally without affecting play.
  - Follow with the key meaning in 13px body color, then Try first on a faint accent background without a left stripe (§7 principle 4). If the source Mod has its own known error, add an amber sentence.
  - Put secondary causes and remedies below a hairline in muted 12px text. The last two lines are faintest: corpus frequency and duplicate-upload evidence, such as 22,998 of 40,326 shared 1.6 logs, then the caveat that these are shared player logs rather than a conclusion about the current list.
  - With no match or only a fallback match, omit the card and let raw evidence fill the right. Suppress the repeated English CLI `pattern:` block (`view.WithoutPatternBlock`). A companion entry matched to a cluster shows that cluster's evidence and card. The TUI's `PatternCard.Lines` puts severity and impact immediately below the heading.
- **The gaps between the three cards are draggable**: drag horizontally between the list and right side to resize the list, or vertically between analysis and raw text to resize analysis. Save these in `ui.gui.log.left` and `ui.gui.log.ana`. Double-click restores a 62% list and 38% right side, with analysis using 40% of the right height. Below 900px, stack the three cards without draggable gaps.
- **The companion area** appears when this Player.log has a companion. Tabs at the top of the list card show Player.log 24 and Archo Monitor 16, or RimCrow Companion 16. Left/right switches tabs.
  - A muted fact line uses the session and exit records for the start–end time. Do not repeat the game version or show the Monitor version. Without an exit, say since 17:51, no exit record (crash/forced close). While live, show since 17:51 and a green dot. Mark when the 32 MiB limit is reached.
  - Entries follow file order and show time, severity icon, a localized short `inferredType` (`view.MonitorKind`: patch, Def configuration, cross-reference, XML loading, assembly conflict, tick, draw, null reference, memory, or missing texture errors), the first message line, ×count when greater than 1, the Mod name or an uninstalled Mod's package ID, and the related file as Mod › relative path when inside a Mod directory. Omit INFO entries without a type.
  - A click or up/down only moves the cursor; right-side raw evidence and analysis follow the current entry. Expandable rows have a leading arrow, right when closed and down when open, with a hover hint. Clicking the arrow also selects the row; Enter at the cursor toggles bounded, scrollable monospace `details` and a Player.log E3 → link. Nonexpandable rows retain an alignment space. Clicking a cluster link selects the Player tab and cluster. Unmatched ERROR or WARNING entries explain that they appear only in ArchoMonitor.log because the game had stopped writing Player.log. Clicking and expanding preserve the row's screen position. Each tab retains its own scroll and measured heights; live refresh retains position and expansion.
  - During play, use the existing `API.Live` polling (§2.16.1 G01), followed by one `API.LogMonitor` call. It reads companion data already tracked in `LiveTracker.Companion`, without another file read or timer.
- If the current plan lacks Archo Monitor, show a muted explanation below the file selector that errors will lack file and Def loading context, plus Add Archo Monitor. `App.AddMonitor` inserts the latest installed version after Harmony in one undoable edit, following the default insertion in 04 §1.5, even if the player previously removed it. If uninstalled, show the explanation and `archo monitor install` without a button. Hide both when the viewed run already has a companion.
- **Use the game's own log colors** for cluster and companion rows. The row's severity determines its color, from `LudeonTK.EditWindow_Log` drawing `Verse.LogMessage.Color`: Error uses `ColorLibrary.LogError` `#ff6666`, Warning uses `Color.yellow` `#ffeb04` (1.7 UnityStubs values 1, .922, .016), and Message is white. The light theme adjusts contrast without changing hue: Error `#eb0000`, Warning `#7e7400`, and Message uses theme text (`view.GameLogColors`, `view.LightLogColors`, `style.css` `--log-*`). Use the log's own severity for Waylith Player.log and companion logs; 1.6 Player.log without severity uses the row state.
  - Go parses a Mod's Unity rich-text colors into spans (`logs.RichSpans` → `view.LogSpans`); the TUI maps the same spans to terminal colors. Recognize nested `<color=#rgb[a]|#rrggbb[aa]|name>`, `<b>`, and `<i>`. Strip size-changing or embedding tags such as `<size>`, retaining their text. Strip unmatched closing tags; unclosed opening tags apply through the end of the line. Other tag-like text, such as `<li Class="…"/>` and `<script>`, remains literal as in the game, because stripping XML from messages would lose information. The UI inserts spans only as text, and colors accept only `#rrggbb`.
  - If a Mod color's contrast against the card is below 4.5, retain hue and saturation while adjusting luminance until sufficient: brighter for the dark theme and darker for the light theme. Each span carries both theme values.
- During live appends (03 §6.6), attribute each new cluster batch and place it in can it run's Current run. A full analysis after exit replaces that result.
- The TUI companion area is pending; `view.MonitorOf` is reusable. TUI technical pages follow `log:E<n>` with Enter, and append the same `PatternCard.Lines` after the cluster text.
