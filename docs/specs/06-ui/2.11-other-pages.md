### 2.15 First-run guide

Implemented (GUI, `guide.js`). Three steps, each allowing Back:
1. **Find environment**, switch between:
   - **Existing game**: automatic discovery (02 §2.2) lists games with multiple selection, or Add this directory directly selects a folder (§3.1 rule 12; TUI still accepts typed paths). Prefill game-version name (`1.6`, or `1.6-2` on collision).
   - **Download a version** (08 §11): without SteamCMD, explain Valve download, size/location; download only after Download SteamCMD. Then list SteamCMD branches (current stable, beta, older versions with Steam descriptions/dates), game directory (default `<drive>\Games\RimWorld <version>`, address/Change opens folder picker), optional Steam account-name override. Anonymous default; blank uses settings, explicit anonymous overrides saved account. Explain password/Steam token are entered only in SteamCMD's window. Show stages (start, login, download, verification), progress and mapped safe stage descriptions, never raw authentication logs. Plain-language failure/retry; success registers environment like existing games and enters step 2.
2. **Read Mods**: subprocess scan with progress (§8.4). If shared Mod folders already scanned, read only new game's `Data`/`Mods` (`scan --game-only`, 02 §4.1); row says these contain N Mods.
3. **Where to start**: game current list (import ModsConfig.xml as first plan) / migrate from RimSort or RimCrow (lists/player data, 04 §8, §9) / open pack or Steam collection (`pack import`, `archo collection`). Select pack with system dialog; paste collection URL separately, never type local paths.

Import uses `view.ReadImport` → `view.PreviewImport` (preview first) → `view.ApplyImport`. Add environment on environment page starts at step 1.

### 2.16 Background tasks

**Automatic checks and data updates**: while GUI/interactive TUI is open, `app.AutomaticLoop` uses one timer for session / mods / tools / data / self. Startup, wake frequency, interval tiers, and due conditions: [§2.16.1 Scheduled behavior](2.16-scheduled-behavior.md) A01–A03, A06–A07, A15. Closing cancels requests; no resident service. Self only checks RimArcho versions; install requires confirmation (07 §5.1). Each round uses an independent connection, runs sequentially, and releases inventory/data indexes afterward; networking holds no page lock. GUI prioritizes player operations when tasks run/queue.

- Settings contains only master `updates.auto` and `updates.interval` (normal / half / double). Defaults/durations: §2.16.1. Describe natural intervals, using daily, weekly, etc. in English.
- SQLite meta `automatic:<category>` records attempt before networking, then result/completion time/pending count. Windows sharing a DB claim checks through conditional update. Neither restart nor failure immediately retries. Manual community update/account verification satisfies its interval. CLI/MCP read status without starting timer (05 §4.2).
- Mod checks read only public SteamCMD Workshop metadata, tracked Git refs, download-page versions; LoversLab uses enabled session to read file pages.
