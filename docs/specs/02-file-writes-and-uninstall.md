## 1. File Write List (Safety Boundary)

Before moving or removing a physical Mod directory, the shared inbound-link plan covers all known games: record intent → detach owned links → move/recycle → update records → rebuild required entry points. Refuse if an affected game is running, a foreign inbound link would break, or link state is unknown; list affected links in the original confirmation preview without another confirmation dialog. On failure, reconnect only to the original target if it remains accessible; recovery after interruption requires confirmed link repair. Startup does not change disk state automatically.

Link inspection is read-only. Link repair must first show the game, full link path, original target, reason, ownership evidence, and action, then run after interface confirmation or CLI `links repair --yes`; links with only a prefix and no ownership evidence also require explicit inclusion per path. [09 §3](09-launch.md#3-link-deployment) defines repair boundaries and revalidation rules. Scanning, opening the problems page, launch checks, and test runs do not authorize deletion; detaching deployment links does not use the recycle bin or expand its allowlist.

RimArcho writes only to the locations below and touches nothing else. Every disk-writing action must have a preview (CLI `--dry-run`, interface preview), require player confirmation (interface) or explicit execution (CLI without `--dry-run`), and be reversible or explain why it cannot be reversed.

Automatic checks (16 §2.16) are an exception to per-action confirmation above: when the master switch is on, they may write check records (including RimArcho version checks), metadata for existing subscriptions, encrypted renewed sessions for enabled accounts, and community data caches; they do not authorize installing Mods, updating external tools or RimArcho, or changing game configuration.

Never do the following:
- Never modify existing files in Workshop items. Only three changes may occur in Workshop directories: after player confirmation, restore `About.xml.disabled` to `About.xml`, recycle the entire item folder, or create `.dds` beside PNG during texture optimization (since 2026-10-22; Steam updates or verification may delete them, which RimArcho detects from its records and prompts to regenerate).
- Never write marker files into Workshop directories (Steam verification or updates would delete them). Record texture optimization's file writes in the database, not Mod folders.
- Never follow links outside a Mod directory for writes; prevent path traversal.
- Network access is limited to player-triggered actions and automatic checks when the master switch is on (16 §2.16): community data updates (08 §2), Workshop descriptions and images (can be disabled in settings, 16 §4.3), reading Steam collections (07 §7), subscribing to Git repositories, reading Mod download page metadata and checking/pulling updates, logging in and validating LoversLab sessions after player opt-in and downloading selected site files (11 §1), SteamCMD Workshop downloads without a Steam client (11 §1), subscribing/unsubscribing through the Steam client (11 §2), and persistent resumable credit replacement subscriptions after player acceptance (11 §1), downloading SteamCMD and using it to read branches/download game versions (11 §3), external tool version metadata checks and downloads (17 §2.1), checking for new RimArcho versions and downloading after confirmation (GitHub Releases, 17 §5.1), model calls (with consent, 15 §3).
- Never ask for, receive, save, or pass passwords, verification codes, Guard, recovery codes, or TOTP secrets for any service. SteamCMD interacts only in its own console; LoversLab only in an isolated original-site window. Session cookies are used only in the secret storage and restricted HTTP client of 11 §4, never in ordinary data or agents.

## 2. Uninstall

First step, "forget account sessions" (`accounts`): deactivate in-memory sessions, delete encrypted cookies, temporary login profiles and download residue, and clear known authentication caches in managed SteamCMD. This is independent of tool deletion and still runs when retaining Mods; leave system browsers and external SteamCMD caches untouched. Stop on cleanup failure, without deleting tools/data or claiming everything was forgotten; players can close login windows and retry. Local forgetting cannot be undone and does not revoke other devices.

Keep the link ledger with data until uninstall target steps finish; detach owned links across all known games before handling lock library, pack, and subscription targets. Leave foreign links, unknown types, and real directories untouched; refuse plans whose later deletions would break foreign inbound links.

Decided on 2026-10-22, implemented (`internal/app/uninstall.go`). Uninstall reverses each row in the table above using its last column: each row names the corresponding step (`accounts`, `links`, `modsconfig`, `textures`, `locked`, `monitor`, `packs`, `saves`, `games`, `steamcmd`, `data`, `program`), or explains why none applies with "None:". `TestUninstallCoversWriteList` checks that every row has this column, all named steps exist, and every step appears in this section.

- **Entry points**: GUI settings › uninstall RimArcho (16 §2.14); TUI command panel "uninstall RimArcho"; CLI `archo uninstall` (without `--yes`, show only the plan, 13 §4.2). MCP has only read-only `preview_uninstall`. **No AI uninstall tool**: uninstall removes the program the player installed and all its records (plans, history, notes); one tool call should not make RimArcho disappear from the player's computer. AI may explain what will happen; only the player can execute it.
- **Preview the plan first**: folders, sizes, and destinations per step; put choices directly in the corresponding row (GUI checkboxes and folder selectors, without a series of dialogs). Defaults: recycle lock library copies, retain packs, move own saves out, retain downloaded games, and keep the current ModsConfig.xml list while removing RimArcho entries.
- **Preview sizes**: GUI marks estimates with `≈`; reuse byte counts for the same path for at most 60 seconds; option changes still recheck paths, processes, and ownership without reusing deletion eligibility. Regenerate the full plan before uninstall, without preview size cache or recursive directory size counting; omit directory sizes in the execution report.
- **One confirmation**: GUI / TUI confirmation and summary are in 16 §2.14; CLI uses `--yes`.
- **Refuse**: a game is running; another RimArcho in the same program folder (window, `archo mcp`, scan subprocess) has the database open; choices conflict (retained copies go into a game to be deleted, or retained saves/packs go into a folder to be deleted). Change nothing on refusal.
- **Order**: links → ModsConfig.xml → texture optimization DDS → lock library → Monitor → packs → own saves → downloaded games → SteamCMD → data → program. If one item fails (for example, recycle bin unavailable, 02 §3), continue the others but skip the final two steps: retain data and database so uninstall can be retried after fixing the issue.
- **Final two steps after RimArcho closes**: Windows cannot delete running programs or open databases, so uninstall writes a cmd script to a temporary folder and launches it detached: wait for this process to exit (up to 5 minutes), delete the data directory and `%LOCALAPPDATA%\RimArcho`, then delete release zip files in the program folder (`archo.exe`, `RimArcho.exe`, `README.md`, `CHANGELOG.md`, `LICENSE`, `fonts/`, `monitor/`) and update leftovers `.archo-update/` (17 §5.1); delete the program folder only if empty; log failures in `%TEMP%\RimArcho-uninstall.log`; finally delete the script itself. The script invokes System32 `tasklist`, `find`, and `ping` by full path (Git's `usr/bin` in PATH would resolve GNU find first). `rd /s` does not enter links. Development builds (`go run`, `guidev`) do not delete the program. Other systems delete directly in-process.
- **No installer**: releases are zip files (17 §5); uninstall deletes files itself. If an installer is added later, the `program` step will invoke its uninstaller.
- **Never touch**: Mods themselves (Workshop, SteamCMD sources, other folders, player-owned folders in `Mods/`; except DDS written by texture optimization, removed in `textures`), Workshop subscriptions, saves in the game's default user data directory, or Mods restored to the game by `unhide`.
- After uninstall, reject every command in this process ("RimArcho was uninstalled; close it"); GUI shows only the report and "close RimArcho"; TUI exits on enter.

## 3. Recycle bin

Before recycling a target, detach all owned incoming links using the ledger phases and recovery from 09 §3. Detaching links does not use the recycle bin or widen the allowlist.

Removing a deployment link is undeployment under 09 §3. Safely delete only the link itself, without creating a recycle-bin entry or expanding this section's allowlist.

RimArcho does not permanently delete player content. Always move it to the system recycle bin, and refuse if the recycle bin is unavailable.

**Allowlist.** Accept only these four categories; reject all other paths:

| Category | Conditions | Callers |
| --- | --- | --- |
| Mod folder | An Instance's real directory inside, but not equal to, its source root: a hidden or unsubscribed Workshop or SteamCMD copy (Steam redownloads subscribed ones), or the player's own `Mods/` or lock-library copy (refuse if the copy itself is a link). Enabled Mods and those used by plans only warn | `trash` (09 §5), mod library "delete" (16 §2.9), 1.2 unsubscribe |
| Pack directory | `<pack name>/` under the pack directory | `pack remove` (10 §4) |
| Save file | A save under the environment's user data `Saves/` or a pack's `userdata/Saves/` (product rules in 12 §4) | Save management (`app.TrashSaves`, 12 §4.4) |
| Player content during uninstall | Lock-library copies (selected by default), packs, own-saves directories, `<data directory>/backups/saves/` and SteamCMD-downloaded games, only when the player chooses deletion. RimArcho-owned folders (data, Monitor and downloaded SteamCMD) are deleted directly rather than recycled | Uninstall (02 §2) |

The single entry point `App.ToTrash` (`internal/app/trash.go`) enforces the path allowlist regardless of the caller. Caller-specific rules for enabled Mods, plan use and subscription are checked beforehand. The path allowlist is as follows; resolve links first, but reject a path that is itself a link:
- A path inside, but not equal to, any source root (Workshop, SteamCMD, `Mods/`, the lock library or other Mod folders, in any environment), or inside any `<game directory>/Mods/`.
- A direct child `<pack name>/` under the pack directory, excluding the root itself and folders inside packs.
- A path inside any environment's user data `Saves/` (the game's default user data folder when the environment names none), a pack's `userdata/Saves/`, an own-saves directory `<data directory>/userdata/<environment name>`, or the save backups `<data directory>/backups/saves` and its descendants.
- An environment's game directory itself, only if it was downloaded by SteamCMD (`steamapps/appmanifest_294100.acf` exists).

Refuse other paths (`ErrNotInTrashList`, `TestTrashAllowList`).

**Platforms:**

- **Windows** uses `SHFileOperationW`, `FO_DELETE`, and the flags `FOF_ALLOWUNDO | FOF_NOCONFIRMATION | FOF_SILENT | FOF_NOERRORUI | FOF_WANTNUKEWARNING`. The last flag causes an error on a volume without a recycle bin, such as a network drive, instead of permanent deletion. Report an error with the shell code if the return value is nonzero or the operation is cancelled.
- **macOS** renames the item into `~/.Trash`, adding `.2`, `.3` on name collisions.
- **Other systems** follow freedesktop: move the item to `$XDG_DATA_HOME/Trash/files/` (default `~/.local/share/Trash`) and write `info/<name>.trashinfo` with `Path` and `DeletionDate`. Add `.2`, `.3` on name collisions.
- A cross-volume rename fails outside Windows. Refuse without falling back to copying and deleting.
