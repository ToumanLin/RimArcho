# 08 · GUI（MVP 最后一版）

> 依据：00 §2 “一套核心，三个表面”；06（TUI v2 + §13 v3 交互模型）。
> 目标：**TUI 和 GUI 共享同一套 Go 业务逻辑，各自实现一套界面。** GUI 不是把 TUI 渲染到窗口里，也不调用 CLI 再解析文字。

| 表面 | 技术 | 职责 |
| --- | --- | --- |
| TUI | Bubble Tea + Bubbles + Lip Gloss | 终端交互和字符界面渲染 |
| GUI | Wails v3 + HTML/CSS/JavaScript | 桌面图形界面 |

## 0. V0 技术验证（2026-10-20，`spikes/gui-v0`）

Wails `v3.0.0-beta.28`（2026-10-05 发布；v3 仍是 beta，锁定这个版本，升级单独验证）。真实环境的数据目录副本，1354 个 Mod。

| 项 | 结果 |
| --- | --- |
| 纯 HTML/JS 调 Go | `import { Call } from "/wails/runtime.js"`，`Call.ByName("包.类型.方法")`。不需要 npm、打包工具，也不需要 `wails3` CLI 生成绑定 |
| CGO | 不需要（`CGO_ENABLED=0` 编译通过） |
| 体积 | 带 Wails 的 exe 18.4 MB（`-s -w`），现有 archo 17.3 MB |
| 速度 | 1354 行数据 106 毫秒到达并显示（含 Loadout 加载）；点一个 Mod 9 毫秒出详情和缩略图；虚拟滚动无卡顿 |
| 内存（任务管理器“内存”口径 = 专用工作集，空闲 60 秒） | Go 进程 55.6 MB；WebView2 6 个进程合计 96.5 MB；**总计 152 MB** |
| 网络端口 | 没有任何 TCP 连接或监听（Wails 在 Windows 上用 WebView2 的资源拦截，不开端口） |

对比：TUI 方案是 archo 约 47 MB + WezTerm 约 100–150 MB；RimCrow 400–500 MB。GUI 的总量与 TUI+WezTerm 相当，**00 设想的 80 MB 只对 Go 进程本身成立**，WebView2 的部分无法压到这个范围（§10）。

## 1. 共享业务逻辑的分层

```
surface/tui   (Bubble Tea)        surface/gui   (Wails 服务 + assets/*.html|css|js)
      │  只做：布局、绘制、按键/鼠标映射      │  只做：把 view 模型序列化给前端、事件推送
      └──────────────┬──────────────────────┘
                internal/view     界面无关的视图模型（新）
                     │
                internal/app      业务（已有，补齐类型化接口）
```

### 1.1 internal/view（新包）

不依赖 Bubble Tea、Lip Gloss、Wails。输入是 `*app.App` 的状态，输出是普通 Go 结构（可以直接 JSON 化）。从 TUI 中搬出（括号内是现在所在的文件）：

| 视图模型 | 内容 |
| --- | --- |
| `Columns` | 三列各有哪些 Mod，每行的序号、来源类型、名称（别名优先）、状态、是否淡化、是否未保存（`columns.go` 的 `reload` / `modItem` / `rowStatus`） |
| `Query` | §5.5 查询语法的解析与匹配、子序列回退、内容类型缓存（`query.go`） |
| `Needs` | “需要处理”的分组、人话文案、合并规则、顶栏数字、行状态；**一键操作是数据**（`Action{Kind, Targets}`），由界面决定绑定到哪个键或按钮（`needs.go`、`problems.go`） |
| `Detail` | 详情各层的数据和顺序：头部事实、问题行、依赖（已启用 / 未启用 / 未安装）、简介来源选择、历史、技术信息（`detail.go`、`fullsec.go`） |
| `Changes` | 最近扫描的变化分组、摘要、文件差异（`changes.go`） |
| `Tags` | 标签候选：固定标签在前，再按使用次数；对选中项标出全有 / 部分有（`tags.go`） |
| `Position` | 位置输入的候选：数字、名称匹配（之前 / 之后）、建议位置、最前 / 最后（`verbs.go` 的 `posOptions`） |
| `Palette` | 命令表（中文名 + 英文别名，**用命令 ID 而不是按键**）、打分与排序（`palette.go`） |
| `Text` | 中英文字符串表 `T` / `Tf`、语言检测、复数、短日期（`i18n.go`） |

### 1.2 internal/app 补齐的类型化接口

TUI 目前的编辑操作是拼 CLI 参数再调用 `cmds.Execute`、读回文字。GUI 不这样做，所以 app 补齐：

- 标签、别名、备注：`Tag` / `Untag` / `SetAlias` / `SetNote`（现在只在 `cmds/playerdata.go` 里）。
- 身份问题回答、日志选择、扫描子进程（`ChildScan` 从 TUI 移入 app）。
- 每个 Mod 的 Def / Patch / Harmony 小结的结构化数据（替代 TUI 解析 `def` / `patches` / `harmony` 命令的文字）。

TUI 随之改为调用这些接口；`cmds.Execute` 只留给本来就是文字的只读场景：排序 / 保存 / 启动的预览（CLI 的 `--dry-run` 文字）、“查看”类操作和全屏详情的 Def / Patch / Harmony 分页，以及玩家自己在命令面板里输入的 archo 命令。

### 1.3 规则

1. 业务规则只能写在 `app` 或 `view` 中。界面层出现“如果是工坊 Mod 就……”这类判断即为缺陷。
2. 两个界面的同一操作调用同一个函数。验收 G1：同一个状态下，TUI 和 GUI 拿到的 `Needs`、`Columns`、`Detail` 完全相同（测试直接比较结构）。
3. 文案只有一份（`view.Text`），GUI 通过一次调用拿到当前语言的整张表。

## 2. 交付形态

同一份源码，链接两次：

| 文件 | 子系统 | 双击 | 用途 |
| --- | --- | --- | --- |
| `archo.exe` | 控制台 | WezTerm 中的 TUI（不变，06 §1.1） | CLI、`archo mcp`、`archo tui`；`archo gui` 启动 GUI |
| `RimArcho.exe` | Windows GUI（`-H windowsgui`，没有控制台黑框） | GUI | 给玩家双击的入口（可带 `--env <名称>`）；带命令参数时按 CLI 执行，供 GUI 的扫描和分析子进程使用 |

- 两个 exe 共用数据目录和数据库，可以同时打开（SQLite WAL 已支持多进程）；一方改动后，另一方在下次获得焦点时按 `ChangeKey` 重新加载。
- `archo gui`：同目录下有 `RimArcho.exe` 就启动它并立即返回；没有就在当前进程中运行 GUI。
- 发布包增加 `RimArcho.exe`（约 18 MB，zip 后约 8 MB）。

## 3. 前端技术约束

- 纯 HTML + CSS + 原生 JavaScript（ES modules）。**不用框架、不用 npm、没有构建步骤**。文件放在 `internal/surface/gui/assets/`，用 `go:embed` 打进 exe。
- 调用 Go：手写的 `api.js` 封装 `Call.ByName`。不使用 `wails3` 生成的绑定，所以构建只需要 `go build`。
- Go → 前端：Wails 事件（扫描进度、工作区变化、外部修改、图片就绪）。
- 列表虚拟滚动：只创建可见行（V0 已验证 1354 行）。
- 安全：页面的 Content-Security-Policy 为 `default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'`。工坊简介和图片都是外部内容：简介由 Go 端解析成 BBCode 块结构后传给前端，前端用 `textContent` 和元素构建，**从不把外部文字当 HTML 插入**；图片只经过 `/img/` 处理器从本地缓存读出，不直接加载远程地址。链接用系统浏览器打开。

## 4. 视觉

- 沿用 06 §2：magpie / Linear 风格，无边框、灰阶分层、单一强调色、色板相同；深色 / 浅色跟随系统。
- 字体：系统界面字体（`Segoe UI Variable`、`Microsoft YaHei UI`），序号用等宽数字。GUI 不依赖附带的 Maple Mono。
- 图标：自绘的简单 SVG（来源、状态），与 06 §3 的含义一一对应。
- 文字按窗口宽度自然换行；列宽可拖动调整，按环境记住（与 TUI 的 `ui.columns` 分开保存为 `ui.gui.columns`）。

## 5. 屏幕结构

与 06 §4.2 相同的信息架构：

```
顶栏    RimArcho · 环境（下拉）· 需要处理 N · 未保存 N · 位置行          排序 · 保存 · 启动 ▶
四区    1 未启用 | 2 已启用 | 3 暂存 | 4 详情（可拖动分隔线）
状态行  ✓ / ✗ / … 一句话                                         当前对象可用的动作（最多 7 个）
```

- 二级界面（需要处理、最近变化、全屏详情）覆盖在四区之上，顶栏换成面包屑，`esc` 或面包屑返回。
- 窗口宽度 < 1100 像素：暂存列收起为顶部的一个可展开条；< 800：详情改为全屏打开。

## 6. 交互

06 §13 的五条规则同样适用于 GUI。补充鼠标和桌面习惯：

| 操作 | 键盘（与 TUI 相同） | 鼠标 |
| --- | --- | --- |
| 移动光标 / 切换区 | `↑↓` / `←→`、`1`–`4` | 单击 |
| 选择 | `shift+↑↓`、`ctrl+space`、`esc` 清除 | `shift+单击` 范围、`ctrl+单击` 切换 |
| 启用 / 停用 | `space` | 双击；拖到另一列 |
| 暂存 / 放回 | `t` | 拖到暂存列 / 拖出 |
| 调整顺序 | `J` `K`、`m` 位置输入 | 在“已启用”内拖动；落点线旁显示“第 N 位” |
| 标签 | `#` | 右键菜单 › 标签 |
| 撤销 / 重做 | `u` / `ctrl+r`，也接受 `ctrl+z` / `ctrl+y` | 状态行里的“撤销”链接 |
| 排序 / 保存 / 启动 | `S` / `w` / `L` | 顶栏按钮 |
| 搜索 | `/`，也接受 `ctrl+f` | 每列标题下的搜索框 |
| 命令面板 | `ctrl+k` | — |

- **右键菜单**列出当前对象此刻能用的动作，和状态行提示同一份数据（`view` 给出）。
- 拖动只是动词的另一种触发方式：松手即生效，可以 `u` 撤销；拖动中按 `esc` 取消。
- 方向键、滚轮、单击永不改动数据（规则 1）。只有双击、拖放、按钮和动词键会改动数据。

## 7. 详情

- 内容和顺序取自 `view.Detail`，与 06 §6.1 一致：它是什么 → 有没有问题 → 简介 → 关系 → 技术信息。
- 缩略图直接用 `<img>` 显示，按比例缩放，不需要 TUI 中的预留行和清屏技巧。
- 简介：06 §6.4 的来源选择和 BBCode 渲染规则不变，渲染为 HTML 元素（标题、列表、表格、引用、代码、链接、图片）。图片在进入可视区域时才请求（`loading="lazy"`）。
- 全屏详情（`enter` 或双击详情标题）：分页 简介 / 关系 / 历史 / Def / Patch / Harmony；`←→` 切换上一个 / 下一个 Mod。

## 8. 需要处理、变化、命令面板、确认

- 内容全部来自 `view`，和 TUI 完全相同（06 §7、§8、§9）。每项的一键操作显示为按钮，按钮文字就是动作（“启用 B”“自动排序”“在工坊打开”）。
- 保存前确认：对话框显示差异和版本改写说明，与 TUI 相同。
- 危险操作（回答身份问题、载入外部修改）用确认对话框代替 TUI 的“再按一次”。

## 9. 长任务

- 扫描和分析与 TUI 相同，在子进程中运行（`archo scan`、`archo analyze`）。进度通过事件推到状态行，界面不阻塞。
- 启动时：有索引就立即显示列表，然后在后台增量扫描（与 TUI 相同）。

## 13. 实施结果（2026-10-20）

### 13.1 结构

- `internal/view`：`text`（中英文表，TUI / GUI 各自用 `Register` 补充自己的按键说明）、`columns`、`query`、`needs`（`Action` 是数据，`Do` 执行修改数据的动作）、`detail`、`changes`、`tags`、`verbs`（`Toggle` / `Stage` / `Unstage` / `MoveBy` / `Place` / `PosOptions`）、`palette`、`preview`（预览与执行排序、保存、启动，撤销，全部放回，换副本）。

### 13.4 实施中的裁定

1. **Wails 绑定名**：服务方法的全名是 `github.com/ToumanLin/RimArcho/internal/surface/gui.API.<方法>`；`api.js` 用 `Proxy` 拼出，前端没有生成文件。
2. **CSP 与运行时**：`script-src 'self'` 下 Wails 运行时正常工作，不需要 `unsafe-eval`。
3. **`[hidden]` 必须强制**：弹层容器的 `display:flex` 会盖过 `hidden` 属性，形成一层看不见的遮罩吃掉所有点击。样式表首行加 `[hidden]{display:none !important}`。
4. **拖到“未启用”**：从暂存拖回“未启用”是“移出暂存、不启用”，为此加了 `view.Unstage`。
5. **标签不进撤销**：标签属于家族数据，不是列表编辑，`u` 不撤销它；GUI 的状态行因此不给标签修改显示“撤销”。
6. **确认文案**：TUI 的“再按一次 L”不适合按钮对话框；`view.Action` 增加 `Warn`，对话框显示它。
7. **最小化时的 WebView2 内存目标**：Wails beta.28 没有公开 `MemoryUsageTargetLevel`（只在内部包中），本版不做。
8. **WebView2 用户数据**放在 `<数据目录>/webview2`，不放 `%APPDATA%\RimArcho.exe`。

## 14. 历史区（2026-10-20 提议，未实现）

> 依据：设计原则的“怎么回去”（06 §13）。按 `u` 撤销时，玩家应该看见撤掉的是哪一步。

- **暂存可折叠**：暂存为空或玩家折叠时，第 3 区只剩标题行；腾出的高度给历史区。TUI 同样处理第 3 列。
- **历史区分两段**：
  - **未保存**：本次工作区的每一步编辑，最新在上，一行一步（“启用 Harmony · 第 2 位”）。光标指向当前状态；`u` / `ctrl+r` 让光标上下移动，单击某一步等于撤销到那一步。数据就是现有的撤销栈。
  - **已保存**：每次写入游戏的版本（v1、v2…），以及启动快照。单击一个版本显示它与工作区的差异，确认后载入（`loadout checkout`）。
- **启动快照**：第一次启动时，把游戏里的 ModsConfig.xml 存为一个快照；以后每次启动，如果游戏里的列表与最新快照不同，就新增一个快照，相同就不记。这样玩家在别的管理器或游戏内改过列表，也能回到改之前。
- 快照和版本复用现有的 Loadout 版本表（04 §3），只多一个来源类型 `snapshot`。

## 15. 图标与 Windows 资源（2026-10-20）

### 15.1 图形

> **修订（2026-10-20，玩家指定）**：图标改用玩家提供的头像插画 `internal/icon/portrait.svg`（80×80，矢量），放在圆角深色底（`#1B1D23`）上。48px 及以上显示整幅；40px 及以下只显示脸部（视框 x 20–64、y 24–68），任务栏上仍能认出。渲染用 `internal/icon/svgr.go` 的小型 SVG 渲染器（路径、圆、椭圆、填充、描边、线性渐变、不透明度），不加依赖，仓库里仍只有 SVG 文本。下面拱心石的设计保留作记录，不再使用。

**拱心石**（已被上面的修订取代）：一座石拱，正中的拱心石用琥珀色。名字里的 Arch 就是拱；拱心石一拿掉，整座拱就塌，对应“一个 Mod 出问题，整份列表都受影响”，也对应正式版把方案砌成整合包（09 §2）。

- 圆角方底，石块用米白，拱心石用琥珀色，只用这三种颜色。拱心石比两侧石块略向外凸出，读起来像“拱顶的那块”。
- 几何以 0–1 的单位方块定义（`internal/icon`），不依赖字体，也不用 RimWorld 的任何元素（Ludeon 的标志、殖民者、游戏贴图）。
- **两档细节**：32px 及以上用 5 块拱石加两根立柱；24px 及以下减到 3 块（左、拱心石、右）加立柱，任务栏和标签页上仍能认出是一座门。石块间的缝宽按像素算，至少 1 px。

### 15.2 不提交二进制

仓库是公开的，不放二进制（07）。图标由 `internal/icon` 的几何在运行时或发布时生成：

- `icon.PNG(size)`：抗锯齿光栅化（每像素超采样），供窗口图标和页面使用。
- `icon.SVG()`：同一几何的矢量版，`docs/assets/rimarcho.svg` 由它生成并提交（文本），README 引用它。
- `go run ./scripts/winres`（发布脚本调用）写 `cmd/archo/rsrc_windows_amd64.syso`：一个 COFF 资源对象，含图标组和版本信息。`.syso` 不提交（`.gitignore`）。

### 15.3 Windows 资源

- **图标组 ID 3**：Wails 窗口按 ID 3 取应用图标；资源管理器取第一个图标组，两者是同一个。尺寸 16、20、24、32、40、48、64、256，每个尺寸是一张 PNG（Vista 起支持）。
- **版本信息**（09 §1 的“Windows 版本资源”）：`FileVersion`、`ProductVersion` 取发布版本号，`ProductName` RimArcho，`FileDescription` 区分 `archo.exe`（RimArcho command line）和 `RimArcho.exe`（RimArcho）。两个 exe 由同一个包构建，所以发布脚本在两次构建之间各写一次 `.syso`。
- **窗口**：没有资源时（开发构建、`spikes/guidev`），窗口用 `application.Options.Icon` 的 PNG（256 px）作后备。页面的 favicon 用 `/icon.svg`，由同一几何生成。

### 15.4 验收

- 发布包里两个 exe 在资源管理器中显示拱心石图标，属性页显示版本号与描述。
- 窗口标题栏和任务栏显示同一图标；`go build` 的开发构建（无 `.syso`）窗口也有图标。
- 16 px 截图能看出三块拱石与琥珀色拱心石。
