## 1. RimArcho 是什么

RimArcho 把 RimWorld 启动器和 Mod 管理器放在一起。选 Mod、排顺序、检查能不能跑、启动游戏、出了错查明原因，都能在一个地方完成，不用在管理器、日志文件、工坊页面和论坛之间来回切换。它面向装了几百个 Mod 的玩家。

所有功能都不需要 AI。AI 助手也能接入（第 20 节），拿到和你相同的事实，遵守相同的规则。

下载一份程序，就有四种使用方式。它们共用同一套代码，显示相同的事实：

| | 程序 | 用途 |
| --- | --- | --- |
| 桌面窗口 | `RimArcho.exe` | 日常使用，支持鼠标和键盘 |
| 终端界面 | `archo`（或 `archo tui`） | 在终端里使用同样的列表编辑器，只用键盘操作 |
| 命令行 | `archo <command>` | 编写脚本、快速查询 |
| MCP 服务器 | `archo mcp` | 供 Claude Code、Codex 等 AI agent 使用 |

### 本指南里的用词

界面使用日常用语，文档和命令行有时使用技术术语。

| 界面 | 命令行 / 文档 | 含义 |
| --- | --- | --- |
| 游戏 | 环境（`env`） | 一份 RimWorld 安装目录，以及它的启动和存档设置 |
| 列表 | 方案 | Mod 列表：启用哪些 Mod，以及加载顺序 |
| 副本 | 实例 | 磁盘上的一个实际 Mod 文件夹 |
| 同一个 Mod 的副本 | 谱系 | 同一个 Mod 的所有副本和版本（工坊、本地、锁定版本等） |
| 整合包 | 整合包 | 一套固定的 Mod 文件，有独立存档 |
| 能不能跑 | 问题 / 检查结果 | RimArcho 发现的所有可能妨碍游戏运行或值得留意的事项 |

## 2. 安装与首次运行

### 安装

1. 下载 `archo-<version>-windows-amd64.zip`，解压到任意位置，例如 `C:\Tools\RimArcho\`。
2. 双击 `RimArcho.exe`。窗口需要 Microsoft Edge WebView2，Windows 10 和 11 已自带。
3. 可选：把该文件夹加入 `PATH`，这样就能在任意终端输入 `archo`。
4. 可选：安装 ilspycmd，用来阅读 Mod 的 C# 代码（需要 .NET SDK）。RimArcho 不会代你安装；缺少时会提示。
   ```
   dotnet tool install --global ilspycmd
   ```

程序没有代码签名。首次运行时，Windows SmartScreen 可能显示“Windows protected your PC”（Windows 已保护你的电脑）：选择 **More info**（更多信息），再选 **Run anyway**（仍要运行）。

**从 Steam 工坊文件夹启动？** 如果你从已订阅的工坊条目文件夹内启动 RimArcho，它会提示通过 **安装 RimArcho** 将程序安装到单独的文件夹（默认为 `%LOCALAPPDATA%\Programs\RimArcho`；用 **更改…** 选择其他位置）。它会显示所需空间，并在磁盘剩余空间不足 10 GB 时提醒。**安装并重启** 会把程序复制过去并重启；**本次在这里运行** 会继续从工坊文件夹运行，同时显示提醒，下次启动还会再问。从工坊文件夹运行时，RimArcho 不会自行更新。

### 首次运行向导

第一次打开窗口时，向导会帮你完成设置。

**托管文件夹。** 首先会问：“RimArcho 应将 SteamCMD、下载的 Mod 和工具存放在哪里？”默认位置是 `%LOCALAPPDATA%\RimArcho`。如果打算下载很多 Mod，就选一个空间充足的盘，然后选择 **使用此目录**（或 **暂不设置**）。

**第 1 步——找到游戏。** “要让 RimArcho 管理哪些 RimWorld？”
- **已有的游戏**：勾选找到的安装（可以添加多个），或用 **添加这个目录** 自己选择。然后选择 **添加并继续**（或 **添加 N 个游戏**）。
- **下载一个版本**：如果没有 SteamCMD，先选择 **下载 SteamCMD**（会显示大小和目标位置）。选择游戏分支、**游戏目录**，可选填 **SteamCMD 账户（可选）**，然后选择 **下载并加入**。密码和 Steam Guard 验证码只在 SteamCMD 自己的窗口里输入，RimArcho 看不到。

**第 2 步——读取 Mod。** RimArcho 会读取每个 Mod 文件夹一次，并按游戏显示进度。以后的扫描只读取有变化的内容。失败后可以 **重新扫描**；选择 **下一步** 继续。

**第 3 步——从哪里开始。** “第一个列表从哪里来？”
- **游戏当前的列表** → **用这个列表**：从游戏目前启用的 Mod 开始。
- **从 RimSort、RimCrow 搬过来** → **导入…**：RimArcho 会在常见位置查找它们的列表、规则和数据库（不会扫描整个磁盘），然后显示将导入什么、哪些已有、哪些跳过、哪些有冲突。已有值会保留；导入玩家数据无法撤销，因此点击导入按钮就代表确认。
- **打开整合包或 Steam 合集** → **选择整合包…**，或粘贴合集链接后选择 **打开**。
- **跳过**：不导入，直接完成。

向导中的操作都不会写入游戏。

### 从命令行首次运行

```
archo env detect                 # 查找游戏、用户数据文件夹和工坊文件夹
archo env add main --detected    # 将它们登记为游戏“main”
archo scan                       # 读取所有 Mod 文件夹（之后为增量扫描）
archo status                     # 概览：Mod、列表、问题数量
```

## 3. 界面导航

### 侧边栏

| 分组 | 页面 | 快捷键 | 用途 |
| --- | --- | --- | --- |
| 在玩 | **启动** | `shift+1` | 选择游戏和列表或整合包，然后启动 |
| | **能不能跑** | `shift+2` | 可能妨碍游戏运行的问题，以及上次游戏的报错 |
| | **游戏日志** | `shift+3` | 查看 Player.log，将报错分组并追溯到 Mod |
| 库 | **列表** | `shift+4` | 编辑当前列表。下面是 **全部列表** 和最近使用的列表 |
| | **整合包** | `shift+5` | 固定的 Mod 组合，有独立存档 |
| | **游戏存档** | — | 按殖民地分组的存档、载入检查、游玩历史 |
| | **Mod 库** | `shift+6` | 所有已安装的 Mod。下面是 **全部 Mod**、**更新**、**添加订阅**、**搜索文件**、**Mod 设置** |
| | **贴图优化** | `shift+7` | 转换贴图，加快游戏加载 |
| | **游戏** | `shift+8` | RimWorld 安装及其设置 |
| 底部 | **后台任务** | `ctrl+j` | 下载、转换和其他耗时操作 |
| 底部 | **设置** | — | 程序设置、账户、文件夹、卸载 |

**能不能跑** 的角标显示你可以处理的事项数量。**列表** 下方，绿色标记表示当前已写入游戏的列表；琥珀色标记表示该列表在 RimArcho 外有修改，等待你处理。

`ctrl+b` 在侧边栏和顶部栏之间切换。

### 通用快捷键

| 快捷键 | 作用 |
| --- | --- |
| `alt+←` / `alt+→`（或鼠标侧键） | 后退 / 前进 |
| `esc` | 关闭最上层窗口、退出详情、清除选择或筛选条件 |
| `tab` / `shift+tab` | 下一个 / 上一个控件 |
| `1`–`9` | 跳到页面上对应编号的区域 |
| `?` | 查看当前页面的快捷键 |
| 菜单键 / `shift+F10` / 右键 | 查看光标所在行可以执行的操作 |
| `ctrl+k` 或 `:` | 命令面板 |

所有页面都遵循两条规则：**方向键只负责移动**（光标、焦点、滚动），不会改动列表；**字母键立即对所选项执行操作**，用 `u`（或 `ctrl+z`）撤销。

窗口支持屏幕阅读器（也支持通过 UI Automation 操作窗口的 AI agent）：页面、控件、行和状态都有名称，列表行会读出“第 n 项，共多少项”及选中状态，也会播报进度和错误。对话框会把键盘焦点保持在内部。

屏幕上缩短显示的路径、ID 和网址旁有复制图标，可以复制完整内容。描述、日志和说明中的文本都能选中复制。拖动卡片之间的间隙可以调整大小；双击间隙恢复默认。

### 命令面板（`ctrl+k`）

一个输入框就能查找命令、Mod、列表和游戏，也能运行 `archo` 命令。

- 搜索很宽松：每个词都可以匹配名称中不同单词的开头，顺序不限（`lib hug` 能找到 HugsLib），少量拼写错误也没关系（`sotr` 能找到排序，`vanilka expnded` 能找到 Vanilla Expanded）。
- `ctrl+n` / `ctrl+p` 在结果间移动；`enter` 执行选中的结果。
- 输入 `problems` 或 `sort --dry-run` 这样的命令：`tab` 补全命令、选项和 Mod 名称，`↑`/`↓` 调出历史，`ctrl+enter` 按原样执行输入的文本，`ctrl+u` 清空。
- **预览排序**、**预览保存** 和 **预览启动** 只显示将发生什么，不实际执行。
- `esc` 关闭面板，保留草稿和上次输出。

### 控件编号（`ctrl+\`）

按 `ctrl+\` 会在每个控件上显示一个红色小编号（如 `lib12`）。反馈问题或求助时，可以说“lib12 做了什么”，不用描述按钮在哪里。重启后编号不变；`ctrl+shift+\` 会重新给页面编号。

## 4. 游戏与 Mod 文件夹

### 游戏页面

**游戏**（`shift+8`）列出 RimArcho 管理的所有 RimWorld 安装，以及版本和文件夹。**添加游戏** 登记另一份安装；**使用这个** 切换到它；**移除游戏** 只让 RimArcho 不再记住它（游戏文件、Mod、存档和列表都会保留）。

每个游戏都有独立设置：

- **游戏目录** 和 **游戏版本**（从游戏的 `Version.txt` 读取）。
- **启动方式**：通过 Steam，或直接运行游戏 exe。Steam 库中的游戏默认通过 Steam 启动。
- **存档**：共用正常的存档文件夹，或为该游戏使用 **独立存档**，这样第二份安装（例如 1.6 和 1.7 并存）就不会碰到另一份的存档和设置。
- 传给游戏的 **附加参数**。

你可以登记多份安装，例如一份 1.6、一份 1.7。列表在游戏间共用，每个游戏会记住自己使用哪个列表。列表可以指定适用的游戏版本，用于其他版本时会提醒。

你可以通过首次运行向导或 `archo env download`，用 SteamCMD 下载其他游戏版本（`archo env branches` 列出实际的公开分支）。下载游戏需要拥有游戏的账户。

### Mod 来自哪里

对于当前游戏，RimArcho 会读取：

- 游戏的 `Data/`（Core 和 DLC）和本地 `Mods/` 文件夹；
- Steam 工坊文件夹；
- SteamCMD 下载文件夹；
- 你添加的额外文件夹（例如其他磁盘上的个人 Mod 收藏）；
- RimArcho 自己的锁定库（第 10 节）和自带的 Archo Monitor；
- 其他已登记游戏的 `Mods/` 文件夹。

这些位置都列在 **设置 › 文件夹** 中，显示真实路径。**重新定位** 用来重新连接你自行移动过的文件夹；**移动到…** 会先预览，再帮你移动。标签、列表和 Mod 身份都会保留。目标位置已被占用时，绝不会覆盖。

### 链接

游戏只能看到自己文件夹里的 Mod。当你启用 SteamCMD 文件夹、额外文件夹、锁定库或其他游戏中的 Mod 时，RimArcho 会在保存列表时，在游戏的 `Mods/` 文件夹里放一个指向它的链接。链接名为 `_Archo_…`（其他游戏的本地 Mod 使用 `_Archo_env_…`）。链接不是副本：不占额外空间，也不需要管理员权限。停用该 Mod 时，RimArcho 会移除链接，而且只创建或移除自己命名的链接。FAT 或 exFAT 格式的磁盘无法存放这种链接；RimArcho 会提示，不会改成复制。

切换游戏时，会先准备新游戏列表所需的链接，再扫描。切换本身不会写入游戏的 Mod 列表。

### 副本与变更

RimArcho 把每个 Mod 文件夹作为一个 **副本** 跟踪，并把同一个 Mod 的副本放在一起。列表指向具体的副本，而不只是包名，因此一个列表可以用工坊版，另一个用锁定的旧版。

两次扫描之间，RimArcho 会记录变化：Mod 出现、更新、移动、复制或消失。消失的副本仍会留在列表里，标为“缺失”，回来后会重新连接。如果无法确定两个文件夹是否属于同一个 Mod，就会在 **能不能跑 › 要你确认** 中询问你（**是同一个**、**是副本**、**无关**；**为什么这样问** 会显示证据）。

## 5. 列表

列表决定启用哪些 Mod，以及加载顺序。你可以创建任意多个列表，随时切换。编辑列表只改动 RimArcho 的工作副本；保存或启动前，都不会写入游戏。

### 列表编辑器

打开 **列表**（`shift+4`）。编辑器有三个区域和详情：

- **已启用**（`2`）：从上到下就是加载顺序。与上次保存不同的条目会有圆点标记。
- **未启用**（`1`）：已安装但不在列表中的 Mod。
- **暂存**（`3`）：在未启用区域下方，临时放置 Mod。放进这里的 Mod 会记住原来的位置。
- 详情（`4`）：位于左侧，包含所选 Mod、筛选条件、排序规则和历史。

**打开列表不等于设为当前列表。** 你可以查看、编辑其他列表，而不影响下次启动所用的列表。保存列表、在编辑器里按 `L`、在 **启动** 页选择它，或选择 **设为当前**，才会让它成为当前列表。

| 操作 | 快捷键 | 鼠标 |
| --- | --- | --- |
| 启用 / 停用 / 放回列表 | `space` | 双击，或在区域间拖动 |
| 启用到… / 移动到… 指定位置或某个 Mod 后面 | `m` | 在已启用区域内拖动 |
| 下移 / 上移一行（十行） | `J` / `K`（`alt+J` / `alt+K`） | |
| 放进暂存，或从暂存放回 | `t` | 拖到暂存区域 |
| 暂存全部已启用项 / 全部放回 | `T` | |
| 切换到该 Mod 的其他副本 | `x` | |
| 标签 / 备注 | `g` / `n` | |
| 排序 | `S` | **排序** |
| 保存到游戏 | `w` | **保存修改** |
| 设为当前并前往 **启动** 页，准备启动（再按一次 `L` 启动） | `L` | **启动** |
| 撤销 / 重做 | `u` 或 `ctrl+z` / `ctrl+y` 或 `ctrl+r` | **撤销** |
| 历史 | `H` | |
| 添加排序规则 | `r` | |
| 重新检查文件 | `A` | |

用 `shift+↑/↓` 或按住 Shift 点击来选择一段，用 `ctrl+space` 或按住 Ctrl 点击来加选一行，用 `ctrl+a` 选择当前显示的全部行。拖动已选中的行会移动整个选区；拖动未选中的行只移动该行。`esc` 取消拖动。

启用 Mod 时，RimArcho 会根据已知的加载顺序约束放置它。

### 搜索与筛选

`/` 或 `ctrl+f` 搜索；`\` 打开筛选栏。点击筛选项表示包含，右键（或 `x`）表示排除。筛选分组包括列表、标签、来源、**位置**（副本所在的文件夹）和内容。搜索框支持：

- 普通词语（名称、作者、包名）、带引号的短语，以及用 `-word` 排除；
- `tag:`、`author:`、`type:`、`has:`（例如 `has:problem`）、`location:"D:\Mods"`。

筛选同时作用于已启用和未启用区域；暂存有独立搜索。

### 暂存：放到一边，不丢位置

暂存既方便排查，也方便准备列表。选中一批可疑 Mod，按 `t`，测试精简后的列表，然后把焦点移到暂存并按 `T`：每个 Mod 都会回到记住的位置。暂存只存在于 RimArcho 中，绝不会写入游戏。

### 撤销与历史

每次编辑都会进入列表的撤销历史（撤销、重做各最多 100 步），关闭 RimArcho 后仍会保留。**历史**（`H`）还保存了各次版本：每次保存、启动、导入，以及在 RimArcho 外所做的修改（游戏 Mod 菜单或其他管理器）。选择一个版本，就能查看差异并 **回到这一版**；这个操作也能撤销。

标签、备注和身份确认不属于列表编辑，不能用 `u` 撤销。

### 保存到游戏

**保存修改**（`w`）把列表写入游戏用户数据文件夹中的 `Config/ModsConfig.xml`（共用文件夹，或启用 **独立存档** 后该游戏自己的文件夹）：

1. 准备列表所需的链接。
2. 把上一个文件保存在旁边，名为 `ModsConfig.xml.rimarcho.bak`。
3. 先写临时文件，再替换原文件，避免崩溃留下只写了一半的文件。

写入前，RimArcho 会检查游戏列表是否在其他地方被修改。如果有，会把外部修改保存为一个历史版本，并在覆盖前询问。

在命令行中，`archo save --dry-run` 可以预览将写入的内容。

### 全部列表：创建、副本、导入、导出

**全部列表** 显示每个列表的 Mod 数量、日期、来源、适用游戏和版本，以及预计内存需求（**算了什么** 按类别和占用最大的 Mod 展开）。

| 操作 | 快捷键 |
| --- | --- |
| **新建 / 导入** | `n`（`i` 直接打开导入） |
| **编辑** | `enter` |
| **改名** | `F2` |
| **创建副本** | `D` |
| **删除**（会先询问；最后一个列表不能删除） | `Delete` |
| **设为当前**（不会写入游戏文件） | |
| 列表适用的 **游戏版本**；**恢复默认** | |
| **导出…** | `e` |
| **创建整合包…** | `B` |

**创建列表。** **从哪里开始**：**空列表**、**复制列表**（当前编辑内容，包含未保存修改，或过去的某个版本）、**从存档**（该存档使用的 Mod），或 **导入**。

**导入。** 选择文件或粘贴文本，然后选择 **预览**。预览会显示哪些 Mod 已安装、哪些缺失（附工坊链接）、版本差异，以及建议的替代品。**全部订阅（N 个）** 通过 Steam 或 SteamCMD 订阅缺少的 Mod。然后选择 **创建并编辑**。在编辑器内，导入还可以 **替换整个列表** 或 **只添加缺少的**；两种都只算一次可撤销的编辑。RimArcho 支持读取：

- RimArcho 列表（`.archolist.json`）和整合包的 `pack.json`；
- 游戏的 `ModsConfig.xml`、游戏内 `.rml` 列表，以及存档中记录的 Mod 列表；
- RimSort 的 XML、JSON 和剪贴板列表；
- RimCrow 的 XML、JSON 和分享码（包括旧的 `RMM1-` 分享码）；
- 纯包名文本、工坊链接或 ID、Rentry 页面，以及 Steam 合集。

导入绝不会写入游戏。

**导出。** 支持 RimArcho 列表、RimCrow 分享码、纯文本、`ModsConfig.xml`、`.rml`、RimCrow `ModList.xml` 或工坊链接。可以 **保存为文件…**（`ctrl+s`）或 **复制**（`ctrl+c`）。RimArcho 列表会记录每个 Mod 版本的指纹，接收者就能判断自己是否拥有相同版本。导出绝不会覆盖已有文件。

### 跟着 Steam 合集

列表可以 **关联** Steam 合集。合集变化时，**看差异** 会显示新增和移除的内容，**跟上合集** 会把这些变化作为一次可撤销的编辑应用：可以 **只加入新增的**，或 **也停用移除的**（从合集移除的 Mod 只会停用，不会退订或删除）。关联合集不会自动订阅其中所有 Mod；缺少的新增 Mod 会附上工坊链接。打开 **全部列表** 且到了检查时间，或你主动要求时，会检查合集变化。

### 从 RimSort 或 RimCrow 迁移

使用 **设置 › 存储 › 导入…**（或首次运行向导）。RimArcho 会找到 RimSort 的列表和用户规则、RimCrow 的数据库和已保存列表，然后预览。对于 RimCrow，还会导入别名、备注、分组（转为标签）和支持的规则。已有值会保留，冲突会报告；源文件不会改动。

## 6. 排序与规则

**排序**（`S`）会调整已启用列表的顺序。它依据：

- Core 和 DLC 的官方顺序；
- 你自己的规则：始终作为强约束，条件相同时优先采用；
- 每个 Mod 的 `About.xml` 声明：依赖、在谁之前 / 之后加载、不兼容项和支持版本；
- 社区规则：通常作为弱约束。

各条规则的分量并不相同。RimArcho 根据数万份玩家分享的日志，统计违反声明规则是否真的引发报错：依赖和确实会导致错误的规则是强约束；没显示出危害的规则（例如很多“在 Core 前加载”的要求）只作为偏好。

只要约束允许，就会保留原顺序，尽量少挪动。缺少 Core 时会补上，默认也会加入 Archo Monitor。排序算一次可撤销的编辑，不会写入游戏。`archo sort --dry-run` 可以先看结果。

排序后，RimArcho 会说明哪些问题没能解决：缺少依赖（可以启用或下载）、找不到条目、建议替换的 Mod，以及互相矛盾的规则。规则矛盾（形成环路）不会阻止保存或启动：RimArcho 会解释哪些规则无法同时满足，并选定一个顺序。

**替代品也算数。** 以下情况都能满足依赖：
- 要求该依赖的 Mod 在 `alternativePackageIds` 中列出的替代品，与游戏的判断一致；
- 社区“Use This Instead”数据指定的续作版本。

因此，给旧 Mod 做的汉化也能配合你实际使用的续作，不用启用过时的原版。Mod 详情会显示替代关系“（代替…）”。游戏自己的 Mod 菜单可能仍会对原版发出警告，但游戏能正常加载。

### 自己的排序规则

在编辑器的 **排序规则** 中（或选中 Mod 后按 `r`），可以添加这样的规则：

- A 在 B 之前 / 之后加载；
- A 紧接 B 之后加载（用于补丁或汉化）；
- A 和 B 不兼容；
- A 靠近开头 / 末尾；
- 忽略一条你不认同的声明或社区规则。

规则属于 Mod，不属于列表，所以对所有列表和游戏生效。可以在 **当前列表** 和 **全部排序规则** 之间切换查看。编辑规则不会自动重新排序。删除规则有独立的撤销操作。

**社区数据** 可以在 **设置 › 社区数据** 中用 **立即更新** 刷新，也可以运行 `archo data update`。

## 7. 能不能跑

**能不能跑**（`shift+2`）回答“这个列表能正常玩吗？”页面分两列：

- **开始之前**：从列表和文件中发现的问题，分为 **会让游戏出错**、**可以留意** 和 **要你确认**。
- **上次玩的时候**：上次游戏的报错，并追溯到相关 Mod（第 9 节）。游戏运行时，本次游戏的报错会单独显示。

每一项都说明证据来自哪里：Mod 自己的声明、RimArcho 的推断、社区数据、游戏日志，或你的规则。确定程度分为确定、很可能、可能。

### 检查哪些内容

- **依赖**：必需的 Mod 或 DLC 缺失或未启用。
- **不兼容**：两个已启用 Mod 声明无法共存，或玩家分享的日志中经常出错的组合。
- **加载顺序**：当前顺序违反的规则，以及 Core / DLC 顺序错误。
- **版本**：未声明支持当前游戏版本的 Mod。（仅缺少声明不代表 Mod 一定不能用。）
- **重复与副本**：同一个 Mod 启用两次、被其他副本遮挡而无法加载的副本、隐藏的 Mod 和退订工坊条目后的残留，以及工坊版本已变化的锁定副本。
- **内容**：RimArcho 按游戏的方式合并所有 Mod 的 Def，并按顺序模拟 XML 补丁。会失败的补丁会显示文件、行号和原因：

  | 原因 | 含义 |
  | --- | --- |
  | `target-inactive` | 补丁目标所在的 Mod 已安装，但未启用 |
  | `target-missing` | 已安装的 Mod 中没有目标定义：可能缺少依赖，或补丁已过时 |
  | `target-later` | 目标要到后面的补丁才会创建 |
  | `node-absent` | Def 存在，但要修改的部分不存在 |
  | `wrong-version-route` | 目标只存在于当前游戏版本不会加载的文件夹中 |
  | `stale-name` | 目标 Mod 已启用，但对应内容改了名；会建议相近名称 |
  | `unguarded-optional` | 针对可选 Mod 的补丁没有检查该 Mod 是否存在 |

  还会找出缺少父定义的 Def（并指出哪个未启用的 Mod 提供它），以及被两个 Mod 重复定义的 Def。
- **代码**：RimArcho 直接从 Mod 的 DLL 读取 Harmony 补丁，不用运行游戏。它会指出被多个 Mod 打补丁的方法、可能跳过原方法的 prefix、同一方法上的多个 transpiler，以及互相遮挡的同名 DLL。当这些方法出现在实际报错中时，才会升级为警告。
- **链接与文件夹**：损坏或缺失的链接、已移动的文件夹。
- **内存**：你的内存和显存是否看起来足够运行该列表。

它按游戏的方式处理版本文件夹和 `LoadFolders.xml`，因此只报告游戏实际会加载的文件。

### 修复

- `F` 一步修复能处理的问题：启用已安装的依赖并排序。撤销一次即可还原。
- 每项都有自己的按钮：启用依赖、订阅依赖、停用两个不兼容 Mod 中的一个、排序、修复链接、接受外部修改，或打开说明。
- `A` 重新检查文件；`l` 打开游戏日志；在内存项上按 `v` 刷新估算。
- 可以对单个 Mod、一组 Mod 或全部 Mod 关闭版本提醒；对该游戏版本的设置会在不同列表间共用。

修复后的项目会变灰，并保留 **撤销**，直到你离开页面。一次修复可能消除多个问题。

命令行：`archo problems`、`archo problems show p:<id>`、`archo problems ignore p:<id>`。

## 8. 启动游戏

**启动**（`shift+1`）有三列：**游戏**、**列表 / 整合包**、**启动**。点击游戏即可切换，点击列表或整合包即可选择（选择本身不会写入任何游戏文件）。列表排在整合包前面，最近玩过的排在前面。

| 控件 | 快捷键 |
| --- | --- |
| **启动游戏** | `L`（或在按钮上按 `enter`） |
| **保存 N 项修改**（只保存，不启动；之后自行通过 Steam 启动游戏） | `w` |
| 聚焦某列 / 选择列表 / 选择游戏 | `1`–`3` / `↑↓` / `←→` |
| **上次游戏**：查看上次游戏日志；如果有报错，则打开能不能跑 | |

启动按钮下方会用一行说明这个列表最可能遇到的问题；点击即可打开 **能不能跑**，也可以 **收起**，直到情况变化。

启动时，RimArcho 会保存列表、准备链接，再按游戏页面的设置启动游戏（通过 Steam 或 exe）。之后会实时跟踪游戏日志。游戏运行时，启动区域会显示“游戏运行中”和错误数量；可能干扰游戏的操作（更新、存档改名、移动文件夹）会等待或拒绝执行。

**内存检查。** 如果列表预计需要的内存多于当前空闲内存，按钮会显示 **内存偏紧，启动游戏** 或 **内存不足，启动游戏**。严重不足时，会打开 **内存可能不足** 对话框，显示 **载入预计需要** 和 **当前可用内存**。默认焦点在 **取消**；是否 **仍然启动** 由你决定。估算只供参考，不是在预测一定会崩溃。

**文件夹挡住了目标副本。** 如果 `Mods/` 中的普通文件夹会遮挡列表所需的副本，RimArcho 可以提供 **移入锁定库并继续**：把该文件夹移入锁定库（使用它的列表仍会继续使用），再链接正确副本。预览会列出每一次移动。

**Mod 设置跟着副本走。** Mod 文件夹改名后（例如从工坊文件夹变成链接），游戏会寻找另一个名字的设置文件。RimArcho 会把已有设置复制到新名字下，绝不覆盖已有文件。

## 9. 游戏日志与 Archo Monitor

### 游戏日志页面

**游戏日志**（`shift+3`）显示 Player.log、Player-prev.log 和 Archo Monitor 的伴随日志。重复报错会合并成错误簇并显示次数（例如 `E1 ×500`），避免一个错误刷满屏幕。分组时会忽略数字、殖民者姓名等变化细节：“Exception ticking Hubbard”和“Exception ticking Martin”会归为同一簇。

选择错误簇，可以查看原始日志行、涉及的 Mod，以及已知错误的 **Archo 日志分析**：有多严重、通常意味着什么、一般怎么解决。

| 快捷键 | 作用 |
| --- | --- |
| `↑↓` | 选择错误 |
| `1` / `2` / `3` | 错误 / 日志文本 / 分析 |
| `←→` | 在 Player.log 和伴随日志之间切换 |
| `enter` | 展开伴随日志条目 |

**把它的错误列入需要处理** 会把旧日志的错误加入 **能不能跑**。**加入 Archo Monitor** 会把辅助 Mod 加入列表（可撤销）。

### 如何把报错追溯到 Mod

报错涉及的每个 Mod 都会标明角色，并附上证据：

| 角色 | 含义 |
| --- | --- |
| **源头** | 它的文件、堆栈中的自身代码，或失败的补丁产生了错误 |
| **补丁方** | 它修改了堆栈中的某个方法。仅凭这一点，不能认定它是元凶 |
| **依赖** | 某个未启用的 Mod 能提供缺少的内容 |
| **被提及** | 出现了它的名字，但没有更强的证据指向它 |

满是 Harmony 补丁的堆栈不等于元凶名单；除非补丁方自己的代码就是源头，否则 RimArcho 会把它们分开标注。证据包括 XML 或 DLL 文件和行号、失败的补丁（与 RimArcho 自己的模拟结果匹配）、哪个 Mod 定义了缺少的 Def、贴图或类，以及堆栈中第一个来自 Mod 的帧。游戏找不到某个类时，会追溯到 XML 中写了这个类名的 Mod，并给出最多三个名称相近的现有类（“你是不是指…”）。

某个 XML 文件加载失败后，后续大量“无法解析引用”错误会折叠到这个首个错误下，方便你从根源开始排查。

### 日志属于哪次游戏

RimArcho 知道每份日志来自哪次启动。日志如果来自另一个列表或整合包、来自之后已被修改的列表，或来自其他游戏版本，就会标记为过期：仍然能看，但会折叠，也不计入 **能不能跑**。直接从 Steam 启动的游戏，也会匹配到 RimArcho 最后保存的列表。

### 实时跟踪

游戏运行时，新错误和增加的次数大约每秒更新一次，不会弹窗打扰。游戏退出后，会重新分析整份日志。

### 来自其他地方的日志

通过命令行或 AI agent，你可以分析任意日志或粘贴的堆栈，包括通过 HugsLib 上传的日志（会跳过上传信息头，也能识别 1.7 日志）：

```
archo log                         # 最新的 Player.log
archo log --prev                  # 上一次的日志
archo log --file "C:\Logs\Player.log"
archo log --text "<pasted error>"
archo log --cluster E1            # 一个错误簇的完整内容
archo log --follow                # 游戏运行时实时跟踪
```

### Archo Monitor

Archo Monitor（`toumanlin.archomonitor`）是 RimArcho 自带的小型辅助 Mod。它在游戏内记录 Player.log 没有的信息：

- 报错时正在加载哪个 XML 文件和 Def；
- 游戏处于哪个阶段：启动、主菜单、载入存档、创建殖民地、游玩中；
- 每个错误重复了多少次，即使游戏已经达到消息上限、不再记录日志，也能继续统计；
- Mod 设置界面包含什么，方便 RimArcho 在游戏外显示设置名称和默认值。

它会在游戏日志旁写入 `ArchoMonitor.log` 和 `ArchoMonitor-prev.log`，不会上传任何内容。这些文件可能包含路径和存档名，分享前请先看看。RimArcho 会把它加到新列表里，紧接 Harmony 之后（可以在 **设置 › 游戏日志 › 自动把 Archo Monitor 加进列表** 中关闭），并保持更新。也支持读取 RimCrow 的伴随日志（`RimCrow_Realtime.log`）。

### “游戏出问题了，怎么办？”

1. 不要反复重启，先打开 **能不能跑** 或 **游戏日志**：游戏只保留两份日志。
2. 确认日志属于你刚玩的列表。
3. 从第一个源头错误，或折叠分组的根错误开始。
4. 阅读角色和证据。不要把堆栈里所有补丁方都移除。
5. 只做一个小改动（启用提供缺失内容的 Mod、停用源头 Mod、更新 Mod、暂存一批 Mod），再启动，对比错误簇。
6. 如果是载入存档出问题，也看看该存档的 **能不能载入？**（第 12 节）。

## 10. Mod 库

**Mod 库 › 全部 Mod**（`shift+6`）显示所有游戏中已安装的每个 Mod，副本归在对应 Mod 下面。左侧是筛选和详情，右侧是表格。

列包括：名称、大小、状态、来源、用在；可以从表头菜单添加更新、版本、作者、标签和上次游玩（`s`；`<`、`>`、`=` 调整宽度）。点击表头排序；拖动可调整列顺序或宽度。**全部折叠** / **全部展开** 用来折叠或展开副本。

Mod 库不改动列表，而是用来管理文件。以下文件操作都会先预览；有列表使用该副本时也会提醒：

- **锁定这个版本**、**更新至工坊版本**、**解除锁定**、**移入锁定库**；
- **取消隐藏**、**重新订阅**、**退订**、**移到回收站**；
- **检查更新**、**更新**、**撤掉订阅**、**打开下载页**；
- **清除贴图优化**；
- **不列为副本**。

快捷键：`enter` 查看详情，`C` 查看变更，`g` 标签，`n` 备注，`R` 重新扫描，`ctrl+o` / `ctrl+w` / `ctrl+s` 打开文件夹 / 工坊 / Steam 页面，`Delete` 执行适用的移除操作。

**清理。** 筛选出没有任何列表使用的副本，展开 Mod 对比各份副本，选择想移除的内容，阅读预览后确认。移除的文件夹进入 Windows 回收站；使用它们的列表会将对应条目标为缺失。回收站不可用时，RimArcho 会拒绝操作，不会永久删除。

### 锁定版本

**锁定这个版本** 会把 Mod 保持在当前状态，不受后续工坊更新影响。RimArcho 把它复制到锁定库，并将当前列表切换到该副本（可撤销）；其他列表继续使用工坊版。工坊版本变化时，RimArcho 会提醒，让你先对比再 **更新至工坊版本**（创建新的锁定副本；旧副本及你对它的修改都会保留）。**解除锁定** 会把列表切回工坊副本，不会删除锁定副本。

### 隐藏的 Mod

一些管理器会把 `About.xml` 改名为 `About.xml.disabled` 来隐藏 Mod。RimArcho 会区分被锁定副本遮挡的工坊原版、退订后的残留，以及主动隐藏的 Mod，并提供合适的操作：对比、**解除锁定**、**取消隐藏**、**重新订阅**、保持隐藏，或移到回收站。

### 标签与标签管理器

选中一个或多个 Mod 后按 `g` 添加标签。所有选中 Mod 都有的标签显示 ✓，只有部分有的显示 ~。输入文字会缩小标签范围，或提供“新标签 …”；`enter` 添加或移除。Mod 自带标签排在前面。

**Mod | 标签** 切换（`v`）可以按标签分组显示 Mod 库（置顶标签在前，**无标签** 在最后）。选中标签分组标题时，详情区会变为标签管理器：

- **改名**（`F2`）、**备注**（`n`，显示在分组标题中）、**合并到…**（`M`）、**删除标签**（`Delete`）；
- **只看这个标签**；**置顶** / **取消置顶**；
- **相似** 会建议合并拼写接近的标签；
- 在 **全部标签** 下，按住 Ctrl 点击多个标签，可以一起合并或删除。

合并和删除会先询问，不能用 `u` 撤销。标签、备注和别名属于 Mod，因此会跟随它在不同列表、游戏中的所有副本。它们绝不会改动游戏文件。

### Mod 详情

在编辑器或 Mod 库中，选中 Mod 按 `enter` 打开完整详情，共六个区域：**Mod**、**副本**、**用在**、**字段**、**历史**、**技术信息**（`1`–`6`）。这里可以看到预览图、作者、标签、描述、问题、每个副本的备注和位置、哪些列表和整合包在使用它、依赖（含替代品）、ID，以及 Mod 的变更历史。**技术信息** 列出 Def、补丁、Harmony 补丁和规则。

`←`/`→` 前往上一个或下一个 Mod，`[`/`]` 切换副本，`esc` 返回。查看其他副本不会改动列表；**在当前列表里用这一份** 才会切换（位置不变，可撤销）。工坊编号旁有 **网页** 和 **Steam 页面** 链接。

## 11. 更新与订阅

### 更新页面

**Mod 库 › 更新** 把 Mod 分为 **等你更新**、**不会再更新** 和 **已经更新**。每次变更都会标明对你的影响：**会影响启动**、**留意** 或 **只是内容**。`a` 在当前列表和全部 Mod 之间切换。

| 操作 | 快捷键 |
| --- | --- |
| **检查更新** | `K` |
| **全部更新** | `U` |
| 更新这一项 | `u` |
| **添加订阅** | `+` |
| 先锁定（保留当前版本） | `p` |
| 查看改动的文件 | `i` |
| 依赖 / 排序 | `D` / `S` |
| 来源页 / 文件夹 | `ctrl+w` / `ctrl+o` |
| **在 Mod 库打开** | `l` |

稳妥的更新方式：先看影响；如果正在玩一局，先锁定当前版本；再更新、阅读预览，最后重新检查列表。

自动检查只查看，不会安装 Mod 更新。游戏运行时，更新会等待。**全部更新** 会把 Git 和 SteamCMD Mod 作为一批排队，把 Steam Mod 合并成一个请求交给 Steam。被删除或设为私有的工坊条目仍可在本地使用，但 RimArcho 会提醒：退订后可能再也找不回来。

### 添加订阅

**添加订阅** 支持：

- **工坊** ID 或链接：**用 Steam 订阅**（通过正在运行的 Steam 客户端，给作者增加订阅数），或 **用 SteamCMD 下载**（不需要 Steam 客户端；不会在你的账户上订阅）；
- **Git** 仓库地址（GitHub 等；不需要安装 Git）：跟踪 **默认分支**、**分支**、**标签**，或固定为 **只用这一个提交**。本地修改会受保护：如果你改过文件夹内容，更新会拒绝覆盖；
- **下载页**，包括 LoversLab：RimArcho 会跟踪页面，让你选择下载内容（ZIP 或文件夹；RAR 和 7z 请先解压）。登录 LoversLab 后可以列出实际文件。

阅读预览后选择 **订阅**（`enter`）。在更新页面粘贴支持的地址，会打开添加订阅并自动填好。

**以后再从 SteamCMD 转到 Steam。** 使用一批 SteamCMD Mod 玩过三次后，RimArcho 可以提议通过 Steam 订阅这些 Mod 并替换下载副本，给作者增加订阅数。列表也会切换过去；关闭这个提议后，该批次不会再提示。

### 账户

**设置 › 账户**：
- **SteamCMD**：**登录** / **重新登录** / **退出账号**。密码和 Steam Guard 验证码只在 SteamCMD 自己的窗口输入；RimArcho 只保存账户名。
- **LoversLab**（可选）：通过独立窗口登录；会话按你的 Windows 用户加密保存，绝不会进入导出文件、整合包、诊断信息或备份。

管理本地游戏和 Mod 不需要 Steam 账户。

## 12. 存档

**游戏存档** 显示所有游戏和整合包的存档，按殖民地分组，分为三张卡片：殖民地与存档、所选存档、这局游戏。

这局游戏卡片显示天数和日期、叙事者、难度、游玩时长、财富、殖民者和死亡人数、近期事件，以及财富和殖民者数量的时间线，每个存档对应一个点。

| --- | --- |
| 搜索 | `/` |
| 选择存档 / 折叠殖民地 | `↑↓` / `←→` |
| **改名**（保留 RimSaves 前缀） | `F2` |
| **复制**、**备份**、**移到回收站…**、**打开位置** | |
| 根据存档的 Mod **新建列表** | |
| 执行显示的快捷操作（启动、新建列表等） | `enter` |

### 能不能载入？

对每个存档，**能不能载入？** 会把保存时使用的 Mod 与所属列表对比（所属整合包、上次启动它的列表，或 Mod 完全相同的列表）。结论分为：

- **用现在的列表能直接载入**
- **丢失内容**
- **无法正常载入**
- **游戏正在写这个文件，存完后会重新读取**（游戏还在保存）

它会说明后果，例如“不带它载入会失去 3 名 Kurin_Race 种族殖民者，其中 1 名已死亡；1 个派系；3 件物品”。缺少的 Mod 如果涉及殖民者、派系或类，提醒会比普通差异更明显。它还会检查损坏或截断的文件（并指出最后一个可读取的存档）、游戏版本变化、新增 Mod 和顺序变化。

修复会按存档顺序启用缺少的 Mod，并订阅尚未安装的 Mod，合为一次可撤销的编辑；可选修复包括停用保存后新增的 Mod，或 **改用存档的顺序**。Steam 下载完成后，请重新扫描并检查。游戏运行时，改名和移到回收站会等待。

命令行：`archo saves list`、`archo saves show <save> --play`。

## 13. 整合包

整合包是列表的一份固定副本：Mod 文件和加载顺序都保持原样，并有独立的存档和设置。工坊更新不会改变它。想让一局长期游玩的游戏保持稳定，或把能正常玩的整合包交给朋友，都可以用它。

**创建。** 在列表中选择 **创建整合包…**（`B`）。RimArcho 会检查缺失的 Mod 和会妨碍运行的问题，对列表的副本排序（你的原列表保持不变），并只复制所选游戏版本会加载的内容（不包含其他版本的文件夹）。Core、DLC 和游戏本体都不会打包。写入前，**先看清单，不写磁盘**（`V`）可以查看内容、所需空间和提醒。

贴图可以按原尺寸预先转换，也可以缩小到 80、75、60、50、40 或 25 %，减小整合包体积（用 `D` 切换；**扫描统计** 可以测量大小）。然后选择 **创建**（`B`）。复制中断后，可以 **重新创建** 或 **删除已复制的**（绝不会改动原始 Mod）。

**游玩。** 在整合包页面选择 **开始游戏**（`L`），或在 **启动** 页面选择它。首次启动时，会把已有的 Mod 设置复制到整合包中，不会覆盖整合包自己的设置。整合包需要相同的游戏大版本（1.6、1.7…）和对应 DLC；同一版本的不同构建只会提醒。

**分享。** **导出**（`e`）会生成带 Mod 文件的 `.archopack`（不含游戏、DLC、存档和设置）。**导出列表**（`E`）会生成一个不含 Mod 文件的小型列表文件。导入时，会根据整合包的文件指纹逐一核对。

游戏关闭后，整合包链接（`!ArchoPack_…`）会保留，让下次启动更快；保存或启动普通列表时会移除它们。如果之后直接从 Steam 启动游戏，RimArcho 会提醒，并提供 **移除链接**。

**移到回收站**（`Delete`）可以移除整合包。

## 14. 贴图优化

**贴图优化**（`shift+7`）把 Mod 的 PNG 贴图转换为 DDS，让游戏加载更快、占用更少内存。它使用免费工具 todds（缺少时选择 **下载 todds…**）。

1. 选择当前列表或全部已安装 Mod，再选择缩放比例。
2. 可以先 **扫描统计**，查看 PNG 和 DDS 的大小，以及预计能节省多少空间。
3. **开始转换**。已经转换的贴图会跳过。

原始 PNG 会留在原处；RimArcho 在旁边写入 DDS，并记住自己创建了哪些文件。**清除全部贴图优化…** 只删除这些文件，让游戏重新使用 PNG。过期的转换结果（转换后 Mod 的 PNG 有了变化）会标出来。

## 15. 搜索文件与 Mod 设置

### 搜索文件

**Mod 库 › 搜索文件** 可以搜索 Mod 内的内容：默认搜索当前列表的 Def、补丁和 `About.xml`，也可以加入 C# 代码（按需用 ilspycmd 反编译）。结果以 Mod → 文件 → 匹配行的树状结构显示，旁边是文件查看器。找到结果后会陆续显示，不必等搜索结束。

`enter` 搜索；`alt+c` 区分大小写；`alt+r` 正则表达式；`n`/`N` 下一个/上一个匹配；`alt+z` 自动换行；`ctrl+o` 打开文件夹；`ctrl+c` 复制路径；`esc` 停止。搜索不会改动 Mod 文件。

### Mod 设置

**Mod 库 › Mod 设置** 列出当前列表中 Mod 的设置文件，包括 HugsLib 设置。选中一个，可以查看已保存的值；如果 Archo Monitor 读取过游戏内的设置界面，还能看到设置名称和默认值。

开关可以直接切换；数值或文本字段用 `enter` 保存、`esc` 取消；**恢复默认** 会移除已保存的值。每次修改都会立即写入文件，并保留一份 `.rimarcho.bak` 备份；游戏运行中或文件在此期间有变化时，会拒绝写入。复杂或含义不明确的值只供查看。**打开 Config 文件夹**（`ctrl+o`）。

## 19. 命令行

`archo help` 列出全部命令；`archo <command> --help` 显示该命令的选项。输出是带缩进的纯文本，AI agent 拿到的也是相同文本。

### 可以直接粘贴的引用

结果中有简短引用，可以用在下一条命令里：

| 引用 | 指向 |
| --- | --- |
| `#a3f9` 或 `a3f9` | 一个 Mod 副本 |
| `L#7c2e` | 同一个 Mod 的所有副本 |
| `pkg:ceteam.combatextended` | 按包 ID 指定 Mod（多个副本匹配时，会让你选择） |
| `ws:2890901044` | 一个工坊条目 |
| `p:3f2a1c` | 一个问题 |
| `log:E3` | 当前日志中的一个错误簇 |
| `r:1` | 你的一条规则 |
| `def:ThingDef/Gun_Revolver` | 一个 Def |
| `v3` | 列表历史中的一个版本 |

在 PowerShell 和 bash 中，开头的 `#` 要加引号（`archo mod "#a3f9"`），或者省略；不加引号会被当成注释开头。

许多会改动文件的命令支持 `--dry-run`，先显示将发生什么。卸载和部分存档操作需要 `--yes`。

## 20. AI agent（MCP）

`archo mcp` 让 AI agent（Claude Code、Codex 或任意 MCP 客户端）使用 RimArcho。它看到的事实和证据与你相同，也能执行相同操作；每个工具返回的内容，都与对应命令的输出完全一致。

**Claude Code：**
```
claude mcp add rimarcho -- C:\Tools\RimArcho\archo.exe mcp
```

**Codex**，在 `~/.codex/config.toml` 中：
```toml
[mcp_servers.rimarcho]
command = 'C:\Tools\RimArcho\archo.exe'
args = ["mcp"]
```

**任意客户端**，在 `.mcp.json` 中：
```json
{ "mcpServers": { "rimarcho": { "command": "C:\\Tools\\RimArcho\\archo.exe", "args": ["mcp"] } } }
```

默认提供诊断和修复列表的工具：读取 Mod、Def、补丁、Harmony 补丁、日志、Mod 设置、存档和 C# 源码；编辑、保存和启动列表；试运行；锁定版本；管理规则；忽略问题。添加 `--tools all`（`"args": ["mcp", "--tools", "all"]`），还可以让它管理整合包、订阅、Mod 库、贴图、内存估算、维护、标签和备注，以及修改 Mod 设置和存档。每个工具都会占用 AI agent 的上下文，所以需要它做这些事时再添加。

然后可以问：“我的日志有 `Patch operation … failed` 报错，是哪个 Mod 的问题？”，也可以直接粘贴堆栈。

**安全。** AI agent 对列表的编辑会进入与你相同的撤销历史。只读工具带有标记，客户端可以自动批准；会改动文件的工具也有相应标记，并且 AI agent 会被要求先预览、再询问你。实际是否需要批准，取决于 AI agent 程序的权限设置，请将其设为修改文件前先询问。AI agent 可以预览卸载，但不能执行卸载。

RimArcho 还自带 `rimworld-probe` agent 技能（位于 `skills/`），让 AI agent 创建一个小型测试 Mod，在游戏中运行，检查某个行为的实际结果（第 21 节）。

内置助手 Archo 计划在 1.1 推出（第 24 节）。

## 21. 试运行

试运行会用一个独立、用完即弃的用户文件夹启动真实游戏，不会影响你的存档、设置和日志。它会检查列表能否进入主菜单（加上 `--map` 则检查能否进入新建的测试地图），并报告加载时间、峰值内存、缺失的 Mod，以及分组后的报错和可能来源。它会与上次游玩的日志、上一次可比的试运行对比，让你看到改动修好了什么、又弄坏了什么。

```
archo test run
archo test run --map
```

**探针运行**（`archo test run --probe <folder>`）会加入一个专门编写的小型测试 Mod，在测试地图里布置场景并报告结果（也可以保存截图）。它用于检查一个具体行为；`rimworld-probe` 技能可以帮助 AI agent 编写探针。探针只在这次运行时链接进游戏，不会加入你的列表。

试运行支持 RimWorld 1.6 和 1.7，可通过命令行或 AI agent（`test_run`）使用。窗口中还没有试运行按钮。

## 22. 文件、备份与卸载

### RimArcho 会写入什么

只有你要求时，RimArcho 才会写入游戏文件：

| 位置 | 内容 |
| --- | --- |
| 游戏用户数据文件夹中的 `Config/ModsConfig.xml` | 保存或启动时写入你的列表；原文件保留为 `ModsConfig.xml.rimarcho.bak` |
| 游戏的 `Mods/` | 名为 `_Archo_…` 和 `!ArchoPack_…` 的链接（锁定副本和本地副本放在锁定库中，通过链接供游戏使用） |
| Mod 设置文件 | 只在你编辑设置时写入（保留 `.rimarcho.bak`），或为改名后的文件夹复制设置 |
| Mod 文件夹，包括工坊文件夹 | 只按要求操作：取消隐藏（`About.xml.disabled` → `About.xml`）、写入你转换的 DDS 贴图、把文件夹移到回收站 |
| 锁定库、整合包、下载位置 | 按你的要求复制和下载，放在你选择的文件夹中 |

除了这些由你发起的操作，不会改动 Mod 文件。移除 Mod、存档和整合包时，会送到 Windows 回收站；清除贴图优化时，RimArcho 自己创建的 DDS 文件会直接删除。

### RimArcho 自己的数据放在哪里

| 文件夹 | 内容 |
| --- | --- |
| `%APPDATA%\RimArcho\` | 数据库（列表、历史、标签、规则）、设置、缓存、日志；源码库、整合包和备份默认也在这里 |
| `%LOCALAPPDATA%\RimArcho\`（或你选择的文件夹） | 锁定副本、Archo Monitor、订阅、SteamCMD 及其下载、工具、账户会话 |
| 程序文件夹 | `RimArcho.exe`、`archo.exe`、文档、自带的 Monitor 和 agent 技能 |

### 备份

- **设置 › 存储 › 备份**（或 `archo db backup`）把数据库保存到数据文件夹中的 `backups\`。尝试旧版本前，请先备份。
- **游戏存档 › 备份** 把存档复制到 `backups\saves`。
- 游戏的列表有一份自动备份（`ModsConfig.xml.rimarcho.bak`）；完整的列表历史保存在 RimArcho 中。

### 卸载

关闭游戏和其他 RimArcho 窗口，再选择 **设置 › 卸载 RimArcho…**（或用 `archo uninstall` 预览，`archo uninstall --yes` 执行）。预览会列出每一步及相关文件夹和大小。默认会：

- 保留整合包和下载的游戏；
- 把只有 RimArcho 保管的存档移到你选择的文件夹；
- 把锁定副本移到回收站；
- 保留游戏当前的列表，但移除其中由 RimArcho 添加的条目；
- 移除它的链接、转换后的贴图、账户会话、数据和程序文件。

绝不会退订工坊条目，也不会移除普通 Mod 和存档。某一步失败时，RimArcho 会保留数据，方便你重试。

## 23. 常见操作

**从零建立新列表。** **全部列表** → **新建 / 导入** → **空列表** → **创建并编辑**。搜索，用 `space` 启用，用 `S` 排序，在 **能不能跑** 按 `F` 补齐依赖，再在编辑器按 `L`，到 **启动** 页面后再按一次 `L`。

**Mod 更新后游戏坏了。** **更新** → 找到该 Mod（**会影响启动**）→ 查看变更。想继续玩，可以对仍然能用的副本选择 **锁定这个版本**（或用 `x` 切换到旧副本），也可以停用它，并用 `t` 暂存依赖它的 Mod。检查 **能不能跑**，再启动。

**找出导致报错的 Mod。** 打开 **游戏日志**，选择第一个源头错误，阅读证据。如果还不明确，把一半可疑 Mod 暂存（`t`），启动并对比；用 `T` 放回。撤销可以还原全部改动。

**长期游玩，不受更新影响。** 把列表做成整合包（**创建整合包…**）。它有独立存档，内容不会改变。也可以只锁定你在意的几个 Mod。

**同时玩 1.6 和 1.7。** 在 **游戏** 页面登记两份安装，为第二份设置 **独立存档**，并标明每个列表的 **游戏版本**。需要旧版游戏时，可以用 SteamCMD 下载。

**把列表分享给朋友。** **导出…** → RimArcho 列表（对方能看到哪些版本一致）或工坊链接。要分享完全相同的文件，就 **导出** 整合包。

**载入朋友的列表。** **新建 / 导入** → 粘贴分享码、文件或合集链接 → **预览** → **全部订阅（N 个）** → **创建并编辑**。

**抢救旧存档。** **游戏存档** → 选择存档 → **能不能载入？** → 应用修复（或根据存档 **新建列表**）→ 检查列表 → 启动。

**从 RimSort 或 RimCrow 搬过来。** **设置 › 存储 › 导入…**，检查预览后导入。旧管理器的文件保持原样。

**请 AI agent 帮忙。** 连接 `archo mcp`（第 20 节），描述问题或粘贴报错。检查它提出的改动；它的编辑也可以撤销。

## 24. 本版本尚未提供的功能

以下功能已列入计划，但尚未提供：

- **Archo，内置 AI 助手**（1.1）：窗口中的助手面板，使用相同工具，改动前会请你确认。目前可以先通过 MCP 连接外部 AI agent。
- **未玩内容**（1.1）：读取不同殖民地的存档，找出你从未用过的 Mod 和内容。
- **一键订阅或退订整个工坊合集**（1.2）；目前已经可以跟随合集。
- **游玩主题与平衡冲突**（1.2）。
- **值得玩**（后续）：根据你还没玩过的内容，分享整合包并提供推荐。
- 窗口中的试运行按钮；把存档匹配到 Mod 列表*几乎*相同的列表；在 RimArcho 内从回收站还原；通用工坊搜索。

已知限制：部分 Mod 自定义的补丁操作无法模拟（RimArcho 会说明）；无法确定运行时才选择的 Harmony 目标；Git 订阅不支持私有仓库、子模块或 LFS；检测游戏是否运行仅支持 Windows。
