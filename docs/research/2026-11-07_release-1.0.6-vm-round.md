# Release 1.0.6: VM round

Date: 2026-11-07. The round walked [release-vm-tests.md](../../UserGuide/release-vm-tests.md) after the 1.0.6 release, on the 1.0.6 tree (9e22cf8f). The rows were merged into 10 VM sessions run by three agents in parallel, one per VM.

Left out by decision:

- every 1.7 part;
- every MCP-with-agent part;
- publishing to the Steam Workshop (rows on `archo workshop publish`);
- the real feedback send (row 59 was checked up to the send button; sent afterwards with the user's authorisation, see "Feedback relay");
- HugsLib's log upload (it posts a public gist);
- the LoversLab sign-in.

The publish exclusion was unnecessary. The real 1.0.5 and 1.0.6 publishes to the production item 3835688284 had already done what those rows ask, and this round checked their result (tags, last line, item contents, zip hash; see P2 below). The refusals need no publish, because `--dry-run` stops before Steam. They were checked on the host afterwards, all refused before Steam with a clear message:

- a description over 8,000 bytes;
- an empty description;
- a BMP preview;
- a 1 MB GIF preview;
- a prerelease version (`1.0.7-rc1`: "prereleases stay on GitHub only");
- a missing `UserGuide/release-post.steam.txt`.

The plain dry run lists the tags `Mod, 1.5, 1.6, 1.7` and both descriptions ending "RimArcho v1.0.6". The three publish rows left the table. Only the check that a 1.0.6 install finds the next release through the Workshop remains, for the next release.

Evidence is kept outside the repository: `D:\RimArcho-test\release-1.0.6\<VM>\<session>\`, with the shared brief in `BRIEF.md`, the queues in `QUEUES.md` and each VM's `findings.md`. The rules were the same as in the [1.0.1 round](2026-11-05_release-1.0.1-vm-round.md), with one change: each VM stopped after 3 confirmed app bugs. New this round: the guest input agent (`scripts/vm/input.mjs`) made the TUI, real-mouse drag and drop and native dialogs testable. The 1.0.1 round could not reach them.

## Result

8 app bugs were found and fixed. Each fix has a regression test. The fixes were merged into `dev/1.0` and all 8 passed a VM retest (see "Retest").

| Commit | Fixes |
| --- | --- |
| `144c8ac7` | **Use This Instead replacements were all ignored** (row 30). Two rules in the current list have a number as `oldPackageId`, and the strict decode dropped the whole file. With no replacement rules, no continuation stood in for the original, so sort, Can it run and Start reported missing dependencies (MultiFloors → Prepatcher). Bad records are now skipped one at a time; the Steam Workshop index and the community sorting rules had the same all-or-nothing decode. **"Install and restart" from the Workshop item deleted the item's own `README.md`, `README.zh-CN.md` and `skills\`** (row 37), the same class as the LICENSE bug fixed on 11-06. **A failed `archo data update` reported "community data updated"** with the downloaded version, after the error and the restore of the old data (row 63); the window's update task did the same. |
| `c547b78d` | **The Launch page redrew itself every 30 s while the game ran**, so the running-game dot blinked again each time and each redraw cost CPU (row 25). **Dragging a Mod across a status badge opened its problem popover**, which covered the rows below and swallowed the drop (row 50). **Adding two games of one version gave both the name `1.6-2`**: the first was added and the second failed (rows 15/19). |
| `30cd43e8` | **Command panel typos did not find commands in a real library** (row 27): `subscirbe` found nothing and `sotr` put `sort` 140 rows down. The palette matched only the command's English display name, not its key. A loose letters-in-order match on a long Mod name also outranked a typo match on a command. The unit test passed only because it built the entry differently from the GUI and the TUI; the new tests build the palette as both surfaces do, with 1,000 Mod names. |
| `edb7c680` | **The window often missed a game that was already running** (row 62): 8 of 11 starts. The Monitor check at every window start dropped the window's board whenever `monitor install` printed `plan:X: not added: no Harmony`, and the snapshot re-read never restored it. `Live` then reported no game, Start offered launch and the save button, and the exit was never noticed. A workspace write before the start hid it, which is why the CLI and TUI never showed it. |

## Feedback relay

Row 59 ran after the round with the user's authorisation, on Eval-2 with the real 1.0.6 release, no relay override, and at most two reports sent.

Passed:

- the window said "sent as #1", and its link opened the issue;
- [#1](https://github.com/ToumanLin/RimArcho/issues/1) and [#2](https://github.com/ToumanLin/RimArcho/issues/2) were opened by `app/rimarcho` with the `feedback` label;
- each body equals the preview and has no contact;
- `wrangler kv key get contact:N` returned the fake contact `relay-test@example.invalid`;
- both issues were closed with a comment.

Two problems, both on the deployed Worker:

- **The one-report-a-minute limit did not refuse a second report sent 13 s after the first** (#2, same sender). The Worker has the `PER_MINUTE` binding (it refuses to run without it). Cloudflare documents its rate-limit binding as approximate and local to each location, so a limit of 1 a minute is not dependable. The daily caps (5 per sender, 30 in total, in KV) still hold. Not fixed: a sturdier check (for example a last-send time per sender in KV, which reads back at once in the same location) needs a code change and a redeploy of the live relay.
- **The deployed Worker is older than the repository.** Its footer reads `Sent from RimArcho's 反馈 page`; the repository's has said "Feedback page" since 4291cb1d (2026-10-31). The last deployments are secret changes on 2026-10-31.

Not covered: the TUI `s` send, because the two-send budget was used up when the second report went through.

## Tooling notes

- `round.ps1` and `vm.ps1` have no `-StandardUser` for round steps on the Staged4 clones (`新玩家` signed in); Eval-3 used a scratch copy with it on.
- On the clones, the game needs Steam for Workshop Mods. With Steam off, Eval-3 used a local copy of Harmony and clicked Ignore on the Steam API dialog with the input agent.
- After one Player-Test revert, Steam ran in session 0, so a game started from a non-interactive `exec` had no window. Restarting Steam from the desktop session fixed it.
- A Launch button with launch mode `steam` on a clone starts Steam, which kicks Player-Test's Steam. It happened once, for under three minutes, and did not hit a Steam-route step.
- `vm.ps1 build` from a worktree without `dist/vm/RimArcho/fonts` makes a zip without the font folder (58 MB instead of 76 MB). It was rebuilt with the folder for the retest.

- On Player-Test, Steam downloaded about 50 of the 123 pending client updates after the Updates page's "Update all" (guest only).
