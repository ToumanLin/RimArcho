## Found and fixed

- **Launch's "last game N errors" counted items, not errors** (row "Shorter paths (D4–D7)", 16 §2.1). After a run whose log had 68 errors from [SSR] Solar System Republic Combat Part (missing its framework) and 1 of unknown source, Launch said `2 个错误`: `view.LastRunErrors` counted Can it run's last-run items. It now adds up the errors those items name. `TestLastRunErrorsAddsTheItemsErrors`.
- **Updates: "checked 3 sources" over a source "not checked yet"** (row "Update marks (V6)", 16 §2.9). After the RC's first automatic check, the summary under Updates counted SteamCMD, Git and the download-page sources, which have no Mods and are not listed, while the one listed (Steam Workshop, 1,299 Mods) showed ○ not checked yet. The summary now counts the listed sources; one reads "checked 1 source" (it said "1 sources"). `TestSourceSummaryCountsListedSources`.
- **"1 mods changed"** on the Launch page in English (row "GUI fixes 2026-11-19", 16 §2.1). One changed Mod is now singular, with its Chinese and Japanese lines. `TestHomeTextSingular`.
- **Play review: Ideology under "never seen" with 36 seen** (row "Play review: map groups and grouping dropdown", 16 §2.11). On colony B 03 (a 1.7 day-0 save), By progress put Ideology alone under never seen in the saves; its In the saves card and `archo saves review` said 36 of 564 seen (culture 18, appearance 12, abilities 4, buildings 1, hediffs 1). The square of a mixed Mod counts only its meet categories (factions, animals, research, events, quests: all 0), and the page then treated part 0 as never seen unless the Mod was only set up. A Mod with part 0 that the saves did show now goes under picked from, some in use. `review.mjs` "a mixed Mod seen only in what is picked from is not under never seen".
- **Editor launch with the game running switched the list and asked about RAM** (row "(a) Launch from the list editor", 16 §2.5). With r11 running, `L` on list `default` made `default` current ("no game file was written") and then opened "RAM may be insufficient", the running game using the RAM; only "launch anyway" would have reached the refusal. The editor now refuses first while a game runs (or another Game Config's on its installation) and changes nothing. The launch logic moved to `editorlaunch.js`; `editorlaunch.mjs`.
- **Launch's last game line stayed "not checked yet"** (row "Shorter paths (D4–D7)", 16 §2.1). With the RC 2 build installed over RC 1, Launch said `last game  Nov 22  not checked yet` while Can it run said "no errors in the last run". The log's stored report is keyed to the analysis and the Mods; a new build, a later check or a Mod Steam updates makes it miss, and Launch only read `Player.log` when it was newer than the last read, so nothing read it until Can it run was opened. Launch now reads it when its report is missing too. `TestHomeReadsALogWhoseReportNoLongerMatches`.
- **A test run without Steam: Workshop Mods "not loaded"** (row "Test run attribution after a stale analysis", 20 §2). With the guest's Steam closed, `archo test run` on r11 (25 Mods) said `NOT TESTED: these Mods were not loaded: Harmony, …` for the 11 Workshop Mods that have a settings class (two runs, 8 of 8 counted). The run took the Workshop folder as visible, so it expected those Mods under `Workshop/<id>`; without Steam the game can only load them from `Mods/`, here through the `_Archo_workshop_<id>` links the 22:37 launch without Steam had left, and after a launch with Steam (links removed) not at all. Test runs only linked SteamCMD, extra-folder and pinned copies. Now, while Steam is not running, the Workshop folder does not count and the list's Workshop Mods are linked as a launch without Steam links them (existing launch links are used as they are). RC 3: 19 of 19 loaded from `Mods/_Archo_workshop_*`, nothing missing, status menu. `TestTestRunWithoutSteamLinksWorkshopMods`.
- **An unsubscribed Workshop Mod stayed "subscribed"** (row "New Mods are marked", 04 §1.2). `archo workshop unsubscribe` on two Mods tagged "I Dont Need It" (Quick Stockpile Creation, Die for me) succeeded and `workshop state` (Steam API) said "installed", not subscribed, but Steam kept both folders (also after a Steam restart). The next scans said "changes: none"; `archo trash` refused ("a subscribed, loadable mod") and `workshop subscribe` said "subscribed already". The ACF listed 1,299 items under `WorkshopItemsInstalled` and 1,297 under `WorkshopItemDetails`: the two missing from Details were exactly the unsubscribed ones. RimArcho counted either list as subscribed; Details is now the subscription list (Installed only when a manifest has no Details entries). `TestACF`.
- **`workshop subscribe` on a removed Mod: "subscribed already"** (row "New Mods are marked", 11 §2). On RC 4, after Steam had deleted the two unsubscribed folders, the scan kept tombstones and Steam said "not subscribed", but `archo workshop subscribe ws:1742151109 ws:2403695576` answered "#kkf5 is subscribed already": only a leftover folder was accepted. A tombstone is now accepted too. `TestWorkshopSubscribe`.
- **1.7: a Steam warning counted as an exception** (row "Game log (1.7)", 06 §1). After the 1.7 launch without Steam, `archo log --env 1.7` listed `log:E3 exception x1 [Steamworks.NET] SteamAPI.Init() failed`, a warning. Its caller stack has an engine frame ending ` [0x6] in D:\Workspaces\…\PlatformBase.Loop.cs:143`; only frames ending ` [0xNN]` counted as caller frames, so that one was taken for an exception frame. The optional ` in <file>:<line>` suffix now counts, and stored log reports are read again (log cache version 24: RC 5 without the bump still showed the stored E3). `TestParseWaylithCallerFramesWithFile`.
- **`env list`: no player-log for the 1.7 own-saves Game Config** (row "`env list` on a 1.7 own-saves Game Config", 03 §3.3). After the 1.7 launch, `archo env list` showed `user-data: …\RimArcho\userdata\1.7` and no `player-log`, while `archo log --env 1.7` read `LocalLow\…\Logs\Player.log`: 1.7 ignores `-logfile`, so the user data folder had no log. `env list` looked only there; it now also takes the default folder's log the way `archo log` does (owned by the newest Waylith launch). `TestWaylithOwnConfigReadsDefaultLogs`.
- **The 1.6 Game Config read the 1.7 run's log** (row "`env list` on a 1.7 own-saves Game Config", 06 §4). After the 1.7 launch, `archo log --env 1.6` showed the 1.7 log `LocalLow\…\Logs\Player.log` with `analysed: as 1.7 (log version); Game Config is 1.6`. env:1.6 uses the default folder, where its own `Player.log` was gone; the 1.7 Game Config has its own saves, so its launches were not among the records checked for a default-folder log, and the file counted as an unknown run of this one. A Waylith-format log whose newest Waylith launch is another Game Config's is now that Game Config's. `TestOlderGameSkipsWaylithRunLog`. Not investigated: what removed env:1.6's `Player.log` between the 23:40 test runs and the 1.7 launch at 00:03.
- **"1 problems"** in the list editor's head (row "(a) Launch from the list editor", 16 §2.5). Opening list `default` (one problem) showed `1 problems`; the problem panel's title had the same plural. Both are singular for one now. `needs.mjs` "the editor's problems button is singular for one problem".

## Open: decisions for the player

- **1.7 memory estimates on small dedicated VRAM** (rows "Memory bars (V1) on real hardware", "Memory estimate: 1.7 texture VRAM/RAM capped", 16 §2.4). DXGI reports VMware SVGA 3D as a hardware adapter with 4 MB of dedicated memory, so Cap17 caps every 1.7 texture estimate at the card's upload watermark: `plan cost` on r11 in 1.7 says RAM for Mods 31–71 MB, against 266–550 MB for the same list on 1.6, and the VRAM bar reads 4.0 MB instead of `—`. The row expected no cap in the VM. Integrated GPUs (small dedicated memory, the Vulkan heap in shared RAM) would get the same understated 1.7 RAM. Either treat a dedicated size under some floor as unknown, or read the Vulkan heap; not changed in this round.
- **Lanzou downloads no longer work** (rows "Self-update from three sources", "Self-update download", 17 §5.1). `archo update` on a 1.0.8-labelled build: GitHub has no v1.0.10 (404), Lanzou lists 1.0.10, and its `downprocess` API answers HTTP 419 (the live probe `TestLiveLanzou` too). The page's own fallback (domain2 `apifile.lanzouw.com`, `kd=0`) answers, but the download node then asks for human verification, so it was reverted, not committed. The update stops safely with the manual path and an ops row "refused". 1.0.10 is on Lanzou only.
- **Can it run kept the old list after `archo plan use`** while the window was open (row "Shorter paths (D4–D7)" setup). Launch followed the CLI's switch to r11; Can it run kept showing list `default` across a page reload until the window restarted. Matters when an agent switches lists through MCP with the window open. Not investigated.
- **env:1.6's `Player.log` disappeared** between the 23:40 test runs and the 1.7 launch at 00:03 (default folder, no RimArcho rotation there). Not investigated; it is what let the 1.6 Game Config read the 1.7 log (fixed above).
