## S1: upgrade from 1.0.8, tags

Player-Test reverted to `RimArcho-Real-Vulkan`. The snapshot's database is a pre-1.0 build (schema 18), so a 1.0.8 home was made first: the real 1.0.8 built from tag `v1.0.8` (the host's `dist\archo-1.0.8-windows-amd64` is a dirty rebuild at schema 35, not the release), a fresh data folder on the real library (1,300 Mods, cold scan 440 s), list `vm109` with Harmony, HugsLib, Vanilla Expanded Framework, Weapons, Apparel, Furniture, Architect, Dubs Bad Hygiene, Alpha Animals and Archo Monitor, tags with one Mod carrying two, a tag note, a stored `tags.pinned` of `framework,weapons,QoL,testing`, and the 202 real saves indexed (15 s). That home is kept in the guest as `%APPDATA%\RimArcho.108-backup` for a repeat. Then build `c3c1dd60` (unversioned `0.0.0-vm`, so the home offers "1.0.8 available"; expected for a test build).

Passed:

- Database 33 → 35 on first open; tags, the note, colours and the stored pinned list kept. The first scan tagged Core and the five DLCs `RimWorld` and put it in front of the stored pinned list once.
- Tag colours and order (CLI and window): `red` and `#ff00f` refused, rename keeps the colour, order sets the first tag. In the editor the three neighbouring VE Mods join into one blue band, custom red on Alpha Animals and Dubs, and Vanilla Weapons (first tag uncoloured, second blue) has no band.
- `RimWorld` removed from Biotech stays removed through a full rescan and a new process; deleting the tag keeps it gone and drops it from the pinned list.
- Tag click in details opens the Tag manager; a colour shows in 28 ms; sort by Mod count and A–Z both ways; no script errors.
- Disabled column grouped by tag on the real 1,289 disabled Mods (the host scripts run against the VM window, with the synthetic names replaced): headers in the Tag manager order, cursor kept, Home / ← / → / ↓, collapse and expand all, header clicks, space and `u`, `tags:content` (a Mod whose first tag is VE shows under VE as "1 / 2"), esc, scroll p95 5.7 ms, grouping and folds kept after a reload.
- Tag manager on a Disabled header and in Mod library › Tags (Home to the first header): F2 rename and back, esc, `n` note field, Del confirmation names the Mod count and cancels, chip jumps to its group.
- Tags popup (`g`): pinned then own tags, typing narrows, a new word gives "new tag …", esc closes.

Found and fixed:

- After the upgrade the home page said the last game had "no errors" while its log was not analysed yet (the log cache version moved to 22, so every upgrading player sees this until the analysis runs; 1.0.8 had said 13 errors). The home's last-game line now says "not checked yet" for a log not analysed yet, in the window and the TUI. Retested on a fresh upgrade of the 1.0.8 home: "还没检查", then 13 errors after the analysis.

Not covered: real-mouse drag of tags in details, Narrator, 150 % scale (session S6), light theme.
