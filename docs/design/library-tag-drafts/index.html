What changes

  1. View switch at the right of the table heading: Mods | Tags. Saved in ui.gui.library.view. Filters, sorting, columns and selection carry over between views.
  2. Tags view adds a group header row per tag: name, Mod count, total size and the first line of the tag note. Mods inside a group sort by the current column; their copies expand as today (└ SteamCMD, └ Workshop).
  3. A Mod with several tags appears in each of its groups; a small +2 marks that it also sits elsewhere. Mods without tags gather in No tag at the end.
  4. Group order follows the tag bar (16 §3.8): pinned tags first, then by Mod count. Groups that the filter empties disappear.
  5. Cursor on a group header, or no Mod selected: the left details become the Tag manager. Cursor on a Mod or copy: the usual Mod and copy details.

Tag manager

  • Rename: the tag name is an editable title. Renaming to an existing tag turns into a merge preview.
  • Note: one note per tag, shown in the group header and in tag candidates.
  • Merge into…: pick a target (or type a new name); the preview counts Mods that already have both. Several tags can be checked in the list and merged at once.
  • Delete: inline confirmation naming the Mod count. Only removes the tag from Mods; files and lists are untouched.
  • Similar tags hint: names equal apart from case, spaces or plural (visuals, Visual, visual effects?) get a one-click merge suggestion.
  • Tag changes stay player data, outside plan undo (16 §3.8), so delete and merge always confirm.
